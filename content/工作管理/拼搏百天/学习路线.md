# 具体技术课题清单（建议你照这个打卡，而不是泛泛地学）

## 1）可观测性 / 告警治理（强烈建议优先）

- RED / USE 的适用边界
- SLI / SLO / Error Budget / Burn Rate
- 告警分层：症状告警 vs 根因线索告警
- 告警风暴抑制、聚合、去重、拓扑收敛
- 指标治理：标签治理、基数治理、命名治理
- Logs / Metrics / Alerts / Events 时间线统一
- Runbook 体系化设计
- 事故复盘如何反哺告警与平台

## 2）K8s / 云原生（必须补）

- Pod 生命周期、探针、驱逐、QoS
- requests/limits 与性能/稳定性的关系
- HPA/VPA 的优缺点与边界
- PDB、滚动发布、发布风险控制
- Service / DNS / Ingress 常见故障
- 节点压力、调度失败、资源争用
- 存储/CSI、网络/CNI 的典型问题
- 多租户资源治理与集群容量模型

## 3）MySQL（作为“底层短板修补包”）

- MVCC 到底解决什么、当前读是什么
- RR 下幻读、间隙锁、next-key lock
- 联合索引与加锁范围
- 执行计划与回表
- 慢 SQL 分析路径
- 连接数、线程池、锁等待、事务时间的关系

## 4）Java/JVM（只补基础核心，不建议重仓）

- JMM：可见性/有序性/原子性
- CAS、AtomicLong、LongAdder 差异
- 线程池参数设计
- 连接池与请求并发关系
- G1 / ZGC 基础思路
- Arthas / JFR / async-profiler 的基本用法和定位场景

## 5）中间件（选 2 个重点）

### Redis

- 热点 key、击穿、雪崩、穿透
- 一致性策略
- 失效抖动治理
- 内存淘汰与命中率分析

### Kafka

- ISR、ACK、重平衡、积压、吞吐瓶颈
- Broker/Topic/Partition 监控体系
- 消费延迟与堆积治理

### ES

- 分片、副本、segment、merge
- 写入/查询性能瓶颈
- 集群健康与扩缩容风险

# 时间规划建议（按你“还要兼顾工作”的现实情况来）

我不建议你搞“大而全”学习。你现在最需要的是**少而深、能形成产出**。

## 0 ~ 3 个月：先补“表达体系 + 底层短板”

**目标：把你已有经验组织起来，并补最容易在面试/沟通里被追问的短板**

- 输出 6~10 个真实故障案例模板
- 把你的告警治理/AIOps项目写成标准化项目说明
- 补 MySQL 锁/事务/索引
- 补 Java 并发/JMM/线程池/连接池核心点
- 学 SLI/SLO/Burn Rate 的实战表达

> 这个阶段的关键不是学很多，而是**把你已经会的东西讲清楚**。

---

## 3 ~ 6 个月：主攻 K8s + 可观测性体系

**目标：把你从“大数据 SRE”往“通用平台/SRE”推进**

- 深补 K8s 运行机制与常见故障
- 建立完整的“症状告警 + 根因线索 + runbook”设计思路
- 把 Logs / Metrics / Events / Alerts 的统一时间线思路补齐
- 尝试把你手头项目中的一些设计沉淀为通用方案

> 这个阶段结束后，你的职业标签会明显更通用。

---

## 6 ~ 12 个月：补中间件稳定性 + 打磨 AIOps 可信能力

**目标：形成你自己的“平台竞争力”**

- 选 2 个中间件深挖（推荐：**Redis + Kafka** 或 **Redis + MySQL**）
- 补 AIOps 的：
    - 证据链
    - 时间线对齐
    - 误判控制
    - 人在回路
    - 价值度量
- 完成 1~2 个可以拿出来讲的“平台化成果”

> 这个阶段的产出，最适合写进简历、答面试、做转岗/跳槽准备。

---

## 12 ~ 18 个月：形成“稳定性平台工程师”的完整标签

**目标：你不再是“大数据 SRE”，而是“稳定性/平台/可观测工程师”**

- 让 K8s、可观测、告警治理、AIOps 四条线形成闭环
- 做一个成熟的项目叙事：  
    “问题背景 → 数据地基 → 平台能力 → 价值结果 → 风险控制”
- 如果环境仍旧消耗大于成长，就可以择机切换平台/infra方向岗位

# 关于你是不是“掉队了”

我尽量说得直接一点，但不做那种拍脑袋式“人群排名”。

## 我的结论：

### **你不但没有掉队，反而在“方向性”和“系统能力”上，属于走得相对快的一类。**

但这个“快”不是那种：

- LeetCode 刷得多
- 八股背得熟
- 某个框架 API 特别熟

而是另一种更稀缺的“快”：

> **你在比较早的阶段，就已经具备了复杂系统、生产环境、稳定性平台、告警治理、运维产品化的视角。**

这在同龄/同年限工程师里，我会把它看成一种**明显的方向性优势**。

---

## 为什么我这么判断

### 你比很多同年限工程师更强的地方：

- 不是只会写业务代码
- 不是只会看 dashboard
- 能抽象问题、做平台、讲边界、懂落地
- 对“真实线上系统”有感觉
- 知道数据地基的重要性，知道 AI 不是魔法

### 你目前不占优的地方：

- 某些底层细节（MySQL、JVM 并发更深层）不够稳定
- 云原生通用性还没完全拉满
- 体系化表达还可以更好

---

## 所以更准确地说：

你不是“掉队”，你是**已经走上了一条比较稀缺、但也更吃体系化和平台化能力的路**。  
只要你未来一年把下面三件事补上：

1. **K8s / 云原生**
2. **可观测/告警/稳定性方法论表达**
3. **关键底层短板（MySQL + JVM/并发）**

你会比很多“只做业务开发”的同龄人更有辨识度。
