### Multi-Agent 规则转换流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant MA as Master Agent<br/>(DeepSeek-V3)
    participant CA as Converter Agent<br/>(DeepSeek-R1)
    participant MaA as Matcher Agent<br/>(DeepSeek-V3)
    participant DB as 数据库

    U->>MA: 发起转换请求（SSE 流式）
    MA->>MA: ReAct 规划执行路径
    MA->>CA: 下发转换任务（≤5条/批）
    CA->>CA: CoT 逐步推导 Zabbix 表达式语义
    CA-->>MA: 返回 Foxeye 格式配置
    MA->>MaA: 提交语义验证
    MaA->>MaA: 新旧规则语义打分
    MaA-->>MA: 验证结果（通过/拒绝）
    MA->>DB: 保存 conversion_task + rule_mapping
    MA-->>U: SSE 推送结果（含工具调用事件）
```

### 规则匹配三层策略

| 层次 | 方式 | 触发时机 |
|------|------|---------|
| L1 Fingerprint | 规则名称 + 阈值结构化匹配 | 定时 rule_sync_job 自动执行 |
| L2 LLM 语义 | Matcher Agent 语义打分 | Fingerprint 未命中时 |
| L3 手动 | 用户在规则管理页手动绑定 | L1/L2 均未命中时 |

### Step 2：端到端验证（3.17-3.19）

```bash
# 启动服务
go run cmd/server/main.go

# 发起转换请求（SSE 流式）
curl -N -X POST http://localhost:8080/api/v1/convert \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"trigger_ids": ["<ID1>","<ID2>"]}'
```

验证要点：
- Master Agent 是否正确规划 ReAct 路径（日志中打印 `[ReAct]` 步骤）
- Converter Agent 返回的 PromQL 是否可在 VM 上执行（Matcher Agent Tool 验证）
- `conversion_task` 和 `rule_mapping` 是否写入 DB

### Step 3：Docker Compose 配置（3.18-3.20）

```yaml
# docker-compose.yml 关键结构
services:
  backend:
    build: .
    environment:
      - ZABBIX_URL=${ZABBIX_URL}
      - FOXEYE_URL=${FOXEYE_URL}

    build: ./web
    ports: ["3000:3000"]

    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=${DB_PASSWORD}
```
