# 日志类告警迁移执行

## 目标

将 Zabbix 中归类为「日志类」的告警规则（基于 log[] item 关键字/正则匹配），通过告警迁移系统转换为 Foxeye LogQL AlertRule，按组件分批完成双跑验证。

## 外部依赖清单

| 依赖项 | 状态 | 说明 |
|---|---|---|
| Alloy 阶段一（系统日志） | ✅ 已上线 | `/var/log/messages` 已接入 Loki |
| Alloy 阶段二（大数据服务日志） | ✅ 主节点已接入 | NN/RM/HS2/DN/NM/HBase/ZK |
| Alloy 阶段二（CVM+中间件） | 🔄 doing（超期） | Kafka/ES/Druid/MySQL |
| Spark 作业日志 | ❌ 不接入 | 作业日志已聚合到 HDFS，不走 Loki |
| Label Schema 统一 | ⚠️ 存量未修正 | 跨组件 LogQL 标签一致性 |

## 日志类告警迁移的关键差异

与指标类不同，日志类告警迁移需要额外验证：
1. Zabbix log[] item 中的**关键字/正则**是否在 Loki 对应日志流中存在
2. LogQL 的 `count_over_time` 阈值是否与 Zabbix `count()` 等价
3. 日志级别过滤是否正确（Loki label `log_level` 与 Zabbix 日志级别对应）

## 执行步骤

### 第一批：Loki 已接入 + Label 规范的大数据组件

1. [ ] 从 [[Zabbix规则迁移状态梳理与分类]] 提取日志类可迁移规则
2. [ ] NameNode 日志告警：Full GC / RPC 超时 / 块上报异常
3. [ ] DataNode 日志告警：磁盘错误 / 块复制超时
4. [ ] ResourceManager 日志告警：应用提交失败 / 队列超限
5. [ ] HiveServer2 日志告警：OOM / 连接池耗尽 / Tez Session 失败
6. [ ] HBase / ZK 日志告警
7. [ ] 每批执行：Converter Agent（LogQL 生成） → Loki 试查验证 → Foxeye 导入 → 双跑

### 第二批：Loki 接入中的组件

8. [ ] Kafka 日志告警（依赖 [[CVM与中间件集群Loki接入]] 完成）
9. [ ] ES/Druid 日志告警（同上）

### 与新建日志告警规则的协调

- 存量 Zabbix 日志规则迁移 → 本任务范围
- **新建** Foxeye 日志告警规则（如 HS2 OOM / NN Full GC 等新场景） → 由 [[Foxeye基于Loki日志的告警规则添加]] 覆盖
- 两者不重复：迁移 = 已有规则平移；新建 = 填补 Zabbix 时期缺失的日志告警

## 验收标准

- 第一批可迁移日志类规则通过系统转换并导入 Foxeye
- 每条 LogQL 在 Loki 中实际查询返回非空结果（验证数据存在）
- 双跑验证漏报率为零
