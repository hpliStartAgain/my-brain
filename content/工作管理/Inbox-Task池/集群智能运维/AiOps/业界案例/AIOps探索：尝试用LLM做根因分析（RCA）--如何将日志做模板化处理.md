借昨天的文章[AIOps探索：尝试用LLM做根因分析（RCA）的可行性探索](https://mp.weixin.qq.com/s?__biz=MjM5MTk1ODE0MA==&mid=2648442347&idx=1&sn=8028c30236b3a49df34d41e8a28c908c&scene=21#wechat_redirect)继续后面的话题。其实这个方案最难搞的就是前面两步。

首先看数据清洗和模板化，这里最常见的数据就是日志，我觉得有必要给大家举一个具体的例子，比如我有这样一段日志：

```
ERROR: Connection timeout to 10.0.0.1 after 3000ms
```

如果在以前，我们会用ELK或者grep硬搜。但现在我们可以使用LLM做智能分析，直接把这些原始日志扔进Prompt或者向量数据库，如果数据量小可能还好，但日志量很大时（比如有上百万行）会有两个大坑：

**1）烧钱（Token 浪费）**：`10.0.0.1和``192.168.1.5对人类来说是同一个意思（IP地址），但对 LLM 来说是完全不同的Token。`

**2）幻觉（干扰语义）**：大量的随机数字、ID、时间戳，会稀释掉日志里的核心报错信息，让模型抓不住重点。

所以，在把日志投喂给AI之前，必须要做一步关键操作：**日志模板化（Log Templating）**。

简单说，就是把“变量”抠掉，只保留“骨架”。我之前尝试过自己写正则（Regex）去匹配，结果刚写了10几个规则就想砸键盘了，因为太TM累了，而且很难覆盖所有情况。

后来发现，业界其实早就有了成熟的算法叫**Drain**（IBM 提出的），而且 Python社区已经有了现成的库`drain3`。不需要自己造轮子，几十行代码就能实现**毫秒级**的日志聚类。

今天把这个脚本整理了一下分享出来，大家可以直接拿去跑跑看。环境准备很简单，装个库就行：

```
pip install drain3
```

代码逻辑很直白：模拟了一批带噪点的日志，通过Drain算法自动提取出通用的模板。脚本内容：

```
import sys
```

执行脚本：

```
python LogTemplateMiner.py  yourlog
```

#### 为什么要这么做？

**1）极度压缩**：哪怕你一天有1000万条日志，经过这么一处理，最终去重的“模板”可能只有几百个。

**2）精准统计**：以前你很难统计“超时错误”出现了多少次，因为每个报错内容都不一样。现在你只需要统计`Template_ID=1出现了多少次，异常检测瞬间变得简单了。`

**3）LLM友好**：当你把`<:IP:> 这种抽象过的模板喂给DeepSeek时，模型不再被细节干扰，它能一眼看出“哦，这是个网络超时问题”。`

做技术这么多年，越来越觉得：**很多时候，难倒我们的不是高深的算法，而是对数据的预处理。**

这个脚本虽然简单，但它是构建**RAG检索增强生成）** 监控系统的地基。先把数据洗干净，再让AI介入，这才是工程落地的正道。
