最近Agent Skills确实很火，于是这两天我也研究了下。有不少同学觉得Skill出来之后是不是就不用再去搞那些MCP了。

先说我的观点：当前阶段在AIOps领域（其它领域不在该文章讨论范围内）我们还得以MCP为主，Skills还不能胜任我们的需求。但后面大趋势肯定是Skills绝对可以替代绝大多数MCP。

#### Skills和MCP对比

一句话总结：MCP 解决的是“怎么连世界”，Skills 解决的是“怎么把事情做好”。

**MCP = USB 协议**

- 统一接口
    
- 标准化连接
    
- 不关心你要“干什么事”
    

**Skills = 应用程序 / 使用说明 + 自动化流程**

- 告诉 AI **什么时候用什么工具**
    
- 告诉 AI **一步步怎么做**
    
- 控制复杂度和注意力
    

|           |                                  |                                 |
| --------- | -------------------------------- | ------------------------------- |
| 维度        | MCP（Model Context Protocol）      | Skills                          |
| 核心定位      | 通用能力连接协议 / 标准接口                  | 面向任务的能力封装与工作流                   |
| 设计目标      | 解决“AI 如何标准化地连接外部世界”              | 解决“AI 如何高效、准确地完成具体事情”           |
| 本质        | 协议层、基础设施层                        | 应用层、方法论层                        |
| 提供方       | 通常由第三方平台或工具提供（如 GitHub、数据库、SaaS） | 通常由 Agent / 开发者 / 团队自行构建        |
| 工具暴露方式    | 一次性全量暴露：连接即注入所有工具定义              | 渐进式披露：先加载元数据，再逐步深入              |
| Token 消耗  | 极高：每个 MCP Server 的所有工具都要进上下文     | 极低：只加载当前阶段所需信息                  |
| 可扩展性成本    | MCP Server 越多，Token 成本和复杂度越高     | Skills 数量增加，对 Token 压力较小        |
| 对模型注意力的影响 | 注意力分散，工具多时调用准确率明显下降              | 注意力聚焦，模型只关注当前步骤                 |
| 工具调用准确率   | 工具越多，准确率越低（基准测试已验证）              | 即使中等模型，也能保持较高准确率                |
| 适合场景      | 通用能力暴露：数据库、云 API、SaaS、地图服务       | 重复性流程：文件处理、代码 Review、写作规范、固定工作流 |
| 是否“按需加载”  | 表面支持，但连接成本已提前支付                  | 真正的按需加载                         |
| 是否会被替代    | 不会被淘汰，但使用频率会下降                   | 将成为 Agent 的主力能力组织方式             |
| 未来角色      | 少量、通用、底层连接                       | 大量、业务化、教 AI“怎么做事”               |
