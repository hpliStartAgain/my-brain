# 学习生命周期协议

本文件定义 `learn` skill 的五阶段状态机、阶段转换规则和会话续接协议。

---

## 一、状态机总览

```
ROADMAP → GAP_CHECK → LEARNING (循环) → COMPLETED
```

学习状态完全编码在文件中（`index.md` 的内容和节点状态），不依赖会话内存。每次调用 skill 时重新检测状态。

---

## 二、阶段转换规则

### ROADMAP → GAP_CHECK

**触发条件**：`<topic>/index.md` 已创建，包含完整的节点列表和依赖图。

**验证检查**：
- index.md 有 YAML frontmatter
- 有 `## 主干道节点` section，包含至少 5 个节点
- 有 `## 节点依赖` section

### GAP_CHECK → LEARNING

**触发条件**：index.md 中已有 `## 知识清单对照` section。

**验证检查**：
- 知识清单对照 section 中有权威源名称
- 每个排除项有明确原因

### LEARNING → LEARNING（节点间循环）

**触发条件**：当前节点学习完成，还有未完成节点。

**动作**：
1. 当前节点笔记文件已创建并写入
2. index.md 中该节点状态更新为 `✅ 已完成`
3. 检查依赖图，找到下一个可学习的节点（前置依赖已完成）

### LEARNING → COMPLETED

**触发条件**：所有节点状态为 `✅ 已完成` 或 `✅ 已合并`。

**动作**：
1. 更新 index.md 的 YAML status 为 `completed`
2. 更新 `USER.md` 已掌握概念
3. 向用户建议后续巩固方式

---

## 三、会话续接协议

### 场景一：用户指定主题

用户说"继续学 Redis"或 `/learn redis`：

1. 读取 `redis/index.md`
2. 解析节点表格，找到第一个 `⬜ 未开始` 的节点
3. 读取该节点的前一个已完成笔记（如果有），快速恢复上下文
4. 向用户报告：

```
Redis 学习进度：3/7 节点已完成。
已完成：01-数据结构、02-持久化、03-复制
下一个：04-哨兵与集群
继续？
```

### 场景二：用户只说"继续"

1. 在仓库根目录搜索所有 `*/index.md` 文件
2. 过滤 `status: in-progress` 的文件
3. 如果只有一个，自动续接
4. 如果有多个，列出让用户选择
5. 如果没有，提示没有进行中的学习主题

### 场景三：学习中断在节点中间

如果上一次会话在某个节点的 Q&A 中间断了（笔记文件不存在但节点未标完成）：

1. 该节点重新开始学习循环
2. 不要试图从上次对话的中间恢复（上下文已丢失）
3. 告知用户："上次在 04-哨兵与集群 中断了，重新开始这个节点。"

---

## 四、日报联动

当在 LEARNING 阶段完成一个节点时：

1. 检查当天日报是否存在（`Work/daily-reports/YYYY-MM-DD-日报.md`）
2. 如果存在，在日报中追加：
   - 学习主题和节点编号
   - 完成时间
   - 关键收获（1-2 句）
3. 如果不存在，不主动创建日报（由每日调度流程负责）

---

## 五、节点状态标记规范

| 标记 | 含义 |
|------|------|
| `⬜ 未开始` | 尚未进入学习 |
| `🔄 进行中` | 正在学习（当前会话正在处理） |
| `✅ 已完成` | 学习完成，笔记已沉淀 |
| `✅ 已合并` | 内容合并到其他节点，原节点不再独立存在 |

注意：`🔄 进行中` 仅在当前会话内使用。如果会话中断，下次检测时视为 `⬜ 未开始`（因为中间状态的笔记不完整）。
