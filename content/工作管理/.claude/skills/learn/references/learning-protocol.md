# 逐节点学习协议

本文件定义 LEARNING 阶段中每个节点的交互学习循环。

---

## 一、节点学习循环

每个节点按以下五个步骤推进：

```
准备 → 呈现 → Q&A → 沉淀 → 更新
```

---

## 二、准备

在向用户呈现内容之前：

1. **获取参考资料**：用 WebFetch 获取该节点相关的官方文档页面
2. **验证链接**：确保参考材料链接可以访问，不可访问的换一个或标注
3. **确定覆盖范围**：从 index.md 中读取该节点的内容描述，明确要覆盖哪些概念
4. **读取前置笔记**：如果有前置节点已完成，快速浏览其笔记，确保内容衔接

---

## 三、呈现

### 内容组织原则

每个概念按以下顺序展开：

1. **问题陈述**：为什么需要这个东西？它解决什么问题？
2. **核心机制**：它是怎么工作的？关键流程是什么？
3. **设计取舍**：为什么选这种方案而不是别的？代价是什么？
4. **实践影响**：这个设计决策对使用者/开发者意味着什么？

### 表达规则

- **语言**：中文讲解，技术术语保留英文原文（如 "partition"、"offset"、"replication"）
- **深度**：不过度压缩。一个概念如果需要 3 段话才能讲清楚，就用 3 段话，不要压成 1 句
- **对比**：凡是有取舍的地方，用对比表格展示

对比表格格式：
```markdown
| 维度 | 方案 A | 方案 B |
|------|--------|--------|
| 优势 | ... | ... |
| 代价 | ... | ... |
| 适用场景 | ... | ... |
```

- **架构图**：复杂的组件关系或数据流用 ASCII 图展示

```
Producer → Broker（写入 log）→ Consumer（pull 读取）
```

- **具体示例**：抽象概念必须配至少一个具体示例。示例优先选择贴近真实业务的场景
- **不提前投喂**：每轮只呈现当前节点的内容。用户没完成当前节点的 Q&A 之前，不要开始讲下一个节点

### 呈现的分段方式

一个节点通常包含 3-6 个核心概念。不要一次性全部倾倒，按以下策略分段：

- 如果概念之间有强依赖（理解 B 必须先理解 A）：逐个呈现，每个概念呈现后附 1-2 个小问题
- 如果概念相对独立：可以一次呈现 2-3 个，然后一起提问

---

## 四、Q&A

### 提问规则

- 每轮呈现后提出 3-5 个问题
- 问题类型分布：
  - **理解确认型**（1-2 个）：确认用户理解了核心概念。如"X 解决的根本问题是什么？"
  - **辨析型**（1-2 个）：区分易混淆概念。如"A 和 B 的核心区别是什么？"
  - **推理型**（1 个）：从已学知识推导。如"如果 X 条件变了，会导致什么后果？"
- 问题难度递进：前面的问题确认基础，后面的问题考验深度

### 回答处理规则

用户回答后，逐条处理：

**用户答对了：**
- 简短确认，如"对"或"正确"
- 如果答案特别好，可以补充一个延伸点

**用户答对了但不精确：**
- 先肯定正确的部分
- 再补全缺失的关键信息
- 格式："你说的 X 是对的。补充一点：Y"

**用户答错了：**
- **必须明确指出错误**，不能模糊带过
- 先说哪里错了，再给正确的解释
- 格式："这里有个偏差：你说的是 X，实际上是 Y。原因是 Z"

**用户完全不知道：**
- 不要批评，直接给出解释
- 但要标记这是用户的知识盲点，沉淀时重点覆盖

### 纠错的重要性

这是从 Kafka 学习中总结出的最重要规则之一：

> **用户回答有错误时，Claude 必须立即、明确地指出。不纠错等于默认认可错误理解，
> 会在后续学习中产生累积偏差。**

常见的需要纠错的场景：
- 因果关系搞反（如把"结果"当成"原因"）
- 概念边界模糊（如把 A 的特性说成 B 的特性）
- 方向性错误（如说"提高可用性"但实际是"提高持久性"）
- 遗漏关键限制条件

---

## 五、沉淀

### 沉淀时机

以下任一条件满足时进入沉淀：
- 用户回答完所有问题且纠错/补充完毕
- 用户说"沉淀""保存笔记""记下来"
- 用户说"下一个节点"（先沉淀当前，再进入下一个）

### 沉淀内容来源

从本轮对话中提取：
1. 呈现阶段的所有概念讲解
2. Q&A 中的纠错和补充
3. 用户提出的有价值的追问及其回答

### 沉淀方式

- 不保留原始的问答对话格式
- 将所有内容重新组织为结构化的笔记（见 [note-template.md](note-template.md)）
- 纠错内容融入正文。例如用户把 A 和 B 搞混了，笔记中就在讲 A 的地方加一句"注意：A 不是 X，虽然表面相似，但根本区别在于 Y"
- 保持笔记的独立可读性——不看对话也能理解所有内容

---

## 六、更新

沉淀完成后：

1. 创建笔记文件 `<topic>/notes/NN-xxx.md`
2. 更新 `<topic>/index.md` 中该节点的状态为 `✅ 已完成`
3. 更新 index.md 的 YAML `updated` 日期
4. 告知用户当前进度："已完成 N/M 个节点。下一个：NN+1-xxx"
5. 等待用户决定是继续下一个节点还是结束当前会话
