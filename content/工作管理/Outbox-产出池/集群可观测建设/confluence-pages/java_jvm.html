 ⚠ java_jvm 是 Zabbix 通用 JMX 模板，非独立服务

这 7 条规则来自 Zabbix 的 Generic Java JMX 模板，被批量应用到所有 Java 服务（Hadoop/HBase/Kafka/HS2/Kyuubi 等）。

在 Foxeye 体系中，各服务已有专用的 jmx_exporter 接入（如 hadoop_hbase_*、hadoop_hive_server_*、kafka_* 等），大部分 JVM 指标已被覆盖。

核心问题：是否还有未被专用 exporter 覆盖的 Java 进程？如有，需为其补充 jmx_exporter 配置。

🔧 jmx_exporter 可覆盖规则（5 条）

规则名称（Zabbix）对应 Prometheus 指标覆盖状态
Memory: Heap memory usage is high jvm_memory_bytes_used{area="heap"} / jvm_memory_bytes_max{area="heap"} ✅ 平台已有：hadoop_hive_server_memory_heap_usage / doris_be_jvm_heap_size_bytes 等；通用 Java 进程需补充 jmx_exporter
Memory: Non-Heap memory usage is high jvm_memory_bytes_used{area="nonheap"} ✅ doris_be_jvm_non_heap_size_bytes；Hadoop 组件已有类似指标
OperatingSystem: Process CPU Load is high jvm_process_cpu_seconds_total 或 process_cpu_usage 🔧 各服务 jmx_exporter 可覆盖；通用进程可用 Categraf procstat cpu_usage
OperatingSystem: Opened file descriptor count is high process_open_fds 🔧 Categraf procstat 插件的 process_num_fds 覆盖；或 jmx_exporter
Runtime: JVM is not reachable JMX 端口探活 🔧 Categraf net_response 探活 JMX 端口（默认 7199 / 9999）；或 procstat 检测进程存活

🗑 建议退休规则（2 条）

规则名称Zabbix 原理建议
Compilation: JVM uses suboptimal JIT compiler 通过 JMX 检测是否使用了非 C2（服务器模式）JIT 编译器 🗑 Retire。现代 JVM（JDK 8+）默认使用 C2 编译器，此规则在生产环境几乎不会触发，且无对应 Prometheus 指标
Runtime: JVM runs suboptimal VM type 通过 JMX 检测 JVM 是否为 Client 模式（而非 Server 模式） 🗑 Retire。64 位 JVM 默认 Server 模式，此规则已无实际意义

📋 行动建议

  1. 盘点未接入 jmx_exporter 的 Java 服务：java_jvm 通用规则的核心价值是覆盖那些没有专用 exporter 的 Java 进程。盘点集群中所有 Java 进程，确认是否有未被覆盖的服务。
  2. 统一 JVM 告警规则：建议在 Foxeye 中创建通用 JVM 告警规则组，基于 jmx_exporter 标准指标（jvm_memory_bytes_used、process_open_fds 等），适用于所有接入 jmx_exporter 的 Java 服务。
  3. JVM 不可达告警：为各 Java 服务添加 procstat 进程存活检测，替代 Zabbix JMX 可达性检查。
  4. Retire 2 条：将 JIT 类型 / VM 类型规则直接在 Zabbix 中禁用，无需迁移。
