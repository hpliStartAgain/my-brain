✅ 已创建规则（Foxeye 新增，子队列 per-queue 覆盖）

背景：Zabbix 通过 LLD（Low-Level Discovery）自动发现每个队列，为每个子队列创建独立 TID，产生了大量高频告警（PendingContainers/AllocatedContainers 积压规则过去1年触发 157次，AppsPending/Running 积压规则触发 105次，PendingMB 溢出规则触发 26次，UsedCapacity>95% 触发 31次）。Foxeye 现有 YARN 规则（FID=452648-452655）全部 hardcode queue="root"，完全不覆盖子队列。以下 4 条规则已在 GID=413 创建并启用，用 queue!="root" 通配方式以单条规则等价替代 Zabbix 数十条 LLD 衍生规则。

平台回读校验（2026-05-22）：4 条规则均启用，Datasource=5，eval_interval=60s，PromQL 均可通过 Foxeye datasource proxy 解析执行；container/apps backlog 当前已有命中样例（H3离线 root.irp_rank），其余当前 0 命中。

实际创建参数（均与现有 YARN 规则保持一致）：

  • group_id: 413（大数据中心-集群-大数据业务-YARN）
  • datasource_ids: [5]（大数据中心-vm0）
  • append_tags: service=resourcemanager
  • notify_rule_ids: [93]，规则均已启用

注意事项：
① 规则 B/C/D 使用 sum by(queue,cluster) 聚合，去掉了 host 维度，告警 label 仅含 queue/cluster；需确认 Foxeye 告警模板兼容缺少 host label 的情况。
② ha_status="active" 确保只基于主 RM 的队列数据计算，避免 Standby RM 零值干扰分母。
③ AllocatedMem 周环比>200% 规则（Zabbix LLD 触发88次）因需要 7d offset 的周同比计算，复杂度较高，暂列为可选规则E，待后续评估。
