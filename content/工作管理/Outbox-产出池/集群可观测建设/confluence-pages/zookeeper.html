🔧 第一组：Categraf ZooKeeper 插件覆盖（7 条指标类告警）

Categraf 内置 zookeeper 插件通过向 ZK 节点发送 mntr 四字命令采集运行状态，覆盖以下所有规则：

规则名称（Zabbix）对应 Categraf 指标建议告警条件
Zookeeper: Too many queued requests zookeeper_outstanding_requests zookeeper_outstanding_requests > 10（队列积压超过阈值说明 ZK 处理能力不足）
Zookeeper: zookeeper.max_latency > 100 zookeeper_max_latency zookeeper_max_latency > 100（单位 ms）
Zookeeper: znode_count > 200000 zookeeper_znode_count zookeeper_znode_count > 200000
Zookeeper: Too many file descriptors used zookeeper_open_file_descriptor_count / zookeeper_max_file_descriptor_count zookeeper_open_file_descriptor_count / zookeeper_max_file_descriptor_count > 0.85
Zookeeper: Too many file descriptors used > 1000 zookeeper_open_file_descriptor_count zookeeper_open_file_descriptor_count > 1000（绝对值告警，与上条互补）
Zookeeper: Server mode has changed zookeeper_server_state（string label） Categraf zookeeper 插件将 server_state（leader/follower/standalone）作为 label 输出；通过 changes(zookeeper_server_state[5m]) > 0 或 Loki 日志关键词 "New election" 检测选举事件
Zookeeper: Version has changed Loki 日志告警 ZK 版本变更极少发生，建议用 Loki Pattern Alert 检测 ZK 启动日志中的版本字符串变化，而非指标告警

🔧 第二组：Categraf procstat/net_response（2 条存活类告警）

规则名称Categraf 方案建议告警条件
Port 2181 of Zookeeper is DOWN Categraf net_response 插件 探活 ZK 客户端端口 2181；net_response_result_code != 0
Processes of Zookeeper are DEAD Categraf procstat 插件 检测 org.apache.zookeeper.server.quorum.QuorumPeerMain 进程；procstat_running == 0
💡 Categraf ZooKeeper 插件配置参考

在各 Categraf 实例的配置目录下新增 conf.d/input.zookeeper/zookeeper.toml：

[[instances]]
  servers = ["zk-node1:2181", "zk-node2:2181", "zk-node3:2181"]
  timeout = 5

启动后将采集 zk_avg_latency、zk_max_latency、zk_outstanding_requests、zk_znode_count、zk_open_file_descriptor_count、zk_server_state 等全部 mntr 输出指标。
