上周开始[从零做AIOps平台](https://mp.weixin.qq.com/s?__biz=MjM5MTk1ODE0MA==&mid=2648442854&idx=1&sn=3c5daaddeb1366cd4f26e72cfa0c3e1a&scene=21#wechat_redirect)，每天记录，今天第三天。

最早做开发规划时，一共分了4个大任务线，从P0到P3。

1. **P0（基础底座）**
    

- 主线：`INFRA + AUTH + MODEL/GATEWAY`
    
- 本质：把平台先跑起来（工程骨架、认证权限、模型统一网关、限流审计文档）。
    

2. **P1（平台能力扩展）**
    

- 主线：`SKILL + MCP`
    
- 本质：把“技能管理 + MCP 管控”做成平台能力（安装升级回滚、签名来源控制、MCP 注册健康检查生命周期、权限隔离、自动恢复）。
    

3. **P2（流程与智能体运行时）**
    

- 主线：`WORKFLOW + AGENT RUNTIME`
    
- 本质：让系统具备可编排与可执行能力（工作流 DSL/执行/重试补偿/版本回放 + Agent 配置/规划/工具/记忆/成本/安全）。
    

4. **P3（知识与生产化发布）**
    

- 主线：`RAG + 稳定性与发布`
    
- 本质：补齐检索增强与生产交付（文档接入、向量化、混合检索、权限过滤、可观测、告警、安全扫描、压测、Helm、开源发布物料）。
    

目前已完成了P0和P1，P2正在开发中。今天把P0和P1任务做一个总结。

## 一、P0 都有什么（任务范围）

### 1) 基础工程模块（INFRA）

**能力：**

- Monorepo 工程结构、前后端基础骨架、配置管理、统一响应格式、request_id 链路日志。**能做的事：**
    
- 一键拉起开发环境；
    
- 快速新增 API/页面且结构统一；
    
- 请求可追踪、问题可定位（通过 request_id）。
    

### 2) 身份与权限模块（AUTH）

**能力：**

- 登录/刷新/退出（JWT）；
    
- 租户/项目/工作区模型；
    
- 角色权限控制（RBAC）；
    
- API Key 管理；
    
- 审计日志。**能做的事：**
    
- 多租户隔离访问；
    
- 给不同角色分配不同操作权限；
    
- 用 API Key 安全调用平台接口；
    
- 追查“谁在什么时候做了什么”。
    

### 3) 模型网关模块（MODEL + GATEWAY）

**能力：**

- Provider 抽象层；
    
- 统一模型调用接口；
    
- 多模型接入（国外/国内/自定义兼容）；
    
- 限流、OpenAPI 文档、调用计量。**能做的事：**
    
- 同一个接口切换不同模型供应商；
    
- 控制调用频率、防止滥用；
    
- 统计 token/耗时/调用量，支持成本分析；
    
- 直接用 `/docs` 联调接口。
    

## 二、P0任务总结

P0阶段围绕“可运行、可治理、可扩展”的基础底座完成建设，已搭建Monorepo工程结构，落地前后端基础骨架与本地依赖编排，形成统一配置、统一响应和request_id日志链路。

在平台能力上，完成了认证鉴权、租户与角色权限模型、API Key管理及审计能力，构建了多租户安全访问基线。模型侧完成Provider抽象与统一推理接口，实现多模型接入与路由，补齐限流、OpenAPI文档和基础计量能力。

整体上，P0已具备“统一网关调用模型+权限控制+可观测审计”的最小可用能力，为P1技能与MCP平台化打下稳定基础。

## 三、P1都有什么

### 1) 技能管理模块（SKILL）

**能力：**

- 技能 manifest 规范与校验；
    
- 安装/卸载/启停；
    
- 升级/回滚；
    
- 签名校验与来源白名单；
    
- 多仓库管理；
    
- 沙箱执行与超时控制。**能做的事：**
    
- 把技能作为“可管理组件”安全接入平台；
    
- 技能异常时快速停用或回滚；
    
- 阻断来源不可信或签名不合法的技能；
    
- 隔离执行高风险技能，降低主系统受影响概率。
    

### 2) MCP 管控模块（MCP）

**能力：**

- MCP Server 注册、查询、更新、删除；
    
- 健康检查与状态监控；
    
- npx 模板化启动；
    
- 生命周期控制（start/stop/restart）；
    
- 租户/项目/工作区级权限绑定；
    
- 异常自动恢复（重试/退避/熔断）；
    
- 持久化与审计落库（P1 收尾已覆盖）。**能做的事：**
    
- 集中纳管 MCP Server；
    
- 自动发现异常并恢复，降低人工值守成本；
    
- 防止跨租户越权访问 MCP 资源；
    
- 对关键运维动作可审计、可追溯。
    

## 四、P1任务总结

P1阶段聚焦“技能与MCP可管可控”，完成Skill与MCP两条主线建设。

Skill侧实现了manifest规范校验、安装/启停/卸载、升级回滚、签名与来源控制、多仓配置及沙箱执行超时控制，建立了可追溯、可回滚、最小权限的技能治理闭环。

MCP侧实现了Server注册管理、健康检查、模板化启动、生命周期控制、租户/项目/工作区权限绑定及异常自动恢复（重试/退避/熔断），并补齐SQLite持久化与关键动作审计落库。

阶段验收显示P1任务已完成并可进入下一阶段，平台从“能用”进一步升级到“可管、可审、可恢复”的工程化状态。
