# 前言

Kubernetes 是一个开源系统，用于自动化容器化应用程序的部署、扩缩容和管理。如果你运行的容器不止几个，或者想要自动化管理你的容器，那么你需要 Kubernetes。本书专注于引导你完成 Kubernetes 集群的高级管理。

本书首先解释 Kubernetes 架构背后的基础知识，并详细涵盖 Kubernetes 的设计。你将发现如何在 Kubernetes 上运行有状态微服务，包括水平 Pod 自动扩缩、滚动更新、资源配额和持久化存储后端等高级特性。通过真实世界的用例，你将探索网络配置的选项，并了解如何设置、运营、保护和排查 Kubernetes 集群。最后，你将学习自定义资源、API 聚合、服务网格和无服务器计算等高级主题。所有内容都是最新的，符合 Kubernetes 1.26 规范。通过阅读本书，你将掌握从中级到高级水平所需的一切知识。

## 目标读者

本书面向具有 Kubernetes 中级知识、希望掌握高级特性的系统管理员和开发人员。你还应具备基本的网络知识。这本高级书籍提供了一条掌握 Kubernetes 的途径。

## 本书涵盖内容

**第 1 章，理解 Kubernetes 架构**，在本章中，我们将共同奠定充分利用 Kubernetes 所需的基础。我们将从理解 Kubernetes 是什么、Kubernetes 不是什么以及容器编排究竟意味着什么开始。然后我们将介绍重要的 Kubernetes 概念，这些概念将构成全书使用的术语。之后我们将深入探讨 Kubernetes 的架构本身，并了解它如何使其为用户提供的所有功能成为可能。最后，我们将讨论 Kubernetes 如何以通用方式支持多种容器运行时。

**第 2 章，创建 Kubernetes 集群**，在本章中，我们将卷起袖子，使用 minikube、KinD 和 k3d 构建一些 Kubernetes 集群。我们将讨论并评估其他工具，如 kubeadm 和 Kubespray。我们还将关注本地、云和裸机等部署环境。

**第 3 章，高可用性与可靠性**，在本章中，我们将深入探讨高可用性集群这一主题。这是一个复杂的主题。Kubernetes 项目和社区尚未就实现高可用性理想的唯一正确方法达成共识。高可用性 Kubernetes 集群涉及许多方面，例如确保控制平面在故障情况下仍能保持运行、保护 etcd 中的集群状态、保护系统数据，以及快速恢复容量和/或性能。不同的系统会有不同的可靠性和可用性要求。

**第 4 章，保护 Kubernetes 安全**，在本章中，我们将探讨安全这一重要主题。Kubernetes 集群是由多层交互组件组成的复杂系统。在运行关键应用程序时，不同层的隔离和分区非常重要。为了保护系统并确保对资源、能力和数据的正确访问，我们必须首先理解 Kubernetes 作为一个运行未知工作负载的通用编排平台所面临的独特挑战。然后我们可以利用各种安全、隔离和访问控制机制来确保集群、其上运行的应用程序以及数据的安全。我们将讨论各种最佳实践以及何时使用每种机制。

**第 5 章，在实践中使用 Kubernetes 资源**，在本章中，我们将设计一个虚构的大规模平台，挑战 Kubernetes 的能力和可扩展性。Hue 平台致力于创建一个无所不知、无所不能的数字助手。Hue 是你在数字世界的延伸。Hue 将帮助你做任何事情、找到任何东西，并且在许多情况下会代你完成大量工作。显然，它需要存储大量信息、与许多外部服务集成、响应通知和事件，并且在与你的交互中表现得足够智能。

**第 6 章，管理存储**，在本章中，我们将了解 Kubernetes 如何管理存储。存储与计算截然不同，但在高层面上，它们都属于资源。Kubernetes 作为一个通用平台，采取的方法是将存储抽象为编程模型和一组存储提供程序插件。

**第 7 章，在 Kubernetes 上运行有状态应用程序**，在本章中，我们将学习如何在 Kubernetes 上运行有状态应用程序。Kubernetes 根据复杂的需求和配置（如命名空间、限制和配额），自动在集群节点间按需启动和重启 Pod，从而替我们承担了大量工作。但当 Pod 运行存储感知型软件（如数据库和消息队列）时，重新定位 Pod 可能导致系统崩溃。

**第 8 章，部署和更新应用程序**，在本章中，我们将探讨 Kubernetes 提供的自动 Pod 可扩展性、它如何影响滚动更新，以及它与配额的交互方式。我们将涉及资源预配这一重要主题，以及如何选择和管理集群的规模。最后，我们将介绍 Kubernetes 团队如何改进 Kubernetes 的性能，以及他们如何使用 Kubemark 工具测试 Kubernetes 的极限。

**第 9 章，打包应用程序**，在本章中，我们将深入探讨 Helm——Kubernetes 的包管理器。每个成功且非平凡的平台都必须有一个良好的打包系统。Helm 由 Deis（2017 年 4 月 4 日被微软收购）开发，后来直接贡献给了 Kubernetes 项目。它于 2018 年成为 CNCF 项目。我们将从理解 Helm 的动机、其架构和组件开始。

**第 10 章，探索 Kubernetes 网络**，在本章中，我们将研究网络这一重要主题。Kubernetes 作为一个编排平台，管理在不同机器（物理或虚拟）上运行的容器/Pod，并需要一个明确的网络模型。

**第 11 章，在多集群上运行 Kubernetes**，在本章中，我们将更上一层楼，在多个云和集群上运行 Kubernetes。Kubernetes 集群是一个紧密耦合的单元，所有组件在相对接近的位置运行，并通过高速网络（通常是物理数据中心或云提供商可用区）连接。这对许多用例来说很好，但有一些重要用例需要系统扩展到单个集群之外。

**第 12 章，Kubernetes 上的无服务器计算**，在本章中，我们将探索云中无服务器计算的迷人世界。"无服务器"这一术语备受关注，但它实际上是一个用词不当的概念，被用来描述两种不同的范式。真正的无服务器应用程序作为用户浏览器中的 Web 应用程序或移动应用程序运行，仅与外部服务交互。我们在 Kubernetes 上构建的无服务器系统类型有所不同。

**第 13 章，监控 Kubernetes 集群**，在本章中，我们将讨论如何确保系统正常运行并正确执行，以及当系统不正常时如何应对。在第 3 章"高可用性与可靠性"中，我们已经讨论了相关主题。本章的重点在于了解系统中正在发生的事情，以及可以使用哪些实践和工具。

**第 14 章，利用服务网格**，在本章中，我们将学习服务网格如何允许你将监控和可观测性等横切关注点从应用程序代码中外部化。服务网格是一种真正的范式转变，改变了你在 Kubernetes 上设计、演进和运行分布式系统的方式。我喜欢将其视为云原生分布式系统的面向切面编程。

**第 15 章，扩展 Kubernetes**，在本章中，我们将深入挖掘 Kubernetes 的内部机制。我们将从 Kubernetes API 开始，学习如何通过直接访问 API、Go 客户端和自动化 kubectl 来以编程方式使用 Kubernetes。然后我们将研究如何通过自定义资源扩展 Kubernetes API。最后一部分是关于 Kubernetes 支持的各种插件。Kubernetes 的许多操作方面都是模块化的，并设计为可扩展的。我们将研究 API 聚合层以及几种插件类型，如自定义调度器、授权、准入控制、自定义指标和存储卷。最后，我们将探讨扩展 kubectl 并添加你自己的命令。

**第 16 章，治理 Kubernetes**，在本章中，我们将了解 Kubernetes 在大型企业组织中日益增长的作用，以及什么是治理以及如何在 Kubernetes 中应用治理。我们将审视策略引擎，回顾一些流行的策略引擎，然后深入探讨 Kyverno。

**第 17 章，在生产环境中运行 Kubernetes**，在本章中，我们将把注意力转向 Kubernetes 在生产环境中的整体管理。重点将放在云端运行多个托管的 Kubernetes 集群上。在生产环境中运行 Kubernetes 涉及太多不同的方面。我们将主要关注计算侧，这是最基础、最核心的部分。

**第 18 章，Kubernetes 的未来**，在本章中，我们将从多个角度审视 Kubernetes 的未来。我们将从 Kubernetes 自诞生以来的发展势头开始，涵盖社区、生态系统和市场份额等维度。剧透警告：Kubernetes 以压倒性优势赢得了容器编排之战。随着 Kubernetes 的发展和成熟，竞争焦点从击败竞争对手转向对抗自身的复杂性。由于容器编排仍然是一个全新、快速发展的领域，且尚未被充分理解，易用性、工具化和教育将发挥重要作用。然后我们将审视一些非常有趣的模式和趋势。
