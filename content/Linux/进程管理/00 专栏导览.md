# Linux 进程管理专栏导览

## 专栏定位

本专栏聚焦 Linux 内核的进程管理子系统，从"进程是什么"这个最基础的问题一路走到"进程之间如何协作"。目标不是整理一份命令速查表，而是建立一套可以解释现象、指导排障的**认知框架**——当一台机器上出现负载虚高、进程杀不掉、容器莫名卡住、日志里冒出 137 这类情况时，能够沿着这套框架快速收敛到原因。

全专栏围绕同一个对象展开：`task_struct`。它承载着一个执行流的全部身份与状态，被内核反复创建、替换、回收、调度，必要时还要与同伴通信。十篇正文从十个不同的侧面观察这个对象——它是什么、长什么样、怎么来、怎么变、怎么走、在什么状态下等、能不能共享、谁来决定它跑、什么时候它必须按时跑、以及它如何与别人说话。**理解了 `task_struct` 与围绕它的那套数据结构关系，这些看似独立的话题就会收敛到同一张地图上。**

## 读者对象与前置知识

本专栏面向中高级工程师、SRE、以及希望深入理解操作系统内核的技术人员。阅读时需要：

- 基本的 Linux 使用与排障经验（会用 `ps`、`top`、`/proc`）；
- C 语言基础（能读懂结构体定义与函数指针）；
- 对虚拟内存、文件系统的基本概念有印象即可，细节在需要处会给出链接。

不要求读者读过内核源码。文中的源码片段用于说明机制，而不是要求逐行理解。

## 专栏主线

这条主线可以概括成四个阶段：

**第一阶段（01-02）建立基础认知。** 进程是什么、它为什么必须存在、内核用什么结构承载它。这两篇是后面所有内容的地基——后面每一次讨论"某个资源被共享还是被复制"，答案都落在 `task_struct` 的字段与指针关系上。

**第二阶段（03-05）走完一次生命周期。** `fork` 造出空壳、`execve` 换掉灵魂、`exit` 交出控制权、父进程 `wait` 收尾。这四步构成一个闭环，闭环之外的每一处都是事故高发区：fork 的页表代价、exec 的资源继承规则、僵尸的回收责任。

**第三阶段（06-07）从"资源容器"转向"执行流"。** 状态机回答"它在等什么"，线程模型回答"一组执行流共享了什么"。这两篇合起来解释了 Linux 进程模型最独特的地方——内核里只有一种实体，进程与线程的差别全部体现在共享粒度上。

**第四阶段（08-10）回答"谁来决定它跑"与"它如何与别人说话"。** 调度器决定 CPU 归谁，实时调度回答"确定性如何被保证"，进程间通信回答"隔离的边界如何被跨越"。

## 阅读建议

- **按序阅读**：四阶段之间的依赖是实在的——不理解 `task_struct` 的字段关系，就很难理解 `fork` 里"哪些复制、哪些共享"的判断；不理解状态机，调度器的公平性就没有落点。
- **只挑重点时**：排查性能问题优先读 06（状态与 D 状态）、08（调度延迟）；排查容器问题优先读 05（僵尸与 PID 1）、07（线程与 cgroup）；做架构选型优先读 09（实时性边界）、10（IPC 选型）。
- **每篇末尾的思考题**：有几道题指向了正文没有展开的边界情况，适合在读过一遍之后回头想。
