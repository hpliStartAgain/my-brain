# Agent 沙箱技术 专栏导览

## 专栏定位

本专栏系统解构 **Agent 沙箱（Agent Sandbox）技术**——从"为什么代码执行型与自主规划型 Agent 必须被严格隔离"的权威威胁模型出发，沿 Linux 内核隔离原语 → 硬件辅助虚拟化（KVM/MicroVM）→ 沙箱平台六层分层体系 → 现代开源沙箱平台（E2B、OpenSandbox、OpenKruise Agents、CubeSandbox、OpenShell）架构深度解析 → 真实生产工程落地 → 生产化深水区的逻辑演进，建立 Agent 沙箱技术的严谨工业级基准与系统认知框架。

本专栏彻底摒弃任何未经公开验证的内部讲义或私有概念，基于 CNCF 云原生标准、Linux 内核安全规范、MITRE ATLAS / OWASP Top 10 for LLM 威胁框架，以及业界主流开源项目的生产级源码与权威实践，回答三个层层递进的核心问题：
1. **隔离边界画在哪里**：从共享内核到用户态内核、MicroVM 的技术路线权衡与代价；
2. **沙箱平台如何构建**：控制面、K8s 编排面、盒内数据面（如 execd/envd）、网络策略与短期凭据治理的架构闭环；
3. **生产环境如何落地**：预热池毫秒认领、状态与持久化拆分、高并发多租户隔离与容灾深水区陷阱。

## 业界开源基准与对照矩阵

本专栏以业界最具代表性的五大现代开源沙箱项目作为实践基准体系：

| 开源项目 | 开源组织 / 厂商 | 核心底层原语 | 关键定位与架构特色 |
| :--- | :--- | :--- | :--- |
| **E2B** (`e2b-dev/E2B`) | E2B | AWS Firecracker MicroVM (KVM) | 开发者 SDK 事实标准，基于 `userfaultfd` 的内存快照按需懒加载与 CoW 磁盘，亚秒级冷启动与 Pause/Resume，边缘 Token 与动态端口路由 |
| **OpenSandbox** (`opensandbox-group/OpenSandbox`) | 阿里巴巴 | 插拔式 Runtime (Docker / K8s / gVisor / Kata) | 协议优先设计（OpenAPI 规范），FastAPI 控制面，盒内统一 `execd` 守护进程（REST/SSE 进程与文件流），出站 Egress 动态审计与 Fail-Closed 机制 |
| **OpenKruise Agents** (`openkruise/kruise`) | CNCF OpenKruise | Kubernetes 原生 CRD / Pod | 云原生沙箱工作负载标准，定义 `Sandbox`、`SandboxSet`、`PoolAutoscaler` CRD，内置预热池高低水位弹性，双向兼容 K8s CRD 与 E2B API，MCP 工具级 ACL 治理 |
| **CubeSandbox** (`TencentCloud/CubeSandbox`) | 腾讯云 | RustVMM + KVM MicroVM | 高性能硬件级隔离，<60ms 极速启动与 <5MB 基础内存底噪，组件包含 `CubeMaster`、`Cubelet` 与基于 eBPF 的网络虚拟交换引擎 `CubeVS`，原生兼容 E2B SDK 协议 |
| **OpenShell** (`NVIDIA/OpenShell`) | NVIDIA | OS 内核级拦截 (eBPF/LSM/Landlock) | 面向自主 Agent 机群的安全治理平台，内核级 syscall/文件/网络动态拦截，Master 凭据全隔离与 Scoped Token 透明注入，形式化策略验证（Formally Verified Policies） |
