# Agent 沙箱技术 专栏导览

## 专栏定位

本专栏系统解构 **Agent 沙箱（Agent Sandbox）技术**——从"为什么代码执行型 Agent 必须被隔离"的威胁模型出发，沿 Linux 隔离原语 → 轻量虚拟化 → 沙箱平台分层 → OpenSandbox 深度解析 → 工程落地 → 生产化深水区的逻辑演进，建立 Agent 沙箱技术的完整框架体系。本专栏不是零散技术点的罗列，而是回答三个层层递进的问题：**隔离边界画在哪里**（技术路线）、**沙箱平台如何构建**（产品架构）、**生产环境如何落地**（工程实践）。

本专栏以蚂蚁开源 **OpenSandbox**（AI 应用通用沙箱平台）为主线案例，融合作者在真实物理机上完成的 PoC 实操（runc/gVisor/Kata 三运行时基准、三类 Agent 镜像化跑通、测试集群建设）与深水区调研（十个生产化盲区、行业共识、状态四本账），并交叉验证 2026 年行业一手资料（kubernetes-sigs/agent-sandbox、E2B、Daytona、Modal、GKE Agent Sandbox）。

## 目标读者

- 需要为 AI Agent 设计代码执行环境与安全边界的平台工程师、SRE 与架构师
- 正在选型或落地 Agent 沙箱（E2B/OpenSandbox/CubeSandbox/自研）的技术决策者
- 想从"会用 Claude Code/OpenCode 等 Agent"进阶到"理解 Agent 在哪、以何种隔离强度运行"的工程师
- 关注容器安全、轻量虚拟化（gVisor/Kata/Firecracker）的云原生开发者
