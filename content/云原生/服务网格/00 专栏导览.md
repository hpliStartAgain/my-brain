# 服务网格 专栏导览

## 专栏定位

本专栏聚焦 **服务网格（Service Mesh）的架构设计与核心原理**——从"治理逻辑放在哪里"这条主线出发，以 Istio + Envoy 为核心分析对象，贯穿数据面引擎（Envoy 线程模型与过滤链）、控制面架构（istiod 与 xDS 协议）、四大能力层（流量管理、mTLS 安全、可观测性），最终以性能账单与 Ambient Mesh 的架构重排收官。

专栏的主线是一个不断回摆的架构问题：治理逻辑应该在应用进程内（SDK）、每 Pod 旁（Sidecar）、节点级（ztunnel）、内核（eBPF）还是应用库内（gRPC 直连）？每一篇都在为这条主线补充机制级的细节——读完不应只是"知道 Istio 有什么功能"，而应能对任何一种网格形态回答"它为什么长这样、代价付在哪里、边界在哪里"。

## 目标读者

- 正在或计划在 [[01 Kubernetes 的诞生与设计哲学|Kubernetes]] 集群中引入服务网格的平台工程师/SRE
- 需要理解 Istio 流量管理、mTLS 安全与可观测体系的微服务架构师
- 对 Envoy、xDS 协议与数据面工程感兴趣的基础设施工程师

## 推荐阅读路径

**核心原理路径**：01 → 02 → 03（治理逻辑为什么外移、决策在哪生成、执行在哪发生）

**能力实践路径**：04 → 05 → 06（流量如何声明、信任如何建立、一切如何被看见）

**演进与选型路径**：07（账单怎么算、形态怎么变、路线怎么选）

首次接触服务网格的读者建议按序号通读；已有实践经验的读者可以按"02 的 xDS、03 的线程模型、05 的迁移方法论、07 的决策框架"四个重点切入。
