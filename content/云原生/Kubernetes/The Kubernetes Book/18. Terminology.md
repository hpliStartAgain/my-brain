 # Kubernetes 术语表

> [!INFO] 信息
> 本术语表定义了书中使用的最常见的 Kubernetes 相关术语。术语按字母顺序排列，便于快速查阅。

---

## A

### 准入控制器（Admission Controller）

验证或修改资源的代码，用于强制执行策略。作为 API 准入链的一部分，在身份认证和授权之后立即运行。

### 注解（Annotation）

对象元数据，可用于公开 alpha 或 beta 功能或与第三方系统集成。

### API（Application Programming Interface）

应用程序编程接口。在 Kubernetes 中，所有资源都在 API 中定义，该 API 是 RESTful 的，通过 API 服务器暴露。

### API 组（API Group）

一组相关的 API 资源。例如，网络资源通常位于 `networking.k8s.io` API 组。

### API 资源（API Resource）

所有 Kubernetes 对象（如 [[Pod]]、Deployment 和 [[Service]]）都在 API 中定义为资源。

### API 服务器（API Server）

通过 HTTPS 在安全端口上暴露 API。运行在[[控制平面]]上。

---

## C

### 云控制器管理器（Cloud Controller Manager）

与底层云平台集成的[[控制平面]]服务。例如，创建 [[LoadBalancer]] [[Service]] 时，云控制器管理器实现配置底层云互联网负载均衡器的逻辑。

### 云原生（Cloud Native）

一个含义丰富的术语，对不同的人有不同的意义。云原生是一种设计、构建和运行现代应用程序及基础设施的方式。个人认为，如果应用程序能够自我修复、按需扩展、执行滚动更新，并可能进行回滚，就可以认为是云原生的。

### 集群（Cluster）

协同运行用户应用程序的[[工作节点]]和[[控制平面]]节点的集合。

### 集群存储（Cluster Store）

保存集群和应用程序状态的[[控制平面]]功能。通常基于 [[etcd]] 分布式数据存储，运行在[[控制平面]]上。可以部署到自己的集群中以获得更高的性能和可用性。

### ConfigMap

用于保存非敏感配置数据的 [[Kubernetes]] 对象。是将自定义配置数据在运行时添加到通用容器中（无需编辑镜像）的绝佳方式。

### 容器（Container）

运行现代应用程序的轻量级环境。每个容器都是一个虚拟操作系统，拥有自己的进程树、文件系统、共享内存等。一个容器运行一个应用程序进程。

### 容器网络接口（Container Network Interface, CNI）

可插拔接口，支持不同的网络拓扑和架构。第三方提供 CNI 插件，支持覆盖网络、BGP 网络以及各种实现方式。

### 容器运行时（Container Runtime）

运行在每个集群[[节点]]上的低级软件，负责拉取容器镜像、启动容器、停止容器以及其他低级容器操作。通常是 [[containerd]]、Docker 或 cri-o。Docker 在 Kubernetes 1.20 中被弃用，在 1.24 中移除了支持。

### 容器运行时接口（Container Runtime Interface, CRI）

Kubernetes 的低级功能，允许容器运行时可插拔。通过 CRI，可以根据需求选择最佳容器运行时（Docker、containerd、cri-o、kata 等）。

### 容器存储接口（Container Storage Interface, CSI）

使外部第三方存储系统能够与 [[Kubernetes]] 集成的接口。存储供应商编写 CSI 驱动程序/插件，作为一组 [[Pod]] 在集群上运行，将存储系统的增强功能暴露给集群和应用程序。

### containerd

大多数 [[Kubernetes]] 集群使用的行业标准容器运行时。由 Docker, Inc. 捐赠给 CNCF。发音为 "container dee"。

### 控制器（Controller）

作为协调循环运行的[[控制平面]]进程，监控集群并进行必要的更改，使集群的观察状态与期望状态匹配。

### 控制平面（Control Plane）

每个 [[Kubernetes]] 集群的大脑。包括 API、API 服务器、调度器、所有控制器等。这些组件运行在每个集群的[[控制平面节点]]上。

### 控制平面节点（Control Plane Node）

托管[[控制平面]]服务的集群[[节点]]。通常不运行用户应用程序。应该部署 3 或 5 个以实现高可用性。

---

## C

### cri-o

容器运行时。常用基于 OpenShift 的 [[Kubernetes]] 集群中。

### 增删改查（CRUD）

四种基本操作：创建（Create）、读取（Read）、更新（Update）和删除（Delete），被许多存储系统使用。

### 自定义资源定义（Custom Resource Definition, CRD）

用于将自定义资源添加到 [[Kubernetes]] API 的 API 资源。

---

## D

### 数据平面（Data Plane）

托管用户应用程序的集群[[工作节点]]。

### Deployment

部署和管理一组无状态 [[Pod]] 的控制器。执行发布和回滚，可以自我修复。使用 [[ReplicaSet]] 控制器来执行扩展和自我修复操作。

### 期望状态（Desired State）

集群和应用程序应该呈现的状态。例如，应用程序微服务的期望状态可能是五个运行 xyz 容器并监听 8080/tcp 端口的副本。这对于[[协调循环]]至关重要。

---

## E

### 端点对象（Endpoints Object）

与 [[Service]] 的标签选择器匹配的、健康 [[Pod]] 的最新列表。基本上是 [[Service]] 发送流量到的 [[Pod]] 列表。最终可能会被 EndpointSlices 取代。

### etcd

用作大多数 [[Kubernetes]] 集群集群存储的开源分布式数据库。

---

## I

### Ingress

暴露多个内部 [[Service]] 的 API 资源，通过一个外部[[负载均衡服务]]。工作在第 7 层，实现基于路径和基于主机的 HTTP 路由。

### Ingress 类（Ingress Class）

允许在集群上指定多个不同 Ingress 控制器的 API 资源。

### 初始化容器（Init Container）

在主应用容器启动之前运行并完成的专用容器。常用于为主应用容器检查/初始化环境。

---

## J

### JSON（JavaScript Object Notation）

JavaScript 对象表示法。[[Kubernetes]] 发送和存储数据的首选格式。

---

## K

### K8s

[[Kubernetes]] 的简写方式。"8" 替换了 "Kubernetes" 中 "K" 和 "s" 之间的八个字符。发音为 "Kates"。这就是为什么人们说 Kubernetes 的女朋友叫 Kate 的原因。

### kubectl

[[Kubernetes]] 命令行工具。通过 API 服务器发送命令并通过 API 服务器查询状态。

### Kubelet

运行在每个集群[[节点]]上的主要 [[Kubernetes]] 代理。它监视 API 服务器以获取新的工作分配，并维护报告通道。

### Kube-proxy

运行在每个集群[[节点]]上，实现处理从 [[Service]] 到 [[Pod]] 流量路由的低级规则。向稳定的 [[Service]] 名称发送流量，kube-proxy 确保流量到达 [[Pod]]。

---

## L

### 标签（Label）

应用于对象的元数据，用于分组。与标签选择器配合使用，将 [[Pod]] 与更高级别的控制器匹配。例如，[[Service]] 根据匹配的标签集将流量发送到 [[Pod]]。

### 标签选择器（Label Selector）

用于识别 [[Pod]] 以执行操作的工具。例如，当 [[Deployment]] 执行滚动更新时，它根据其标签选择器知道要更新哪些 [[Pod]]——只有标签与 [[Deployment]] 标签选择器匹配的 [[Pod]] 才会被替换和更新。

### 清单文件（Manifest File）

保存一个或多个 [[Kubernetes]] 对象配置的 YAML 文件。例如，[[Service]] 清单文件通常是保存 [[Service]] 对象配置的 YAML 文件。当将清单文件发布到 API 服务器时，其配置会被部署到集群。

---

## M

### 微服务（Microservices）

现代应用程序的设计模式。应用程序功能被分解为独立的小型应用程序（微服务/[[容器]]），通过 API 通信。它们共同协作形成有用的应用程序。

### 命名空间（Namespace）

将单个 [[Kubernetes]] 集群分区为多个虚拟集群的方法。适用于在单个集群上应用不同的配额和访问控制策略。不适合强工作负载隔离。

---

## N

### 节点（Node）

也称为[[工作节点]]。集群中运行用户应用程序的[[节点]]。运行 kubelet 进程、容器运行时和 kube-proxy。

### 观察状态（Observed State）

也称为当前状态或实际状态。集群和运行中应用程序的最新视图。控制器始终致力于使观察状态与期望状态匹配。

---

## O

### 编排器（Orchestrator）

部署和管理应用程序的软件。现代应用程序由许多协同工作形成有用应用程序的小型微服务组成。[[Kubernetes]] 编排/管理这些服务，保持它们健康，扩展和缩减它们，以及更多……[[Kubernetes]] 是基于[[容器]]的微服务应用程序事实上的编排器。

### 持久卷（Persistent Volume, PV）

用于映射集群上存储卷的 [[Kubernetes]] 对象。外部存储资源必须先映射到 PV 才能被应用程序使用。

### 持久卷声明（Persistent Volume Claim, PVC）

类似于允许应用程序使用持久卷（PV）的票券/凭证。没有有效的 PVC，应用程序无法使用 PV。与 [[存储类]] 结合使用以实现动态卷创建。

### Pod

[[Kubernetes]] 上最小的调度单位。运行在 [[Kubernetes]] 上的每个[[容器]]都必须运行在 [[Pod]] 内。[[Pod]] 提供共享的执行环境——IP 地址、卷、共享内存等。

---

## R

### RBAC（Role-Based Access Control）

基于角色的访问控制。授权模块，决定已认证的用户是否可以对集群资源执行操作。

### 协调循环（Reconciliation Loop）

通过 API 服务器监视集群状态的控制器进程，确保观察状态与期望状态匹配。大多数控制器（如 [[Deployment]] 控制器）作为协调循环运行。

### ReplicaSet

作为控制器运行，执行自我修复和扩展。由 [[Deployment]] 使用。

### REST（REpresentational State Transfer）

表现层状态转移。创建基于 Web 的 API 最常见的架构。使用常见的 HTTP 方法（GET、POST、PUT、PATCH、DELETE）来操作和存储对象。

---

## S

### Secret

用于敏感配置数据的 [[ConfigMap]]。将敏感数据存储在[[容器]]镜像外部并在运行时插入[[容器]]中的方法。

### Service

带大写"S"。用于为运行在 [[Pod]] 中的应用程序提供网络访问的 [[Kubernetes]] 对象。通过在[[Pod]]集合前放置 [[Service]]，[[Pod]]可以失败、扩展和缩减、替换，而访问它们的网络端点不会改变。可以与云平台集成并配置互联网负载均衡器。

### 服务网格（Service Mesh）

实现流量加密到 Pod 间通信、增强网络遥测和高级路由等功能的基础设施软件。与 [[Kubernetes]] 一起使用的常见服务网格包括 Consul、Istio、Linkerd 和 Open Service Mesh。还有其他选择。

### Sidecar

与主应用[[容器]]一起运行并增强其功能的专用[[容器]]。服务网格通常实现为注入到 [[Pod]] 中的 sidecar [[容器]]，添加网络功能。

### StatefulSet

部署和管理有状态 [[Pod]] 的控制器。类似于 [[Deployment]]，但用于有状态应用程序。

### 存储类（Storage Class, SC）

在集群上创建不同存储层/类的方法。例如，可能有一个名为 "fast" 的 SC 创建基于 NVMe 的存储，另一个名为 "medium-three-site" 的 SC 创建跨三个站点复制的较慢存储。

---

## V

### 卷（Volume）

持久存储的通用术语。

---

## W

### WebAssembly (Wasm)

用于执行应用程序的安全沙箱虚拟机格式。

### 工作节点（Worker Node）

用于运行用户应用程序的集群[[节点]]。有时称为 "Node" 或 "worker"。

---

## Y

### YAML（Yet Another Markup Language）

一种标记语言。通常用于编写 [[Kubernetes]] 配置文件。它是 JSON 的超集。
