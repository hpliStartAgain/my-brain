# Kubernetes 架构深度剖析：从设计哲学到生产实战

> 本专栏是 Kubernetes 的**系统化深度剖析**——不是"怎么用 K8s"的入门教程，而是"K8s 为什么这样设计、各组件如何实现、生产环境如何用好"的工程级深度专栏。
>
> 专栏的核心理念：**理解 K8s 的设计哲学比记住命令更重要**。声明式 API、控制器模式、面向终态协调、Level-triggered 设计——这些原则贯穿 K8s 的每一个组件。理解了这些原则，你就能预测任何 K8s 资源的行为，而不是死记硬背每个参数。
>
> 专栏从 Borg 到 K8s 的设计哲学出发，深入剖析控制平面（API Server、etcd、控制器、调度器）和数据平面（kubelet、kube-proxy、CNI、CSI）的实现原理，最后落地到生产实战（多租户、可观测性、弹性伸缩、多集群）。每篇文章 500+ 行，源码级深度，生产实战导向。
>
> **前置知识**：[[云原生/Docker/00 专栏导览|Docker 专栏]]（Namespace、Cgroups、UnionFS、容器网络、OCI 标准）。
>
> **与已有 K8s 笔记的关系**：已有 `云原生/Kubernetes/` 下的分模块笔记（架构原则、API Server、控制器、网络、生命周期、生产实践）是组件级参考，本专栏是系统化的深度剖析，聚焦"为什么这样设计"和"源码级实现"，两者互补。

---

## 专栏结构

### 第一部分：设计哲学与架构全景

回答"K8s 是什么、它解决什么问题、它的核心设计原则是什么"。建立贯穿全专栏的思维方式——声明式 API、控制器模式、面向终态协调。

| 序号 | 文章标题 | 核心内容 |
|------|---------|---------|
| 01 | Kubernetes 的设计哲学：从 Borg 到云原生操作系统 | Borg 的经验教训、K8s 解决的核心问题、声明式 vs 命令式、面向终态、Level-triggered vs Edge-triggered、K8s 的"低门槛高天花板"设计 |
| 02 | 声明式 API 与面向终态协调：K8s 的核心范式 | 声明式 API 的本质、Spec/Status 分离、控制器协调循环、为什么声明式比命令式更适合分布式系统、K8s API 的 RESTful 设计 |
| 03 | 架构全景：控制平面、数据平面与一个 Pod 的完整生命周期 | 控制平面（API Server/etcd/Scheduler/Controller Manager）与数据平面（kubelet/kube-proxy/容器运行时）、一个 Pod 从提交到运行的完整链路、组件间的通信协议 |

### 第二部分：API Server 深度剖析

API Server 是 K8s 的"前台总调度"——所有组件都通过它读写集群状态。理解 API Server 的请求链路、安全机制和 List-Watch 协议，是理解 K8s 的关键。

| 序号 | 文章标题 | 核心内容 |
|------|---------|---------|
| 04 | API Server 请求链路：从 HTTP 请求到 etcd 写入 | API Server 的多层架构、请求处理流水线、Scheme/Codec/Converter、RESTStorage 映射、etcd 读写路径、API Server 的缓存层 |
| 05 | 认证、授权与准入控制：K8s 的安全三级防线 | 认证（TLS/Token/OIDC/ServiceAccount）、授权（RBAC/ABAC/Node）、准入控制（MutatingWebhook/ValidatingWebhook）、安全上下文与 Pod Security Standards |
| 06 | List-Watch 与 Informer：K8s 的分布式神经系统 | List-Watch 协议、Informer 框架、Reflector/Delta FIFO/Local Cache/Indexer、Resync 机制、Informer 的内存管理与性能优化 |

### 第三部分：状态存储与共识

etcd 是 K8s 的"唯一记忆"——集群所有状态都存在 etcd 中。理解 etcd 的共识机制和 K8s 如何使用 etcd，是理解 K8s 一致性保证的关键。

| 序号 | 文章标题 | 核心内容 |
|------|---------|---------|
| 07 | etcd 深度剖析：Raft 共识、MVCC 与 Watch 机制 | etcd 的 Raft 实现、Leader 选举与日志复制、MVCC 多版本并发控制、Watch 的实现原理、etcd 的性能特性与压缩机制 |
| 08 | K8s 的 ResourceVersion 与乐观并发控制 | ResourceVersion 的本质（etcd ModRevision）、乐观并发控制 vs 悲观锁、冲突重试机制、为什么 K8s 不用分布式锁、ResourceVersion 在 List-Watch 中的作用 |

### 第四部分：控制器与调度器

控制器是 K8s 的"自动驾驶员"——它们持续协调实际状态向期望状态收敛。调度器决定 Pod 运行在哪个节点上。

| 序号 | 文章标题 | 核心内容 |
|------|---------|---------|
| 09 | 控制器模式与协调循环：从 Deployment 到 Operator | 控制器的通用模式、协调循环（Reconcile Loop）、期望状态 vs 实际状态、Deployment→ReplicaSet→Pod 的级联控制、控制器的最终一致性 |
| 10 | StatefulSet 深度解析：有序部署与持久化身份 | StatefulSet vs Deployment、有序部署与网络身份、PV 绑定与 Pod 的稳定关系、Headless Service、StatefulSet 的滚动更新与回滚 |
| 11 | Scheduler 调度算法：预选、优选与扩展机制 | 调度器的两阶段（Filter/Score）、预选谓词与优选打分、节点亲和性/反亲和性、Taint/Toleration、调度扩展（Scheduler Framework/Extender） |
| 12 | 自定义控制器与 CRD/Operator 模式 | CRD 的定义与验证、Controller-Runtime 框架、Operator 的设计模式、Helm vs Operator 的应用交付对比、生产级 Operator 的最佳实践 |

### 第五部分：数据平面

数据平面是 K8s 的"执行者"——kubelet 管理 Pod 生命周期，kube-proxy 实现 Service 网络，CNI 负责 Pod 网络，CSI 负责持久化存储。

| 序号 | 文章标题 | 核心内容 |
|------|---------|---------|
| 13 | kubelet 深度剖析：Pod 生命周期与容器运行时接口 | kubelet 的架构、CRI 接口、Pod 的创建/更新/删除流程、PLEG（Pod Lifecycle Event Generator）、健康检查与就绪探针、kubelet 的垃圾回收 |
| 14 | Service 与 kube-proxy：iptables/IPVS/eBPF 数据面演进 | Service 的本质（虚拟 IP + 负载均衡）、kube-proxy 的 iptables 模式、IPVS 模式、eBPF 模式（Cilium）、Service 的会话亲和与流量策略 |
| 15 | CNI 网络模型与数据面对比：Flannel/Calico/Cilium | K8s 网络模型、CNI 插件规范、Flannel 的 VXLAN/Host-GW、Calico 的 BGP/eBPF、Cilium 的 eBPF 数据面、NetworkPolicy 的实现差异 |

### 第六部分：生产实战与进阶

从"理解 K8s"到"用好 K8s"——生产环境的集群管理、可观测性、弹性伸缩和多集群架构。

| 序号 | 文章标题 | 核心内容 |

| 17 | 集群可观测性与故障排查：监控、日志、追踪与诊断 | Prometheus + Grafana 监控、Loki/Fluentd 日志、Jaeger/OpenTelemetry 追踪、K8s 核心组件的故障排查方法、常见问题诊断流程 |
| 18 | 弹性伸缩与多集群：HPA/VPA/Cluster Autoscaler 与 KubeFed | HPA 的指标与算法、VPA 的资源推荐、Cluster Autoscaler 的节点伸缩、KEDA 的事件驱动伸缩、多集群管理（KubeFed/Cluster API/Karmada） |
