# Kubernetes 组件——API Server 专栏导览

## 这一列解决什么问题

`Kubernetes架构深度剖析` 那套已经把 API Server 的机制拆过了：请求链路怎么走（第 04 篇）、三级安全防线怎么串（第 05 篇）、List-Watch 的 informer 怎么工作（第 06 篇）。所以本专栏不再重讲这些内部实现。

这一列回答的是另一组问题：怎么配、配错的症状是什么、出故障先看哪里、容量怎么算。

具体是六件事：请求被拒时错误码归属哪一层（401/403/400/409/429 各自的责任方不同）；证书与 Token 怎么轮换、不轮换会怎样；RBAC 权限怎么审计、越权有几条路径；准入 webhook 怎么变成"全集群写不进去"的单点；watch 断连与控制器缓存不同步怎么判断；过载时靠什么机制不整体崩（APF）。

**技术版本**：Kubernetes 1.37。涉及 Beta/GA 的字段与特性（ValidatingAdmissionPolicy、APF 的 `flowcontrol.apiserver.k8s.io` 版本、BoundServiceAccountTokenVolume、结构化认证配置等）在正文标注版本，不确定处写「以对应版本文档为准」。

分工原则：本文只写"我该把参数设成多少、出问题先看哪里"；讲"代码怎么走的"一律一句话 + 双链指回 `Kubernetes架构深度剖析`。

前置知识：API 对象模型（GVR/GVK）、etcd 的基本角色。
