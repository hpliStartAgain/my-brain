# Java OOP 设计模式专栏导览

## 这一列怎么读

设计模式的书籍已经够多了，缺的从来不是"23 种模式是什么"，而是"我这段代码该不该引入一层抽象"。所以本列不写模式图鉴，每一篇都围绕三件事：这个模式封装的"变化点"是什么、不这样写会退化成什么样、什么时候不该用它。

十个位置，两条主线：前八篇按 GoF 的分组走，每组只挑最有辨析价值的模式——因为模式之间的分界比模式本身更重要（策略 vs 状态、代理 vs 装饰器 vs 适配器、工厂方法 vs 抽象工厂、责任链 vs 装饰器）。后两篇是全列收口：09 写 Spring、10 写 JDK，都不是"框架用了哪些模式"的罗列，而是"框架的设计者当年面对什么约束、为什么选了这个模式、留下了什么历史包袱"。

技术版本：Java 17 / 21 LTS，Spring 6.x / Boot 3.x。JDK 的实现细节都标了版本——`java.util.Observer` 在 JDK 9 已弃用、偏向锁在 JDK 15 废弃、`String` 在 JDK 9 起是 `byte[]` 而非 `char[]`。

## 两条阅读路径

按需查：直接看目录里与手头问题对应的那篇。每篇都独立成立，不依赖前一篇。

按线读：01（SOLID 与过度设计的成本）→ 02-03（创建型：一次性构造的问题）→ 04-05（结构型：包装与共享）→ 06-08（行为型：行为的分派）→ 09-10（真实框架里的取舍）。这条路径的落点是"判断一层抽象值不值得"，不是"记住 23 个名字"。
