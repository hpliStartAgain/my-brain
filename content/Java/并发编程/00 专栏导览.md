# Java 并发编程 专栏导览

## 这一列解决什么问题

并发知识的麻烦在于：网上流传的版本大多停在 JDK 8，而 JDK 15 废弃了偏向锁、JDK 14 重写了 AQS、JDK 21 转正了虚拟线程、JDK 24 又刚把轻量级锁换掉、顺带修掉了 `synchronized` 的虚拟线程 pinning。照旧文章推理，会在最需要判断的地方对不上。

所以这一列的写法是：每篇都对着当前 JDK 的源码与规范核一遍，把"教科书上这么讲、但现在不是这样"的地方明确写出来。

**技术版本**：基线 JDK 21（LTS），JDK 24/25 的变化在相关篇目单独标注。凡涉及版本敏感行为的地方都写明是哪一版，核实不了的写「以对应版本源码为准」。

**这一列的组织**：17 篇分四组，从硬件往上走，最后落到实战。

- 第一组（01-02）讲物理层与语言规范——MESI 与内存屏障、happens-before 规则集。这是后面一切的根。
- 第二组（03-05）讲三个最常用的原语——`volatile`、`synchronized`、CAS 与原子类。
- 第三组（06-10、14-16）讲 JUC 的骨架与构件——AQS、锁、并发容器、协调工具、`ThreadLocal`、虚拟线程。
- 第四组（11-13）讲线程池与异步编排。
- 收口（17）给一套可执行的判断流程。

## 阅读路径

- **想理解原理**：01 → 02 → 03 → 04 → 05 → 06，这六篇是地基，跳过前面直接读 AQS 会在细节上反复卡住。
- **要排并发 Bug**：02（happens-before 推理）→ 04（死锁定位）→ 15（ThreadLocal 泄漏）→ 09/10（容器语义）→ 17（判断流程）。
- **要做性能优化**：17（先判断该不该动）→ 11/12（线程池与分治）→ 05/09（无锁与容器）→ 16（虚拟线程是否适用）。
- **要选型**：07（锁的选择）→ 08（读多写少）→ 10（容器选择）→ 11（线程池配置）→ 16（要不要上虚拟线程）。

> [!warning] 读这一列的一个前提
> 这一列里很多结论与网上流传的说法相反（偏向锁还活着、JMM 有八大规则、`StampedLock` 比读写锁快所以优先用……）。原因不是那些文章写错了，是 JDK 变了。读的时候留意每篇标注的版本，尤其 04、06、16 三篇——它们纠正的正是流传最广的那部分。
