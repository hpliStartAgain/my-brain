# HDFS 深度解析专栏导览

## 这一列怎么读

HDFS 的原理图到处都有，缺的是"出问题时该看什么"。所以这一列不重复讲"NN 存元数据、DN 存数据"，而是按**一次读/写会依次碰到什么**来排：它为什么被造成这样（01）→ 三个角色的分工与锁（02）→ 元数据怎么持久化（03）→ 数据怎么流动（04）→ 副本怎么挑节点（05）→ 坏了怎么切（06）→ 装不下怎么扩（07）→ DN 怎么管盘（08）→ 数据坏了怎么修（09）→ 最后落到小文件治理与存算分离（10）。

每一篇都落三类东西：机制到源码级、配置项与它调大调小的代价、故障形态与判据（日志关键字 + 该看哪个指标）。

**与 `读书笔记-大数据概览/01 HDFS` 的分工**：那篇是 survey 口径的概述，讲"HDFS 是什么、能干什么"；本列讲"每个机制怎么实现、出问题怎么判"。

**技术版本**：Hadoop 3.3.x。几个容易按旧资料配错的值在篇内都标了：`dfs.blockreport.intervalMsec` 默认 6 小时、`dfs.namenode.lease-hard-limit-sec` 是 1200（20 分钟）、`dfs.blocksize` 默认仍是 128MB（256MB 是调优值）。

## 一条排查顺序

存储侧出问题，按这个顺序定位能少走弯路：

| 现象 | 先去哪篇 | 看什么 |
| :--- | :--- | :--- |
| 写入慢、P99 长尾 | 04 | `Slow BlockReceiver`、`Slow flushOrSync`、Pipeline 有没有缩链 |
| 读不到、`Could not obtain block` | 04 / 09 | 副本是否都坏、`fsck -list-corruptfileblocks` |
| NN RPC 队列堆积 | 02 | `CallQueueLength`、读锁/写锁的持有时间、有没有人在跑 `fsck` |
| 重启卡在 safemode | 03 | DN 是否都起来了、块汇报是否完成、`safemode.threshold-pct` |
| 副本数一直不足 | 05 / 09 | `UnderReplicatedBlocks`、复制名额是否被占用、DN 负载是否被 `considerLoad` 排除 |
| 集群切换后两个 Active | 06 | fencing 有没有配、旧 Active 的日志有没有 `fenced` |
| 文件数上不去、NN 堆告警 | 01 / 10 | 小文件数、每个对象的元数据开销、先治理还是先扩 Federation |
