# Mysql 内核架构读书笔记专栏导览

**摘要：** 本专栏是《MySQL 内核架构》一书的逐章研读笔记，共 19 篇，覆盖从 Server 层总体架构到 InnoDB 各子系统、再到复制与分布式事务的完整链路。与原书按章节组织不同，本专栏每篇都围绕一个"为什么这样设计"的问题展开：先说明这个机制要解决什么问题，再讲它的实现与代价，最后落到生产环境中的观测手段与参数依据。专栏的取舍是**保留源码级的结构分析（关键结构体与调用链）与内核视角的机制推导**，但把"逐行贴代码"改为"讲清代码在解决什么"——因为前者会过时，后者不会。

> [!note] 专栏定位
> 本专栏与同目录下的《[[中间件/MySQL/MySQL架构与底层原理/00 专栏导览|MySQL 架构与底层原理]]》专栏存在主题交集（缓冲池、日志、索引、事务）。两者的差异在于组织方式：**本专栏按"内核模块"组织**（每个子系统一篇，自底向上），**后者按"一条 SQL 的生命周期"组织**（自顶向下串讲）。建议先读本专栏建立模块级认知，再用后者串联成完整数据流。

> [!info] 阅读顺序建议
> 第 1-3 篇（总体架构、通信协议、数据字典）是**全局地图**，建议先读；第 4-12 篇（缓冲池、插入缓冲、自适应哈希、日志、双写、后台线程、表空间、索引、事务）是 **InnoDB 内核主体**，可按需跳读；第 13-19 篇（复制、组复制、崩溃恢复、原子 DDL、权限、角色、分布式事务）是**架构与运维层**。

## 阅读建议

- **想理解"一条 SQL 为什么慢"**：从第 11 篇（索引）与第 4 篇（缓冲池）入手，再回看第 1 篇的整体链路。
- **想排查"写入抖动"**：重点看第 7、8、9 篇（日志、双写、后台线程），这三者共同决定刷盘行为。
- **想设计高可用架构**：第 13、14、15 篇（复制、组复制、崩溃恢复）是基础，第 19 篇覆盖跨实例一致性。
- **想理清权限与安全**：第 17、18 篇。

> [!warning] 前置知识
> 本专栏假设读者能读写基本 SQL、了解操作系统层面的进程/内存/磁盘 IO 概念，并至少见过一次 `SHOW ENGINE INNODB STATUS` 的输出。涉及事务隔离与锁的部分，建议先读《[[中间件/MySQL/MySQL架构与底层原理/00 专栏导览|MySQL 架构与底层原理]]》的第 7、8 篇。
