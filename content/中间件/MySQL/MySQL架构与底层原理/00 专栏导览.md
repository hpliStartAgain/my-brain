# MySQL 架构与底层原理专栏导览

## 这一列怎么读

仓库里已有 `读书笔记-Mysql内核架构`（19 篇，每篇 12,000+ 字）把 InnoDB 的机制拆到了源码级：Buffer Pool 的分区、WAL 的两阶段、MVCC 的 read view、B+Tree 的分裂合并。

所以这一列不再重讲机制。它写的是**运行期的判据**——同一个 Buffer Pool，读书笔记那列告诉你 LRU 链表怎么组织，这一列告诉你命中率算出来 99.9% 却仍然慢是为什么、`innodb_buffer_pool_size` 该按什么算、`wait_free` 涨了说明什么。

十篇按"一次故障会依次怀疑到哪里"排序：先看是不是 SQL 慢（01），再查内存（02）、日志（03）、长事务（04）、索引（05）、表结构（06）、锁（07）、隔离级别（08）、优化器选错（09），最后才是复制（10）。每一篇都给指标名、阈值与"先动哪个旋钮"的顺序。

**技术版本**：MySQL 8.0 / 8.4 LTS。8.0.30 的 redo 参数变化、8.4 移除 `mysql_native_password` 这类版本敏感项在篇内标注；核实不了的写「以对应版本文档为准」。

**验收口径**：本列走综述与选型口径（8,000-10,000 字 / 350+ 行），`python3 scripts/verify_batch.py "<文件>" --survey`。
