# Go 网络编程与持久化 专栏导览

## 专栏定位

本专栏聚焦 **网络传输、应用协议与持久化理论**——服务端 Go 程序几乎总在两处边界上工作：向上是 HTTP（或 gRPC）等应用协议，向下是 TCP 连接与数据库连接。这两层边界都有各自的"物理事实"：TCP 是无边界的字节流，应用必须自己成帧；连接池里的每一条连接都是一份有生命周期的操作系统资源，泄漏它不需要显式错误，只需忘记读尽 Body；数据库事务不是抽象的原子操作，而是一次对单一物理连接的强绑定。

本专栏的目标不是教你用 `net/http` 或 `database/sql`，而是讲清这些抽象层之下的物理约束——因为线上事故大多发生在抽象漏出的地方。

## 目标读者

- 用 Go 编写微服务/网关/中间件，但被连接泄漏、超时配置、粘包拆包困扰的工程师
- 需要为服务端做优雅停机、连接池调优、事务边界设计的后端负责人
- 对应用协议设计、连接池状态机、事务物理边界感兴趣的技术爱好者
