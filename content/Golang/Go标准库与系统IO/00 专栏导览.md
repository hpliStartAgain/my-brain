# Go 标准库与系统 I/O 专栏导览

## 专栏定位

本专栏聚焦 **Go 标准库的设计契约与资源抽象**——Go 的"简单"在很大程度上来自标准库对系统资源的克制封装：`io.Reader`/`io.Writer` 用两个方法把文件、网络、内存、管道统一成同一种流，`bufio` 用一层用户态缓冲把系统调用的次数从"每次一个字节"降到"每次一块"，`time` 用双时钟字段把墙上时钟与单调时钟的语义分离，`encoding/json` 用反射与元数据缓存把动态数据映射回静态类型。

理解这些契约，才能理解为什么"标准库够用"是 Go 的一条工程信条，也才能理解在契约边界之外（短读、部分写、截断、时钟跳变、精度漂移）究竟会发生什么。本专栏不做 API 手册，只讲契约背后的数学与系统事实。

## 目标读者

- 日常使用 `io`/`os`/`bufio`/`time`/`encoding/json` 但被短读、Flush 丢失、时钟跳变等问题困扰的开发者
- 需要为文件系统、序列化、时间处理做可靠性设计或做安全加固的工程师
- 对"用户态抽象如何覆盖操作系统事实"这一主题感兴趣的技术爱好者
