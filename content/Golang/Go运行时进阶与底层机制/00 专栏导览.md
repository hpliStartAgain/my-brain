# Go 运行时进阶与底层机制 专栏导览

## 专栏定位

本专栏聚焦 **从编译器前端到底层运行时的完整链路**——Go 编译器把源码变成 SSA 中间表示，做逃逸分析、内联、去虚拟化等优化，再生成机器码；Go 运行时用 mcache/mcentral/mheap 三级分配器和三色标记 GC 管理堆内存；而在语言的最底层，`reflect` 用元数据打通动态与静态的边界，`unsafe` 与 `cgo` 则直接触碰内存布局与跨语言调用约定。

本专栏承接《[[Golang/Go语言核心/00 专栏导览|Go 语言核心]]》的数据语义，专门回答"编译器和运行时为了让 Go 又快又安全，究竟做了什么、代价是什么"。内存分配器与垃圾回收两篇由原 Go 语言核心专栏迁移而来，并在此专题内进一步与编译器优化、跨语言边界形成呼应。

## 目标读者

- 希望理解 Go 编译期优化（逃逸分析、内联、开放编码 defer）决策依据的性能敏感型开发者
- 需要读懂 Go 反汇编、剖析 GC 停顿、评估反射与 cgo 性能代价的工程师
- 对 Go 编译器后端、运行时内存管理与跨语言互操作感兴趣的技术爱好者
