# 对撞指针入门：有序数组中的两数之和

**摘要：**

对撞指针是最容易上手的双指针模型：两个指针从数组两端出发，根据当前两端的和与目标值的大小关系，决定哪一端内缩。本文从 Two Sum II 出发，**严格证明对撞指针的正确性**（为什么每次移动不会错过答案），然后推广到 Valid Palindrome、Reverse String 与"平方后有序数组"，揭示对撞指针在"从两端向中间消解"问题中的统一模式。文中用 Go 语言实现，并逐层追问：为什么"有序性"是对撞指针的前提（无序数组会怎样）、循环条件该用 `left < right` 还是 `left <= right`、以及内层"跳过非法字符"的循环为什么必须带边界保护。掌握本篇，你就掌握了对撞指针的全部要素。

---

## 第 1 章 问题引入：无序版 Two Sum 的局限

### 1.1 LeetCode 1 vs LeetCode 167

两题看似极其相似，但有一个关键差别：

| | LC 1（Two Sum） | LC 167（Two Sum II） |
|--|-----------------|----------------------|
| 输入 | **无序**数组 | **升序**数组 |
| 返回 | 下标（0-indexed） | 下标（1-indexed） |
| 标准解法 | 哈希表，$O(n)$ 时间、$O(n)$ 空间 | 对撞指针，$O(n)$ 时间、$O(1)$ 空间 |

LC 1 用哈希表：扫描数组，对每个 `x` 检查 `target-x` 是否在哈希表中。**LC 167 的输入已经有序，这个额外保证让我们能用 $O(1)$ 空间的对撞指针。** **有序性才是对撞指针的关键，不是题目本身。**

### 1.2 为什么有序才能用对撞指针

先看一个对比实验。给**无序**数组 `[3,1,4,2]`、target = 3，从两端出发：

```text
left=0(3), right=3(2): 和 5 > 3 → right--
left=0(3), right=2(4): 和 7 > 3 → right--
left=0(3), right=1(1): 和 4 > 3 → right--
left=0, right=0: 循环结束 → 输出"无解"
```

**但实际上 `nums[1] + nums[3] = 1 + 2 = 3` 是有解的——对撞指针在无序数组上直接失效。**

**失效的根本原因**：在无序数组中，`right--` 之后新的 `nums[right]` 不一定更小，"和偏大就缩小右端"的推论失去依据。

> [!info] 有序性：对撞指针的"充电器"
> 对撞指针的每一步，都依赖"排除这整行/列是安全的"这一论断。**而它成立的基础是数组有序**——有序才保证"移动后的新值必然更大/更小"。**遇到对撞指针不生效的题，先问：输入有序吗？不有序能先排序吗？**

## 第 2 章 LeetCode 167：两数之和 II

### 2.1 题目

**LeetCode 167 - Two Sum II**（中等）

给你一个下标从 **1** 开始、已按**非递减**排列的数组 `numbers`，找出和为 `target` 的两个数，以 `[index1, index2]`（**1-indexed**）返回。**必须只使用常量级额外空间。**

```text
输入: [2,7,11,15], target=9  →  [1,2]
输入: [2,3,4],     target=6  →  [1,3]
输入: [-1,0],      target=-1 →  [1,2]
```

### 2.2 Go 实现

```go
func twoSum(numbers []int, target int) []int {
    left, right := 0, len(numbers)-1
    for left < right {
        sum := numbers[left] + numbers[right]
        switch {
        case sum == target:
            return []int{left + 1, right + 1} // 转 1-indexed
        case sum < target:
            left++ // 和偏小，右移左指针
        default:
            right-- // 和偏大，左移右指针
        }
    }
    return []int{-1, -1} // 题目保证有解
}
```

**复杂度**：时间 $O(n)$、空间 $O(1)$。**代码极简，但正确性需严格证明。**

### 2.3 正确性证明：为什么不会错过答案

**命题**：若存在下标对 $(i^*, j^*)$（$i^* < j^*$）满足 `numbers[i*] + numbers[j*] == target`，对撞指针一定能找到它（或另一个合法答案对）。

**证明（反证法）**：假设对撞指针在某步执行了 `left++`（从 `l` 移到 `l+1`），此时 `left == l`、`right == r`，且 `numbers[l] + numbers[r] < target`。

**我们想证明：此步不会错过"以 `l` 为左端点"的任何解。**

由于数组有序，$r' \le r$ 时 `numbers[l] + numbers[r'] ≤ numbers[l] + numbers[r] < target`。**因此，以 `l` 为左端点、任意 $j \le r$ 为右端点的所有组合，和都小于 target，都不是解。**

对撞指针在执行 `left++` 之前，`right` 是当前最大的右端点 $r$；**以 `l` 为左端点的所有可能右端点的和都小于 target。因此，以 `l` 为左端点的所有对都不是解，可以安全排除 `l`**，即 `left++`。

对称地，若 `numbers[l] + numbers[r] > target`，则对任意 $i \ge l$，`numbers[i] + numbers[r] >= numbers[l] + numbers[r] > target`，**以 `r` 为右端点的所有对也都不是解**，可以安全 `right--`。

**结论**：每次 `left++` 或 `right--` 都排除了当前左端或右端的所有合法组合，**不遗漏任何解**。$\square$

> [!info] 核心概念：排除是"行/列级别"的
> `left++` 排除的是"以当前 `left` 为左端点的所有可能右端点"（**整行**）；`right--` 排除的是"以当前 `right` 为右端点的所有可能左端点"（**整列**）。**两种操作合计排除 $O(n)$ 行/列，而指针总移动步数也是 $O(n)$，因此时间是 $O(n)$。**

### 2.4 边界条件

**边界一，`while left < right` 还是 `left <= right`？** 题目要求两个下标不同（`index1 < index2`），所以 `left`、`right` 不能相等。**用 `left < right` 自然避免"同一元素用两次"。**

**边界二，存在负数是否影响正确性？** **不影响。** 正确性证明只依赖"数组有序"，不要求元素为正。如样例 `[-1, 0]`、target = -1。

**边界三，只有两个元素时。** `left=0`、`right=1`，直接检查 `numbers[0] + numbers[1]`——**正好等于 target 就返回，否则退出循环**（因为 `left < right` 不成立）。

## 第 3 章 LeetCode 125：验证回文串

### 3.1 题目

**LeetCode 125 - Valid Palindrome**（简单）

把所有大写转小写、移除所有非字母数字字符后，若短语正读反读相同，则为回文串。

```text
输入: "A man, a plan, a canal: Panama"  → true
输入: "race a car"                      → false
输入: " "                               → true（空串是回文）
```

### 3.2 Go 实现

```go
func isPalindrome(s string) bool {
    left, right := 0, len(s)-1
    for left < right {
        for left < right && !isAlnum(s[left]) { // 左指针跳过非字母数字
            left++
        }
        for left < right && !isAlnum(s[right]) { // 右指针跳过非字母数字
            right--
        }
        if toLower(s[left]) != toLower(s[right]) {
            return false
        }
        left++
        right--
    }
    return true
}

func isAlnum(c byte) bool {
    return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || (c >= '0' && c <= '9')
}

func toLower(c byte) byte {
    if c >= 'A' && c <= 'Z' {
        return c + 32
    }
    return c
}
```

**复杂度**：时间 $O(n)$（每个字符最多被访问两次）、空间 $O(1)$。

### 3.3 为什么不先预处理字符串

另一种思路：先遍历过滤出字母数字字符、构造新串，再比较它与反转。**这完全正确，但空间是 $O(n)$。**

**对撞指针的优势正是 $O(1)$ 空间**——直接在原串上操作。**在空间敏感场景（如处理超大字符串流）下，$O(1)$ 的对撞指针明显优于 $O(n)$ 的预处理。**

### 3.4 边界条件

**边界一，空串或全非字母数字字符。** 如 `" "`，左右跳过后 `left >= right`，循环不进入，返回 `true`——**符合题意（空串是回文）。**

**边界二，内层 `while` 的边界不能省。** `left < right` 这一判断必须带上。**若字符串全是非字母数字字符（如 `"!!!"`），不带边界的话左指针会一直向右越界。**

**边界三，奇数长度。** 如 `"aba"`，`left=0(a)`、`right=2(a)` 相等，`left=1`、`right=1` 时 `left < right` 为假退出——**中间的 `b` 不需判断，正确。**

## 第 4 章 LeetCode 344：反转字符串

### 4.1 题目与实现

**LeetCode 344 - Reverse String**（简单）：原地反转字符数组，**只使用 $O(1)$ 额外空间。**

```go
func reverseString(s []byte) {
    left, right := 0, len(s)-1
    for left < right {
        s[left], s[right] = s[right], s[left]
        left++
        right--
    }
}
```

### 4.2 从反转到回文：统一的视角

反转字符串与判断回文，本质上是同一个对撞指针框架：

| 操作 | 反转字符串 | 判断回文 |
|------|-----------|---------|
| 初始化 | `left=0, right=n-1` | `left=0, right=n-1` |
| 每次操作 | **交换** `s[left]`、`s[right]` | **比较** `s[left]`、`s[right]` |
| 终止 | `left >= right` | `left >= right` 或不相等 |

**理解了这个统一框架，遇到"从两端向中间处理"的问题，首先想到对撞指针。**

## 第 5 章 变体：有序数组的其他对撞问题

### 5.1 平方后有序数组（LeetCode 977）

**题目**：给一个非递减数组，返回"每个数字的平方"组成的非递减数组。

**直觉**：平方后，**最大的平方在两端**（最大正数、绝对值最大的负数）。用对撞指针从两端取较大的平方，**从后往前填结果数组**：

```go
func sortedSquares(nums []int) []int {
    n := len(nums)
    result := make([]int, n)
    left, right := 0, n-1
    pos := n - 1 // 从结果数组末尾开始填

    for left <= right {
        leftSq, rightSq := nums[left]*nums[left], nums[right]*nums[right]
        if leftSq > rightSq {
            result[pos] = leftSq
            left++
        } else {
            result[pos] = rightSq
            right--
        }
        pos--
    }
    return result
}
```

**复杂度**：时间 $O(n)$（比"先平方再排序"的 $O(n \log n)$ 更优）。

**这道题的特别之处**：**对撞指针的"单调性"来源不是"和偏大则收缩右端"，而是"平方值在两端最大，从两端取较大值"。** **不同的单调性，相同的框架**——这正是对撞指针的普适性。

### 5.2 移动零（LeetCode 283）

**题目**：把所有 `0` 移到数组末尾，保持非零元素相对顺序。

**它用的是"同向双指针"**——`slow` 指向下一个应填非零元素的位置、`fast` 扫描数组：

```go
func moveZeroes(nums []int) {
    slow := 0
    for fast := 0; fast < len(nums); fast++ {
        if nums[fast] != 0 {
            nums[slow], nums[fast] = nums[fast], nums[slow]
            slow++
        }
    }
}
```

**注意这里不是对撞指针，而是同向双指针**（`slow`、`fast` 都从左向右）。**但其核心思路仍是"`fast` 扫描、`slow` 维护结果区间"。**

**这提示了一个重要模式**：**双指针不一定要从两端出发，"同向双指针"在原地去重/过滤类问题中同样常用。**

## 第 6 章 对撞指针的边界总结

### 6.1 三个必须确认的边界

**问题一，循环条件用 `left < right` 还是 `left <= right`？**

- 找两个**不同位置**的元素：`left < right`（避免同一元素用两次）；
- 两端向中间**消解**（反转、回文）：`left < right`（奇数长度时中间元素不需处理）；
- 特殊情况 `left == right` 也需处理：`left <= right`（较少见，如 LC 977）。

**问题二，移动指针后是否需要 `continue`？** Two Sum II 找到答案直接 `return`；但若需去重（如 3Sum），找到答案后还要跳过重复元素（详见下一篇）。

**问题三，输入是否保证非空？** 面试中主动询问或加防御性判断。

### 6.2 三个常见错误

**错误一，在无序数组上直接用对撞指针。** 不具备全局有序性，正确性证明失效。**解决：先排序（$O(n\log n)$），再用对撞指针。**

**错误二，漏了"跳过非法字符"的内层边界。** Valid Palindrome 的内层 `while` 必须带 `left < right`。

**错误三，返回值是 1-indexed 时忘记 `+1`。** Two Sum II 的常见低级错误。

### 6.3 一个可复用的判断

**遇到"两元素配对"类问题，先问三句**：

1. **数组有序吗？** 有序用对撞指针；无序考虑哈希表或先排序；
2. **要不要返回原始下标？** 要则哈希表更自然（排序会打乱下标）；
3. **循环条件用 `<` 还是 `<=`？** 看"是否允许同一元素用两次"。

**这三句，能定下对撞指针题的方案。**

## 小结

对撞指针的精髓可以用一句话概括：**利用有序性，每次移动一端，永久消除"以当前端点为左/右端点"的所有组合。** 本篇覆盖了三道主线题——**Two Sum II**（最标准的模板，含正确性证明）、**Valid Palindrome**（结合字符过滤，注意内层边界）、**Reverse String**（最基础的原型操作），以及两道变体（平方后有序数组、移动零）。

贯穿全篇的核心认知有两条。其一，**"有序性"是对撞指针的充要前提**——无序数组会让它失效，这也是 LC 1 用哈希表的原因。其二，**对撞指针的"单调性"可以有不同来源**——"和的大小关系"（两数之和）、"平方值在两端最大"（LC 977），**不同的单调性，相同的框架**。**把这两条握住，你面对任何"两端配对"的问题，都能先判断"有没有有序性"。**
