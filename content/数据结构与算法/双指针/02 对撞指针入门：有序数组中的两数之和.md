# 对撞指针入门：有序数组中的两数之和

**摘要：**

对撞指针是最容易上手的双指针模型：两个指针从数组两端出发，根据当前两端的和与目标值的大小关系，决定哪一端内缩。本文从 Two Sum II 出发，**严格证明对撞指针的正确性**（为什么每次移动不会错过答案），然后推广到 Valid Palindrome、Reverse String 与"平方后有序数组"，揭示对撞指针在"从两端向中间消解"问题中的统一模式。文中用 Go 语言实现，并逐层追问：为什么"有序性"是对撞指针的前提（无序数组会怎样）、循环条件该用 `left < right` 还是 `left <= right`、以及内层"跳过非法字符"的循环为什么必须带边界保护。掌握本篇，你就掌握了对撞指针的全部要素。

---

## 第 1 章 问题引入：无序版 Two Sum 的局限

### 1.1 LeetCode 1 vs LeetCode 167

两题看似极其相似，但有一个关键差别：

| | LC 1（Two Sum） | LC 167（Two Sum II） |
|--|-----------------|----------------------|
| 输入 | **无序**数组 | **升序**数组 |
| 返回 | 下标（0-indexed） | 下标（1-indexed） |
| 标准解法 | 哈希表，$O(n)$ 时间、$O(n)$ 空间 | 对撞指针，$O(n)$ 时间、$O(1)$ 空间 |

LC 1 用哈希表：扫描数组，对每个 `x` 检查 `target-x` 是否在哈希表中。**LC 167 的输入已经有序，这个额外保证让我们能用 $O(1)$ 空间的对撞指针。** **有序性才是对撞指针的关键，不是题目本身。**

### 1.2 为什么有序才能用对撞指针

先看一个对比实验。给**无序**数组 `[3,1,4,2]`、target = 3，从两端出发：

```text
left=0(3), right=3(2): 和 5 > 3 → right--
left=0(3), right=2(4): 和 7 > 3 → right--
left=0(3), right=1(1): 和 4 > 3 → right--
left=0, right=0: 循环结束 → 输出"无解"
```

**但实际上 `nums[1] + nums[3] = 1 + 2 = 3` 是有解的——对撞指针在无序数组上直接失效。**

**失效的根本原因**：在无序数组中，`right--` 之后新的 `nums[right]` 不一定更小，"和偏大就缩小右端"的推论失去依据。

> [!info] 有序性：对撞指针的"充电器"
> 对撞指针的每一步，都依赖"排除这整行/列是安全的"这一论断。**而它成立的基础是数组有序**——有序才保证"移动后的新值必然更大/更小"。**遇到对撞指针不生效的题，先问：输入有序吗？不有序能先排序吗？**

## 第 2 章 LeetCode 167：两数之和 II

### 2.1 题目

**LeetCode 167 - Two Sum II**（中等）

给你一个下标从 **1** 开始、已按**非递减**排列的数组 `numbers`，找出和为 `target` 的两个数，以 `[index1, index2]`（**1-indexed**）返回。**必须只使用常量级额外空间。**

```text
输入: [2,7,11,15], target=9  →  [1,2]
输入: [2,3,4],     target=6  →  [1,3]
输入: [-1,0],      target=-1 →  [1,2]
```

### 2.2 Go 实现

```go
func twoSum(numbers []int, target int) []int {
    left, right := 0, len(numbers)-1
    for left < right {
        sum := numbers[left] + numbers[right]
        switch {
        case sum == target:
            return []int{left + 1, right + 1} // 转 1-indexed
        case sum < target:
            left++ // 和偏小，右移左指针
        default:
            right-- // 和偏大，左移右指针
        }
    }
    return []int{-1, -1} // 题目保证有解
}
```

**复杂度**：时间 $O(n)$、空间 $O(1)$。**代码极简，但正确性需严格证明。**

### 2.3 正确性证明：为什么不会错过答案

**命题**：若存在下标对 $(i^*, j^*)$（$i^* < j^*$）满足 `numbers[i*] + numbers[j*] == target`，对撞指针一定能找到它（或另一个合法答案对）。

**证明（反证法）**：假设对撞指针在某步执行了 `left++`（从 `l` 移到 `l+1`），此时 `left == l`、`right == r`，且 `numbers[l] + numbers[r] < target`。

**我们想证明：此步不会错过"以 `l` 为左端点"的任何解。**

由于数组有序，$r' \le r$ 时 `numbers[l] + numbers[r'] ≤ numbers[l] + numbers[r] < target`。**因此，以 `l` 为左端点、任意 $j \le r$ 为右端点的所有组合，和都小于 target，都不是解。**

对撞指针在执行 `left++` 之前，`right` 是当前最大的右端点 $r$；**以 `l` 为左端点的所有可能右端点的和都小于 target。因此，以 `l` 为左端点的所有对都不是解，可以安全排除 `l`**，即 `left++`。

对称地，若 `numbers[l] + numbers[r] > target`，则对任意 $i \ge l$，`numbers[i] + numbers[r] >= numbers[l] + numbers[r] > target`，**以 `r` 为右端点的所有对也都不是解**，可以安全 `right--`。

**结论**：每次 `left++` 或 `right--` 都排除了当前左端或右端的所有合法组合，**不遗漏任何解**。$\square$

> [!info] 核心概念：排除是"行/列级别"的
> `left++` 排除的是"以当前 `left` 为左端点的所有可能右端点"（**整行**）；`right--` 排除的是"以当前 `right` 为右端点的所有可能左端点"（**整列**）。**两种操作合计排除 $O(n)$ 行/列，而指针总移动步数也是 $O(n)$，因此时间是 $O(n)$。**

### 2.4 边界条件

**边界一，`while left < right` 还是 `left <= right`？** 题目要求两个下标不同（`index1 < index2`），所以 `left`、`right` 不能相等。**用 `left < right` 自然避免"同一元素用两次"。**

**边界二，存在负数是否影响正确性？** **不影响。** 正确性证明只依赖"数组有序"，不要求元素为正。如样例 `[-1, 0]`、target = -1。

**边界三，只有两个元素时。** `left=0`、`right=1`，直接检查 `numbers[0] + numbers[1]`——**正好等于 target 就返回，否则退出循环**（因为 `left < right` 不成立）。

### 2.5 深度对比：在有序数组上，为什么不用"固定左端 + 二分查找右端"？

面对有序数组的 Two Sum II，不少刚学完二分查找的读者会提出另一种解法：外层用 `for i := 0; i < n; i++` 枚举左端点 `numbers[i]`，内层在右侧子数组 `numbers[i+1 .. n-1]` 中用二分查找寻找 `target - numbers[i]`。这样空间复杂度同样是 $O(1)$，时间复杂度是 $O(n \log n)$。

为什么 $O(n)$ 的对撞指针比 $O(n \log n)$ 的"枚举 + 二分"更优？"**枚举 + 二分"到底浪费了什么信息？**

答案在于**独立二分丢弃了跨轮次之间的历史单调性**。
假设当外层枚举 $i = 0$ 时，我们在右侧二分查找 `target - numbers[0]`，发现右侧最后一个小于等于 `target - numbers[0]` 的位置停在下标 $r_0$（这意味着对于任意 $j > r_0$，都有 `numbers[0] + numbers[j] > target`）。
现在外层循环推进到 $i = 1$。由于数组是升序的，必有 `numbers[1] >= numbers[0]`，从而对所有 $j > r_0$：

$$\text{numbers}[1] + \text{numbers}[j] \ge \text{numbers}[0] + \text{numbers}[j] > target$$

这意味着：**在 $i = 0$ 时已经被证明"偏大"的右侧后缀区间 `(r0, n-1]`，在 $i = 1, 2, \ldots$ 时必然更加偏大，永远不可能成为合法右端点**。"枚举 + 二分"傻乎乎地在每一轮 $i$ 开始时都把二分上界重置回 `n - 1`，把上一轮早就排除掉的 `(r0, n-1]` 又重新纳回搜索范围折半了一遍；而对撞指针通过让右游标 `right` **单向继承上一轮缩减后的位置 `r0` 继续向左走**，把 $n$ 次独立的对数查找摊还成了一次总长不超过 $n$ 步的线性滑行。

当然，如果遇到极端不对称的场景——譬如要在单次步进中跨越一长串连续过小或过大的平坦元素——我们还可以将对撞指针与二分查找结合起来：当 `numbers[left] + numbers[right] < target` 时，不单步执行 `left++`，而是用 `lowerBound` 在 `[left + 1, right - 1]` 中直接二分跳到第一个满足 `>= target - numbers[right]` 的新 `left` 位置（这在数组存在极端长尾但实际有效跳跃仅有几次时能逼近 $O(\log n)$）。

## 第 3 章 LeetCode 125：验证回文串

### 3.1 题目

**LeetCode 125 - Valid Palindrome**（简单）

把所有大写转小写、移除所有非字母数字字符后，若短语正读反读相同，则为回文串。

```text
输入: "A man, a plan, a canal: Panama"  → true
输入: "race a car"                      → false
输入: " "                               → true（空串是回文）
```

### 3.2 Go 实现

```go
func isPalindrome(s string) bool {
    left, right := 0, len(s)-1
    for left < right {
        for left < right && !isAlnum(s[left]) { // 左指针跳过非字母数字
            left++
        }
        for left < right && !isAlnum(s[right]) { // 右指针跳过非字母数字
            right--
        }
        if toLower(s[left]) != toLower(s[right]) {
            return false
        }
        left++
        right--
    }
    return true
}

func isAlnum(c byte) bool {
    return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || (c >= '0' && c <= '9')
}

func toLower(c byte) byte {
    if c >= 'A' && c <= 'Z' {
        return c + 32
    }
    return c
}
```

**复杂度**：时间 $O(n)$（每个字符最多被访问两次）、空间 $O(1)$。

### 3.3 为什么不先预处理字符串

另一种思路：先遍历过滤出字母数字字符、构造新串，再比较它与反转。**这完全正确，但空间是 $O(n)$。**

**对撞指针的优势正是 $O(1)$ 空间**——直接在原串上操作。**在空间敏感场景（如处理超大字符串流）下，$O(1)$ 的对撞指针明显优于 $O(n)$ 的预处理。**

### 3.4 边界条件

**边界一，空串或全非字母数字字符。** 如 `" "`，左右跳过后 `left >= right`，循环不进入，返回 `true`——**符合题意（空串是回文）。**

**边界二，内层 `while` 的边界不能省。** `left < right` 这一判断必须带上。**若字符串全是非字母数字字符（如 `"!!!"`），不带边界的话左指针会一直向右越界。**

**边界三，奇数长度。** 如 `"aba"`，`left=0(a)`、`right=2(a)` 相等，`left=1`、`right=1` 时 `left < right` 为假退出——**中间的 `b` 不需判断，正确。**

## 第 4 章 LeetCode 344：反转字符串

### 4.1 题目与实现

**LeetCode 344 - Reverse String**（简单）：原地反转字符数组，**只使用 $O(1)$ 额外空间。**

```go
func reverseString(s []byte) {
    left, right := 0, len(s)-1
    for left < right {
        s[left], s[right] = s[right], s[left]
        left++
        right--
    }
}
```

### 4.2 从反转到回文：统一的视角

反转字符串与判断回文，本质上是同一个对撞指针框架：

| 操作 | 反转字符串 | 判断回文 |
|------|-----------|---------|
| 初始化 | `left=0, right=n-1` | `left=0, right=n-1` |
| 每次操作 | **交换** `s[left]`、`s[right]` | **比较** `s[left]`、`s[right]` |
| 终止 | `left >= right` | `left >= right` 或不相等 |

**理解了这个统一框架，遇到"从两端向中间处理"的问题，首先想到对撞指针。**

## 第 5 章 变体：有序数组的其他对撞问题

### 5.1 平方后有序数组（LeetCode 977）

**题目**：给一个非递减数组，返回"每个数字的平方"组成的非递减数组。

**直觉**：平方后，**最大的平方在两端**（最大正数、绝对值最大的负数）。用对撞指针从两端取较大的平方，**从后往前填结果数组**：

```go
func sortedSquares(nums []int) []int {
    n := len(nums)
    result := make([]int, n)
    left, right := 0, n-1
    pos := n - 1 // 从结果数组末尾开始填

    for left <= right {
        leftSq, rightSq := nums[left]*nums[left], nums[right]*nums[right]
        if leftSq > rightSq {
            result[pos] = leftSq
            left++
        } else {
            result[pos] = rightSq
            right--
        }
        pos--
    }
    return result
}
```

**复杂度**：时间 $O(n)$（比"先平方再排序"的 $O(n \log n)$ 更优）。

**这道题的特别之处**：**对撞指针的"单调性"来源不是"和偏大则收缩右端"，而是"平方值在两端最大，从两端取较大值"。** **不同的单调性，相同的框架**——这正是对撞指针的普适性。

### 5.2 移动零（LeetCode 283）

**题目**：把所有 `0` 移到数组末尾，保持非零元素相对顺序。

**它用的是"同向双指针"**——`slow` 指向下一个应填非零元素的位置、`fast` 扫描数组：

```go
func moveZeroes(nums []int) {
    slow := 0
    for fast := 0; fast < len(nums); fast++ {
        if nums[fast] != 0 {
            nums[slow], nums[fast] = nums[fast], nums[slow]
            slow++
        }
    }
}
```

**注意这里不是对撞指针，而是同向双指针**（`slow`、`fast` 都从左向右）。**但其核心思路仍是"`fast` 扫描、`slow` 维护结果区间"。**

**这提示了一个重要模式**：**双指针不一定要从两端出发，"同向双指针"在原地去重/过滤类问题中同样常用。**

### 5.3 验证回文串 II：当对撞指针遇到一次"容错免死金牌"（LeetCode 680）

在第 3 章的 LeetCode 125 中，两端字符一旦失配（`s[left] != s[right]`），函数就立即判死刑返回 `false`。如果题目给你一张"免死金牌"——**最多允许从字符串中删除 1 个字符，问能否使剩余部分构成回文串（LeetCode 680）**，对撞指针该如何演进？

我们依然让 `left = 0, right = len(s) - 1` 从两端相向夹逼：
- 只要 `s[left] == s[right]`，外层首尾已经完美对称，我们绝不浪费宝贵的删除机会，直接 `left++; right--` 向内收缩；
- 一旦在某处首次撞见失配 `s[left] != s[right]`，此时外侧的 `s[0..left-1]` 与 `s[right+1..n-1]` 已经配对完毕，要想挽救局面，**唯一的希望就是动用那仅有的一次删除机会，要么删掉左端失配字符 `s[left]`（考察剩余子串 `s[left+1 .. right]` 是否严格回文），要么删掉右端失配字符 `s[right]`（考察剩余子串 `s[left .. right-1]` 是否严格回文）**。只要这两条分支中有一条能走通，整体就返回 `true`：

```go
package main

// validPalindrome LeetCode 680：最多删除一个字符判断是否回文
// 时间复杂度：严格 O(n)（至多在首次失配处分叉扫描两次剩余区间），空间复杂度：O(1)
func validPalindrome(s string) bool {
	isPal := func(l, r int) bool {
		for l < r {
			if s[l] != s[r] {
				return false
			}
			l++
			r--
		}
		return true
	}

	left, right := 0, len(s)-1
	for left < right {
		if s[left] != s[right] {
			// 首次失配时，二选一：删左端 s[left] 或删右端 s[right]
			return isPal(left+1, right) || isPal(left, right-1)
		}
		left++
		right--
	}
	return true
}
```

这里有一个极其重要的贪心陷阱：**为什么首次遇到 `s[left] != s[right]` 时，不能只看 `s[left+1] == s[right]` 就武断地决定删左边，而必须把两条分支 `isPal(left+1, right)` 和 `isPal(left, right-1)` 都试一遍？**
考虑反例 `"cupuufxoohdfpgjdmysgvhmvffcnqxjjxqncffvmhvgsymdjgpfdhooxfuupucu"`（简化版如 `"abca"` 或 `"ececabbacec"`）：当左端是 `'e'`、右端是 `'c'`，而 `s[left+1]` 恰巧也是 `'c'`、`s[right-1]` 恰巧也是 `'e'` 时，单看紧邻的下一个字符两边都能配上，但只有其中一条分支能一直对称到中心。由于分叉只发生在**第一次**失配的瞬间，且分叉后不再允许任何删除，两条分支各扫一遍剩余区间的总耗时依然不超过 $2n = O(n)$，因此直接或运算 `||` 双路验证既简洁又绝对完备。

### 5.4 平方数之和（LeetCode 633）与救生艇配对（LeetCode 881）

对撞指针在数学与贪心领地里还有两道经典的"隐式有序数组"变形：

1. **LeetCode 633：平方数之和（Sum of Square Numbers）**：给定一个非负整数 $c$，判断是否存在两个整数 $a$ 和 $b$，使得 $a^2 + b^2 = c$。
   - 这里没有显式给你数组，但非负整数 $0, 1, 2, \ldots, \lfloor \sqrt{c} \rfloor$ 天然就是一个严格升序的虚拟数组。
   - 令 `left = 0`，`right = int(math.Sqrt(float64(c)))`。注意题目允许 $a == b$（譬如 $c = 2 = 1^2 + 1^2$），故循环条件必须写 **`for left <= right`**。若 $left^2 + right^2 < c$ 则 `left++`；若 $> c$ 则 `right--`；相等则返回 `true`，耗时 $O(\sqrt{c})$，空间 $O(1)$。

2. **LeetCode 881：救生艇（Boats to Save People）**：给定数组 `people` 表示每个人的体重，每艘救生艇最大载重为 `limit`，且每艘船**最多只能坐 2 个人**。求载完所有人所需的最少船数。
   - 将体重数组升序排列后，`people[right]` 是当前最重的人。他必须上船，那谁跟他拼船最划算？
   - 根据贪心交换论证：如果当前最轻的人 `people[left]` 连跟 `people[right]` 拼船都会超重（`people[left] + people[right] > limit`），那么其他人就更不可能跟 `people[right]` 拼船了，此时 `people[right]` 只能独占一艘船（`right--; boats++`）；
   - 反之，如果最轻的人能跟 `people[right]` 拼上船（`people[left] + people[right] <= limit`），让他们俩同乘一艘船（`left++; right--; boats++`）一定不会比留着 `people[left]` 去跟别人拼更差——因为 `people[right]` 是最难伺候的胖子，能把最难伺候的人顺手带走，留给后续中等体重者的配对空间就越宽裕：

```go
package main

import (
	"math"
	"sort"
)

// judgeSquareSum LeetCode 633：在隐式升序空间 [0, sqrt(c)] 上对撞查找 a^2 + b^2 == c
func judgeSquareSum(c int) bool {
	left, right := 0, int(math.Sqrt(float64(c)))
	for left <= right { // 允许 a == b，故使用 <=
		// 用减法代替 left*left + right*right，彻底预防 32 位整型加法溢出
		diff := c - right*right
		if left*left == diff {
			return true
		} else if left*left < diff {
			left++
		} else {
			right--
		}
	}
	return false
}

// numRescueBoats LeetCode 881：排序 + 首尾对撞贪心拼船
func numRescueBoats(people []int, limit int) int {
	sort.Ints(people)
	left, right := 0, len(people)-1
	boats := 0

	for left <= right {
		// 最重者 people[right] 必上船；若最轻者 people[left] 能搭顺风船则一并带走
		if people[left]+people[right] <= limit {
			left++
		}
		right--
		boats++
	}
	return boats
}
```

### 5.5 反转类对撞指针的家族扩展（LC 345、541、151、189）

第 4 章的反转字符串（LC 344）还可以与条件过滤或分段翻转组合成一族高频字符串与数组操作题：
- **反转字符串中的元音字母（LeetCode 345）**：与验证回文串（LC 125）的代码结构完全同构——外层 `for left < right`，内层两个 `for` 循环分别让 `left` 跳过非元音、让 `right` 跳过非元音，停下后交换 `s[left]` 与 `s[right]` 并双双内缩；
- **轮转数组（LeetCode 189）与翻转字符串里的单词（LeetCode 151）**：如何仅用 $O(1)$ 额外空间，把数组 `[1, 2, 3, 4, 5, 6, 7]` 向右轮转 $k = 3$ 个位置变成 `[5, 6, 7, 1, 2, 3, 4]`？
  - 如果每次向右挪 1 格、重复 $k$ 轮，耗时高达 $O(nk)$；
  - 如果把原数组看作左块 $A = [1, 2, 3, 4]$（长 $n - k$）和右块 $B = [5, 6, 7]$（长 $k$），轮转的目标其实就是把分块序列 $AB$ 变成 $BA$；
  - 利用线性代数中转置（逆）的穿透性质 $(A^R B^R)^R = B A$（或先整体反转 $(AB)^R = B^R A^R$，再把前 $k$ 个元素 $(B^R)^R = B$ 和后 $n-k$ 个元素 $(A^R)^R = A$ 各自用对撞指针反转一次），仅需 **三次对撞指针原地反转**，每个元素恰好交换两次，即可在严格 $O(n)$ 时间、$O(1)$ 空间内完成块级乾坤大挪移：

```go
package main

// rotate LeetCode 189：三次对撞指针反转法实现 O(1) 空间数组右旋 k 步
func rotate(nums []int, k int) {
	n := len(nums)
	if n <= 1 {
		return
	}
	k %= n // 处理 k >= n 的周期折返
	if k == 0 {
		return
	}

	reverse := func(sub []int) {
		for l, r := 0, len(sub)-1; l < r; l, r = l+1, r-1 {
			sub[l], sub[r] = sub[r], sub[l]
		}
	}

	// 1. 全局反转: [1,2,3,4, 5,6,7] -> [7,6,5, 4,3,2,1]
	reverse(nums)
	// 2. 反转前 k 个: [7,6,5] -> [5,6,7]
	reverse(nums[:k])
	// 3. 反转后 n-k 个: [4,3,2,1] -> [1,2,3,4]
	reverse(nums[k:])
}
```

### 5.6 最短无序连续子数组：从两端向中间逼近的逆序边界（LeetCode 581）

对撞/双向逼近思想还能用来定位数组中"乱序核心区"的起止边界。在 **LeetCode 581：最短无序连续子数组**中，给你一个整数数组 `nums`，你需要找出一个连续子数组 `nums[left..right]`，如果只对这一个子数组进行升序排序，那么整个数组都会变为升序排序；请返回该子数组的最短长度。

设想整个数组被划分为三段：左段有序前缀 `nums[0..left-1]`、中间乱序核心区 `nums[left..right]`、右段有序后缀 `nums[right+1..n-1]`。
- 怎么一次性锁定乱序核心区的**右边界 `right`**？从左往右扫描，维护前缀最大值 `maxSeen`。如果当前位置 `i` 处于右侧合法有序后缀中，它必须大于等于左边见过的所有数（`nums[i] >= maxSeen`）；一旦发现 **`nums[i] < maxSeen`**，说明 `nums[i]` 被左边某个更大的数压制了，位置 `i` 必然属于乱序区，而**最后一个满足 `nums[i] < maxSeen` 的下标 `i` 就是乱序区的右边界 `right`**；
- 对称地，从右往左扫描，维护后缀最小值 `minSeen`。**最后一个（最靠左的）满足 `nums[i] > minSeen` 的下标 `i` 就是乱序区的左边界 `left`**：

```go
package main

import "math"

// findUnsortedSubarray LeetCode 581：双向扫描锁定乱序子数组的精确左右边界，时间 O(n)，空间 O(1)
func findUnsortedSubarray(nums []int) int {
	n := len(nums)
	maxSeen, minSeen := math.MinInt32, math.MaxInt32
	left, right := -1, -1

	for i := 0; i < n; i++ {
		// 正向推进 i：寻找最后一个小于左侧历史最大值的失序右界 right
		if nums[i] < maxSeen {
			right = i
		} else {
			maxSeen = nums[i]
		}

		// 逆向推进 n-1-i：寻找最靠左的大于右侧历史最小值的失序左界 left
		j := n - 1 - i
		if nums[j] > minSeen {
			left = j
		} else {
			minSeen = nums[j]
		}
	}

	if right == -1 {
		return 0 // 全程无任何逆序，原数组已完全升序
	}
	return right - left + 1
}
```

## 第 6 章 对撞指针的边界总结

### 6.1 三个必须确认的边界

**问题一，循环条件用 `left < right` 还是 `left <= right`？**

- 找两个**不同位置**的元素：`left < right`（避免同一元素用两次）；
- 两端向中间**消解**（反转、回文）：`left < right`（奇数长度时中间元素不需处理）；
- 特殊情况 `left == right` 也需处理：`left <= right`（较少见，如 LC 977）。

**问题二，移动指针后是否需要 `continue`？** Two Sum II 找到答案直接 `return`；但若需去重（如 3Sum），找到答案后还要跳过重复元素（详见下一篇）。

**问题三，输入是否保证非空？** 面试中主动询问或加防御性判断。

### 6.2 三个常见错误

**错误一，在无序数组上直接用对撞指针。** 不具备全局有序性，正确性证明失效。**解决：先排序（$O(n\log n)$），再用对撞指针。**

**错误二，漏了"跳过非法字符"的内层边界。** Valid Palindrome 的内层 `while` 必须带 `left < right`。

**错误三，返回值是 1-indexed 时忘记 `+1`。** Two Sum II 的常见低级错误。

### 6.3 一个可复用的判断

**遇到"两元素配对"类问题，先问三句**：

1. **数组有序吗？** 有序用对撞指针；无序考虑哈希表或先排序；
2. **要不要返回原始下标？** 要则哈希表更自然（排序会打乱下标）；
3. **循环条件用 `<` 还是 `<=`？** 看"是否允许同一元素用两次"。

**这三句，能定下对撞指针题的方案。**

## 第 7 章 进阶延伸：双序列对撞、中心扩散与原地修改对比

### 7.1 两个有序数组间的隐式对撞：查找两数组最小差值对（面试高频题）

前面讨论的 Two Sum II 是在**同一个**有序数组内部让 `left = 0, right = n - 1` 相向运动。如果给你**两个独立的无序数组 `A` 和 `B`**，要求从中各挑一个数 $a \in A, b \in B$，使得它们的绝对差值 $|a - b|$ 最小（即《程序员面试金典》16.06 最小差），该怎么设置双指针？

先把 `A` 和 `B` 各自升序排列（耗时 $O(m \log m + n \log n)$）。注意此时我们要最小化的是 $|A[i] - B[j]|$（即让 $A[i]$ 与 $B[j]$ 尽可能相等，差值接近 `0`）：
- 如果把 `i` 放在 `A` 的开头 `0`，而把 `j` 放在 `B` 的末尾 `n - 1`（相向放置），当 $A[i] < B[j]$ 时，增大 `i`（让 $A[i]$ 变大）和减小 `j`（让 $B[j]$ 变小）**都会**让两者的差值缩小，你立刻陷入"到底该移 `i` 还是该移 `j`"的二路分支困境；
- 正确的做法是让 `i = 0, j = 0` **同时从两个有序数组的左端最小值出发（同向追逐）**：
  - 若 `A[i] < B[j]`：此时 $A[i]$ 比 $B[j]$ 小。如果我们移动 `j++`，由于 $B$ 是升序的，$B[j]$ 只会变得更大，与 $A[i]$ 的差距只会越拉越远（因此以当前 `A[i]` 配对后续任何 $B[j']$ 都绝不可能比当前更近，`A[i]` 的历史使命已经完成）；唯一有可能缩小差距的动作，就是令较小的 **`i++`**，换一个更大的 $A[i]$ 去逼近 $B[j]$；
  - 对称地，若 `A[i] > B[j]`，则令较小的 **`j++`**。

这就引出了一条极为深刻的定律：**在单调递增序列上，若目标是固定"两数之和 $A[i] + B[j] = T$"，由于两个变量同号相加，一个变大则另一个必须变小，故采用一左一右的"相向对撞指针"；若目标是固定"两数之差 $A[i] - B[j] = T$"（或让两数尽可能接近），由于两个变量异号相减，一个变大则另一个也必须变大，故采用同一起点的"同向追逐双指针"**。

```go
package main

import (
	"math"
	"sort"
)

// smallestDifference 排序 + 同向双指针追逐求两数组最小绝对差
// 时间复杂度：O(m log m + n log n)，额外空间复杂度：O(1)
func smallestDifference(a []int, b []int) int {
	sort.Ints(a)
	sort.Ints(b)

	i, j := 0, 0
	minDiff := math.MaxInt64

	for i < len(a) && j < len(b) {
		diff := int64(a[i]) - int64(b[j])
		if diff < 0 {
			diff = -diff
		}
		if diff < int64(minDiff) {
			minDiff = int(diff)
			if minDiff == 0 {
				return 0 // 绝对差最小不可能低于 0，提前短路
			}
		}

		// 谁更小，谁就向右推进以尝试缩小与对方的差距
		if a[i] < b[j] {
			i++
		} else {
			j++
		}
	}
	return minDiff
}
```

### 7.2 回文问题的反向对偶：从"两端向内对撞"到"中心向外扩散"（LeetCode 5 & 647）

在第 3 章（验证回文串 LC 125）和第 5.3 节（验证回文串 II LC 680）中，我们都是检验**一整个已知边界的字符串**是不是回文，因此让 `left` 和 `right` 从两端往中心对撞（收缩）。

但如果题目反过来问你：在一个长字符串 `s` 中，找出**最长的回文子串**（LeetCode 5）或者统计**回文子串的总个数**（LeetCode 647）呢？

此时子串的左右边界未知，若枚举所有子串两端再向内对撞验证，总共需要 $O(n^2)$ 个起点乘以 $O(n)$ 验证，耗时 $O(n^3)$。但请注意回文串的递归对称结构：**如果一个长串 `s[l..r]` 是回文串，那么去掉首尾字符后的内核 `s[l+1..r-1]` 必然也是回文串；反过来，只要从回文中心出发，向外一步步同步扩张 `l--; r++`，一旦某一步发现 `s[l] != s[r]`，再往外扩的所有同心子串就百分之百都不是回文串，可以当场剪枝停止**。

一个长度为 $n$ 的字符串，共有多少个可能的回文中心？
- **奇数长度回文串**的中心落在某个具体字符 `s[i]` 上（共 $n$ 个）；
- **偶数长度回文串**的中心落在两个相邻字符 `s[i]` 与 `s[i+1]` 的缝隙上（共 $n - 1$ 个）。

合计只有 **$2n - 1$ 个回文中心**。对每个中心执行一次背向双指针扩散 `l--; r++`，即可在 $O(n^2)$ 时间、**严格 $O(1)$ 额外空间**（优于二维动态规划的 $O(n^2)$ 空间）内同时解出 LeetCode 5 与 LeetCode 647：

```go
package main

// countSubstrings LeetCode 647：枚举 2n-1 个中心执行背向双指针扩散，时间 O(n^2)，空间 O(1)
func countSubstrings(s string) int {
	n := len(s)
	total := 0

	expand := func(l, r int) {
		for l >= 0 && r < n && s[l] == s[r] {
			total++
			l--
			r++
		}
	}

	for i := 0; i < n; i++ {
		expand(i, i)   // 奇数长度回文中心
		expand(i, i+1) // 偶数长度回文中心
	}
	return total
}
```

把"两端向中心对撞（验证已知区间回文）"与"中心向两端扩散（搜索未知区间回文）"放在一起，你就彻底打通了回文类双指针的任督二脉。

## 小结

对撞指针的精髓可以用一句话概括：**利用有序性，每次移动一端，永久消除"以当前端点为左/右端点"的所有组合。** 本篇覆盖了三道主线题——**Two Sum II**（最标准的模板，含正确性证明）、**Valid Palindrome**（结合字符过滤，注意内层边界）、**Reverse String**（最基础的原型操作），以及两道变体（平方后有序数组、移动零）。

贯穿全篇的核心认知有两条。其一，**"有序性"是对撞指针的充要前提**——无序数组会让它失效，这也是 LC 1 用哈希表的原因。其二，**对撞指针的"单调性"可以有不同来源**——"和的大小关系"（两数之和）、"平方值在两端最大"（LC 977），**不同的单调性，相同的框架**。**把这两条握住，你面对任何"两端配对"的问题，都能先判断"有没有有序性"。**
