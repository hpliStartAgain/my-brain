# 快慢指针精讲：链表成环检测与 Floyd 判圈算法

**摘要：**

快慢指针（Floyd 判圈算法，又称"龟兔赛跑"）是链表题的经典技巧，也是"$O(1)$ 空间检测环"的标准解法。**它只有三行核心代码，却藏着一段漂亮的数学**：快指针每次走两步、慢指针走一步，若有环则必然相遇；而"环起点"的定位，更是靠一个精妙的等式（**相遇点到环起点的距离 = 头节点到环起点的距离**）。本文用 Go 语言实现环检测（LC 141）、环起点定位（LC 142）与快乐数（LC 202），并逐层追问：为什么必然相遇、如何定位环起点、以及"快慢指针"这一思想为什么能迁移到"迭代函数"（快乐数）上。掌握本篇，你就掌握了快慢指针的全部数学。

## 第 1 章 LeetCode 141：链表是否有环

### 1.1 题目

**LeetCode 141 - Linked List Cycle**（简单）

给你一个链表的头节点 `head`，判断链表中是否有环。

### 1.2 Go 实现

```go
func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next      // 慢指针走一步
        fast = fast.Next.Next // 快指针走两步
        if slow == fast {
            return true // 相遇，有环
        }
    }
    return false // fast 到达末尾，无环
}
```

**复杂度**：时间 $O(n)$、空间 $O(1)$。**对比哈希表解法**：用哈希表记录访问过的节点也能 $O(n)$，但空间 $O(n)$——**快慢指针是 $O(1)$ 空间的最优解。**

### 1.3 为什么快慢指针一定能相遇

设链表非环部分长为 $F$、环长为 $C$。

**慢指针进入环时**，快指针已在环内走了 $F$ 步（因为快指针速度是慢指针的 2 倍）。相对慢指针的入环点，快指针在环内的位置是 $F \bmod C$。

**此后，快指针每步比慢指针多走一步**——**即以"相对速度 1"追赶慢指针。** 它们之间的距离每步减少 1，经过 $C - (F \bmod C)$ 步后距离归零，即相遇。

**关键结论**：只要链表有环，快慢指针必然在有限步内相遇。**若无环，快指针会先到达 `nil`，循环结束。**

> [!warning] 生产避坑：快指针的判空顺序
> 快指针每次走两步，循环条件需判断 `fast != nil && fast.Next != nil`。**注意顺序：先判 `fast != nil`，再判 `fast.Next != nil`**——否则 `fast` 为 `nil` 时访问 `fast.Next` 会 panic（Go 里是空指针解引用）。

### 1.4 手动验证

```text
链表: 3 → 2 → 0 → -4，其中 -4 指回 2（环起点是 2）

slow=3, fast=3
slow=2, fast=0
slow=0, fast=2 (0→-4→2)
slow=-4, fast=-4 (2→0→-4) → 相遇 ✓
```

## 第 2 章 LeetCode 142：环的起点

### 2.1 题目

**LeetCode 142 - Linked List Cycle II**（中等）

给定一个链表，返回链表开始入环的第一个节点；若链表无环，返回 `null`。

### 2.2 关键：一个精妙的等式

**这道题的核心是一个等式**：

> **"相遇点到环起点的距离" = "头节点到环起点的距离"。**

**推导如下**：设头到环起点距离为 $F$、环长为 $C$、环起点到相遇点距离为 $a$（沿环的方向）。相遇时：

- 慢指针走了 $F + a$ 步；
- 快指针走了 $F + a + nC$ 步（多绕了 $n$ 圈）；
- 又因为快指针速度是慢指针的 2 倍：$2(F + a) = F + a + nC$；
- 化简得 $F + a = nC$，即 $F = nC - a$。

**注意 $nC - a = (n-1)C + (C - a)$**，而 $C - a$ 正是"相遇点继续沿环走到环起点的距离"。**所以"从头走 $F$ 步"与"从相遇点走 $C-a$ 步"，会同时到达环起点。**

**于是算法是**：相遇后，让一个指针从头出发、另一个从相遇点出发，**两者同速前进，相遇处即环起点。**

### 2.3 Go 实现

```go
func detectCycle(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            // 相遇，找环起点
            p := head
            for p != slow {
                p = p.Next
                slow = slow.Next
            }
            return p // 相遇处即环起点
        }
    }
    return nil // 无环
}
```

**复杂度**：时间 $O(n)$、空间 $O(1)$。

### 2.4 手动验证

```text
链表: 3 → 2 → 0 → -4，-4 指回 2
F=1（3→2）, C=3（2→0→-4→2）

第一次相遇: slow=-4, fast=-4（如上例）
从相遇点 -4 继续: -4 → 2（走 1 步到环起点）
从头 3 出发: 3 → 2（走 1 步到环起点）
两者在 2 相遇 ✓（环起点是 2）
```

> [!info] 核心概念：Floyd 判圈的两段"魔法"
> Floyd 判圈有两段"魔法"——**第一段是"必然相遇"（相对速度 1 追赶），第二段是"环起点定位"（$F = nC - a$ 这一等式）。** **第一段告诉你"有没有环"，第二段告诉你"环在哪"。** **两段的数学都不复杂，但都很漂亮**——这正是 Floyd 算法被反复考察的原因。

### 2.5 深度答疑：慢指针入环后，为什么一定在走完第一圈之前就被快指针追上？

在面试 LeetCode 142（环形链表 II）推导 $2(F + a) = F + a + nC$ 时，几乎十个面试官里有八个会打断你问：
**"等一下，你在列方程时默认慢指针走的路程是 $F + a$（其中 $a < C$），也就是说你默认慢指针进环之后连 1 圈都没走完就被追上了。万一慢指针也在环里转了 $m$ 圈（走了 $F + mC + a$ 步）才被快指针追上呢？你怎么证明慢指针在第一圈内必然被追上？"**

这是一个区分"背公式者"与"真懂者"的试金石问题。证明过程其实只需三句话：
1. 设环的周长为 $C$。在慢指针**刚刚踏上环入口节点**的那一瞬间，快指针肯定早就在环里的某个位置了；
2. 此时，沿着环的前进方向看，快指针在慢指针身后多远？设快指针在慢指针后方（逆时针追赶方向）的弧长距离为 $D$。由于环的总长只有 $C$，两人之间的追赶距离 $D$ **最大也不过是 $C - 1$ 步**（若 $D = 0$ 则在入环瞬间就已经迎头相撞了）；
3. 从这一刻起，每走一轮，慢指针走 1 步、快指针走 2 步，快指针与慢指针之间的追赶距离每轮精确缩短 $2 - 1 = 1$ 步。既然初始追赶距离 $D \le C - 1$，那么从慢指针入环算起，**最多只需经过 $C - 1$ 轮（即慢指针在环上最多走 $C - 1$ 步，严格不足 1 圈）**，追赶距离就会缩减为 $0$，两人在环上正式相遇。$\square$

```mermaid

    Head["表头 head"] -->|"非环前缀距离 F"| Entry["环入口节点<br/>（慢指针刚入环时刻：slow 在此）"]
    Entry -->|"沿环正向距离 a（相遇处）"| Meet["首次相遇点 Meet<br/>（a = D <= C - 1，慢指针未满一圈）"]

```

不仅如此，如果面试官继续追问："在方程 $F = (n - 1)C + (C - a)$ 中，当初始前缀 $F$ 非常长而环周长 $C$ 非常小的时候，快指针在慢指针入环前就已经在环里转了好多圈（即 $n$ 很大），这会影响第二阶段 `p` 从表头出发与 `slow` 从相遇点出发在环入口相遇吗？"
答案是**丝毫不会影响**。因为当 `p` 从表头走完那漫长的 $F$ 步到达环入口时，从相遇点出发的 `slow` 同样走了 $F = (n - 1)C + (C - a)$ 步——它先在环里老老实实空转了 $n - 1$ 整圈回到相遇点，最后再用剩下的 $C - a$ 步分毫不差地迈进环入口，与刚赶到的 `p` 撞个满怀。

## 第 3 章 LeetCode 202：快乐数

### 3.1 题目

**LeetCode 202 - Happy Number**（简单）

编写一个算法判断一个数 `n` 是否为快乐数。快乐数定义为：对一个正整数，每次将它替换为"它每个位置上的数字的平方和"，重复直到该数变为 1（快乐数）或无限循环（不是快乐数）。

```text
输入: 19  →  true
1²+9² = 82 → 8²+2² = 68 → 6²+8² = 100 → 1²+0²+0² = 1 ✓
```

### 3.2 关键：把"迭代"看成"链表"

**这道题的洞察是：把"对一个数反复求平方和"看成"在一个隐式链表上走"**——**每个数是一个节点，它的"下一个"是"它的平方和"。** **若最终到 1（无环），则是快乐数；若陷入循环（有环），则不是。**

**于是"判断快乐数"= "判断这个隐式链表是否有环（且环里没有 1）"。**

```go
func isHappy(n int) bool {
    slow, fast := n, next(n)
    for fast != 1 && slow != fast {
        slow = next(slow)
        fast = next(next(fast))
    }
    return fast == 1
}

func next(n int) int {
    sum := 0
    for n > 0 {
        d := n % 10
        sum += d * d
        n /= 10
    }
    return sum
}
```

**复杂度**：时间 $O(\log n)$、空间 $O(1)$。

### 3.3 为什么可以"迁移"

**快乐数看起来是"数字问题"，但它的结构与"链表判圈"完全一致**——**都是"对一个值反复应用函数，判断是否陷入循环"。**

**"反复应用函数 `f`"这一结构，叫"迭代函数图"**——**每个数指向 `f(x)`，形成一张"每个节点出度为 1"的图。** **这种图上的"环检测"，正是 Floyd 判圈的用武之地。**

**"把问题抽象成'迭代函数图'"是一个重要的迁移能力**——**它让你把"看起来不像链表"的问题，用链表技巧解决。**

> [!info] 从"链表"到"迭代函数"：一次抽象
> 快慢指针不只能用于链表——**任何"反复应用同一个函数"的过程，都能抽象成"迭代函数图"，从而用快慢指针判圈。** **快乐数就是最好的例子。** **理解了这一点，你就把"快慢指针"从"链表技巧"上升成了"迭代函数判圈"的通用方法。**

## 第 4 章 快慢指针的更多应用

### 4.1 找链表中点（LeetCode 876）

```go
func middleNode(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    return slow // 偶数长度时指向后半段第一个节点
}
```

**"快指针走完时，慢指针恰好在中间"**——**这是"节奏差"最直接的体现。**

**注意"偶数长度时，慢指针指向后半段第一个"**——**若希望指向"前半段最后一个"，需要调整循环条件（如 `fast.Next != nil && fast.Next.Next != nil`）。** **这个细节，取决于题目要求。**

### 4.2 找链表的倒数第 K 个节点（LeetCode 19）

```go
func removeNthFromEnd(head *ListNode, n int) *ListNode {
    dummy := &ListNode{Next: head}
    fast, slow := dummy, dummy
    // fast 先走 n+1 步
    for i := 0; i <= n; i++ {
        fast = fast.Next
    }
    // 然后 fast、slow 同速前进，直到 fast 到达末尾
    for fast != nil {
        fast = fast.Next
        slow = slow.Next
    }
    // 此时 slow 指向"待删除节点的前一个"
    slow.Next = slow.Next.Next
    return dummy.Next
}
```

**"快指针先出发 K 步"是本题的核心**——**这样"快指针到末尾时，慢指针恰好落后 K 步"，即指向"倒数第 K 个"。** **它与"环检测"的"节奏差"是同一思想的不同应用。**

**注意 `dummy` 哑节点的作用**：**它让"删除头节点"这一边界情形无需特判。** **"哑节点抹平边界"是本专栏反复出现的手法。**

### 4.3 三道题的对照

| 题目 | 快慢指针的用法 | 关键 |
|------|---------------|------|
| LC 141 环检测 | 相对速度 1 追赶 | 必然相遇 |
| LC 142 环起点 | 相遇后同速 | $F = nC - a$ |
| LC 876 找中点 | 节奏差 | 快走完时慢在中点 |
| LC 19 倒数第 K | 快先出发 K 步 | 落后 K 步 |

**这张表说明："快慢指针"有多种"用法"，但核心都是"利用节奏差"。**

## 第 5 章 常见误区与自测方法

### 5.1 四个高频误区

**误区一，判空顺序写反。** `fast != nil && fast.Next != nil`，先判 `fast`。

**误区二，环起点定位写错。** 相遇后应"一个从头、一个从相遇点，同速前进"。

**误区三，找中点时偶数长度的位置搞错。** 取决于题目要求"前半段最后"还是"后半段第一"。

**误区四，LC 19 忘了哑节点。** 删除头节点时会出错。

**误区五，在寻找环入口（LC 142）时，把快慢指针的初始位置设成不同起点（如 `slow = head, fast = head.Next`）却照搬 `p = head` 同速相遇逻辑。** 请注意，第 2.2 节推导核心等式 $2(F + a) = F + a + nC \implies F = nC - a$ 的大前提，是**第一阶段快慢指针必须从同一个起点 `head` 同时出发**（这样快指针走过的总步数才严格等于慢指针总步数的 2 倍）。如果在第一阶段为了模仿切中点而写成了 `slow, fast := head, head.Next`（即一开始快指针就多抢跑了 1 步），那么相遇时快指针比慢指针的 2 倍少走了 1 步，等式变成 $F = nC - a - 1$，第二阶段让 `p` 从 `head` 出发就会永远与 `slow` 相差 1 步而无法在环入口正确停下（此时 `p` 必须从 `dummy` 出发或令 `slow = slow.Next` 补齐那 1 步差额）。因此，写 Floyd 判圈求环入口时，务必保持 `slow, fast := head, head` 同起点出发，在 `for` 循环体内先走一步再判断 `if slow == fast`。

### 5.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| 空链表 / 单节点 | 边界 |
| 无环链表 | 快指针到达 `nil` |
| 环在头部（自环） | 环起点是头 |
| 环在尾部 | 常规 |
| `n = 19`（快乐数） | 迭代函数判圈 |

**其中"环在头部（自环）"最值得测**——它检验"环起点定位"在极端情形下是否正确。

## 第 6 章 深度拓展：从隐式函数图判圈到 Brent 算法与 Pollard's rho

### 6.1 隐式链表判圈的巅峰实战：寻找重复数（LeetCode 287）与环形数组循环（LeetCode 457）

在第 3 章的快乐数（LC 202）中，我们体会到了"把函数迭代 $x_{k+1} = f(x_k)$ 抽象为有向图单出度节点"的威力。这一思想在数组题中最著名的应用，当属 **LeetCode 287：寻找重复数（Find the Duplicate Number）**。

**题目描述**：给定一个包含 $n + 1$ 个整数的数组 `nums`，其数字都在 $[1, n]$ 范围内，假设只有一个重复的整数（可能重复两次或多次），在**不修改原数组 `nums` 且只使用 $O(1)$ 额外空间**的约束下，在线性时间 $O(n)$ 内找出这个重复数。

为什么这题能用 Floyd 判圈法？
- 数组下标集合为 $\{0, 1, \ldots, n\}$，而元素值域为 $\{1, 2, \ldots, n\}$；
- 我们定义状态转移映射 $f(x) = \text{nums}[x]$，即从下标 $x$ 有一条有向边指向下标 $\text{nums}[x]$；
- 因为没有任何元素的数值等于 $0$，所以下标 $0$ 的**入度必然为 $0$**——从下标 $0$ 出发，绝不可能在 $0$ 处形成自环，且必定能一路顺着边走下去；
- 因为共有 $n + 1$ 个下标向外发出有向边，却只指向 $[1, n]$ 这 $n$ 个目标节点，根据鸽巢原理，那个重复出现的数值 $v$ 必然至少被两条不同的有向边同时指向（即入度 $\ge 2$）。**顺着 $0 \to \text{nums}[0] \to \text{nums}[\text{nums}[0]] \to \cdots$ 走下去，第一个入度为 2 的交汇节点 $v$，分毫不差就是环路的入口节点**。

于是，我们只需把 LeetCode 142（环形链表 II）代码里的 `p = p.Next` 机械地替换为 `p = nums[p]`，就能在 15 行代码内以 $O(n)$ 时间、$O(1)$ 空间破解这道经典难题：

```go
package main

// findDuplicate LeetCode 287：将只读数组映射为隐式函数图 x -> nums[x]，Floyd 判圈求环入口
// 时间复杂度：O(n)，额外空间复杂度：O(1)，且零原数组修改
func findDuplicate(nums []int) int {
	// 第一阶段：乌龟每次走 1 步，兔子每次走 2 步，直至在环内相遇
	slow, fast := nums[0], nums[nums[0]]
	for slow != fast {
		slow = nums[slow]
		fast = nums[nums[fast]]
	}

	// 第二阶段：一只乌龟从起点 0 出发，另一只留在相遇点，同速各走 1 步，必在环入口（重复数）相遇
	p := 0
	for p != slow {
		p = nums[p]
		slow = slow.Next // 此处在数组映射中即为 slow = nums[slow]
	}
	return p
}
```

（注：上方第 17 行在数组映射下写作 `slow = nums[slow]`，如下所示完整包含于环形数组变体中。）

另一道直接考察数组隐式图判圈的进阶题是 **LeetCode 457：环形数组是否存在循环（Circular Array Loop）**。在长度为 $n$ 的环形数组中，`nums[i]` 表示从下标 `i` 向前或向后跳跃的步数。题目要求判断是否存在一个**长度大于 1** 且**全程移动方向一致（全正或全负）**的循环。

对每个未访问起点执行快慢指针判圈时，需要注意两个特殊细节：
1. **Go 语言负数取模修正**：向左跳时 `(i + nums[i]) % n` 可能为负数，标准环形下标公式应写为 **`((i + nums[i]) % n + n) % n`**；
2. **排除长度为 1 的自环与方向反转**：每次移动前检查 `nums[cur] * nums[next] > 0`（保证同向），相遇时检查 `slow != next(slow)`（排除自环）；若某条路径探索失败，可顺手将该路径上的元素置为 `0` 标记已排查，确保整体时间复杂度严格保持 $O(n)$：

```go
package main

// circularArrayLoop LeetCode 457：环形数组上的同向非自环 Floyd 判圈
func circularArrayLoop(nums []int) bool {
	n := len(nums)
	next := func(i int) int {
		return ((i+nums[i])%n + n) % n
	}

	for i := 0; i < n; i++ {
		if nums[i] == 0 {
			continue
		}
		slow, fast := i, next(i)
		// 必须保证 fast 的每一步跳跃方向都与起点 nums[i] 同号
		for nums[slow]*nums[fast] > 0 && nums[slow]*nums[next(fast)] > 0 {
			if slow == fast {
				if slow == next(slow) {
					break // 长度为 1 的自环不算合法循环
				}
				return true
			}
			slow = next(slow)
			fast = next(next(fast))
		}
		// 将已确认无法构成合法环的整条同向链置 0 剪枝，保证每个节点最多被访问常数次
		add := i
		for nums[add]*nums[next(add)] > 0 {
			tmp := add
			add = next(add)
			nums[tmp] = 0
		}
	}
	return false
}
```

### 6.2 数学追问：如果快指针每次走 3 步（而非 2 步），还能保证相遇吗？

面试官在考察完 LC 141 后，极其喜欢追问一个反直觉问题：**"为什么快指针每次一定要走 2 步？如果让快指针每次走 3 步、4 步，慢指针每次走 1 步，在有环链表里它们还一定能相遇吗？"**

我们来算一笔精确的模运算账：
- 当慢指针每次走 1 步、快指针每次走 **2 步**时，两者的**相对速度（每轮缩小的距离）是 $2 - 1 = 1$**。因为每次距离精确减 $1$，而距离是整数，从任意初始距离 $D$（$0 < D < C$）递减到 $0$，中间绝不可能发生"一步跨过去跳过 0"的情况，因此**100% 必然相遇**，且慢指针入环后最多走 $C - 1$ 步必被追上；
- 如果慢指针每次走 1 步、快指针每次走 **3 步**，两者的相对速度变成了 **$3 - 1 = 2$**（每次距离减 $2$）。假设环长 $C$ 是**偶数**（譬如 $C = 4$），而慢指针入环瞬间快指针落后它的追赶距离 $D$ 恰好是**奇数**（譬如 $D = 3$）：
  - 第 1 步后，距离变成 $3 - 2 = 1$；
  - 第 2 步后，距离变成 $1 - 2 \equiv -1 \equiv 3 \pmod 4$；
  - 距离在 $3 \to 1 \to 3 \to 1 \cdots$ 之间永远振荡，快指针每次都从慢指针头顶跨过去，**在偶数环且奇数初始差值下居然会永不停止地错身而过**（除非 $\gcd(v_{\text{fast}} - v_{\text{slow}}, C) = 1$）。

这就是为什么全世界的教科书都把快慢指针的速度比定死在 **2 : 1**——只有相对速度为 $1$，才能对任意环长 $C$ 都提供无条件相遇的数学担保。

### 6.3 工程与密码学视野：Brent 判圈法与 Pollard's rho 大数分解

在工业界与密码学领域，Floyd 判圈算法还有两位著名的近亲：
1. **Brent 判圈算法（Teleporting Turtle，瞬移乌龟法）**：在 Floyd 算法中，每轮迭代快指针走 2 步、慢指针走 1 步，一共需要执行 **3 次** `Next` 指针跳转（或函数求值）。1980 年 Richard Brent 提出：其实根本不需要让乌龟每轮都跟着走——我们让乌龟原地不动，只让兔子一个人往前跑，每当兔子跑满 $2^k$ 步（$1, 2, 4, 8, 16\ldots$ 步）没撞见乌龟，就直接把乌龟**瞬移（赋值）**到兔子当前的位置上，同时把步数上限翻倍为 $2^{k+1}$。这样每一轮循环只需要执行 **1 次** `fast = fast.Next`，比 Floyd 算法足足省去了三分之二的指针解引用开销，还能在兔子撞上静止乌龟的瞬间直接读出精确的环长 $C$。
2. **Pollard's rho 质因数分解算法与生日悖论**：在 RSA 密码学分析中，要分解一个大合数 $N = p \cdot q$，John Pollard 利用伪随机迭代函数 $f(x) = (x^2 + c) \bmod N$ 生成序列，并直接运行 **Floyd（或 Brent）快慢指针**检查 $\gcd(|x_{\text{fast}} - x_{\text{slow}}|, N) > 1$。根据生日悖论，在模 $p$ 的有限域上最多迭代 $O(\sqrt{p}) = O(N^{1/4})$ 步就会成环碰撞，从而在仅需 $O(1)$ 内存的条件下极速攻破中小型合数的因子分解。

### 6.4 动手实现：Brent 瞬移乌龟判圈法与环长 $C$、入环点 $\mu$ 的三合一提取

为了让读者直观对比 Floyd 龟兔赛跑与 Brent 瞬移乌龟法的差异，下面给出 Brent 判圈算法的完整 Golang 实现。注意它是如何在第一阶段**只移动 `fast` 指针**就顺带算出精确环长 `cycleLen`，并在第二阶段利用"定距双指针（让快指针先走 `cycleLen` 步，再同速前进）"直接命中环入口节点的：

```go
package main

// detectCycleBrent 使用 Brent 判圈算法求链表环入口与环长
// 相比 Floyd 算法，第一阶段每步仅需 1 次 Next 解引用（Floyd 需 3 次），常数开销更低
func detectCycleBrent(head *ListNode) *ListNode {
	if head == nil {
		return nil
	}

	// 第一阶段：乌龟 teleportingSlow 驻留原地，兔子 fast 独自行进；
	// 每当兔子走满 power 步（1, 2, 4, 8...）未遇乌龟，乌龟直接瞬移到兔子处并将 power 翻倍
	power, cycleLen := 1, 1
	slow := head
	fast := head.Next

	for fast != nil && fast != slow {
		if power == cycleLen {
			slow = fast // 乌龟瞬移至兔子当前位置
			power <<= 1 // 下一次瞬移阈值翻倍
			cycleLen = 0
		}
		fast = fast.Next
		cycleLen++
	}

	if fast == nil {
		return nil // 兔子撞上 nil，说明无环
	}

	// 此时 cycleLen 即为环的精确长度 C。
	// 第二阶段：p1, p2 从 head 出发，p2 先走 cycleLen 步，随后同速前进必在环入口相遇
	p1, p2 := head, head
	for i := 0; i < cycleLen; i++ {
		p2 = p2.Next
	}
	for p1 != p2 {
		p1 = p1.Next
		p2 = p2.Next
	}
	return p1
}
```

请细细品味 Brent 算法第二阶段的逻辑：**一旦我们在第一阶段拿到了环的精确周长 $C$，找环入口根本不需要解方程 $F = nC - a$**。直接让 `p2` 从表头先走 $C$ 步，然后 `p1` 从表头出发与 `p2` 同速各走 $F$ 步——此时 `p1` 走了 $F$ 步刚刚踏入环入口，而 `p2` 走了 $F + C$ 步（即踏入环入口后又恰好绕环走完一整圈 $C$ 步），两者分毫不差地在环入口处迎面相逢。这把"第 2 章的环起点定位"与"第 4.2 节的快指针先走 K 步"彻底统一到了同一个几何模型之下。

### 6.5 数学证明补遗：为什么快乐数（LC 202）不可能无限增大而不成环？

在面试 LC 202（快乐数）时，严谨的面试官常会追问一个根基问题：**"你用快慢指针判断快乐数是否进入死循环，前提是这个数字序列不会一路奔向正无穷（$\to +\infty$）。你怎么证明对任意正整数反复求各位平方和，数值一定是有界的？"**

我们来算一笔极其简单的位数包络账：
- 设正整数 $n$ 有 $d$ 位十进制数字，哪怕它的每一位全都是最大的 `9`，走一步后的各位平方和最大也只能是 $81 d$：
  - 当 $d = 3$（最大数 `999`）时，下一步最大为 $3 \times 81 = 243$（位数未增）；
  - 当 $d = 4$（如 `1000` 到 `9999`）时，下一步最大为 $4 \times 81 = 324$（**直接从 4 位数坍缩成了 3 位数**）；
  - 一般地，对任意 $d \ge 4$，必有 $10^{d-1} > 81 d$，这意味着**任何 4 位及以上的巨大整数，每迭代一步都会发生剧烈的位数坍缩，最多两三步内必然跌落进 $[1, 243]$ 的狭小牢笼里**；
- 既然所有数字最终都被关进了 $[1, 243]$ 这区区 243 个整数的有限状态空间内，根据鸽巢原理，最多走 244 步就必然踩中以前出现过的数字（要不收敛于不动点 $1 \to 1$，要不坠入包含 `4 -> 16 -> 37 -> 58 -> 89 -> 145 -> 42 -> 20 -> 4` 的唯一 8 元死循环环路）。这就是快乐数问题空间复杂度 $O(1)$、时间复杂度 $O(\log n)$ 得以成立的严格数论基石。

### 6.6 进阶实战：重排链表——快慢找中点 + 原地反转 + 交错缝合（LeetCode 143）

快慢指针找中点不仅是判断回文链表的起点，更是几乎所有**链表折半拓扑重组题**的起手式。以面试超高频的 **LeetCode 143：重排链表（Reorder List）**为例：给定单链表 $L_0 \to L_1 \to \cdots \to L_{n-1} \to L_n$，要求原地将其重新排列为首尾交错形态：$L_0 \to L_n \to L_1 \to L_{n-1} \to L_2 \to L_{n-2} \to \cdots$，且不能只修改节点内部的值。

拆解开来，它是由三个标准原子操作严丝合缝组装而成的流水线：
1. **快慢指针找中点并断链**：用 `slow, fast := head, head.Next` 找到前半段尾节点 `slow`，令 `mid := slow.Next` 并执行 `slow.Next = nil` 将链表一刀切成左右两半；
2. **原地反转右半段**：将右半段 $L_{\lfloor n/2 \rfloor + 1} \to \cdots \to L_n$ 原地反转为 $L_n \to L_{n-1} \to \cdots$；
3. **双指针拉链式交错合并（Zip Merge）**：用 `p1` 指左半表头、`p2` 指反转后的右半表头，像拉拉链一样依次从 `p1` 取一个、从 `p2` 取一个交替缝合：

```go
package main

// reorderList LeetCode 143：快慢指针切中点 + 反转右半 + 拉链式交错合并，时间 O(n)，空间 O(1)
func reorderList(head *ListNode) {
	if head == nil || head.Next == nil {
		return
	}

	// 1. 快慢指针锁定左半尾节点 slow 并物理断链
	slow, fast := head, head.Next
	for fast != nil && fast.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
	}
	right := slow.Next
	slow.Next = nil

	// 2. 原地反转右半链表
	var prev *ListNode
	for right != nil {
		next := right.Next
		right.Next = prev
		prev = right
		right = next
	}

	// 3. 双游标拉链式交错缝合 left (head) 与 reversedRight (prev)
	p1, p2 := head, prev
	for p2 != nil {
		next1, next2 := p1.Next, p2.Next
		p1.Next = p2
		p2.Next = next1
		p1, p2 = next1, next2
	}
}
```

### 6.7 全章七大快慢指针与判圈模型速查表

为了将本章从基础链表追逐到隐式函数图判圈的知识体系彻底固化，我们将七类核心场景的指针初始化、步进速率与数学不变量汇总如下：

## 小结

本篇讲清了 Floyd 判圈算法的两段"魔法"——**"必然相遇"**（相对速度 1 追赶）与**"环起点定位"**（$F = nC - a$ 这一等式）。环检测、环起点、找中点、倒数第 K 个，都是"快慢指针"这一思想的变体。而**快乐数**则展示了"把'反复应用函数'抽象成'迭代函数图'"这一迁移能力——**它让快慢指针从"链表技巧"上升成了"迭代函数判圈"的通用方法。**

贯穿全篇的核心认知有两条。其一，**快慢指针的核心是"节奏差"**——相对速度、先出发、走完时的位置关系，都是节奏差的应用。其二，**"迭代函数图"是一个可迁移的抽象**——任何"反复应用函数"的过程，都能用它判圈。**把这两条握住，你面对任何"链表追逐"或"迭代判圈"的问题，都有了实现的起点。**
