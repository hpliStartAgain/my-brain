# 棋盘型回溯：N-Queens 与数独求解

**摘要：**

棋盘型回溯是"约束满足问题（CSP）"的典型——**它要在满足多重约束的前提下，放置棋子或填数**。本文用两道经典题展开：LeetCode 51/52（N 皇后）讲**"按行放置 + 三方向冲突检测"**（列、主对角线、副对角线），以及用**位运算**把冲突检测压到 $O(1)$；LeetCode 37（数独求解）讲**"逐格填充 + 三重约束"**（行、列、宫格），以及用**位掩码**记录"每行/列/宫已用数字"。两题的共同点是：**回溯骨架不变，变的是"冲突检测"这一约束**。全文用 Go 语言实现，并逐层追问：为什么 N 皇后"按行放置"就能避免行冲突、对角线如何用下标映射、以及位运算如何把"约束检测"变成一次位操作。

## 第 1 章 N 皇后：按行放置

### 1.1 题目

**LeetCode 51 - N-Queens**（困难）

将 `n` 个皇后放置在 $n \times n$ 的棋盘上，使皇后彼此之间不能相互攻击（即任意两个皇后不在同一行、同一列、同一斜线上）。返回所有不同的解法。

```text
输入: n = 4
输出: [[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]
```

### 1.2 关键：按行放置，避免"行冲突"

**"皇后不在同一行"这一约束，可以用"按行放置"自动满足**——**第 `row` 行只放一个皇后，然后递归到 `row+1`。** 于是只需检测**列、主对角线、副对角线**三种冲突。

**"按行放置"是一个重要的建模技巧**——**它把"选位置"从"二维"降成了"一维"（每行只需决定"放哪一列"）。**

```go
func solveNQueens(n int) [][]string {
    var res [][]string
    cols := make([]bool, n)      // 列是否被占
    diag1 := make([]bool, 2*n-1) // 主对角线（row-col 固定）
    diag2 := make([]bool, 2*n-1) // 副对角线（row+col 固定）
    pos := make([]int, n)        // pos[row] = 该行皇后所在的列

    var dfs func(row int)
    dfs = func(row int) {
        if row == n {
            res = append(res, buildBoard(pos, n))
            return
        }
        for col := 0; col < n; col++ {
            d1 := row - col + n - 1 // 主对角线编号
            d2 := row + col         // 副对角线编号
            if cols[col] || diag1[d1] || diag2[d2] {
                continue // 冲突，跳过
            }
            cols[col], diag1[d1], diag2[d2] = true, true, true
            pos[row] = col
            dfs(row + 1)
            cols[col], diag1[d1], diag2[d2] = false, false, false
        }
    }
    dfs(0)
    return res
}
```

### 1.3 对角线如何用下标映射

**这是 N 皇后的核心技巧**——**"同一对角线"可以用一个下标来标识**：

- **主对角线**（从左上到右下）：`row - col` 相同的格子在同一主对角线上。加偏移 `n-1` 使其非负，范围 `[0, 2n-2]`；
- **副对角线**（从右上到左下）：`row + col` 相同的格子在同一副对角线上。范围 `[0, 2n-2]`。

**"用下标标识对角线"是本题的钥匙**——**它把"斜线冲突"这一几何约束，转化成了"下标相等"这一数值判断。**

### 1.4 位运算优化

**用位掩码记录"哪些列/对角线被占"，可以把冲突检测压到一次位操作**：

```go
func totalNQueens(n int) int {
    count := 0
    var dfs func(row, cols, d1, d2 int)
    dfs = func(row, cols, d1, d2 int) {
        if row == n {
            count++
            return
        }
        // available 的第 col 位为 1 表示该列可用
        available := ((1 << n) - 1) & ^(cols | d1 | d2)
        for available != 0 {
            p := available & (-available) // 取最低位的 1
            available &= available - 1    // 消去该位
            dfs(row+1, cols|p, (d1|p)<<1, (d2|p)>>1)
        }
    }
    dfs(0, 0, 0, 0)
    return count
}
```

**注意 `(d1|p)<<1` 与 `(d2|p)>>1`**——**主对角线的约束"随行下移而左移一位"，副对角线"右移一位"，用移位表达。** **位运算版把 N 皇后的效率提升了一个量级。**

> [!info] 位运算：把"集合"压进一个整数
> 位运算优化的核心，是"**用一个整数的位表示一个集合**"——第 `col` 位为 1 表示"第 `col` 列可用"。于是"判断可用列"= 按位与，"标记占用"= 按位或。**这与二叉树专栏第 07 篇数独的位掩码、字符串专栏的位运算技巧是同一思想。** **当"状态集合"的元素不多（不超过机器字长）时，位掩码几乎总是最快、最省的。**

## 第 2 章 数独求解：逐格填充 + 三重约束

### 2.1 题目

**LeetCode 37 - Sudoku Solver**（困难）

编写程序，通过填充空格来解决数独问题。数独规则：每行、每列、每个 $3 \times 3$ 宫内，数字 1-9 只能出现一次。

### 2.2 思路：逐格填充 + 三重约束

**从第一个空格开始，尝试填入 1-9，检查"行、列、宫格"三重约束，递归下一格，失败则回溯。**

```go
func solveSudoku(board [][]byte) {
    var dfs func() bool
    dfs = func() bool {
        for i := 0; i < 9; i++ {
            for j := 0; j < 9; j++ {
                if board[i][j] != '.' {
                    continue
                }
                for d := byte('1'); d <= '9'; d++ {
                    if isValid(board, i, j, d) {
                        board[i][j] = d
                        if dfs() {
                            return true // 找到解，一路返回
                        }
                        board[i][j] = '.' // 回溯
                    }
                }
                return false // 1-9 都试过，无解，回溯
            }
        }
        return true // 没有空格了，找到解
    }
    dfs()
}

func isValid(board [][]byte, row, col int, d byte) bool {
    for k := 0; k < 9; k++ {
        if board[row][k] == d || board[k][col] == d {
            return false // 行或列冲突
        }
    }
    br, bc := (row/3)*3, (col/3)*3
    for i := br; i < br+3; i++ {
        for j := bc; j < bc+3; j++ {
            if board[i][j] == d {
                return false // 宫格冲突
            }
        }
    }
    return true
}
```

**注意 `dfs` 返回 `bool`**——**因为"数独只有一个解"，一旦找到就应"一路返回 `true`"，无需继续搜索。** **这是"求一个解"与"求所有解"的差异**（N 皇后是"求所有解"，数独是"求一个解"）。

### 2.3 优化：位掩码记录"已用数字"

**`isValid` 每次 $O(27)$ 检查，可用位掩码压到 $O(1)$**：

```go
rows := make([]int, 9)  // rows[i] 的第 d 位为 1 表示第 i 行已用数字 d
cols := make([]int, 9)
boxes := make([]int, 9)
// 判断可用：rows[i] & (1<<d) == 0 && ...
```

**这与二叉树专栏第 07 篇（Valid Sudoku）的位掩码完全一致**——**"每行/列/宫的已用数字"用一个整数的 9 位表示。**

**位掩码版把 `isValid` 的 $O(27)$ 降到 $O(1)$**，在"数独求解"这种"搜索量大"的场景下，提速显著。

## 第 3 章 两题的对比与"约束满足"框架

### 3.1 对比

| 维度 | N 皇后 | 数独 |
|------|--------|------|
| 放置单位 | 每行一个皇后 | 每格一个数字 |
| 约束 | 列、主对角、副对角 | 行、列、宫格 |
| 目标 | 所有解 | 一个解 |
| 优化 | 位运算（对角线移位） | 位掩码（行/列/宫） |

**它们都是"约束满足问题（CSP）"**——**在满足多重约束的前提下做放置/填充。**

### 3.2 CSP 的通用框架

**约束满足问题的通用框架**：

```go
var dfs func(state) bool/void
dfs = func(state) {
    if 完成 {
        记录/返回
        return
    }
    for 候选 := range 当前位置的候选集 {
        if !满足约束(候选) { continue }
        放置(候选)
        dfs(新状态)
        撤销(候选)
    }
}
```

**"约束"是可替换的**——N 皇后是"三方向冲突"，数独是"三重唯一性"。**理解了这一框架，你面对任何 CSP，都有了拆解起点。**

### 3.3 约束传播：CSP 的进阶技巧

**"约束传播（Constraint Propagation）"**是 CSP 的高阶技巧——**每放置一个值，就"传播"它的影响，提前排除其他位置的候选。** 数独里"某格只剩一个候选时直接填入"（唯一候选），就是约束传播的简单形式。

**"Dancing Links（舞蹈链）"是数独的高效解法**——它把数独建模成"精确覆盖问题"，用十字链表实现高效的"选择-撤销"。**但实现复杂，面试中"回溯 + 位掩码"已足够。**

> [!info] 从"暴力搜索"到"约束传播"
> 朴素回溯是"试错"——试一个值、不行再换。**而"约束传播"是"推理"——每做一个决定，就推出更多必然的结论，从而减少试错。** 这是 CSP 的进阶方向。**理解了"试错 vs 推理"的差别，你就明白为什么高级的 CSP 求解器（如 SAT 求解器）能在天文数字的搜索空间里找到解——因为它们"推理"得足够多。**

## 第 4 章 常见误区与自测方法

### 4.1 四个高频误区

**误区一，N 皇后没"按行放置"。** 会导致行冲突检测复杂。

**误区二，对角线下标算错。** 主对角是 `row-col`（加偏移），副对角是 `row+col`。

**误区三，数独 `dfs` 不返回 `bool`。** 会搜完所有解（浪费）。

**误区四，数独忘了"宫格"约束。** 只查行、列不够。

### 4.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `n=1`（N 皇后） | 最简 |
| `n=2,3`（N 皇后） | 无解 |
| `n=4`（N 皇后） | 2 个解 |
| 空数独 | 求解 |
| 只有唯一解的数独 | `dfs` 提前返回 |

**其中 `n=2,3` 最值得测**——它们无解，检验"搜索完无解"的分支。

## 第 5 章 约束满足问题的更多技巧与工程应用

### 5.1 约束传播：从"试错"到"推理"

**朴素回溯是"试错"**——试一个值，不行就换。**而"约束传播（Constraint Propagation）"是"推理"**——每做一个决定，就推出更多"必然的结论"，从而减少试错。

**数独里的"唯一候选"是最简单的约束传播**：若某格只剩一个候选数字，就直接填入（无需试错）。**更进一步的传播**：若某数字在某行只能放在某一格，就直接填入。**这些"推理"能把搜索空间大幅压缩。**

**"约束传播 + 回溯"是约束求解器（如 SAT/SMT 求解器）的核心**——**它们用"传播"推出大量必然结论，再用"回溯"处理剩下的不确定性。**

### 5.2 Dancing Links：数独的高效解法

**Dancing Links（舞蹈链，DLX）是 Knuth 提出的"精确覆盖问题"高效解法**——**它把数独建模成"精确覆盖问题"，用十字双向链表实现 $O(1)$ 的"覆盖/恢复"。**

**"精确覆盖问题"是"从一堆集合里，选出若干，使每个元素恰好被覆盖一次"**——数独的约束（每行/列/宫各数字一次、每格填一个数字）恰好能表达成精确覆盖。

**DLX 的核心是"十字链表 + 覆盖/恢复"**——**它把"做选择、撤销选择"这两步，用链表的"删除/恢复"实现，效率极高。** **但实现复杂，面试中"回溯 + 位掩码"已足够。**

**DLX 的价值在于"展示了'选择-撤销'可以用数据结构加速"**——**这与本专栏"用位掩码加速约束检测"是同一思路（用底层优化加速回溯）。**

### 5.3 位运算技巧小结

**棋盘型回溯里的位运算，有两个常用技巧**：

**其一，"取最低位的 1"**：`p := available & (-available)`——它取出"最右边的一个可用位置"。

**其二，"消去最低位的 1"**：`available &= available - 1`——它把"刚取出的位置"从可用集合里去掉。

**这两个技巧，是"遍历一个集合的所有元素"的高效写法**——**比"逐位检查"快得多。** **它们在"位掩码版 N 皇后"里被反复使用。**

### 5.4 CSP 在工程里的应用

**约束满足问题在工程里非常常见**：

- **排课/排班**：满足"教师、教室、时间"的多重约束；
- **调度**：满足"依赖、资源、时间窗"的约束；
- **配置验证**：检查"配置项之间的兼容性约束"；
- **SAT/SMT 求解**：验证硬件电路、求解程序约束；
- **寄存器分配**：编译器的"把变量分配到寄存器"，是图着色问题（一种 CSP）。

**它们的共同点，都是"在满足多重约束的前提下找赋值"。** **而"回溯 + 约束传播"，是它们的通用解法。**

### 5.5 一个值得记住的对照

| 技巧 | 作用 | 复杂度改善 |
|------|------|-----------|
| 朴素回溯 | 试错 | 指数级 |
| 约束传播 | 推理，减少试错 | 大幅减少分支 |
| 位运算 | 加速约束检测 | 每次检测 $O(1)$ |
| Dancing Links | 加速"选择-撤销" | 常数级提升 |

**这张表说明：CSP 的优化有多条路径**——**"推理（约束传播）"减少分支，"底层优化（位运算/DLX）"加速每步操作。** **两者结合，能把"天文数字"的搜索空间压到可行。**

> [!info] 从"暴力搜索"到"智能求解"
> 约束满足问题的优化史，就是一部"从暴力搜索到智能求解"的历史——**从朴素回溯，到约束传播，到 SAT 求解器。** **每一次进步，都来自"更早地排除不可能"或"更快地执行每一步"。** 理解了这一脉络，你不仅会解棋盘题，也理解了"约束求解"这一 AI 核心领域的思路。

### 5.6 一个可复用的判断

**遇到"约束满足"类问题，按这个顺序问**：

1. **约束有哪些？** 行/列/宫、列/对角；
2. **能否按"某个维度"放置以避免一类约束？** 如 N 皇后"按行放置"避免行冲突；
3. **约束检测能否用位运算加速？** 状态集合元素不多时，可以；
4. **能否约束传播？** 有"唯一候选"时，可以。

**这四问，能定下 CSP 题的方案。**

## 第 6 章 棋盘回溯的面试追问与复杂度速查

### 6.1 五个高频追问

**追问一："为什么 N 皇后'按行放置'？"** 答：**因为它把"行冲突"自动满足**——每行只放一个皇后，于是只需检测列、主对角、副对角三种冲突。**它把"二维选位置"降成了"每行选列"。**

**追问二："主对角与副对角为什么用 `row-col` 与 `row+col`？"** 答：**因为同一主对角线上 `row-col` 相同，同一副对角线上 `row+col` 相同**——用下标标识对角线，把"斜线冲突"转化成"下标相等"。

**追问三："位运算版的 `(d1|p)<<1` 表达什么？"** 答：**它表达"主对角线的约束随行下移而左移一位"**——因为下一行的主对角冲突位置相对上一行左移一格。

**追问四："数独的 `dfs` 为什么返回 `bool`？"** 答：**因为数独只有一个解，一旦找到就应"一路返回 `true`"**——无需继续搜索。**N 皇后要求所有解，所以不返回 `bool`。**

**追问五："约束传播与朴素回溯的区别？"** 答：**朴素回溯是"试错"，约束传播是"推理"**——每做一个决定就推出更多必然结论，从而减少试错。

### 6.2 复杂度速查

| 题目 | 时间 | 空间 |
|------|------|------|
| LC 51 N 皇后 | $O(n!)$（有剪枝更快） | $O(n)$ |
| LC 52 N 皇后 II | $O(n!)$ | $O(n)$ |
| LC 37 数独 | 指数级（约束传播加速） | $O(1)$（棋盘原地） |

**N 皇后的实际性能，取决于剪枝强度**——**位运算版比朴素版快一个量级。**

### 6.3 一个值得养成的习惯

**写棋盘题前，先问三句**：

1. **能否按某维度放置以消除一类约束？** 如 N 皇后按行；
2. **约束检测能否用位运算？** 状态集合不大时可以；
3. **求一个解还是所有解？** 决定 `dfs` 是否返回 `bool`。

**这三句，能定下棋盘题的方案。**

> [!info] 棋盘题的"三要素"
> 棋盘题的差异，可以归结为三要素：**放置维度（行/格）、约束（冲突/唯一性）、解的数量（一个/全部）。** **把这三要素想清楚，棋盘题就成了填空。** 这与回溯题"三要素"、组合题"三处旋钮"是同一思路。

### 6.4 一个总体的建议

**棋盘题的练习，建议"按约束类型"分类**：

- **冲突约束**：N 皇后（列 + 对角）；
- **唯一性约束**：数独（行 + 列 + 宫）；
- **位运算优化**：N 皇后 II。

**"约束类型"决定了"检测方式"与"优化手段"。**

## 第 7 章 约束满足问题的数学视角与更多变体

### 7.1 N 皇后的解数

**N 皇后的"解数"是一个有趣的数列**：$n=1$ 有 1 个解、$n=4$ 有 2 个、$n=8$ 有 92 个、$n=12$ 有 14200 个……**它增长极快，且没有简单公式。**

**"解数增长极快"解释了为什么 N 皇后是"指数级搜索"**——**搜索空间是 $O(n!)$，而"有剪枝"让它实际可行。**

**"剪枝把 $n!$ 的搜索空间，压到了'实际可算'的范围"**——**这正是剪枝的价值：它不改变"最坏复杂度"，但大幅降低"实际代价"。**

### 7.2 图着色与排课（LeetCode 1042）

**题目**：有 $n$ 个花园，每个花园要种 4 种花之一，相邻花园不能种同一种。给定"相邻关系"，求一种合法方案。

**它是"图着色问题"**——**用贪心（每个花园选"与邻居不同的最小颜色"）即可，无需回溯：**

```go
func gardenNoAdj(n int, paths [][]int) []int {
    adj := make([][]int, n+1)
    for _, p := range paths {
        adj[p[0]] = append(adj[p[0]], p[1])
        adj[p[1]] = append(adj[p[1]], p[0])
    }
    color := make([]int, n+1)
    for i := 1; i <= n; i++ {
        used := map[int]bool{}
        for _, nb := range adj[i] {
            used[color[nb]] = true // 记录邻居用过的颜色
        }
        for c := 1; c <= 4; c++ {
            if !used[c] {
                color[i] = c
                break
            }
        }
    }
    return color[1:]
}
```

**注意这道题"贪心即可"**——**因为"4 种颜色"保证"总能找到与邻居不同的"**（每个花园最多 3 个邻居）。**这说明"约束满足"不一定需要回溯**——**当"贪心能保证成功"时，贪心更快。**

**"什么时候用贪心、什么时候用回溯"，取决于"贪心是否总能成功"**——**这是 CSP 的一个重要判断。**

### 7.3 约束满足的形式化

**约束满足问题（CSP）可以形式化为三元组 $(X, D, C)$**：

- $X$：变量集合（如 N 皇后的"每行放哪列"、数独的"每格填什么"）；
- $D$：每个变量的取值域（如 N 皇后的"0..n-1"、数独的"1..9"）；
- $C$：约束集合（如"不同列""不同对角""行/列/宫唯一"）。

**"求解 CSP"就是"给每个变量赋一个值，使所有约束满足"。** **而"回溯"是求解 CSP 的通用方法。**

**理解了这一形式化，你就能把"任何约束满足问题"都建模成 $(X, D, C)$**——**建模之后，回溯的框架就自然浮现了。**

### 7.4 一个值得记住的对照

| 问题 | 变量 | 取值域 | 约束 |
|------|------|--------|------|
| N 皇后 | 每行 | 0..n-1 | 列/对角不冲突 |
| 数独 | 每格 | 1..9 | 行/列/宫唯一 |
| 图着色 | 每个节点 | 颜色集 | 相邻不同色 |
| 排课 | 每门课 | 时间段 | 教师/教室不冲突 |

**这张表说明："任何 CSP 都能建模成 $(X, D, C)$"**——**建模之后，"回溯 + 约束检测"就是通用解法。**

> [!info] CSP：一个通用的建模框架
> 约束满足问题（CSP）是一个极通用的建模框架——**从 N 皇后到数独，从图着色到排课，都能建模成 $(X, D, C)$。** **理解了这一框架，你面对任何"约束下赋值"的问题，都有了统一的建模方式。** 这是本专栏"从具体到抽象"的又一次体现。

### 7.5 一个可复用的判断

**遇到"约束满足"类问题，按这个顺序问**：

1. **变量、取值域、约束分别是什么？** 建模成 $(X, D, C)$；
2. **贪心能否保证成功？** 能则用贪心（如图着色）；
3. **约束检测能否用位运算？** 状态集合不大时可以；
4. **能否约束传播？** 有"唯一候选"时，可以。

**这四问，能定下 CSP 题的方案。**

## 第 9 章 棋盘回溯的工程应用

### 9.1 排课与排班

**"排课/排班"是 CSP 的典型应用**——**它要满足"教师、教室、时间、班级"的多重约束，且"不能冲突"。**

**它的规模远大于 N 皇后**（几十门课、几十个时间段），**所以"朴素回溯"往往不可行**——**工程上用"约束传播 + 启发式"（如"先排约束最多的课"）来加速。**

**"先排约束最多的变量"是一个重要的启发式**——**它叫"最少剩余值（MRV）启发式"，能大幅减少回溯。**

### 9.2 寄存器分配

**编译器的"寄存器分配"是一种"图着色问题"**——**把"变量"当成"节点"、"同时活跃"当成"边"，用"图着色"分配寄存器。**

**"图着色"是 CSP 的特例**——**而"寄存器分配"是它最重要的工程应用之一。** **当寄存器不够时，需要"溢出到内存"（Spilling），这是"图着色 + 优化"的组合。**

### 9.3 SAT/SMT 求解

**SAT 求解器（判断"布尔公式是否可满足"）是 CSP 的布尔特例**——**它用"DPLL 算法"（回溯 + 单元传播 + 冲突学习）。**

**"单元传播"是约束传播的布尔版**——**"若某个子句只剩一个未赋值变量，则它必须取某值"。** **而"冲突学习"是它的高级优化——"从冲突中学习新子句，避免重复冲突"。**

**SAT 求解器是"约束求解"的巅峰**——**现代 SAT 求解器能处理"数百万变量"的问题。**

### 9.4 一个值得记住的对照

| 应用 | CSP 类型 | 加速手段 |
|------|---------|---------|
| 排课/排班 | 多约束赋值 | MRV 启发式 |
| 寄存器分配 | 图着色 | 溢出策略 |
| SAT 求解 | 布尔 CSP | DPLL + 冲突学习 |
| 数独 | 唯一性约束 | 约束传播 |

**这张表说明："CSP"是"约束求解"的通用框架**——**从排课到 SAT，都用到它。**

> [!info] CSP：约束求解的通用框架
> 约束满足问题（CSP）是"**约束求解**"这一大类应用的通用框架——**从排课到寄存器分配，从数独到 SAT 求解。** **理解了"回溯 + 约束传播"这套骨架，你不仅会解棋盘题，也能理解这些工程场景的实现。** 这是本专栏反复强调的"从题到工程"。

### 9.5 一个可复用的判断

**遇到"约束求解"类问题，按这个顺序问**：

1. **规模多大？** 小规模用朴素回溯；
2. **能否约束传播？** 能则大幅减少分支；
3. **能否用启发式？** 如 MRV（先排约束最多的）；
4. **能否用位运算？** 状态集合不大时可以。

**这四问，能定下"约束求解"题的方案。**

## 第 11 章 一句话总结

**如果只能从本篇带走一句话，那就是：**"棋盘题的差异，在'约束'——N 皇后是三方向冲突，数独是三重唯一性。"

- **N 皇后**：按行放置 + 列/对角冲突 + 位运算；
- **数独**：逐格填充 + 行/列/宫唯一 + 位掩码；
- **共同点**：都是"约束满足问题（CSP）"。

**而"位掩码"是把约束检测压到 $O(1)$ 的通用武器**——**当状态集合的元素不多时，用一个整数的位表示它。**

**最后，棋盘题与"排课""寄存器分配""SAT 求解"相通**——**它们都是"约束下赋值"的应用。**

> [!note] 一句话带走
> **"约束满足：变量、取值域、约束；回溯 + 约束检测（可用位运算）。"** 记住这一句，你面对任何棋盘题或 CSP，都能快速定下方案。
