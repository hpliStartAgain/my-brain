# BFS 与 DFS 全景导览：搜索算法的本质与适用边界

**摘要：**

面试中提到"搜索"，大多数人的条件反射是"BFS 或 DFS，选一个套模板"。但真正能在面试中脱颖而出的工程师，能清楚回答：这道题为什么用 BFS？换成 DFS 会怎样？复杂度差在哪里？本文不涉及具体题目，而是从**状态空间（State Space）**这一统一视角出发，推导 BFS 与 DFS 的本质差异、各自优劣，以及选型的决策逻辑。**核心结论只有一条：需要"最短路径"用 BFS，需要"所有方案"用 DFS（回溯）。** 本文用 Go 语言实现两套模板，并逐层追问：什么是状态空间、队列与栈的差异如何决定探索顺序、为什么 DFS 找不到最短路径、以及回溯与动态规划的分界在哪。这是整个搜索专栏的理论基石。

---

## 第 1 章 一切搜索问题的本质：状态空间树

### 1.1 什么是状态空间

在深入 BFS 与 DFS 之前，必须先建立"状态空间"的直觉。**几乎所有搜索问题，都可以用下面这套框架描述**：

- **状态（State）**：问题在某一时刻的完整描述。例如 Word Ladder 里状态是"当前单词"，N-Queens 里状态是"已放置的皇后位置"；
- **初始状态（Initial State）**：搜索的起点；
- **目标状态（Goal State）**：想到达的终点；
- **转移函数（Transition Function）**：从一个状态能到达哪些相邻状态，它定义了状态之间的"边"；
- **代价函数（Cost Function）**：状态转移的代价。**当代价均匀为 1 时，BFS 能找到最短路径**；代价不均匀时需要 Dijkstra。

**这五个要素共同构成"状态空间图"。所有搜索算法，本质上都是在这张图上做遍历。**

### 1.2 状态空间的三种常见形态

**形态一，显式图。** 节点和边被明确给出（邻接表/邻接矩阵）：

```text
图：4 个城市，3 条边
A -- B
A -- C
B -- D
```

问题通常是：从 A 能否到达 D？最短几步？

**形态二，矩阵/格子图。** 矩阵中每个格子是一个状态，四个（或八个）方向的邻格是相邻状态。**"图"的结构是隐式的，需要通过方向数组即时枚举。**

```text
矩阵（每格是一个状态，四方向相邻）：
1 0 1
1 1 0
0 1 1
```

问题通常是：连通分量数量、最短路径、某区域是否可达。

**形态三，递归树（搜索树）。** 状态是"已做的选择"，转移函数是"下一步可做哪些选择"。**这里的图不是预先给定的，而是在搜索过程中动态展开的。** 回溯算法的状态空间就是这种形态。

```text
状态：[1, 2] 表示已选了 1 和 2
转移：从 {3, 4} 中选一个，得到 [1,2,3] 或 [1,2,4]
```

**这种形态下，状态空间的"图"可能极大（指数级），必须剪枝。**

> [!info] 核心概念：状态空间
> **把问题抽象为状态空间图，是解决任何搜索题的第一步。** 面试时若不确定用 BFS 还是 DFS，先问自己：**这道题的状态是什么？相邻状态是什么？目标状态是什么？** 把这三个问题回答清楚，算法选型就自然浮现了。

## 第 2 章 BFS：层层推进的宽幅探索

### 2.1 BFS 的直觉

**广度优先搜索（BFS）的行为，像一波波涟漪向外扩散**——先访问所有距离起点为 1 的节点，再访问距离为 2 的，以此类推。

**这种"按层扩展"的特性，使得 BFS 第一次到达某节点时，走的路径一定最短**（在等权图中）。**这是 BFS 最重要的性质，也是它的核心优势。**

### 2.2 Go 标准实现

```go
// BFS 标准模板（无权图最短路径）
func bfs(graph map[int][]int, start, target int) int {
    queue := []int{start}
    visited := map[int]bool{start: true}
    steps := 0 // 从 start 出发的步数

    for len(queue) > 0 {
        size := len(queue) // 固定当前层节点数
        for i := 0; i < size; i++ {
            cur := queue[0]
            queue = queue[1:]
            if cur == target {
                return steps // 第一次到达目标，即最短路径
            }
            for _, nb := range graph[cur] {
                if !visited[nb] {
                    queue = append(queue, nb)
                    visited[nb] = true // 入队时立即标记
                }
            }
        }
        steps++ // 整层处理完，步数 +1
    }
    return -1 // target 不可达
}
```

**三处设计理由**：

- **`visited[nb] = true` 在入队时（而非出队时）标记**——若出队时才标记，同一节点可能被多次入队，浪费内存甚至死循环。**入队时立即标记，是 BFS 的关键实现细节。**
- **`size := len(queue)` 固定当前层大小**——确保内层循环只处理当前层，而不会"越界"到下一层。**这是"层序感知"的技巧。**
- **队列（FIFO）**——保证先入队的先被处理，维护"按层扩展"的顺序。

### 2.3 复杂度

设图有 $V$ 个节点、$E$ 条边：

- **时间 $O(V+E)$**：每个节点最多入队/出队一次，每条边最多检查两次；
- **空间 $O(V)$**：最坏情况（星形图）队列里同时存放所有 $V-1$ 个叶节点。

**关键推论**：**BFS 的空间开销，正比于"当前层的宽度"。** 若状态空间是深度 $d$、分支因子 $b$ 的树，最宽的层有 $b^d$ 个节点——**BFS 空间是 $O(b^d)$，在分支因子大或深度深时会非常耗内存。这是 BFS 的主要劣势。**

## 第 3 章 DFS：一头扎到底的深度探索

### 3.1 DFS 的直觉

**深度优先搜索（DFS）的行为，像一个迷失在迷宫里的探险家**——沿着一条路一直走，直到走不通，再原路返回（回溯），尝试其他路。

**这种"深入一条路"的特性，使得 DFS 在空间消耗上远比 BFS 高效**——只需记录当前路径（递归栈），而不必存储所有待处理节点。

### 3.2 两种实现

**方式一，递归（隐式栈）**：

```go
func dfs(graph map[int][]int, cur int, visited map[int]bool) {
    visited[cur] = true // 进入时标记
    for _, nb := range graph[cur] {
        if !visited[nb] {
            dfs(graph, nb, visited) // 递归深入
        }
    }
    // 函数返回时，相当于"回溯"到父节点
}
```

**方式二，显式栈（迭代）**：

```go
func dfsIter(graph map[int][]int, start int) {
    stack := []int{start}
    visited := map[int]bool{}
    for len(stack) > 0 {
        cur := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        if visited[cur] {
            continue // 出栈时才标记
        }
        visited[cur] = true
        for _, nb := range graph[cur] {
            if !visited[nb] {
                stack = append(stack, nb) // 入栈时不标记，可能重复入栈
            }
        }
    }
}
```

> [!warning] 生产避坑：递归版与迭代版的标记时机不同
> **递归版在"进入递归"时标记，迭代版在"出栈"后标记。** 这不是笔误——迭代版若在入栈时标记，由于栈的 LIFO 特性，遍历顺序会与递归版不一致，某些场景（尤其是需要记录路径的回溯）下会出错。**面试中推荐递归版**，更简洁且不易错。

### 3.3 复杂度

- **时间 $O(V+E)$**，与 BFS 相同；
- **空间 $O(V)$（visited）+ $O(H)$（递归栈深度，$H$ 为最大深度）**。

**关键推论**：**DFS 的空间正比于"当前路径深度"，而非"当前层宽度"。** 对深度 $d$、分支因子 $b$ 的树，DFS 只需 $O(d)$ 栈空间，而 BFS 需 $O(b^d)$。**DFS 在深度较大时空间上远优于 BFS。**

## 第 4 章 BFS vs DFS：核心差异的本质

### 4.1 队列 vs 栈：探索顺序的差异

BFS 与 DFS 的实现差异，表面是"队列 vs 栈"，本质是**探索顺序**的差异：

- **BFS（队列，FIFO）**：先入队的先处理 → 离起点近的先处理 → "层次"扩展；
- **DFS（栈/递归，LIFO）**：后入栈的先处理 → 最近发现的邻居先探索 → "深度优先"。

**一个有趣的事实：把 BFS 代码里的队列换成栈，就得到了 DFS 的迭代版。** 两者框架几乎相同，只是数据结构不同。

### 4.2 完备性与最优性

| 性质 | BFS | DFS |
|------|-----|-----|
| 完备性（能否找到解） | ✅ 有限图中保证 | ✅ 有限图中保证 |
| 最优性（能否找最短路） | ✅ 等权图中保证 | ❌ 不保证 |
| 空间 | $O(b^d)$（层宽大时很糟） | $O(d)$（与深度成正比） |
| 时间 | $O(b^d)$ | $O(b^d)$（最坏相同，常数更小） |

**直接推论**：

- 需要**最短路径**？用 BFS（DFS 找到的第一条不是最短的）；
- 需要**所有路径/判断连通性**？两者都行，DFS 更简洁；
- 状态空间**层宽很大**但**深度较浅**？BFS 内存压力大，DFS 更省；
- 状态空间**分支因子极大**且**目标很深**？DFS 可能陷太深，BFS 更可靠。

### 4.3 什么时候"非 BFS 不可"

**一句话判断：如果题目要求"最少步数/最短路径/最少操作次数"，且每步代价相同，就必须用 BFS。DFS 不能保证最优性。**

具体场景：

1. **无权图最短路径**：Word Ladder 的"最少变换次数"；
2. **最小跳跃步数**：跳跃游戏、骑士最少步数；
3. **多源最短路径**：从多个起点同时出发；
4. **层序相关信息**：二叉树层序遍历、某节点到根的距离。

**若题目不要求"最短"，或明确要找"所有方案"，则 BFS/DFS 均可，通常选 DFS（回溯）。**

> [!note] 设计哲学：为什么 DFS 找不到最短路径
> DFS 的本质是"沿一条路走到底再回头"，**它找到目标时走的路不一定最短**——可能绕了一大圈。BFS 则保证：**第一次到达某节点时，路径一定最短**。这是因为 BFS 是"按距离排序"地扩展——所有距起点为 $k$ 的节点，都在任何距起点为 $k+1$ 的节点被处理之前处理完毕。

## 第 5 章 回溯：DFS 的高频面试变体

### 5.1 回溯的本质

**回溯（Backtracking）是 DFS 在"递归树（搜索树）"上的应用**——它不是新算法，而是 DFS 在"做选择、探索、撤销选择"这一场景下的专用名称。

**为什么需要"撤销选择"？** 因为在递归树的搜索中，**同一个节点可能从不同路径被多次"考虑"**，若不撤销对全局状态的修改，下一条路径的搜索就会被污染。

以"全排列"为例：

```text
输入：[1, 2, 3]

搜索树：
            []
       /    |    \
     [1]   [2]   [3]
    /   \
  [1,2] [1,3]
  /       \
[1,2,3] [1,3,2]
```

**探索完 `[1,2]` 的子树后，要回溯到 `[1]`，再去探索 `[1,3]`**——"撤销选择"就是把 `2` 从路径移除、并把它重新标记为"可用"。

### 5.2 回溯 vs 暴力枚举：剪枝

**纯暴力枚举会生成所有候选解，再过滤**；**回溯的关键优化是剪枝（Pruning）**——一旦发现当前路径不可能通向有效解，立即停止这条路径的探索。

**剪枝是回溯的核心价值。没有剪枝的回溯，和暴力枚举在复杂度上没有区别。**

**两种主要剪枝**：

1. **可行性剪枝**：当前状态已违反约束（如数独里同行有重复），立即回溯；
2. **最优性剪枝**：当前路径代价已超过已知最优解，不可能更好。

### 5.3 回溯 vs 动态规划

| 维度 | 回溯 | 动态规划 |
|------|------|---------|
| 目标 | 枚举所有满足条件的方案 | 求最优解（最值/计数） |
| 子问题 | 有重叠，但通常不利用 | 有重叠，且利用（记忆化） |
| 状态修改 | 需要撤销（回溯） | 不需要撤销 |
| 典型题 | 全排列、组合、N 皇后 | 背包、最长公共子序列 |

**本质规律：要求"所有方案（枚举）"用回溯；要求"最优解（计数/最值）"优先考虑 DP。** 两者并不互斥——许多 DP 题（如 Unique Paths）也可以用"加了记忆化的 DFS"解决，性能相同。

> [!info] 回溯与 DP 的"桥"
> **"记忆化搜索"是回溯与 DP 的桥梁**——它是"带缓存的 DFS"，保留了回溯的递归形式，又获得了 DP 的"避免重复子问题"。**理解了这座桥，你就明白"回溯与 DP 不是对立的，而是同一问题的两种视角"。** 第 10 篇会展开这一点。

## 第 6 章 搜索算法的复杂度分析框架

### 6.1 图搜索

- 时间 $O(V+E)$：每节点最多访问一次，每边最多检查两次；
- 空间 $O(V)$：visited 集合，外加 BFS 队列或 DFS 递归栈。

### 6.2 矩阵搜索（$m \times n$）

- 时间 $O(mn)$：最多 $mn$ 个格子；
- 空间 $O(mn)$：visited 数组或 BFS 队列。

### 6.3 回溯

| 问题类型 | 搜索树大小 | 时间复杂度 |
|---------|-----------|-----------|
| 排列（$n$ 元素） | $n!$ 个叶节点 | $O(n \cdot n!)$ |
| 组合（$n$ 选 $k$） | $C(n,k)$ 个叶节点 | $O(k \cdot C(n,k))$ |
| 子集（$n$ 元素） | $2^n$ 个叶节点 | $O(n \cdot 2^n)$ |
| 棋盘放置（$n \times n$） | 最坏 $O(n!)$ | $O(n!)$（有剪枝时更快） |

**每个叶节点代表一个完整方案，系数（$n$ 或 $k$）是构建/记录这个方案所需的时间。**

## 第 7 章 常见误区与解题策略

### 7.1 四个高频误区

**误区一："BFS 能解的，DFS 也能解"。** 错。若要求"最少步数"，DFS 找到第一个解时不保证最优，必须搜完所有路径，**退化为穷举**。

**误区二："visited 可以在出队时标记"。** 错。BFS 中若出队才标记，同一节点可能被多次入队，退化甚至死循环。**必须在入队时标记。**

**误区三："回溯一定要生成所有方案才能求最优"。** 错。带剪枝的回溯（Branch and Bound）能在搜索中剪掉不可能更优的分支。

**误区四："DFS 的空间是 $O(1)$"。** 错。递归栈深度等于搜索树深度 $d$，最坏（链状图）$d = V$，栈空间 $O(V)$。

### 7.2 面试答题策略

看到搜索题，按这个顺序思考：

1. **定义状态**：状态是什么？状态空间多大？
2. **确定转移**：从一个状态能转移到哪些状态？
3. **明确目标**：是否需要最短路径？
4. **选择算法**：需要最短 → BFS；需要所有方案 → 回溯（DFS）；只需连通性 → 均可；
5. **考虑剪枝**：哪些状态可提前排除？
6. **分析复杂度**：状态总数 × 每状态处理时间。

### 7.3 一个可复用的判断

**"状态空间有多大、要最短还是要全部"——这两问，能定下搜索题的算法选型。** 而这，正是本专栏反复强调的"先理解问题，再选工具"。

## 第 8 章 为什么搜索算法是面试的核心考点

**搜索算法之所以高频，是因为它的泛化能力极强**——绝大多数算法问题，本质上都是在某个状态空间上做搜索：

- **动态规划**：带记忆化的搜索（避免重复子问题）；
- **贪心**：每步选局部最优的搜索（不回溯）；
- **图论算法**：在图这个特定状态空间上做搜索；
- **回溯**：在搜索树上带撤销的 DFS。

**理解了 BFS 与 DFS 的本质差异、掌握了状态空间的抽象方法，后续无论面对哪种具体题型，都有清晰的思考框架。** 这正是本专栏从"概念篇"开始的原因——**先把地基打好，再盖楼。**

## 第 9 章 搜索算法的工程身影

### 9.1 搜索在工程里无处不在

**"搜索"不是算法题的专属，它是工程里最基础的能力之一**：

- **路由与网络**：路由器用"最短路径算法"（Dijkstra、BFS）决定数据包怎么走；
- **依赖解析**：包管理器用"图搜索"判断"依赖是否可满足、是否有环"（DFS）；
- **爬虫与索引**：网络爬虫用 BFS 逐层抓取，搜索引擎用"图遍历"建索引；
- **游戏 AI**：用 A*、Minimax 在"游戏状态空间"里搜索最优走法；
- **编译器**：用"图搜索"做"控制流分析、数据流分析"；
- **数据库**：查询优化器用"搜索"在"执行计划空间"里找最优计划。

**它们的共同点，都是"在某个状态空间里，找一条路径/一个解/一个最优"。** **这正是搜索算法要解决的问题。**

### 9.2 "搜索"是一种问题求解范式

**更抽象地说，"搜索"是"问题求解"的通用范式**——**把问题建模成"状态 + 转移 + 目标"，然后在状态空间里找解。** 这一范式，覆盖了：

- **规划问题**：从初始状态到目标状态的一系列动作；
- **约束满足**：在满足约束的前提下找赋值；
- **最优化**：在状态空间里找"代价最小"的解。

**理解了"搜索即问题求解"，你就明白为什么搜索算法如此重要**——**它是"通用的问题求解器"。**

### 9.3 BFS 与 DFS 在工程里的分工

| 场景 | 用 BFS | 用 DFS |
|------|--------|--------|
| 最短路径（无权） | ✅ | ❌ |
| 连通性检测 | ✅ | ✅（更省空间） |
| 拓扑排序 | ❌（需 DFS） | ✅ |
| 环检测 | ✅ | ✅（更自然） |
| 爬虫（按层抓） | ✅ | ❌ |
| 依赖解析（找环） | ❌ | ✅ |

**这张表的落点，仍是"目标决定算法"**——**要最短用 BFS、要拓扑序/找环用 DFS。**

> [!info] 从"算法题"到"工程能力"
> 搜索算法不是"面试完就忘"的东西——**它是工程里"问题求解"的基础设施。** 理解了"搜索即问题求解"这一抽象，你不仅会解算法题，也能在工程里"把问题建模成状态空间、再选搜索策略"。**这是本专栏最想传达的一层认知。**

### 9.4 一个跨领域的观察

**"搜索"与"动态规划""贪心"的关系，也值得玩味**：

- **动态规划**：带记忆化的搜索（避免重复子问题）；
- **贪心**：每步选局部最优的搜索（不回溯）；
- **回溯**：带撤销的 DFS；
- **BFS/DFS**：图的系统遍历。

**它们都是"在状态空间里找解"，只是"策略"不同。** **理解了这一点，你就把"搜索"与"DP/贪心"统一到了"问题求解"这一大框架下。**

## 第 10 章 搜索算法的面试追问与表达

### 10.1 五个高频追问

**追问一："为什么这道题用 BFS 而不是 DFS？"** 答：因为它要求"最短路径/最少步数"，而 DFS 找到的第一条路径不保证最短——**要保证最短，必须"按距离排序"地扩展，这正是 BFS。**

**追问二："BFS 和 DFS 的复杂度一样吗？"** 答：时间复杂度都是 $O(V+E)$，**但空间不同**——BFS 是 $O(w)$（最宽层），DFS 是 $O(h)$（最深路径）。**"空间差异"才是它们的主要区别。**

**追问三："visited 为什么在入队时标记？"** 答：因为出队时标记会导致同一节点多次入队。**入队时标记保证"每个节点最多入队一次"。**

**追问四："回溯为什么必须撤销？"** 答：因为同一状态可能从不同路径被多次考虑，**不撤销会污染后续分支的搜索。**

**追问五："什么时候用记忆化搜索？"** 答：当"搜索树有重叠子问题"（即"树变成图"）时。**若搜索树无重叠（如全排列），记忆化无用。**

**这五个追问，覆盖了搜索题面试的核心考点。**

### 10.2 面试表达的顺序

**讲搜索题，建议按这个顺序**：

1. **定义状态**："状态是什么、状态空间多大"；
2. **明确目标**："要最短、要全部、还是要数量"；
3. **选算法**："按目标选 BFS / 回溯 / 记忆化"；
4. **讲复杂度**："时间与空间各是多少"；
5. **主动补边界**："visited 时机、撤销、标记恢复"。

**第 1、2 步是关键**——它们表明你"理解了问题"，而非"套模板"。

### 10.3 一个值得养成的习惯

**遇到搜索题，先在纸上"画状态空间"**——**把"状态是什么、相邻状态是什么、目标是什么"写下来。** **很多搜索题的难点，不在代码，而在"把问题抽象成状态空间"**——而这一步，恰恰是"画出来"最容易想清楚的。

**"先画状态空间、再选算法、最后写代码"**——这三步，是应对搜索题的通用流程。

> [!info] 搜索题的"抽象先行"
> 搜索题与别的题最大的不同，是**"抽象先行"**——你必须先把"问题"抽象成"状态空间"，才能选算法、写代码。**而"抽象"这一步，恰恰是最容易出错、也最需要练习的。** 本专栏反复强调"先定义状态"，正是为了培养这一习惯。

### 10.4 一个总体的建议

**搜索题的学习，建议"按状态空间的形态"组织**：

- **显式图**（邻接表）：BFS/DFS 模板；
- **矩阵**：四方向遍历 + 标记；
- **递归树**：回溯 + 剪枝；
- **隐式图**（转移规则）：枚举邻居 + visited。

**四种形态，对应四套模板。** **识别出"这题属于哪种形态"，就能选对模板。**

## 第 11 章 复杂度速查与选型总结

### 11.1 复杂度速查

| 算法 | 时间 | 空间 |
|------|------|------|
| BFS（图） | $O(V+E)$ | $O(V)$ |
| DFS（图） | $O(V+E)$ | $O(V)$（栈） |
| BFS（矩阵） | $O(mn)$ | $O(mn)$ |
| DFS（矩阵） | $O(mn)$ | $O(mn)$ |
| 回溯（排列） | $O(n \cdot n!)$ | $O(n)$ |
| 回溯（子集） | $O(n \cdot 2^n)$ | $O(n)$ |
| 双向 BFS | $O(b^{d/2})$ | $O(b^{d/2})$ |

**这张表是全专栏的"复杂度底稿"**——**每篇的复杂度，都是它的一行。**

### 11.2 选型总结

**搜索题的选型，可以浓缩成一句话**：**"要最短用 BFS，要全部用回溯，要数量用记忆化。"**

**而"状态空间多大"是第二层判断**——**大则考虑双向、剪枝、记忆化。**

## 小结

本篇从"状态空间"这一统一视角，把 BFS 与 DFS 还原成了"在同一张图上、以不同顺序探索"的两套策略。**BFS 用队列、按层扩展、保证最短路径，但空间正比于层宽；DFS 用栈/递归、一条路走到底、空间正比于深度，但不保证最短。** 回溯则是 DFS 在"选择-探索-撤销"场景下的特化，其核心价值是剪枝。

贯穿全篇的核心认知有两条。其一，**"要不要最短路径"是 BFS/DFS 选型的第一判据**——要最短用 BFS，要全部用 DFS。其二，**搜索算法的复杂度，本质是"状态空间大小 × 每状态处理时间"**——理解了这一点，你就能估出任何搜索题的量级。**把这两条握住，你面对任何搜索题，都能先定状态、再选算法。**
