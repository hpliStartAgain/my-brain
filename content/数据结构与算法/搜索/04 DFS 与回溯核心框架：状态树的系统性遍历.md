# DFS 与回溯核心框架：状态树的系统性遍历

**摘要：**

回溯（Backtracking）是面试频率最高的搜索变体，也是"看起来会、写起来错"的重灾区。它的本质，其实是 DFS 在"**做选择、探索、撤销选择**"这一场景下的特化——**不是一个新算法，而是 DFS 在搜索树上的应用**。本文先讲清回溯的三要素（选择、路径、结束条件）与通用模板，再深入"剪枝"这一核心价值（**没有剪枝的回溯，和暴力枚举没有区别**），最后用 LeetCode 130（Surrounded Regions）展示 DFS 在矩阵上的另一种用法——**"反向标记"**。全文用 Go 语言实现，并逐层追问：为什么必须"撤销选择"、剪枝如何把指数级降到可行、以及"从边界出发"这一技巧为什么能简化问题。掌握本篇，你就掌握了回溯的通用框架。

---

## 第 1 章 回溯的本质：DFS 在搜索树上的特化

### 1.1 回溯不是新算法

**回溯（Backtracking）是 DFS 在"递归树（搜索树）"上的应用。** 它把"求解过程"建模成"在一棵决策树上做选择"：

- **节点**：一个"部分解"（已做的选择）；
- **边**：一步选择；
- **叶节点**：一个"完整解"（或"确定无解"）。

**所以回溯 = "在决策树上 DFS" + "撤销选择"。**

### 1.2 为什么必须"撤销选择"

**因为在决策树的搜索中，同一个状态可能从不同路径被多次"考虑"。** 若不撤销对全局状态的修改，下一条路径的搜索就会被污染。

以"全排列"为例：

```text
输入：[1, 2, 3]

搜索树：
            []
       /    |    \
     [1]   [2]   [3]
    /   \
  [1,2] [1,3]
  /       \
[1,2,3] [1,3,2]
```

**探索完 `[1,2]` 的子树后，要回溯到 `[1]`，再去探索 `[1,3]`**——"撤销选择"就是把 `2` 从路径移除、并把它重新标记为"可用"。**不撤销，`[1,3]` 的探索就会带着 `2` 的残留，出错。**

### 1.3 回溯三要素

**任何回溯题，都能拆成三要素**：

1. **路径**：已做的选择（当前的部分解）；
2. **选择列表**：当前还能做哪些选择；
3. **结束条件**：什么时候算"得到完整解"。

**把这三要素想清楚，代码就自然出来了。**

## 第 2 章 回溯通用模板

### 2.1 模板

```go
func backtrack(路径, 选择列表) {
    if 满足结束条件 {
        记录结果(路径) // 注意：要复制
        return
    }
    for 选择 := range 选择列表 {
        做选择         // 把选择加入路径、更新状态
        backtrack(路径, 新的选择列表)
        撤销选择       // 从路径移除、恢复状态
    }
}
```

**这个模板是"整个回溯专题的灵魂"**——后续每道题都是它的具体实例化。

### 2.2 一个完整的例子：全排列

```go
func permute(nums []int) [][]int {
    var res [][]int
    used := make([]bool, len(nums))
    var path []int

    var dfs func()
    dfs = func() {
        if len(path) == len(nums) { // 结束条件：选够了
            tmp := make([]int, len(path))
            copy(tmp, path) // 必须复制
            res = append(res, tmp)
            return
        }
        for i := 0; i < len(nums); i++ {
            if used[i] {
                continue // 已在路径中，跳过
            }
            used[i] = true          // 做选择
            path = append(path, nums[i])
            dfs()
            path = path[:len(path)-1] // 撤销选择
            used[i] = false
        }
    }
    dfs()
    return res
}
```

**注意两处**：其一，**记录结果时必须"复制"**（`copy`）——因为 `path` 会被后续回溯修改；其二，**"做选择"与"撤销选择"必须成对**。

### 2.3 两处最容易出错的地方

**其一，记录时不复制。** `res = append(res, path)` 会存下 `path` 的引用，**后续回溯改坏它**，结果全乱。

**其二，"做选择"与"撤销"不成对。** 会导致状态在分支间残留。

**这两处，与二叉树专栏第 10 篇（路径问题）的"复制路径""回溯撤销"完全一致**——**它们是回溯题的两条铁律。**

## 第 3 章 剪枝：回溯的核心价值

### 3.1 没有剪枝，回溯就是暴力

**纯暴力枚举会生成所有候选解、再过滤**；**回溯的关键优化是剪枝（Pruning）**——一旦发现当前路径不可能通向有效解，立即停止这条路径的探索。

**没有剪枝的回溯，和暴力枚举在复杂度上没有区别。** **剪枝，是回溯的核心价值。**

### 3.2 两种剪枝

**可行性剪枝**：当前状态已违反约束。例如数独里某格填入后同行有重复，立即回溯。

**最优性剪枝**：当前路径代价已超过已知最优解。常见于"求最优解"的搜索（Branch and Bound）。

### 3.3 剪枝的前提：排序 + 单调性

**很多剪枝依赖"排序"**——**排序后，一旦某分支"超限"，其后的分支也必然超限，可以整段跳过。**

例如"组合总和 II"（LC 40）里，排序后相同的元素相邻，可以"跳过同一层的重复值"。**"排序 + 剪枝"是回溯题的高频组合。**

> [!info] 剪枝的本质：提前判定"这一支无解"
> 剪枝的本质，是"**利用问题的单调性，提前判定某分支不可能有解，从而整支砍掉**"。这与二分"排除一半"、单调栈"提前结算"是同一思想——**都是"用结构性质省掉无效搜索"。** 理解了这一点，你就明白为什么剪枝往往要"先排序"——**排序提供了单调性。**

## 第 4 章 矩阵上的 DFS：Surrounded Regions

### 4.1 题目

**LeetCode 130 - Surrounded Regions**（中等）

给定一个 $m \times n$ 的矩阵，包含 `'X'` 和 `'O'`。**找到所有被 `'X'` 围绕的区域，并将这些区域里的 `'O'` 用 `'X'` 填充。**

```text
输入: [["X","X","X","X"],
      ["X","O","O","X"],
      ["X","X","O","X"],
      ["X","O","X","X"]]
输出: [["X","X","X","X"],
      ["X","X","X","X"],
      ["X","X","X","X"],
      ["X","O","X","X"]]  ← 左下角的 O 没被围绕
```

### 4.2 反向思考：从边界出发

**正向思考是"找被围绕的 O"，这很麻烦**（要判断"是否连通到边界"）。**反向思考简单得多**：

**"不被围绕的 O" = "能从边界通过 O 走到"的那些 O。** 于是：

1. **从边界的每个 O 出发，DFS/BFS 标记"能到达的 O"**（标记为 `'#'`）；
2. **遍历整个矩阵**：`'O'`（未被标记的）→ `'X'`，`'#'` → `'O'`。

```go
func solve(board [][]byte) {
    if len(board) == 0 {
        return
    }
    m, n := len(board), len(board[0])

    var dfs func(i, j int)
    dfs = func(i, j int) {
        if i < 0 || i >= m || j < 0 || j >= n || board[i][j] != 'O' {
            return
        }
        board[i][j] = '#' // 标记为"可到达边界"
        dfs(i+1, j)
        dfs(i-1, j)
        dfs(i, j+1)
        dfs(i, j-1)
    }

    // 1. 从四条边界的 O 出发，标记
    for i := 0; i < m; i++ {
        dfs(i, 0)
        dfs(i, n-1)
    }
    for j := 0; j < n; j++ {
        dfs(0, j)
        dfs(m-1, j)
    }

    // 2. 遍历矩阵：O → X，'#' → O
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            switch board[i][j] {
            case 'O':
                board[i][j] = 'X'
            case '#':
                board[i][j] = 'O'
            }
        }
    }
}
```

### 4.3 "反向思考"为什么有效

**正向"找被围绕的 O"要判断"连通分量是否触边"，需要"先搜一遍、再判断"。** 而**反向"从边界出发"只需一遍搜索**——因为"触边的 O"恰好就是"从边界可达的 O"。

**"从边界出发、反向标记"是矩阵搜索题的一个常用技巧**——**它把"判断连通分量的性质"转化为"从已知条件出发的搜索"，从而简化问题。** 这与第 09 篇（Word Search 的"反向剪枝"）是同一种思路。

> [!info] 反向思考：一个可迁移的技巧
> 当"正向求解"需要"先搜一遍、再判断"时，**不妨反向问"哪些是已知的、从它们出发能到达什么"。** 本题的"从边界出发"、第 09 篇的"从单词首字母出发"，都是这一技巧的实例。**"反向思考"往往能把"复杂的判定"变成"简单的搜索"。**

## 第 5 章 常见误区与自测方法

### 5.1 四个高频误区

**误区一，记录结果时不复制路径。** 会被后续回溯改坏。

**误区二，"做选择"与"撤销"不成对。** 状态残留，污染后续分支。

**误区三，Surrounded Regions 正向思考。** 会陷入"判断连通分量是否触边"的复杂逻辑。

**误区四，DFS 越界检查不全。** 四个方向都要检查边界。

### 5.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| 空矩阵 | 边界 |
| 全 `'O'` 矩阵 | 边界都是 O，全不填充 |
| 全 `'X'` 矩阵 | 无 O |
| 中间被围绕的 O | 核心逻辑 |
| 触边的 O | 不被填充 |

**其中"触边的 O"最值得测**——它检验"反向标记"是否正确（触边的 O 不应被填充）。

## 第 6 章 回溯的题型分类与工程应用

### 6.1 回溯的五大题型

**回溯题可以按"决策树的形态"分成五类**：

| 题型 | 决策 | 代表题 |
|------|------|--------|
| 组合 | 从集合里选若干 | 组合总和（39、40）、组合（77） |
| 排列 | 把集合排成序 | 全排列（46）、全排列 II（47） |
| 子集 | 每个元素选/不选 | 子集（78）、子集 II（90） |
| 分割 | 把字符串切成若干段 | 分割回文串（131）、IP 恢复（93） |
| 棋盘 | 在网格上放置 | N 皇后（51）、数独（37） |

**五类题型的骨架一致，差异只在"决策是什么"**——**"选哪些""怎么排""选不选""怎么切""放哪里"。** **识别出"这题属于哪类"，回溯的框架就定了。**

### 6.2 回溯在工程里的应用

**回溯不只是算法题，它在工程里有真实应用**：

- **配置生成**：从"选项空间"里生成所有合法配置组合；
- **测试用例生成**：枚举"输入参数的所有组合"，做穷举测试；
- **约束求解器**：SAT 求解器、SMT 求解器，底层是"回溯 + 约束传播"；
- **正则引擎**：回溯引擎（PCRE）用"回溯"匹配正则；
- **游戏求解**：数独、扫雷、棋类的"求解器"；
- **规划系统**：从"动作空间"里搜索"达成目标的动作序列"。

**它们的共同点，都是"在'选择空间'里系统地探索"。** **这正是回溯要解决的问题。**

### 6.3 回溯与递归的关系

**回溯是"递归"的一种特定用法**——**"递归 + 撤销"**。而"递归"本身，是"用函数调用栈来管理状态"。

**理解了"回溯 = 递归 + 撤销"，你就明白为什么回溯题的代码高度一致**——**它们都是"在递归的每一层，做选择、递归、撤销"。** **而"撤销"这一步，正是回溯区别于普通递归的地方。**

### 6.4 一个可复用的判断

**遇到"枚举/搜索"类问题，按这个顺序问**：

1. **要枚举所有方案，还是求一个最优？** 枚举用回溯，最优可能用 DP/贪心；
2. **属于五大题型中的哪类？** 组合/排列/子集/分割/棋盘；
3. **有没有剪枝空间？** 排序 + 单调性、前向剪枝；
4. **有没有重复解？** 需要去重（同层/同枝）。

**这四问，能定下回溯题的完整方案。**

> [!info] 回溯的"通用性"
> 回溯之所以"通用"，是因为**"枚举所有方案"是一类极广泛的需求**——从"生成所有配置"到"求解约束问题"，都能归约为它。**而回溯的"统一框架"（选择、递归、撤销），又让它极易复用。** **"通用 + 统一"是回溯成为面试高频考点的原因**——它考察的是一种"可以迁移到任何枚举问题"的思维。

## 第 7 章 回溯的面试追问与表达

### 7.1 五个高频追问

**追问一："回溯与 DFS 是什么关系？"** 答：**回溯是 DFS 在"选择-探索-撤销"场景下的特化**——它不是一个新算法，而是"DFS + 撤销"。

**追问二："为什么必须撤销选择？"** 答：因为同一状态可能从不同路径被多次考虑，**不撤销会污染后续分支。**

**追问三："记录结果时为什么要复制？"** 答：因为 `path` 会被后续回溯修改，**不复制会存下引用，导致结果被改坏。**

**追问四："剪枝为什么能提升效率？"** 答：因为它"**提前判定某分支无解，整支砍掉**"——**没有剪枝的回溯，和暴力枚举没有区别。**

**追问五："回溯与动态规划怎么选？"** 答：**要枚举所有方案用回溯；要数量/最优优先 DP。** 但两者不互斥——DP 也可看成"带记忆化的搜索"。

### 7.2 复杂度速查

| 问题 | 搜索树大小 | 时间 |
|------|-----------|------|
| 全排列 | $n!$ | $O(n \cdot n!)$ |
| 子集 | $2^n$ | $O(n \cdot 2^n)$ |
| 组合（$n$ 选 $k$） | $C(n,k)$ | $O(k \cdot C(n,k))$ |
| N 皇后 | 最坏 $O(n!)$ | $O(n!)$ |

**这张表说明：回溯的复杂度由"搜索树大小"决定。**

### 7.3 一个值得养成的习惯

**写回溯前，先写"三要素"的注释**：

```go
// dfs：在决策树的某个节点上，path 是当前部分解，start 是下一个可选起点
// 结束条件：path 满足某条件
// 选择列表：从 start 开始的候选
```

**"先写三要素注释、再写代码"这一习惯，能把"意图"固化下来**——**很多回溯 bug，正是因为"想的和写的不一致"。**

> [!info] 回溯的"三要素"：把变化点提炼出来
> 回溯题的差异，都可以归结为三要素：**路径（当前解）、选择列表（下一步能选什么）、结束条件（何时算完整解）。** **把这三要素写清楚，回溯题就成了填空**——这与组合题"三处旋钮"、BFS 题"三要素"是同一思路。**"把变化点提炼成要素"，是算法进阶的核心能力。**

### 7.4 一个总体的建议

**回溯题的练习，建议"按题型"分类**：

- **组合**：39、40、77、216；
- **排列**：46、47；
- **子集**：78、90；
- **分割**：131、93；
- **棋盘**：51、37。

**五类题型，各练一道，就能覆盖回溯的主要考点。**

## 第 8 章 回溯与分治、动态规划的关系

### 8.1 三者的对照

**回溯、分治、动态规划，都是"把大问题拆成子问题"**——**但"子问题的形态"与"是否重复"不同**：

| 方法 | 子问题 | 是否重复 | 是否撤销 |
|------|--------|---------|---------|
| 分治 | 独立子问题 | 不重复 | 否 |
| 回溯 | 决策树分支 | 通常不利用 | 是 |
| 动态规划 | 重叠子问题 | 重复且利用 | 否 |

**"是否重复"是分治与 DP 的分界，"是否撤销"是回溯与 DP 的分界。**

### 8.2 记忆化搜索：回溯与 DP 的桥

**"记忆化搜索"是"回溯 + 缓存"**——**它保留了回溯的递归形式，又获得了 DP 的"避免重复"。**

**当"决策树有重叠子问题"时，记忆化搜索就派上用场**——**例如"单词拆分"（LC 139）、"不同路径"（LC 62）。** **而"全排列""N 皇后"没有重叠，记忆化无用。**

**"搜索树是树还是图"，决定了"该不该记忆化"**——**树（无重叠）用回溯，图（有重叠）用记忆化。**

### 8.3 一个统一的理解

**从"状态空间"的视角看，三者是同一件事的三个侧面**：

- **分治**：把问题拆成"独立"的子问题；
- **回溯**：在"决策树"上搜索所有方案；
- **动态规划**：在"有重叠"的状态空间上，用缓存避免重复。

**它们都在"状态空间"里求解，只是"子问题是否独立、是否重复、是否撤销"不同。**

**理解了这一点，你就把"分治、回溯、DP"统一到了"状态空间求解"这一大框架下**——**这正是本专栏反复强调的"从具体到抽象"。**

### 8.4 一个值得记住的对照

| 问题 | 方法 | 原因 |
|------|------|------|
| 归并排序 | 分治 | 子问题独立 |
| 全排列 | 回溯 | 枚举所有方案 |
| 不同路径 | DP / 记忆化 | 子问题重叠 |
| 单词拆分 | 记忆化 | 子问题重叠 + 要判断存在 |

**这张表说明："方法的选择，取决于'子问题的性质'"**——**独立用分治、要枚举用回溯、有重叠用 DP。**

> [!info] "子问题性质"决定方法
> 算法方法的选择，归根结底取决于"**子问题的性质**"——**独立、枚举、还是重叠。** **理解了这一点，你就不再"凭题目类型选方法"，而是"按子问题性质选方法"。** 这是本专栏最想传达的一层认知——**方法是为问题服务的，而非相反。**

### 8.5 一个可复用的判断

**遇到"拆分/枚举/求最优"类问题，按这个顺序问**：

1. **子问题独立吗？** 独立用分治；
2. **要枚举所有方案吗？** 要则用回溯；
3. **子问题重叠吗？** 重叠用 DP / 记忆化；
4. **要撤销状态吗？** 回溯要，DP 不要。

**这四问，能定下"拆分/枚举/求最优"类问题的方法。**

## 第 9 章 回溯的完整知识地图

### 9.1 回溯题型全景

**这张地图的"根"，是"选择、路径、结束条件"三要素**——**所有题型都在"三要素"的框架下，只是"选择"与"去重"不同。**

### 9.2 回溯的三个"维度"

**回溯题的差异，可以归纳成三个维度**：

**维度一，选择方式**：选元素、排列、切分、放置；
**维度二，去重方式**：同层、同枝、集合、无；
**维度三，剪枝方式**：排序 + 单调性、前向剪枝、约束检测。

**三个维度的组合，覆盖了所有回溯题。**

### 9.3 一个值得记住的对照

**回溯与"其他算法"的关系**：

| 算法 | 与回溯的关系 |
|------|-------------|
| DFS | 回溯是"DFS + 撤销" |
| 记忆化搜索 | 回溯 + 缓存 |
| 动态规划 | 记忆化的自底向上版 |
| 分治 | 子问题独立、无需撤销 |
| 贪心 | 不回溯的搜索 |

**这张表说明："回溯"是"枚举型搜索"的原型**——**记忆化、DP 都是它的"优化版"。**

> [!info] 回溯：枚举型搜索的原型
> 回溯是"枚举所有方案"这一需求的原型——**记忆化搜索是"回溯 + 缓存"、DP 是"记忆化的自底向上版"。** **理解了回溯，你就理解了"枚举型搜索"这一家族的核心。** 这是本专栏"从具体到抽象"的又一次体现。

### 9.4 一个可复用的判断

**遇到"枚举"类问题，按这个顺序问**：

1. **属于五大题型的哪类？** 组合/排列/子集/分割/棋盘；
2. **用 `start` 还是 `used`？** 组合用 `start`，排列用 `used`；
3. **要去重吗？** 同层（组合）、同枝（排列）、集合（不能排序）；
4. **能否剪枝？** 排序 + 单调性、前向剪枝。

**这四问，能定下回溯题的完整方案。**

## 第 10 章 回溯的时间优化

### 10.1 剪枝的量化分析

**"剪枝"能把搜索空间缩小多少？** 这取决于"剪枝强度"。**以 N 皇后为例**：

- **无剪枝**：搜索空间是 $n^n$（每行 $n$ 种选择）；
- **列剪枝**：降到 $n!$（每行选一个未用的列）；
- **列 + 对角剪枝**：进一步降低；
- **位运算**：常数级提升。

**"每加一层剪枝，搜索空间就缩小一个量级"**——**这正是剪枝的价值。**

### 10.2 排序：剪枝的前提

**很多剪枝依赖"排序"**——**排序后，"一旦某分支超限，其后的分支也必然超限"，可以整段跳过（`break` 而非 `continue`）。**

**例如"组合总和"（LC 39）排序后**：**若 `candidates[i] > remain`，则"后面的元素更大、更不可能"，直接 `break`。** **这比"逐个 `continue`"更高效。**

**"排序 + `break`"是剪枝的标准组合**——**它把"逐元素判断"变成"整段跳过"。**

### 10.3 记忆化：从"树"到"图"

**若"搜索树有重叠子问题"，记忆化能把"树"压成"图"**——**搜索空间从"搜索树大小"降到"不同状态数"。**

**例如"单词拆分"（LC 139）**：**朴素回溯是指数级，记忆化后是 $O(n^2)$**（$n$ 个位置、每个位置 $O(n)$ 次切分）。**这是"从指数到多项式"的质变。**

**"记忆化"是回溯的"终极优化"**——**它把"重复计算"彻底消除。**

### 10.4 一个值得记住的对照

| 优化 | 手段 | 效果 |
|------|------|------|
| 剪枝 | 排序 + `break` | 缩小搜索空间 |
| 记忆化 | 缓存子问题 | 从指数到多项式 |
| 位运算 | 状态压进整数 | 常数级提升 |
| 前向剪枝 | 生成时保证合法 | 避免生成非法解 |

**这张表说明："回溯的优化，围绕'剪枝'与'记忆化'展开"。**

> [!info] 回溯优化的"两条路"
> 回溯优化有两条路：**其一，"剪枝"（缩小搜索空间）；其二，"记忆化"（避免重复计算）。** **前者把"不可能的分支"砍掉，后者把"重复的分支"合并。** **两者结合，能把"指数级"的搜索压到"可行"。** 理解了这两条路，你面对任何"搜索太慢"的回溯题，都有了优化方向。

### 10.5 一个可复用的判断

**遇到"回溯太慢"时，按这个顺序问**：

1. **能否排序 + 剪枝？** 能则整段跳过；
2. **有无重叠子问题？** 有则记忆化；
3. **状态能否压缩？** 小状态用位掩码；
4. **能否前向剪枝？** 生成时保证合法。

**这四问，能定下回溯的优化方案。**

## 第 11 章 回溯的复杂度速查与练习建议

### 11.1 复杂度速查

| 题型 | 搜索树大小 | 时间 |
|------|-----------|------|
| 全排列 | $n!$ | $O(n \cdot n!)$ |
| 子集 | $2^n$ | $O(n \cdot 2^n)$ |
| 组合（$n$ 选 $k$） | $C(n,k)$ | $O(k \cdot C(n,k))$ |
| 分割（$n$ 个位置） | $2^n$ | $O(n \cdot 2^n)$ |
| 棋盘（$n \times n$） | 最坏 $O(n!)$ | $O(n!)$ |
| 记忆化搜索 | 状态数 | 多项式 |

**"搜索树大小 × 每节点时间"是回溯复杂度的通用估算公式。**

|--------|---------|

### 11.4 一个值得记住的对照

| 回溯 | 对应 DP |
|------|---------|

| 无缓存 | 有缓存 |
| 需要撤销 | 不需要撤销 |

**这张表说明："回溯"与"DP"是一对**——**"枚举"用回溯，"求最优"用 DP。**

> [!info] 从"回溯"到"DP"：一对孪生
> 回溯与 DP 是一对——**"枚举所有方案"用回溯，"求数量/最优"用 DP。** **而"记忆化搜索"是它们的桥——"带缓存的回溯"。** **理解了这一点，你就把"回溯"与"DP"打通了。** 这是本专栏"从具体到抽象"的体现。

### 11.5 一个可复用的判断

**遇到"枚举/搜索"类问题，按这个顺序问**：

1. **要枚举所有方案吗？** 要则用回溯；
2. **属于五大题型的哪类？** 组合/排列/子集/分割/棋盘；
3. **有没有剪枝空间？** 排序 + 单调性、前向剪枝；
4. **有无重叠子问题？** 有则记忆化。

**这四问，能定下回溯题的完整方案。**

## 第 12 章 一句话总结

**如果只能从本篇带走一句话，那就是：**"回溯不是新算法，而是'DFS + 撤销选择'——而它的核心价值，是剪枝。"

- **三要素**：路径、选择列表、结束条件；
- **两条铁律**：记录要复制、选择要成对撤销；
- **一个核心**：剪枝（没有剪枝的回溯就是暴力）。

**这三条，是回溯题的通用框架。** **而"子问题是否重复"，决定了"该用回溯还是记忆化/DP"。**

**最后，回溯与"文本处理""约束求解"相通**——**从分词到 SAT 求解，都用到"做选择、探索、撤销"。**

> [!note] 一句话带走
> **"路径、选择列表、结束条件；记录要复制、选择要撤销、剪枝是核心。"** 记住这一句，你面对任何回溯题，都能快速定下方案。**而"搜索树是树还是图"，决定了"该不该记忆化"。**

## 小结

本篇讲清了回溯的通用框架——**"路径、选择列表、结束条件"三要素 + "做选择、递归、撤销"模板**，并强调了剪枝（**没有剪枝的回溯就是暴力**）与两处铁律（**记录要复制、选择要成对撤销**）。随后用 Surrounded Regions 展示了 DFS 在矩阵上的另一种用法——**"从边界出发、反向标记"**。

贯穿全篇的核心认知有两条。其一，**回溯不是新算法，而是"DFS + 撤销选择"**——理解了这一点，你就明白为什么回溯题的骨架高度一致。其二，**"反向思考"能把复杂判定变成简单搜索**——从边界出发、从已知条件出发，往往比正向求解更清晰。**把这两条握住，你面对任何回溯题或矩阵搜索题，都有了拆解的起点。**

下一篇 [[05 矩阵 BFS DFS：连通分量与 Flood Fill]] 将聚焦矩阵搜索的经典题：Surrounded Regions 与 Number of Islands，讲清四方向/八方向遍历、`visited` 数组 vs 原地标记、以及与并查集的对比。

**最后补充一点落点。** 回溯与动态规划是"一对孪生"——**"枚举所有方案"用回溯、"求数量/最优"用 DP，而"记忆化搜索"是它们的桥。** 理解了这一点，你就把"回溯"与"DP"统一到了"状态空间求解"这一大框架下。**而这，是本专栏最想传达的一层认知。**

**再补充一点。** 回溯题的"难度分层"很清楚——**第一层是"能写出模板"，第二层是"会剪枝"，第三层是"能判断该不该记忆化"。** 大多数人停在第 1.5 层，**而面试拉开差距的，正是"剪枝"与"记忆化"这两层。** 建议把"剪枝"与"记忆化"当成回溯的两个核心技能来练。

**再补充最后一点。** 回溯的"三要素"（路径、选择列表、结束条件）是它的"通用语言"——**任何回溯题，都能用这三要素描述。** 而"两条铁律"（记录要复制、选择要撤销）是它的"安全网"——**守住它们，回溯题就不会"结果错"。** **把三要素与两条铁律背熟，回溯题就"稳了"。**
