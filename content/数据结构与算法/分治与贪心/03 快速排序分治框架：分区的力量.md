# 快速排序分治框架：分区的力量

**摘要：**

快速排序是工程实践中使用最广泛的排序算法，也是分治法的经典示范。但面试中考察的不仅是"能不能写出快速排序"，更重要的是：理解**分区（Partition）操作**的多种变体（Lomuto、Hoare、三路分区）及其各自的适用场景；能从快速排序自然推导出**快速选择（QuickSelect）**，在 $O(n)$ 期望时间内找到第 K 大元素。本文深度剖析这两道核心题目：LeetCode 215（数组中的第 K 个最大元素）和 LeetCode 75（颜色分类，即荷兰国旗问题），还原每个设计选择背后的"为什么"。

---

## 第 1 章 快速排序的分治结构

### 1.1 与归并排序的对比

快速排序和归并排序都是 $O(n \log n)$ 的分治排序算法，但它们的设计哲学截然相反：

| 维度 | 归并排序 | 快速排序 |
|------|---------|---------|
| 复杂工作在哪一阶段 | **合并阶段**（combine 代价高） | **分解阶段**（divide 代价高） |
| 分解方式 | 简单取中点（$O(1)$） | 分区操作（$O(n)$） |
| 合并方式 | 有代价的合并（$O(n)$） | 不需要合并（$O(1)$） |
| 空间复杂度 | $O(n)$（需要临时数组） | $O(\log n)$（原地操作，只需递归栈） |
| 稳定性 | 稳定 | 不稳定（元素交换破坏相对顺序） |
| 最坏情况 | $O(n \log n)$（始终如此） | $O(n^2)$（分区极不平衡时） |

快速排序的核心操作是 **Partition（分区）**：选择一个枢轴元素（pivot），将数组重新排列，使得所有小于 pivot 的元素在左边，所有大于 pivot 的元素在右边，pivot 本身在正确位置上。

**分区之后不需要合并**：这是快速排序最优雅的地方。分区完成后，pivot 已经在最终位置，递归分别对左半部分和右半部分排序，两部分之间天然不需要再合并（左段的所有元素都 ≤ pivot ≤ 右段的所有元素）。

### 1.2 快速排序的整体结构

```go
func quickSort(arr []int, left, right int) {
	if left >= right {
		return // 基础情形：0 或 1 个元素，已有序
	}
	// 分区：返回 pivot 最终所在的下标（pivot 本身已在正确位置，不参与后续递归）
	pivotIndex := partition(arr, left, right)
	quickSort(arr, left, pivotIndex-1)
	quickSort(arr, pivotIndex+1, right)
}
```

复杂度分析：
- **最优/平均情况**：每次分区将数组均匀对半切，$T(n) = 2T(n/2) + O(n)$，即 $O(n \log n)$
- **最坏情况**：每次分区极不平衡（如 pivot 始终是最小或最大元素），$T(n) = T(1) + T(n-1) + O(n)$，展开后是 $O(n^2)$

## 第 2 章 分区操作的三种变体

### 2.1 Lomuto 分区

Lomuto 分区是最容易理解的变体，通常用数组最后一个元素作为 pivot：

```go
func partitionLomuto(arr []int, left, right int) int {
	pivot := arr[right] // 选最后一个元素为 pivot
	i := left - 1       // i 是小于 pivot 的区域的末尾（exclusive）

	for j := left; j < right; j++ {
		if arr[j] <= pivot {
			// arr[j] 应该放入"小于等于 pivot"的区域
			i++
			arr[i], arr[j] = arr[j], arr[i]
		}
	}
	// 将 pivot 放到正确位置 i+1
	arr[i+1], arr[right] = arr[right], arr[i+1]
	return i + 1 // 返回 pivot 的最终下标
}
```

**不变量**：在每次迭代结束时：
- `arr[left..i]`：所有元素 ≤ pivot
- `arr[i+1..j-1]`：所有元素 > pivot（待处理）
- `arr[j..right-1]`：尚未处理
- `arr[right]`：pivot

循环结束后（`j == right`），将 `arr[right]`（pivot）交换到 `i+1` 的位置，分区完成。

**Lomuto 的缺点**：当数组有大量重复元素时，Lomuto 分区会将所有重复元素划分到同一侧，导致极不平衡的分区，退化到 $O(n^2)$。

### 2.2 Hoare 分区

Hoare 分区是快速排序的原始设计，使用双指针从两端向中间扫描：

```go
func partitionHoare(arr []int, left, right int) int {
	pivot := arr[left+(right-left)/2] // 选中间元素为 pivot
	i, j := left-1, right+1

	for {
		// 从左向右找第一个 >= pivot 的元素
		for i++; arr[i] < pivot; i++ {
		}
		// 从右向左找第一个 <= pivot 的元素
		for j--; arr[j] > pivot; j-- {
		}
		if i >= j {
			return j // 两指针相遇或交叉，分区完成
		}
		arr[i], arr[j] = arr[j], arr[i] // 交换：让大的去右边，小的去左边
	}
}
```

**Hoare 分区的注意事项**：
1. 返回的是 `j`（右指针），不是 pivot 的最终下标。递归时要用 `quickSort(arr, left, j)` 和 `quickSort(arr, j+1, right)`，注意边界包含 `j`。
2. Hoare 分区不保证 pivot 在返回的下标位置上——它只保证 `arr[left..j]` 的元素都 ≤ pivot，`arr[j+1..right]` 的元素都 ≥ pivot。
3. Hoare 分区在实践中**性能优于 Lomuto**：Hoare 平均做的交换次数是 Lomuto 的约 1/3。

### 2.3 三路分区（Dutch National Flag）

三路分区（也叫荷兰国旗分区）将数组分成三个区域：小于 pivot、等于 pivot、大于 pivot。这是专门针对大量重复元素设计的优化：

```go
// partition3Way 三路分区：返回 [lt, gt]，满足
// arr[left..lt-1] < pivot | arr[lt..gt] == pivot | arr[gt+1..right] > pivot
func partition3Way(arr []int, left, right int) (lt, gt int) {
	pivot := arr[left+(right-left)/2]
	lt, gt, i := left, right, left

	for i <= gt {
		switch {
		case arr[i] < pivot:
			arr[lt], arr[i] = arr[i], arr[lt]
			lt++
			i++
		case arr[i] > pivot:
			arr[i], arr[gt] = arr[gt], arr[i]
			gt--
			// 注意：i 不递增，因为 arr[gt] 原来的值还未处理
		default:
			i++ // arr[i] == pivot，直接跳过
		}
	}
	return lt, gt
}

// quickSort3Way 使用三路分区的快速排序（arr[lt..gt] 都等于 pivot，无需递归）
func quickSort3Way(arr []int, left, right int) {
	if left >= right {
		return
	}
	lt, gt := partition3Way(arr, left, right)
	quickSort3Way(arr, left, lt-1)  // 对小于 pivot 的部分递归
	quickSort3Way(arr, gt+1, right) // 对大于 pivot 的部分递归
}
```

**三路分区的关键优势**：当数组中有大量重复元素时，所有等于 pivot 的元素在一次分区后就"彻底完成了"，不再参与后续递归。例如，对全部相同的数组，三路分区只需 $O(n)$（只做一次分区，递归不再继续），而 Lomuto/Hoare 需要 $O(n^2)$。

## 第 3 章 LeetCode 75：颜色分类（荷兰国旗问题）

### 3.1 题目

**LeetCode 75 - Sort Colors**（中等）

给定一个包含红色、白色和蓝色、共 `n` 个元素的数组 `nums`，**原地**对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色顺序排列。我们使用整数 `0`、`1` 和 `2` 分别表示红色、白色和蓝色。

**必须不使用库的 sort 函数来解决这个问题。**

```
输入: nums = [2, 0, 2, 1, 1, 0]
输出: [0, 0, 1, 1, 2, 2]

输入: nums = [2, 0, 1]
输出: [0, 1, 2]
```

### 3.2 为什么不用通用排序

这道题三种元素，用计数排序（统计 0、1、2 各有多少个，然后填回）$O(n)$ 时间、$O(1)$ 空间，正确且高效。但这会有两次遍历（第一次统计，第二次填回）。

面试官的考察重点是：**能否用一次遍历（单趟）完成分类？**这正是三路分区（荷兰国旗）算法的价值所在。

### 3.3 三路分区的直观过程

以 pivot = 1（白色）为基准，将数组分为三段：

```
[0, 0, ..., 0 | 1, 1, ..., 1 | ?, ?, ..., ? | 2, 2, ..., 2]
               lt             i              gt
```

- `[0, lt-1]`：已知都是 0（红色）
- `[lt, i-1]`：已知都是 1（白色）
- `[i, gt]`：未知区域，需要处理
- `[gt+1, n-1]`：已知都是 2（蓝色）

初始时 `lt = 0, i = 0, gt = n-1`，未知区域覆盖整个数组。我们从 `i` 开始处理，直到 `i > gt`（未知区域为空）：

```go
// sortColors LeetCode 75：荷兰国旗三路分区，时间 O(n)，空间 O(1)
func sortColors(nums []int) {
	lt, gt, i := 0, len(nums)-1, 0

	for i <= gt {
		switch nums[i] {
		case 0: // 红色：与 lt 交换，lt 与 i 同步右移（lt 位置原来是 1，移到 i 后无需重查）
			nums[i], nums[lt] = nums[lt], nums[i]
			lt++
			i++
		case 2: // 蓝色：与 gt 交换，gt 左移，但 i 不动（gt 原来的值未知，还需处理）
			nums[i], nums[gt] = nums[gt], nums[i]
			gt--
		default: // 白色（1）：已在中间区域，直接跳过
			i++
		}
	}
}
```

**为什么 `nums[i] == 2` 时 i 不递增？**

当 `nums[i] == 2`，我们把 `nums[i]` 与 `nums[gt]` 交换，然后 `gt--`。交换后 `nums[i]` 的新值是原来 `nums[gt]` 的值——这个值我们还没有处理过（`gt` 的位置在未知区域里），所以不能推进 `i`，需要在下一次循环中继续处理 `nums[i]`。

相反，当 `nums[i] == 0`，我们把 `nums[i]` 与 `nums[lt]` 交换，`lt` 右移，`i` 右移。这里可以推进 `i` 是因为：`lt` 始终 ≤ `i`，`nums[lt]` 要么是 1（白色，已处理过并标记为"白色区域"）要么等于 0（在 `lt == i` 时）。交换后 `nums[i]` 是 1，这是已处理好的状态（1 本就属于中间区域），所以可以推进 `i`。

### 3.4 手工演示

以 `nums = [2, 0, 2, 1, 1, 0]` 为例：

| 步骤 | nums | lt | i | gt | 操作 |
|------|------|----|---|----|------|
| 初始 | [2,0,2,1,1,0] | 0 | 0 | 5 | |
| 1 | [0,0,2,1,1,2] | 0 | 0 | 4 | nums[0]=2，与 nums[5] 交换，gt-- |
| 2 | [0,0,2,1,1,2] | 1 | 1 | 4 | nums[0]=0，与 nums[0] 交换（lt=i=0），lt++, i++ |
| 3 | [0,0,2,1,1,2] | 1 | 1 | 4 | nums[1]=0，与 nums[1] 交换，lt++, i++ |

等等，让我重新演示：

初始 `lt=0, i=0, gt=5`，`nums=[2,0,2,1,1,0]`：

1. `nums[0]=2`：与 `nums[5]` 交换 → `[0,0,2,1,1,2]`，`gt=4`，i 不变=0
2. `nums[0]=0`：与 `nums[0]` 交换（自交换）→ `[0,0,2,1,1,2]`，`lt=1, i=1`
3. `nums[1]=0`：与 `nums[1]` 交换（自交换）→ `[0,0,2,1,1,2]`，`lt=2, i=2`
4. `nums[2]=2`：与 `nums[4]` 交换 → `[0,0,1,1,2,2]`，`gt=3`，i 不变=2
5. `nums[2]=1`：i++，`i=3`
6. `nums[3]=1`：i++，`i=4`
7. `i=4 > gt=3`，循环结束

最终 `[0,0,1,1,2,2]`，正确。

**复杂度**：时间 $O(n)$（一次遍历），空间 $O(1)$（原地操作）。

## 第 4 章 LeetCode 215：数组中的第 K 个最大元素

### 4.1 题目

**LeetCode 215 - Kth Largest Element in an Array**（中等）

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

注意，你需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。

**请不使用排序来解决这个问题。**（严格来说，面试中 $O(n \log n)$ 的排序解法通常可以接受，但题目鼓励追求更优解）

```
输入: [3, 2, 1, 5, 6, 4], k = 2
输出: 5

输入: [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4
输出: 4
```

### 4.2 直觉解法：排序后取下标

将数组排序（降序），然后取 `nums[k-1]`。时间 $O(n \log n)$，空间 $O(1)$（原地排序）。

但是，题目提示"不使用排序"，面试官期望的是 $O(n)$ 期望时间的解法——**快速选择（QuickSelect）**。

### 4.3 快速选择：从快速排序到线性选择

**核心洞察**：排序是为了找到"排名第 k 的元素"，但排序做了很多"不必要"的工作——它对所有元素进行了全局排序，而我们只需要知道第 k 个位置的元素是什么。

快速选择利用了分区操作的一个特性：**分区后，pivot 处于其最终位置，我们知道它在整个数组中的排名**。
- 如果 pivot 的排名（下标）恰好是 k，直接返回 pivot
- 如果 pivot 排名 < k，第 k 大元素在右侧（更大的那侧），递归处理右侧
- 如果 pivot 排名 > k，第 k 大元素在左侧（较大的那侧），递归处理左侧

每次递归只需处理一侧（而不是像快速排序那样处理两侧），这是快速选择 $O(n)$ 期望复杂度的来源。

### 4.4 第 K 大 vs 第 K 小的下标转化

约定数组降序排列，第 k 大的元素在下标 `k-1` 处；等价地，第 k 大的元素 = 升序排列后下标为 `n-k` 处的元素。

在代码实现中，通常将"第 k 大"转化为"第 k 小"来处理，避免混淆：找第 k 大 = 找升序排列第 `n-k` 小（0-indexed）。

### 4.5 完整实现

```go
// findKthLargest LeetCode 215：三路随机化快速选择，期望时间 O(n)
func findKthLargest(nums []int, k int) int {
	// 第 k 大 = 升序排列中第 (n-k) 小（0-indexed）
	return quickSelect(nums, 0, len(nums)-1, len(nums)-k)
}

// quickSelect 在 nums[left..right] 中返回升序第 targetRank 小（0-indexed）的元素
func quickSelect(nums []int, left, right, targetRank int) int {
	if left == right {
		return nums[left] // 只有一个元素，直接返回
	}

	// 随机化 pivot 选择：防止最坏情况（如有序数组的退化）
	pivotIdx := left + rand.Intn(right-left+1)
	nums[left], nums[pivotIdx] = nums[pivotIdx], nums[left]
	pivot := nums[left]

	// 三路分区：nums[left..lt-1] < pivot | nums[lt..gt] == pivot | nums[gt+1..right] > pivot
	lt, gt, i := left, right, left+1
	for i <= gt {
		switch {
		case nums[i] < pivot:
			nums[lt], nums[i] = nums[i], nums[lt]
			lt++
			i++
		case nums[i] > pivot:
			nums[i], nums[gt] = nums[gt], nums[i]
			gt--
		default:
			i++
		}
	}

	switch {
	case targetRank < lt:
		return quickSelect(nums, left, lt-1, targetRank) // 目标在左段
	case targetRank > gt:
		return quickSelect(nums, gt+1, right, targetRank) // 目标在右段
	default:
		return nums[lt] // 目标落在等值区，nums[lt..gt] 都等于 pivot
	}
}
```

### 4.6 随机化枢轴的重要性

为什么需要随机化 pivot 选择？

**对抗最坏情况**：如果总是选第一个或最后一个元素作为 pivot，当输入是有序数组时，每次分区只能从两端"剥离"一个元素，退化为 $O(n^2)$。面试中已知存在刻意构造最坏输入的情况。

**期望 $O(n)$ 复杂度的推导**：随机化后，期望每次分区将数组大致对半切（至少 25%:75% 的概率是 0.5），期望递归深度是 $O(\log n)$，但因为每次只递归一侧，总期望工作量是：

$$T(n) = T(3n/4) + O(n)$$（期望最坏情况：每次至少去掉 1/4 的元素）

用主定理：$a=1, b=4/3, f(n)=O(n)$，$\log_{4/3} 1 = 0 < 1$，满足情形三，$T(n) = O(n)$。

更严格的分析（利用 indicator 随机变量）可以证明期望比较次数为 $\leq 4n$。

> [!warning] 生产避坑：快速选择是原地修改的
> `quickSelect` 会修改传入的数组（分区操作会交换元素）。如果调用方不希望数组被修改，需要先复制一份。LeetCode 题目中通常不成问题，但在实际工程代码中要注意这个副作用。

### 4.7 备选方案：最小堆 TopK

面试中还有一种常见解法：用一个大小为 k 的最小堆维护"当前遇到的最大 k 个元素"。

```go
// findKthLargestHeap 最小堆 TopK：维护大小为 k 的最小堆，堆顶即第 k 大
// 时间复杂度：O(n log k)，空间复杂度：O(k)
func findKthLargestHeap(nums []int, k int) int {
	h := &minHeap{}
	heap.Init(h)
	for _, num := range nums {
		heap.Push(h, num)
		if h.Len() > k {
			heap.Pop(h) // 弹出当前最小的，维持堆大小为 k
		}
	}
	return (*h)[0] // 堆顶就是第 k 大的元素
}

type minHeap []int

func (h minHeap) Len() int            { return len(h) }
func (h minHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h minHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *minHeap) Pop() interface{} {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}
```

**堆解法的适用场景**：
- 时间复杂度：$O(n \log k)$（每个元素最多做一次 $O(\log k)$ 的堆操作）
- 空间复杂度：$O(k)$
- **适合流式场景**：当数据是流式输入（不能全部存入内存），或者 $k \ll n$ 时，堆解法更实用。
- **不适合 $k \approx n$ 的场景**：此时 $\log k \approx \log n$，性能接近全排序，不如快速选择。

| 解法 | 时间复杂度 | 空间复杂度 | 适用场景 |
|------|-----------|-----------|---------|
| 排序后取下标 | $O(n \log n)$ | $O(1)$ 或 $O(n)$ | 简单，任何场景 |
| 快速选择 | $O(n)$ 期望 | $O(\log n)$ 递归栈 | 全量内存，追求最优 |
| 最小堆 | $O(n \log k)$ | $O(k)$ | 流式数据，$k \ll n$ |
| BFPRT | $O(n)$ 最坏 | $O(n)$ | 对最坏情况有严格保证 |

## 第 5 章 枢轴选择策略深度对比

### 5.1 固定枢轴的风险

**首元素枢轴**：对已排序或逆序排列的数组，每次分区只剥离一个元素，退化 $O(n^2)$。

**末元素枢轴（Lomuto 默认）**：与首元素枢轴同样的问题。

**中间元素枢轴（Hoare 默认）**：对已排序数组表现良好，但对专门构造的"反中间点"输入仍可能退化。

### 5.2 随机化枢轴

从 `[left, right]` 均匀随机选一个位置作为 pivot。期望复杂度 $O(n \log n)$（排序）或 $O(n)$（选择），能对抗绝大多数构造输入。

缺点：对性能有极高要求的场景（如实时系统），期望值不提供最坏情况保证。

### 5.3 三数取中（Median of Three）

取 `arr[left]`、`arr[mid]`、`arr[right]` 三者的中位数作为 pivot。

这是实际工程中（如 C++ STL 的 `std::sort`、Java 的 `Arrays.sort`）常用的优化，能有效避免已排序输入的退化，且不引入随机数开销。

### 5.4 BFPRT：线性时间最坏保证

BFPRT 算法（由 Blum-Floyd-Pratt-Rivest-Tarjan 五位作者提出）通过选择"中位数的中位数"作为 pivot，保证每次分区至少去掉 30% 的元素，从而在最坏情况下也是 $O(n)$。

但 BFPRT 的实现复杂，常数因子大，实际性能不如随机化的快速选择。在面试中了解其存在即可，极少要求手写。

## 第 7 章 快速排序的工程演进：尾递归消除、Introsort 与 pdqsort

### 7.1 从教科书到生产库：快速排序必须跨过的四道坎

教科书上的快速排序在生产环境中直接使用会遭遇四道坎，每一道都对应一项工程优化：

1. **最坏 $O(n^2)$ 退化**：当枢轴选择不当（如对已排序数组固定取首元素）时，切分会极度偏斜。**随机化枢轴**（第 4.6 节）把期望复杂度拉回 $O(n \log n)$，但仍有极小概率退化；
2. **递归栈溢出**：最坏切分下递归深度达 $O(n)$。**尾递归消除**（第 01 篇第 8.2 节）把栈深压到 $O(\log n)$；
3. **大量重复元素退化**：全相等数组会让二路分区退化为 $O(n^2)$。**三路分区（Dutch National Flag，第 2.3 节）**把全相等数组一次切完，复杂度降为 $O(n)$；
4. **小数组常数开销**：递归到小区间时，函数调用与切分开销超过插入排序。**小区间切换插入排序**（阈值通常取 16~24）。

### 7.2 Introsort：混合算法的工业标准答案

C++ 标准库的 `std::sort` 采用的 **Introsort（内省排序）**正是上述四道坎的集大成者：
- 主体跑快速排序（三数取中枢轴 + 尾递归消除 + 小区间插入排序）；
- **递归深度监控**：当递归深度超过 $2 \log_2 n$ 时，判定当前切分已经偏斜到危险程度，**果断放弃快排、切换为堆排序**（堆排序最坏 $O(n \log n)$，绝不退化）；
- 最终小区间统一交给插入排序收尾。

```go
package main

// introsort Introsort 骨架：快排主体 + 深度超限切换堆排序 + 小区间插入排序
func introsort(nums []int) {
	introsortHelper(nums, 0, len(nums)-1, 2*log2(len(nums))+2)
	insertionSort(nums)
}

func introsortHelper(nums []int, lo, hi, depthLimit int) {
	for hi-lo > 16 {
		if depthLimit == 0 {
			heapSortRange(nums, lo, hi) // 深度超限，切换堆排序保底
			return
		}
		mid := partition(nums, lo, hi)
		// 尾递归消除：只递归较小半区
		if mid-lo < hi-mid {
			introsortHelper(nums, lo, mid-1, depthLimit-1)
			lo = mid + 1
		} else {
			introsortHelper(nums, mid+1, hi, depthLimit-1)
			hi = mid - 1
		}
	}
}

func log2(n int) int {
	r := 0
	for n > 1 {
		n >>= 1
		r++
	}
	return r
}

func insertionSort(nums []int) {
	for i := 1; i < len(nums); i++ {
		key := nums[i]
		j := i - 1
		for j >= 0 && nums[j] > key {
			nums[j+1] = nums[j]
			j--
		}
		nums[j+1] = key
	}
}

func heapSortRange(nums []int, lo, hi int) {
	// 标准堆排序（略），对 nums[lo..hi] 原地建堆后逐个弹出
	_ = nums
	_ = lo
	_ = hi
}
```

### 7.3 pdqsort：2021 年后的新王者

Rust 标准库与 Go 1.19+ 的 `sort.Slice` 底层采用的 **pdqsort（Pattern-Defeating Quicksort）**在 Introsort 之上又叠了三层优化：
1. **模式侦测（Pattern Defeating）**：检测输入是否已经接近有序（如检测前几个元素的升降趋势），若是则直接切换为**部分插入排序**，对近乎有序的输入达到 $O(n)$；
2. **枢轴黑名单**：当某种枢轴选择策略连续失败（切分极度偏斜）时，记入黑名单并更换策略；
3. **分区平衡性监控**：当切分比例超过阈值时，用"随机打散一小段再切分"的方式打破恶意构造的退化输入。

### 7.4 延伸实战：最接近原点的 K 个点（LeetCode 973）

快速选择（第 4 章）不仅能按数值选第 K 小，还能按**任意比较键**选 TopK。以 **LeetCode 973：最接近原点的 K 个点**为例，比较键从 `nums[i]` 换成了欧氏距离平方 `x*x + y*y`（避免开方与浮点误差），直接复用三路随机化快速选择模板，在期望 $O(n)$ 时间内选出前 K 个最近点——比堆解法的 $O(n \log k)$ 与排序解法的 $O(n \log n)$ 都更快。

### 7.5 本章核心结论

- 教科书快排与生产级排序库之间隔着**随机化、尾递归消除、三路分区、小区间切换、深度监控切换堆排**五道工程坎；
- Introsort 用"深度超限切堆排"给了快排一张最坏 $O(n \log n)$ 的保底牌；pdqsort 再叠模式侦测，对近乎有序的真实数据达到 $O(n)$；
- 快速选择的比较键可以任意定制（距离平方、字典序、自定义权重），是 TopK 问题的期望线性时间通解。


### 7.5 延伸实战：最接近原点的 K 个点（LC 973）的完整实现

在第 7.4 节我们提到快速选择的比较键可以任意定制。下面给出 **LeetCode 973：最接近原点的 K 个点**的三路随机化快速选择完整实现：

```go
package main

import "math/rand"

type point struct{ x, y int }

func dist2(p point) int { return p.x*p.x + p.y*p.y }

// kClosest LeetCode 973：三路随机化快速选择按距离平方选前 K 近的点
// 时间复杂度：期望 O(n)，空间复杂度：O(n)（切片拷贝，避免破坏原数组）
func kClosest(points [][]int, k int) [][]int {
	pts := make([]point, len(points))
	for i, p := range points {
		pts[i] = point{p[0], p[1]}
	}

	lo, hi := 0, len(pts)-1
	for lo < hi {
		pivotIdx := lo + rand.Intn(hi-lo+1)
		pts[pivotIdx], pts[hi] = pts[hi], pts[pivotIdx]
		pivot := dist2(pts[hi])

		// 三路分区：[lo, lt) < pivot | [lt, gt] == pivot | (gt, hi] > pivot
		lt, i, gt := lo, lo, hi
		for i <= gt {
			d := dist2(pts[i])
			if d < pivot {
				pts[lt], pts[i] = pts[i], pts[lt]
				lt++
				i++
			} else if d > pivot {
				pts[i], pts[gt] = pts[gt], pts[i]
				gt--
			} else {
				i++
			}
		}

		if k-1 < lt {
			hi = lt - 1
		} else if k-1 > gt {
			lo = gt + 1
		} else {
			break // 第 k 个恰好落在等值区
		}
	}

	res := make([][]int, k)
	for i := 0; i < k; i++ {
		res[i] = []int{pts[i].x, pts[i].y}
	}
	return res
}
```

### 7.6 三种 TopK 方案在 LC 973 上的横向对照

| 方案 | 时间复杂度 | 空间复杂度 | 是否破坏原数组 | 适用场景 |
|------|------------|------------|----------------|----------|
| 全排序 | $O(n \log n)$ | $O(\log n)$ | 是（或需拷贝） | 代码最短，n 较小 |
| 大小为 K 的最大堆 | $O(n \log k)$ | $O(k)$ | 否 | **流式数据**（元素逐个到达） |
| 三路随机化快速选择 | 期望 $O(n)$ | $O(1)$ 额外 | 是（原地分区） | **静态数组**求一次答案 |

在面试中，当面试官追问"如果数据是流式的怎么办"，正确答案是切换到堆方案——因为快速选择需要一次性拿到全数组才能分区，而堆可以逐元素增量维护。这一追问恰好呼应了第 01 篇"分治 vs 数据结构加速"的辩证关系。

### 7.7 本章核心结论补充

- 快速选择的比较键可以任意定制（距离平方、字典序、自定义权重），是 TopK 问题的期望线性时间通解；
- 三路分区（荷兰国旗）不仅解决重复元素退化，还是处理"值域极小"输入的最优分区策略；
- 生产级排序库（Introsort、pdqsort）是本章全部工程坎的集大成者，阅读其源码是深化分治理解的绝佳途径。


### 7.8 延伸实战：数组中的第 K 个最大元素（LC 215）的堆解法完整实现

在第 7.5 节我们给出了 LC 973（最接近原点的 K 个点）的快速选择实现。这里补齐最小堆 TopK 的完整 Go 实现，凑齐三种 TopK 方案的代码拼图：

```go
package main

import "container/heap"

type minHeap []int

func (h minHeap) Len() int            { return len(h) }
func (h minHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h minHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *minHeap) Pop() interface{} {
	old := *h
	n := len(old)
	x := old[n-1]
	*h = old[:n-1]
	return x
}

// findKthLargestHeap LeetCode 215：大小为 k 的最小堆"守门员"模式
// 时间复杂度：O(n log k)，空间复杂度：O(k)
func findKthLargestHeap(nums []int, k int) int {
	h := &minHeap{}
	heap.Init(h)
	for _, num := range nums {
		heap.Push(h, num)
		if h.Len() > k {
			heap.Pop(h) // 弹出当前最小的，维持堆大小恒为 k
		}
	}
	return (*h)[0] // 堆顶即第 k 大元素
}
```

这个"守门员"模式的精髓在于：**堆里永远只保留当前见过的最大的 k 个元素，堆顶是这 k 个中最小的（即全局第 k 大的候选）**。每当新元素到来，若它比堆顶大，就挤掉堆顶入堆；否则直接丢弃。这一模式是《排序与查找》专栏第 07 篇流式 TopK 的标准引擎，在监控系统的 TopN 告警聚合、搜索引擎的 TopN 召回截断中都是生产级首选。

### 7.9 三种 TopK 方案的完整对照

| 方案 | 时间复杂度 | 空间复杂度 | 是否破坏原数组 | 流式支持 | 适用场景 |
|------|------------|------------|----------------|----------|----------|
| 全排序 | $O(n \log n)$ | $O(\log n)$ | 是（或需拷贝） | 否 | 代码最短，n 较小 |
| 大小为 K 的最小堆 | $O(n \log k)$ | $O(k)$ | 否 | **是** | 流式数据、k 远小于 n |
| 三路随机化快速选择 | 期望 $O(n)$ | $O(1)$ 额外 | 是（原地分区） | 否 | 静态数组求一次答案 |


### 7.10 快速排序工程演进的终检清单

把本章的全部工程坎浓缩为一份终检清单：其一，随机化枢轴（或三数取中）对抗有序输入退化；其二，尾递归消除把最坏栈深从 $O(n)$ 压到 $O(\log n)$；其三，三路分区把全相等数组从 $O(n^2)$ 救回 $O(n)$；其四，小区间（长度 16~24 以下）切换插入排序消掉递归常数；其五，递归深度超过 $2\log_2 n$ 时切换堆排序保底（Introsort），pdqsort 再叠模式侦测对近乎有序输入达到 $O(n)$。这五道坎的每一道，都对应着分治范式从教科书走向生产库的一次进化，也是面试官区分"背过快排"与"理解快排"的五道试金石。

### 7.11 快速选择的期望复杂度严格证明与工程终检

快速选择期望 $O(n)$ 的严格证明基于指示器随机变量：设 $X_{ij}$ 为第 $i$ 小与第 $j$ 小元素在分区中被比较的指示变量，$E[X_{ij}] = 2/(j - i + 1)$，求和得期望比较次数 $\sum_{i<j} 2/(j-i+1) = O(n)$。工程终检清单：其一，随机化枢轴（或三数取中）对抗有序输入退化；其二，三路分区把全相等数组从 $O(n^2)$ 救回 $O(n)$；其三，只递归目标一侧使期望工作量满足 $T(n) = T(3n/4) + O(n) = O(n)$；其四，原地分区会修改传入数组，调用方需注意副作用。这四条与 Introsort、pdqsort 的五道工程坎共同构成了快速排序家族从教科书走向生产库的完整进化链。

### 7.12 快速排序与归并排序的工程对照终检

把本章与《排序与查找》专栏的归并排序对照，可以提炼出分治两大骨架的工程分野：归并排序是"先递归后合并"的自底向上骨架，合并阶段稳定 $O(n)$、排序稳定、缓存局部性好，但需要 $O(n)$ 辅助数组；快速排序是"先分区后递归"的自顶向下骨架，分区原地 $O(1)$ 额外空间、缓存友好，但不稳定且最坏退化。生产库的选择因此呈现清晰的场景分化：链表排序用归并（无需随机访问）、内存排序用 Introsort/pdqsort（快排骨架 + 堆排保底）、外部排序用多路归并（归并骨架 + Loser Tree）。这一对照与本章第 7 章的五道工程坎共同构成了快速排序家族的完整进化链。

### 7.13 快速选择只递归一侧的复杂度终检

快速选择与快速排序的本质分野在于递归范围：排序必须两侧都递归（$T(n) = 2T(n/2) + O(n) = O(n \log n)$），而选择只需递归目标所在的一侧（$T(n) = T(n/2) + O(n) = O(n)$——等比级数求和 $n + n/2 + n/4 + \cdots = 2n$）。这一"砍掉一半工作量"的剪枝，是分治范式从"全量求解"到"定向求解"的关键跃迁，也是本章第 4 章快速选择与第 7 章 Introsort 工程演进的共同根基。终检时请确认：三路分区返回 `[lt, gt]` 后，目标排名落在等值区时直接返回 `nums[lt]`，绝不递归等值区内部。

### 7.14 快速排序的稳定性与缓存局部性终检

快速排序与归并排序的工程分野还可从稳定性与缓存局部性两个维度终检：稳定性方面，Lomuto 分区的 `<=` 交换会打乱相等元素的相对次序，因此快速排序不稳定；若业务要求稳定排序（如多关键字排序的第二遍），必须切换归并排序。缓存局部性方面，快速排序的原地分区具有完美的顺序访存模式（`i` 与 `j` 双向扫描），而归并排序的合并需要额外的临时数组读写，缓存命中率略低——这也是为什么在纯内存、无稳定性要求的场景下，生产库几乎清一色选择快排骨架。终检口诀：**要稳定用归并，要省内存用快排，要最坏保底用 Introsort，要流式 TopK 用堆**。

### 7.15 快速排序与快速选择的终检口诀

把本章的终检浓缩为三条口诀：口诀一，**Lomuto 简单但交换多，Hoare 交换少但边界易错，三路分区专治重复元素**——三种分区的选型依据是输入的重复度与对交换次数的敏感度；口诀二，**排序两侧递归 $O(n \log n)$，选择只递归一侧期望 $O(n)$**——快速选择砍掉一半工作量的剪枝是分治从"全量求解"到"定向求解"的关键跃迁；口诀三，**随机化枢轴 + 尾递归消除 + 小区间插入排序 + 深度超限切堆排**——四道工程坎的每一道都对应生产库的一次进化，pdqsort 的模式侦测则是第五道。三条口诀与第 7 章的 Introsort/pdqsort 工程演进共同构成了快速排序家族从教科书走向生产库的完整进化链。
## 小结

1. **分区是快速排序的灵魂**：快速排序"难"的工作在分区，"简单"的工作在合并（无需合并）——这与归并排序正好相反。

2. **三路分区是重复元素的正确解**：大量重复元素时，Lomuto/Hoare 退化，三路分区能将等于 pivot 的元素一次性放到正确位置，避免退化。

3. **快速选择：单侧递归 + 三路分区 = $O(n)$ 期望**：快速排序两侧都递归（分治），快速选择只递归一侧（按需），这是从 $O(n \log n)$ 降到 $O(n)$ 的本质原因。

4. **随机化枢轴是工程必须**：面试中凡是用快速选择，必须加随机化，否则在已排序输入上会 TLE。

5. **堆 vs 快速选择的权衡**：流式/内存受限场景用堆，全量内存追求最优用快速选择。面试中能说清楚两种方案的适用边界，是加分点。
