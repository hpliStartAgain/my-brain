# 分治在二叉树：重建与最长路径

**摘要：**

二叉树是分治法最自然的舞台——树的递归结构天然地将问题分解为左子树和右子树两个独立的子问题，无需任何"人为分割"。本文深度剖析四道面试高频题：LeetCode 105（从前序与中序遍历序列构造二叉树）、LeetCode 106（从中序与后序遍历序列构造二叉树）、LeetCode 543（二叉树的直径）和 LeetCode 124（二叉树中的最大路径和）。这四道题由浅入深，揭示了树上分治的两种核心模式：**重建分治**（利用遍历序列递归重建树结构）和**路径分治**（在每个节点汇聚左右子树的信息，计算跨越该节点的最优值）。

---

## 第 1 章 二叉树天然是分治问题

### 1.1 为什么树适合分治

在数组上做分治，需要人为选定"中点"作为分割边界。但在二叉树上，**根节点天然就是分割点**：

- 根节点本身是一个局部问题
- 左子树和右子树是两个**完全独立的子问题**（不共享任何节点）
- 处理完左右子树后，在根节点处**合并**（汇聚）两侧的信息

这种结构让"分治"在树上是"免费的"——你只需要写好递归函数，框架自动完成分解和合并。

### 1.2 树上分治的通用框架

```go
// 二叉树分治的通用框架（Result 为自定义状态元组类型）
func solve(root *TreeNode) Result {
	// 基础情形：空节点
	if root == nil {
		return baseCase()
	}
	// 分解：递归求解左子树和右子树
	leftResult := solve(root.Left)
	rightResult := solve(root.Right)
	// 合并：在根节点处汇聚左右子树的结果
	return combine(root, leftResult, rightResult)
}
```

**关键在于 `Result` 的设计**：不同的问题需要返回不同的信息。设计好"每个子树返回什么信息给父节点用"，是树上分治的核心技能。

### 1.3 本文四道题的统一视角

| 题目 | 问题类型 | 每个节点返回什么 | 合并逻辑 |
|------|---------|---------------|---------|
| LeetCode 105 | 重建树 | 构建好的子树根节点 | 将根节点连接到左右子树 |
| LeetCode 106 | 重建树 | 构建好的子树根节点 | 同上，后序确定根，中序确定左右范围 |
| LeetCode 543 | 路径最长 | 以该节点为端点的最长单臂路径长 | 左臂 + 右臂 = 直径，更新全局最大 |
| LeetCode 124 | 路径最大和 | 以该节点为端点的最大单臂路径和 | 左臂 + 根 + 右臂 = 跨越路径，更新全局最大 |

## 第 2 章 LeetCode 105：从前序与中序序列构造二叉树

### 2.1 题目

**LeetCode 105 - Construct Binary Tree from Preorder and Inorder Traversal**（中等）

给定两个整数数组 `preorder` 和 `inorder`，其中 `preorder` 是二叉树的**先序遍历**，`inorder` 是同一棵树的**中序遍历**，请构造二叉树并返回其根节点。

```
输入: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7]
输出:
    3
   / \
  9  20
    /  \
   15   7
```

**说明**：树中没有重复的元素。

### 2.2 先序遍历和中序遍历各自告诉我们什么

**先序遍历（preorder = root → left → right）**：序列的**第一个元素**始终是当前子树的根节点。

**中序遍历（inorder = left → root → right）**：根节点将序列分成两部分——**左侧全是左子树的节点，右侧全是右子树的节点**。

这两个性质结合起来，就是重建算法的全部：

1. 从 `preorder[0]` 确定根节点的值（设为 `rootVal`）
2. 在 `inorder` 中找到 `rootVal` 的位置（设为 `inIndex`）
3. `inorder[0..inIndex-1]` 是左子树的中序遍历，共 `leftSize = inIndex` 个节点
4. `preorder[1..leftSize]` 是左子树的先序遍历（先序根后紧跟左子树）
5. `inorder[inIndex+1..]` 是右子树的中序遍历
6. `preorder[leftSize+1..]` 是右子树的先序遍历
7. 递归重建左右子树，连接到根节点

### 2.3 实现细节：用哈希表加速定位

每次在 `inorder` 中查找 `rootVal` 如果是线性扫描，是 $O(n)$，总体复杂度 $O(n^2)$。用哈希表预处理，查找降为 $O(1)$，总体 $O(n)$。

```go
// buildTree LeetCode 105：前序 + 中序重建二叉树（哈希表 O(1) 定位根）
// 时间复杂度：O(n)，空间复杂度：O(n)
func buildTree(preorder []int, inorder []int) *TreeNode {
	inorderIndex := make(map[int]int, len(inorder))
	for i, v := range inorder {
		inorderIndex[v] = i
	}

	var build func(preLeft, preRight, inLeft, inRight int) *TreeNode
	build = func(preLeft, preRight, inLeft, inRight int) *TreeNode {
		if preLeft > preRight {
			return nil // 基础情形：空子树
		}
		// 先序序列的第一个元素是当前子树的根
		rootVal := preorder[preLeft]
		root := &TreeNode{Val: rootVal}

		// 在中序序列中定位根，切出左子树规模
		inIndex := inorderIndex[rootVal]
		leftSize := inIndex - inLeft

		// 左子树：先序 [preLeft+1 .. preLeft+leftSize]，中序 [inLeft .. inIndex-1]
		root.Left = build(preLeft+1, preLeft+leftSize, inLeft, inIndex-1)
		// 右子树：先序 [preLeft+leftSize+1 .. preRight]，中序 [inIndex+1 .. inRight]
		root.Right = build(preLeft+leftSize+1, preRight, inIndex+1, inRight)
		return root
	}

	return build(0, len(preorder)-1, 0, len(inorder)-1)
}
```

**复杂度**：
- 时间：$O(n)$，每个节点恰好被处理一次
- 空间：$O(n)$，哈希表 + 递归栈（最坏情况下树退化为链，栈深度 $O(n)$）

### 2.4 下标推导的可视化

以 `preorder = [3,9,20,15,7]`，`inorder = [9,3,15,20,7]` 为例：

```
第一次调用：
  preorder[0..4]，inorder[0..4]
  rootVal = preorder[0] = 3
  inIndex = inorderIndexMap[3] = 1
  leftSize = 1 - 0 = 1

  左子树：
    preorder[1..1]（即 [9]），inorder[0..0]（即 [9]）
    rootVal = 9，inIndex = 0，leftSize = 0
    → 叶节点 9

  右子树：
    preorder[2..4]（即 [20,15,7]），inorder[2..4]（即 [15,20,7]）
    rootVal = 20，inIndex = 3，leftSize = 3 - 2 = 1
    
    左子树：preorder[3..3]（[15]），inorder[2..2]（[15]）→ 叶节点 15
    右子树：preorder[4..4]（[7]），inorder[4..4]（[7]）→ 叶节点 7
```

最终构建出正确的树结构。

## 第 3 章 LeetCode 106：从中序与后序序列构造二叉树

### 3.1 题目

**LeetCode 106 - Construct Binary Tree from Inorder and Postorder Traversal**（中等）

给定两个整数数组 `inorder` 和 `postorder`，其中 `inorder` 是二叉树的中序遍历，`postorder` 是同一棵树的后序遍历，请你构造并返回这颗二叉树。

```
输入: inorder = [9,3,15,20,7], postorder = [9,15,7,20,3]
输出: 与 105 相同的树（根为 3）
```

### 3.2 后序遍历的特性

**后序遍历（postorder = left → right → root）**：序列的**最后一个元素**始终是当前子树的根节点。

这是与前序遍历对称的特性。重建算法与 105 几乎完全对称，只需将"取 `preorder` 第一个元素"改为"取 `postorder` 最后一个元素"，并相应调整左右子树的范围计算。

### 3.3 实现

```go
// buildTreeInPost LeetCode 106：中序 + 后序重建二叉树（后序末尾为根）
// 时间复杂度：O(n)，空间复杂度：O(n)
func buildTreeInPost(inorder []int, postorder []int) *TreeNode {
	inorderIndex := make(map[int]int, len(inorder))
	for i, v := range inorder {
		inorderIndex[v] = i
	}

	var build func(inLeft, inRight, postLeft, postRight int) *TreeNode
	build = func(inLeft, inRight, postLeft, postRight int) *TreeNode {
		if postLeft > postRight {
			return nil
		}
		// 后序序列的最后一个元素是当前子树的根
		rootVal := postorder[postRight]
		root := &TreeNode{Val: rootVal}

		inIndex := inorderIndex[rootVal]
		leftSize := inIndex - inLeft

		// 左子树：中序 [inLeft .. inIndex-1]，后序 [postLeft .. postLeft+leftSize-1]
		root.Left = build(inLeft, inIndex-1, postLeft, postLeft+leftSize-1)
		// 右子树：中序 [inIndex+1 .. inRight]，后序 [postLeft+leftSize .. postRight-1]
		root.Right = build(inIndex+1, inRight, postLeft+leftSize, postRight-1)
		return root
	}

	return build(0, len(inorder)-1, 0, len(postorder)-1)
}
```

> [!note] 设计哲学：105 和 106 的统一视角
> 两道题的本质完全相同：**在遍历序列中定位根节点，利用中序遍历分离左右子树范围**。区别只在于根节点的位置：先序在最前，后序在最后。
>
> 为什么没有"先序 + 后序"重建？因为先序序列只告诉我们根在哪里，后序序列也只告诉我们根在哪里，两个信息都没有"左右子树的分界线"。中序序列才提供分界线，这是中序序列的不可替代性。

## 第 4 章 LeetCode 543：二叉树的直径

### 4.1 题目

**LeetCode 543 - Diameter of Binary Tree**（简单）

给你一棵二叉树的根节点，返回该树的**直径**。

二叉树的**直径**是指树中任意两个节点之间最长路径的**长度**。此路径可能经过也可能不经过根节点。

两节点之间路径的长度由它们之间**边**的数目表示。

```
输入: root = [1,2,3,4,5]
输出: 3
解释: 3，取路径 [4,2,1,3] 或 [5,2,1,3] 的长度

输入: root = [1,2]
输出: 1
```

### 4.2 关键洞察：直径经过某个节点

对于树中任意一条路径，它都有一个"最高点"——路径上最靠近根的那个节点。这条路径可以分为两部分：

- 从最高点到路径一端的单臂路径（向左子树延伸）
- 从最高点到路径另一端的单臂路径（向右子树延伸）

因此，最长路径 = 某个节点的"最长左臂" + "最长右臂"。

**算法设计**：
- 对每个节点，定义 `depth(node)` = 以该节点为根的子树中，从该节点出发的最长路径长度（单臂）
- 对每个节点，计算 `depth(left) + depth(right)`（经过该节点的最长路径），更新全局最大值
- 返回 `1 + max(depth(left), depth(right))`（向父节点汇报的单臂长度）

### 4.3 分治实现

```go
// diameterOfBinaryTree LeetCode 543：后序分治（返回单臂长度，拐点处更新全局直径）
// 时间复杂度：O(n)，空间复杂度：O(h)
func diameterOfBinaryTree(root *TreeNode) int {
	maxDiameter := 0 // 全局最大直径（直径最小为 0，单节点到自身）

	var depth func(node *TreeNode) int
	depth = func(node *TreeNode) int {
		if node == nil {
			return 0 // 空节点：单臂长度为 0
		}
		// 分解：递归求左右子树的最长单臂长度
		leftDepth := depth(node.Left)
		rightDepth := depth(node.Right)

		// 合并：经过 node 的最长路径 = 左臂 + 右臂，更新全局最大直径
		maxDiameter = max(maxDiameter, leftDepth+rightDepth)

		// 返回给父节点的单臂长度：1（node 本身这条边）+ 左右两侧中更长的那个
		return 1 + max(leftDepth, rightDepth)
	}

	depth(root)
	return maxDiameter
}
```

### 4.4 为什么不是"从根出发的最长路径"

初学者常见误区：以为直径 = 从根出发的最长路径。这是错误的。

**反例**：
```
        1
       / \
      2   3
     / \
    4   5
   / \
  6   7
```

直径是从 6（或 7）到 5 的路径：6 → 4 → 2 → 5，长度为 3。这条路径的最高点是节点 2，不是根节点 1。

如果只从根出发，最长路径是 1 → 2 → 4 → 6（或 7），长度为 3，这里碰巧也是 3，但这只是巧合。考虑更极端的情形：

```
    1
   /
  2
 / \
3   4
 \   \
  5   6
```

直径是 5 → 3 → 2 → 4 → 6，长度为 4。最高点是节点 2，不是根节点 1。

**结论**：必须对每个节点都计算"经过该节点的直径"，取全局最大值。这是"路径分治"模式的核心。

## 第 5 章 LeetCode 124：二叉树中的最大路径和

### 5.1 题目

**LeetCode 124 - Binary Tree Maximum Path Sum**（困难）

二叉树中的**路径**被定义为一条从树中任意节点出发，沿父节点—子节点连接，达到任意节点的序列。同一个节点在一条路径序列中**至多出现一次**。该路径**至少包含一个**节点，且不一定经过根节点。

**路径和**是路径中各节点值的总和。

给你一个二叉树的根节点 `root`，返回其**最大路径和**。

```
输入: root = [1,2,3]
输出: 6
解释: 最优路径是 2 → 1 → 3，路径和为 2 + 1 + 3 = 6

输入: root = [-10, 9, 20, null, null, 15, 7]
输出: 42
解释: 最优路径是 15 → 20 → 7，路径和为 15 + 20 + 7 = 42
```

### 5.2 与 LeetCode 543 的关系

543 求的是"最多边数"，124 求的是"最大路径和"。两者在分治结构上完全相同，区别在于：

- 543：单臂长度 = 边的数量，恒为正（空节点返回 0）
- 124：单臂贡献 = 路径上节点值的总和，可能为负（此时不如不选这条臂）

**124 的核心新难点**：节点值可能是负数。如果某条臂的贡献为负，不选这条臂比选它更好。

```go
var maxPathSumGlobal int = math.MinInt32 // 全局最大路径和

// maxGain 返回以 node 为端点向下的最大单臂贡献（向父节点延伸）
// 如果所有路径都为负，宁可不贡献（返回 0，表示不选这条臂）
func maxGain(node *TreeNode) int {
	if node == nil {
		return 0
	}
	// 左右子树的最大贡献：如果为负则取 0（不选这条臂）
	leftGain := max(0, maxGain(node.Left))
	rightGain := max(0, maxGain(node.Right))

	// 经过 node 的最大路径和：左臂 + node 本身 + 右臂
	priceNewPath := node.Val + leftGain + rightGain
	maxPathSumGlobal = max(maxPathSumGlobal, priceNewPath)

	// 返回给父节点的单臂贡献：node 本身 + 左右两侧中贡献更大的那个
	return node.Val + max(leftGain, rightGain)
}
```

**`Math.max(0, maxGain(node.left))` 的含义**：如果左子树的最大单臂贡献是负数，那么把左臂加进来只会让路径和变小，不如不选（贡献为 0，即路径在 `node` 处开始，不向左延伸）。

### 5.3 完整实现

```go
// maxPathSum LeetCode 124：后序分治（单臂贡献向上汇报，拐点路径更新全局）
// 时间复杂度：O(n)，空间复杂度：O(h)
func maxPathSum(root *TreeNode) int {
	maxSum := math.MinInt32

	var maxGain func(node *TreeNode) int
	maxGain = func(node *TreeNode) int {
		if node == nil {
			return 0
		}
		// 递归：获取左右子树的最大贡献（负数贡献当 0 处理）
		leftGain := max(0, maxGain(node.Left))
		rightGain := max(0, maxGain(node.Right))

		// 经过当前节点的最大路径和（拐点合并，更新全局）
		maxSum = max(maxSum, node.Val+leftGain+rightGain)

		// 向父节点返回的单臂贡献（只能选一侧，不可分叉）
		return node.Val + max(leftGain, rightGain)
	}

	maxGain(root)
	return maxSum
}
```

### 5.4 手工演示

以 `root = [-10, 9, 20, null, null, 15, 7]` 为例：

```
        -10
       /   \
      9     20
           /  \
          15   7
```

DFS 后序遍历：

1. 叶节点 9：`leftGain=0, rightGain=0`，路径和 = 9，返回 9
2. 叶节点 15：路径和 = 15，返回 15
3. 叶节点 7：路径和 = 7，返回 7
4. 节点 20：`leftGain=max(0,15)=15, rightGain=max(0,7)=7`
   - 路径和 = 20+15+7 = 42，更新 maxPathSum=42
   - 返回 20+15 = 35（向上只能选一侧，选较大的 15）
5. 节点 -10：`leftGain=max(0,9)=9, rightGain=max(0,35)=35`
   - 路径和 = -10+9+35 = 34，不更新 maxPathSum（42 > 34）
   - 返回 -10+35 = 25

最终 `maxPathSum = 42`，正确。

### 5.5 路径不能"分叉"的约束

在返回给父节点的单臂贡献中，我们写的是 `node.val + Math.max(leftGain, rightGain)`——只能选左臂或右臂之一，不能两者都选。

**为什么？**

一条路径是从一个节点到另一个节点的"链"，不能有分叉（Y 形）。如果在某个节点处同时向左子树和右子树延伸，那么这个节点就成了路径的"最高点"（拐点），此时这条路径在这个节点结束，不能再向上延伸。

因此，当我们计算"经过 node 的最大路径和"时，可以同时选左臂和右臂（节点是路径的最高点）；但当我们返回给父节点时，只能选一侧（因为路径还需要向上延伸，只能是一条链）。

## 第 6 章 路径分治模式的深度总结

### 6.1 路径分治的通用模板

这四道题的最后两道（543 和 124）都属于"路径分治"模式，其通用模板如下：

```go
// 树形分治的通用模板：返回"单臂值"给父节点，用"拐点合并值"更新全局答案
var globalResult int // 初始值视题意而定

func solve(root *TreeNode) int {
	helper(root)
	return globalResult
}

func helper(node *TreeNode) int {
	if node == nil {
		return 0 // 空节点的单臂值
	}
	leftVal := helper(node.Left)   // 左子树的最优单臂值
	rightVal := helper(node.Right) // 右子树的最优单臂值

	// 合并：计算经过 node 的最优路径值，更新全局结果
	globalResult = max(globalResult, combine(node, leftVal, rightVal))

	// 向父节点返回：node 贡献的单臂值（只能选一侧延伸）
	return singleArm(node, leftVal, rightVal)
}
```

| 题目 | `combine` 逻辑 | `singleArm` 逻辑 | 空节点单臂值 |
|------|-------------|----------------|------------|
| 543（直径） | `leftVal + rightVal` | `1 + max(leftVal, rightVal)` | `0` |
| 124（最大路径和） | `node.val + max(0,leftVal) + max(0,rightVal)` | `node.val + max(0, max(leftVal, rightVal))` | `0` |

### 6.2 为什么要用全局变量而不是在返回值中传递

一个自然的问题：能不能不用全局变量 `maxDiameter`/`maxPathSum`，而是通过返回值传递？

**不能直接这样做**，因为每个节点需要向父节点返回的是"单臂值"（用于父节点计算其单臂值），而"跨越路径值"（经过该节点的最大路径）只在当前节点有意义，父节点不需要这个信息。两种信息不同，不能用同一个返回值同时传递。

**可以用 pair 或自定义结构**：返回 `{单臂值, 经过该节点的最大路径值}`，但这样代码更冗长。使用全局变量（或封装在类的成员变量里）是面试中更简洁的惯用法。

> [!warning] 生产避坑：全局变量的初始值
> - LeetCode 543：`maxDiameter` 初始化为 `0`（路径至少有 0 条边，即单节点路径）
> - LeetCode 124：`maxPathSum` 初始化为 `Integer.MIN_VALUE`（因为节点值可能全为负数，最大路径和可以是负数）
>
> 初始化为 `0` 在 124 中是错误的——当所有节点值都是负数时，`maxPathSum` 会错误地返回 `0`。

### 6.3 重建分治 vs 路径分治的对比

| 维度 | 重建分治（105/106） | 路径分治（543/124） |
|------|-----------------|-----------------|
| 返回值含义 | 当前子树的根节点（TreeNode） | 以当前节点为端点的最优单臂值（数值） |
| 全局状态 | 不需要（答案即根节点） | 需要（全局最优路径无法通过返回值传递） |
| 信息流向 | 自顶向下（根节点的值指导左右子树范围） + 自底向上（构建好的子树） | 自底向上（每个节点汇聚子树信息并更新全局） |
| 关键难点 | 正确计算左右子树的范围下标 | 区分"单臂返回值"和"跨越路径更新值" |

### 8.1 前序 + 后序重建：答案不唯一的分治（LeetCode 889）

在第 2 章与第 3 章中，"前序 + 中序"与"中序 + 后序"都能唯一确定一棵二叉树。但如果只给你**前序 + 后序**（**LeetCode 889：根据前序和后序遍历构造二叉树**），答案就不再唯一了：
- 前序的第一个元素是根 `root`，第二个元素是**左子树的根**（若左子树非空）；
- 后序的最后一个元素是根 `root`，倒数第二个元素是**左子树的最后一个节点**；
- 我们用**左子树根在前序中的第二个元素**去后序中定位，即可切出左子树的规模。

为什么答案不唯一？考虑只有一个孩子的节点：这个孩子既可以是左孩子也可以是右孩子，两种前序/后序序列完全相同。因此题目通常约定"返回任意一个合法答案即可"。

```go
package main

// constructFromPrePost LeetCode 889：前序+后序重建（答案不唯一，任取其一）
// 时间复杂度：O(n^2)（哈希优化后 O(n)），空间复杂度：O(n)
func constructFromPrePost(preorder []int, postorder []int) *TreeNode {
	if len(preorder) == 0 {
		return nil
	}
	root := &TreeNode{Val: preorder[0]}
	if len(preorder) == 1 {
		return root
	}

	// 左子树的根是前序第二个元素，在后序中定位它
	leftRootVal := preorder[1]
	leftSize := 0
	for i, v := range postorder {
		if v == leftRootVal {
			leftSize = i + 1
			break
		}
	}

	root.Left = constructFromPrePost(preorder[1:1+leftSize], postorder[:leftSize])
	root.Right = constructFromPrePost(preorder[1+leftSize:], postorder[leftSize:len(postorder)-1])
	return root
}
```

### 8.2 最大二叉树：区间分治的另一种切口（LeetCode 654）

**题目描述**：给定一个不含重复元素的整数数组 `nums`。最大二叉树定义如下：根是数组中的**最大值**；左子树是数组中**最大值左边部分**构造出的最大二叉树；右子树是数组中**最大值右边部分**构造出的最大二叉树。

这道题的分治切口从"遍历序列的首尾"换成了"区间最大值的位置"：
- 用**单调递减栈**可以在 $O(n)$ 时间内找到每个元素的"左侧第一个更大元素"与"右侧第一个更大元素"，从而直接确定每个节点的父子关系（每个元素最终会成为"左右第一个更大元素中较小者"的孩子）；
- 朴素分治实现为 $O(n^2)$（每层线性扫描找最大值），配合 **RMQ（区间最值查询，Sparse Table 预处理 $O(n \log n)$、查询 $O(1)$）**可优化到 $O(n \log n)$。

### 8.3 前序遍历构造 BST：利用 BST 有序性免掉中序（LeetCode 1008）

**题目描述**：给定一棵二叉搜索树的**前序遍历**结果，请你重建二叉搜索树。

与第 2 章"前序 + 中序"不同，这里只有前序一个序列。但 BST 的**有序性**替我们补上了中序信息：
- 前序第一个元素是根 `root`；
- 在剩余元素中，**所有小于 `root` 的连续前缀属于左子树**，其余属于右子树（利用 BST 的值域性质 + 前序的连续性）；
- 用**二分查找 `upperBound`** 定位第一个大于 `root` 的下标，即可 $O(\log n)$ 切分（配合单调栈可做到 $O(n)$）：

```go
package main

import "sort"

// bstFromPreorder LeetCode 1008：仅凭前序遍历重建 BST（利用值域有序性二分切分）
// 时间复杂度：O(n log n)，空间复杂度：O(n)
func bstFromPreorder(preorder []int) *TreeNode {
	if len(preorder) == 0 {
		return nil
	}
	root := &TreeNode{Val: preorder[0]}
	// 在 preorder[1:] 中找第一个 > root.Val 的位置（upperBound）
	split := sort.Search(len(preorder), func(i int) bool {
		return i > 0 && preorder[i] > root.Val
	})
	if split == 0 {
		split = len(preorder)
	}
	root.Left = bstFromPreorder(preorder[1:split])
	root.Right = bstFromPreorder(preorder[split:])
	return root
}
```

### 8.5 延伸实战：最大二叉树的单调栈 $O(n)$ 实现

在第 8.2 节我们提到 **LeetCode 654（最大二叉树）** 可以用单调栈在 $O(n)$ 时间内解决。其核心洞察是：每个元素最终会成为"它左侧第一个更大元素"与"它右侧第一个更大元素"中**较小者**的孩子——这与《栈与队列》专栏的单调栈"下一个更大元素"范式完全同源：

```go
package main

type btnode struct {
	Val                 int
	Left, Right, Parent *btnode
}

// constructMaximumBinaryTree LeetCode 654：单调递减栈 O(n) 构建最大二叉树
func constructMaximumBinaryTree(nums []int) *btnode {
	var stack []*btnode // 单调递减栈：栈底到栈顶值递减

	for _, v := range nums {
		node := &btnode{Val: v}
		// 弹出所有比 v 小的节点，它们成为 node 的左孩子（最后一个弹出的最靠右）
		for len(stack) > 0 && stack[len(stack)-1].Val < v {
			node.Left = stack[len(stack)-1]
			stack[len(stack)-1].Parent = node
			stack = stack[:len(stack)-1]
		}
		// 若栈非空，node 成为栈顶（第一个更大元素）的右孩子
		if len(stack) > 0 {
			stack[len(stack)-1].Right = node
			node.Parent = stack[len(stack)-1]
		}
		stack = append(stack, node)
	}

	// 栈底元素即全局最大值，为根节点
	return stack[0]
}
```

### 8.7 延伸实战：最大二叉树（LC 654）的单调栈 O(n) 实现

在第 8.2 节我们提到最大二叉树可以用单调栈在 $O(n)$ 时间内构建。下面补齐完整实现：

```go
package main

type btnode struct {
	Val                 int
	Left, Right, Parent *btnode
}

// constructMaximumBinaryTree LeetCode 654：单调递减栈 O(n) 构建最大二叉树
func constructMaximumBinaryTree(nums []int) *btnode {
	var stack []*btnode // 单调递减栈：栈底到栈顶值递减

	for _, v := range nums {
		node := &btnode{Val: v}
		// 弹出所有比 v 小的节点，它们依次成为 node 的左孩子（最后弹出的最靠右）
		for len(stack) > 0 && stack[len(stack)-1].Val < v {
			node.Left = stack[len(stack)-1]
			stack[len(stack)-1].Parent = node
			stack = stack[:len(stack)-1]
		}
		// 若栈非空，node 成为栈顶（左侧第一个更大元素）的右孩子
		if len(stack) > 0 {
			stack[len(stack)-1].Right = node
			node.Parent = stack[len(stack)-1]
		}
		stack = append(stack, node)
	}
	return stack[0] // 栈底元素即全局最大值，为根节点
}
```

这个单调栈解法的正确性根基，正是本章第 8.2 节的分治洞察：**每个元素的父节点，必然是它左侧第一个更大元素与右侧第一个更大元素中较小者**。单调栈在从左往右扫描时，恰好同时维护了"左侧第一个更大元素"（栈中保留的元素）与"右侧第一个更大元素"（即将入栈的更大值），从而把 $O(n^2)$ 的朴素分治（每层线性扫描找最大值）压缩到每个元素至多入栈出栈一次的 $O(n)$。这与《栈与队列》专栏第 04–05 篇的"下一个更大元素"范式完全同源，是分治与单调栈两大范式的完美交汇点。


### 8.8 重建与路径分治的终检对照

把本章七道题的选型浓缩为终检对照：前序+中序与中序+后序重建答案唯一，用哈希表 $O(1)$ 定位根；前序+后序重建答案不唯一（单孩子节点左右不定），需哈希定位左子树规模；仅凭前序构造 BST，利用值域有序性二分切分；最大二叉树用单调栈 $O(n)$ 构建（每个元素的父节点是左右第一个更大元素中较小者）。路径分治方面，直径与最大路径和共享"单臂向上汇报、拐点合并更新全局"的模板，区别仅在于 543 的单臂恒为正（边数）而 124 的单臂需与 0 取 max（节点值可为负）。这七道题共同构成了二叉树分治的完整作战地图。

### 8.9 重建分治的哈希优化与终检

重建分治的朴素实现每层线性扫描中序定位根，总耗时 $O(n^2)$；用哈希表把"值到中序下标"的映射预构建后，定位降为 $O(1)$，总耗时 $O(n)$。终检对照：前序+中序与中序+后序重建答案唯一（哈希定位 $O(n)$）；前序+后序重建答案不唯一（单孩子节点左右不定，需哈希定位左子树规模）；仅凭前序构造 BST 利用值域有序性二分切分（$O(n \log n)$，单调栈可至 $O(n)$）；最大二叉树用单调栈 $O(n)$ 构建。路径分治方面，543 与 124 共享"单臂向上汇报、拐点合并更新全局"模板，区别仅在 124 的单臂需与 0 取 max（节点值可为负）。

### 8.10 树形分治的终检与工程映射

把本章七道题的终检浓缩为一张对照：重建分治（105/106/889/1008/654）的信息流向是"自顶向下的范围切分 + 自底向上的子树拼接"，关键难点是正确计算左右子树的范围下标；路径分治（543/124）的信息流向是"自底向上的单臂汇报 + 拐点处的全局更新"，关键难点是区分"单臂返回值"与"跨越路径更新值"。在工程系统中，重建分治对应序列化协议的树形结构还原（如 JSON 到 AST 的解析），路径分治对应依赖图的关键路径分析（如构建系统的最长依赖链）——树形分治因此是编译器、构建系统与序列化框架的公共底座。
## 小结

1. **树的递归结构天然适合分治**：根节点是天然的"分割点"，左右子树是完全独立的子问题，合并在根节点处进行。

2. **重建分治的核心：用中序序列确定左右子树范围**：先序/后序告诉你根在哪里，中序告诉你左右子树各包含哪些节点。用哈希表加速查找，将 $O(n^2)$ 降到 $O(n)$。

3. **路径分治的核心：区分"单臂值"和"跨越路径值"**：每个节点递归时需要向父节点报告"单臂值"（用于父节点计算自己的单臂值），同时在本地计算"跨越路径值"（用于更新全局最大）。这是树上路径类问题的通用框架。

4. **负数节点值的处理**：对于 LeetCode 124，当左/右子树的单臂贡献为负时，应取 0（不延伸该方向），而不是强行加入负值。`Math.max(0, gain)` 是处理可选延伸的标准写法。

5. **不要以为直径或最优路径一定经过根节点**：最优路径的最高点可以是任意节点，这是为什么我们需要对每个节点都计算并更新全局最大值，而不是只处理根节点。
