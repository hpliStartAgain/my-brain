# 二叉搜索树的数量与生成：Unique BST I-II

**摘要：**

本篇从"验证已有的 BST"切换到"枚举所有可能的 BST"——这是二叉树专题第一次明显进入动态规划与分治生成。LeetCode 96（不同的二叉搜索树）问的是"给定 `n`，有多少种结构不同的 BST"，答案是著名的 **Catalan 数**；LeetCode 95（不同的二叉搜索树 II）进一步要求"把所有合法结构都生成出来"。两道题看似一"计数"一"生成"，内核却是同一个——**选定根节点后，左右子树的取值范围被唯一确定，于是问题被拆成两个独立的子问题**。本文用 Go 语言完整实现，并逐层追问：为什么计数是"左右相乘再求和"、为什么 95 的递归里空区间要返回一个 `nil`、以及 Catalan 数为什么在"树结构计数"里反复出现。掌握"选根"这一统一视角，你就抓住了这两道题的全部。

---

## 第 1 章 统一视角：一切从"选根"开始

### 1.1 选根之后，左右子树的取值范围就定了

对一棵以 `1..n` 为节点的 BST，**关键洞察是：一旦选定了根节点 `i`，左右子树能用的值就唯一确定了**——左子树只能用 `1..i-1`，右子树只能用 `i+1..n`。这是因为 BST 的"左小右大"约束，恰好把取值范围按根的值切成了两段。

**于是问题被拆成了两个"互不重叠、互相独立"的子问题**：以 `1..i-1` 能构造多少棵 BST？以 `i+1..n` 能构造多少棵？两者组合起来，就是"以 `i` 为根"的全部 BST。

**"选根"这一视角，是 96 与 95 共同的起点。** 记住它，两道题就都成了一道题。

### 1.2 为什么子树之间"独立"

有人会担心："左子树和右子树会不会相互影响？"**不会。** 因为左子树的所有值都小于根、右子树的所有值都大于根，**两组值被根完全隔开，互不干扰。** 所以"以 `i` 为根的 BST 数量"就是"左子树数量 × 右子树数量"——**乘法，因为左右的选择是独立的。**

**这个"独立 → 相乘"的判断，是动态规划里一条反复出现的规律**：互斥的方案用加法，独立的方案用乘法。**它也是 Catalan 数递推式的来源。**

## 第 2 章 LeetCode 96：不同的二叉搜索树（计数）

### 2.1 题目

**LeetCode 96 - Unique Binary Search Trees**（中等）

给你一个整数 `n`，求恰由 `n` 个节点组成、且节点值从 `1` 到 `n` 互不相同的二叉搜索树有多少种。

```text
输入: n = 3  →  输出: 5
```

### 2.2 状态与转移

定义 `dp[i]` 为"由 `i` 个节点能组成的 BST 数量"。选根后，若左子树有 `j-1` 个节点、右子树有 `i-j` 个节点，则：

$$dp[i] = \sum_{j=1}^{i} dp[j-1] \times dp[i-j]$$

**注意这里是"先乘后加"**：对每个根 `j`，左右组合数是乘法；对所有根 `j` 求和是加法。**这个"先乘后加"的结构，正是 Catalan 数的递推式。**

```go
func numTrees(n int) int {
    dp := make([]int, n+1)
    dp[0], dp[1] = 1, 1 // 空树算 1 种
    for i := 2; i <= n; i++ {
        for j := 1; j <= i; j++ {
            dp[i] += dp[j-1] * dp[i-j] // 左 j-1 个、右 i-j 个
        }
    }
    return dp[n]
}
```

**复杂度**：时间 $O(n^2)$，空间 $O(n)$。

### 2.3 Catalan 数：为什么它总在"结构计数"里出现

上面这个递推式 `dp[i] = Σ dp[j-1] * dp[i-j]`，正是 **Catalan 数**的递推定义（$C_0 = 1$）。它的通项是：

$$C_n = \frac{1}{n+1}\binom{2n}{n}$$

**Catalan 数在"结构计数"类问题里反复出现**，例如：$n$ 对括号的合法组合数、$n$ 个节点的 BST 数量、$n$ 个节点的满二叉树数量、凸多边形三角划分数……**它们共享同一个"递推结构"：把一个问题拆成"左半 + 右半"两个独立部分，再求和。** 这也解释了为什么"选根"这一视角如此通用——**凡是能被"选一个分割点、左右独立"的方式拆解的结构，其计数往往就是 Catalan 数。**

> [!info] 从"计数"到"通项"：一条可选的优化
> 递推式需要 $O(n^2)$ 时间。若用 Catalan 数的通项 $C_n = \frac{1}{n+1}\binom{2n}{n}$，可以做到 $O(n)$（配合组合数计算）。**面试中先给递推式（思路清晰）即可；若面试官追问"能否更快"，再提通项。** 但要注意：通项涉及大数，`n` 稍大就会溢出，实际工程里递推式反而更稳。

## 第 3 章 LeetCode 95：不同的二叉搜索树 II（生成）

### 3.1 题目

**LeetCode 95 - Unique Binary Search Trees II**（中等）

给你一个整数 `n`，请生成并返回所有由 `n` 个节点组成、且节点值从 `1` 到 `n` 互不相同的不同二叉搜索树。

```text
输入: n = 3  →  输出 5 棵 BST
```

### 3.2 从"计数"到"生成"：返回一组树

第 96 题返回"有多少种"，第 95 题要求"把每一棵都造出来"。**思路完全一致——仍是"选根"，只是"乘法"变成了"笛卡尔积"**：

- 对每个可能的根 `i`，递归生成"左子树的所有可能"与"右子树的所有可能"；
- 然后**把每一个左子树与每一个右子树两两组合**，挂在根 `i` 下。

```go
func generateTrees(n int) []*TreeNode {
    if n == 0 {
        return nil
    }
    var build func(start, end int) []*TreeNode
    build = func(start, end int) []*TreeNode {
        if start > end {
            return []*TreeNode{nil} // 空区间：返回"一棵空树"，供上层组合
        }
        var res []*TreeNode
        for i := start; i <= end; i++ { // 枚举根
            leftTrees := build(start, i-1)
            rightTrees := build(i+1, end)
            // 笛卡尔积：每个左 × 每个右
            for _, l := range leftTrees {
                for _, r := range rightTrees {
                    res = append(res, &TreeNode{Val: i, Left: l, Right: r})
                }
            }
        }
        return res
    }
    return build(1, n)
}
```

### 3.3 为什么空区间要返回 `[]*TreeNode{nil}`

这是本题最容易写错、也最关键的一个细节。**当 `start > end`（区间为空）时，它代表的不是"没有树"，而是"有一棵空树"。** 若返回空切片 `nil`，那么上层"笛卡尔积"的循环就不会执行，**导致"左子树为空"或"右子树为空"的那些合法 BST 被漏掉**。

**用一个 `[]*TreeNode{nil}`（含一个 `nil` 元素的切片）表示"一棵空树"，恰好让笛卡尔积能正常工作**——因为空树也是"一种可能"。**这个"空不是无、而是一种取值"的视角，是递归生成题里极常见的坑**（第 06 篇的"空区间要返回 `nil`"、第 08 篇的"空树是一种合法 BST"都是同一件事）。

> [!warning] 生产避坑：递归的"基准情况"要返回"一个合法结果"，而非"零个结果"
> 在"生成所有结构"的递归里，基准情况（空区间）应当返回**一个合法结果**（空树），而不是**零个结果**（空切片）。**因为空树本身是一种合法结构，它需要参与上层的组合。** 若基准情况返回零个结果，那么"任何一侧为空"的结构都会被静默丢掉——这类 bug 极隐蔽，往往只在特定 `n` 下暴露。

### 3.4 复杂度

时间上，输出的树共有 $C_n$ 棵（Catalan 数），**每棵树的节点数是 $n$，所以仅"输出规模"就是 $O(n \cdot C_n)$**——当 `n = 8` 时，$C_8 = 1430$，输出已相当大。**这提醒我们：生成题的复杂度下界，往往由"输出规模"决定**，任何算法都至少要把答案写出来。

## 第 4 章 两道题的对照与延伸

### 4.1 对照

| 维度 | LC 96 计数 | LC 95 生成 |
|------|-----------|-----------|
| 目标 | 返回数量 | 返回所有树 |
| 核心动作 | 左右数量**相乘**再求和 | 左右树集合**笛卡尔积** |
| 空区间 | `dp[0] = 1`（空树算 1 种） | 返回 `{nil}`（空树是一种可能） |
| 复杂度 | $O(n^2)$ | $O(n \cdot C_n)$ |

**两道题共享同一个"选根"内核**：96 把"组合"抽象成了"计数"，95 则把"组合"具体成了"枚举"。**理解了 96 的递推，95 就只是把"数量相乘"展开成"逐个组合"。**

### 4.2 延伸：所有可能的满二叉树（LeetCode 894）

**题目**：给你一个整数 `n`，返回所有包含 `n` 个节点的满二叉树（每个节点有 0 或 2 个孩子）。

**这道题是 95 的"结构版"**——它没有 BST 的值约束，只枚举"形状"。**选根之后，左右子树节点数之和为 `n-1`（且都为奇数）**，于是：

```go
func allPossibleFBT(n int) []*TreeNode {
    if n%2 == 0 {
        return nil // 偶数个节点无法构成满二叉树
    }
    if n == 1 {
        return []*TreeNode{{Val: 0}}
    }
    var res []*TreeNode
    for left := 1; left < n; left += 2 { // 左子树节点数必须为奇数
        for _, l := range allPossibleFBT(left) {
            for _, r := range allPossibleFBT(n - 1 - left) {
                res = append(res, &TreeNode{Val: 0, Left: l, Right: r})
            }
        }
    }
    return res
}
```

**这道题与 95 的对照很有价值**：95 里"根选哪个值"决定了左右子树的**取值范围**（值约束），894 里"左子树几个节点"决定了左右子树的**节点数分配**（结构约束）。**两者都是"选一个分割点、左右独立"——这正是 Catalan 结构的共同形态。**

### 4.3 一个统一的观察

96、95、894 三道题，可以统一成一句话：**"把 `n` 个节点的结构，按'左半 + 根 + 右半'拆开，左右独立。"** 它们的差别，只在"拆的依据"：96/95 按"根的值"，894 按"左子树的节点数"。**抓住这个统一形态，你面对任何"结构计数/生成"题，都能先问一句"按什么拆、拆完是否独立"。**

## 第 5 章 Catalan 数：一个反复出现的计数模型

第 2.3 节提到"Catalan 数总在结构计数里出现"。本章把这个模型展开，让你在别的题里也能认出它。

### 5.1 Catalan 数的递推与通项

$$C_0 = 1,\quad C_n = \sum_{i=1}^{n} C_{i-1} \cdot C_{n-i},\quad C_n = \frac{1}{n+1}\binom{2n}{n}$$

前几项是：$1, 1, 2, 5, 14, 42, 132, \dots$。**递推式里的 `C_{i-1} * C_{n-i}` 与求和，正是"选一个分割点、左右独立、再合并"的数学表达。** 只要能把自己的问题套进这个形状，答案就是 Catalan 数。

### 5.2 四个"看起来无关、实为同源"的问题

**问题一，$n$ 对括号的合法组合数。** 一个合法括号串，必可写成 `( A ) B` 的形式，其中 `A` 与 `B` 都是合法括号串——**`A` 用掉 `i-1` 对、`B` 用掉 `n-i` 对，两者独立，于是计数正是 `C_{i-1} * C_{n-i}` 的求和。** 这与 BST 的"左子树 + 右子树"结构完全一致。

**问题二，$n$ 个节点的 BST 数量。** 就是本篇的主题，选根后左右独立。

**问题三，$n$ 个节点的满二叉树数量。** 与 894 题同源：选根后左右子树的节点数之和为 `n-1`，独立。

**问题四，凸 $n+2$ 边形的三角划分数。** 固定一条边，选一个顶点与它构成三角形，两侧多边形独立——**同样是"选分割点、左右独立"。**

**这四个问题的答案都是 $C_n$**，因为它们共享同一个"左右独立"的递归结构。**认出 Catalan 数，本质上就是认出"这个问题能不能被'选一个分割点、左右独立'地拆开"。**

### 5.3 一个可复用的识别方法

拿到一道"计数/生成"题，按下面的步骤判断它是不是 Catalan 结构：

1. **能不能选一个"分割点"？**（BST 选根、括号选最外层、多边形选一个三角形）；
2. **分割后，左右两部分是否独立？**（BST 的左右子树值域不重叠、括号的 `A` 与 `B` 拼接独立）；
3. **问题的规模是否由"左右规模之和"决定？**（`i-1 + (n-i) = n-1`）。

**三问都"是"，答案大概率就是 Catalan 数。** 这套识别方法，比记住"哪些题是 Catalan"更有用——**它让你能判断一道新题是不是。**

> [!note] 从"记住结论"到"识别结构"
> 很多人学 Catalan 数，是"记住'括号生成和 BST 计数都是 Catalan'"。**但这只能应付见过的题。** 真正有用的是"识别结构"——**当你能一眼看出"这题能按'选分割点、左右独立'拆开"时，你就不再依赖记忆。** 这正是本专栏反复强调的：**掌握"为什么"，比记住"是什么"更有价值。**

## 第 6 章 常见误区与自测方法

### 5.1 四个高频误区

**误区一：96 题忘了 `dp[0] = 1`。** 空树算一种结构，否则递推会全为 0。

**误区二：95 题空区间返回空切片。** 会丢掉"一侧为空"的合法结构，必须返回 `{nil}`。

**误区三：把"先乘后加"写反。** 左右是独立选择（乘法），不同根是互斥方案（加法）。

**误区四：894 题没排除偶数节点。** 满二叉树的节点数必为奇数，偶数直接返回空。

### 5.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `n = 0` | 边界（96 返回 1，95 返回空） |
| `n = 1` | 最简（1 种） |
| `n = 2` | 2 种 |
| `n = 3` | 5 种（Catalan 数 $C_3$） |
| `n = 4` | 14 种 |

**其中 `n = 0` 与 `n = 1` 最值得测**——它们分别检验"空树算不算一种"与"最简结构"，是递推基准情况正确性的照妖镜。**凡是结构计数题，先用 `n = 0, 1, 2` 手算一遍，验证基准与递推。**

## 第 7 章 生成题的复杂度与验证

### 7.1 复杂度由输出规模决定

第 3.4 节提过：生成题的复杂度下界是"输出规模"。对 95 题，输出是 $C_n$ 棵、每棵 $n$ 个节点的树，**所以仅"把答案写出来"就要 $O(n \cdot C_n)$。**

**这是一个容易被忽视的复杂度视角——"输出敏感"（output-sensitive）。** 很多人看到"生成所有结构"就以为算法低效，其实**任何算法都至少要把答案写出来，因此"输出规模"就是无法突破的下界。** 判断一个生成算法是否"足够好"，标准是"它是否只比输出规模多花了一个常数/多项式因子"，而不是"它是不是线性"。

**$C_n$ 的增长极快**：$C_8 = 1430$、$C_{10} = 16796$、$C_{15} \approx 9.7 \times 10^6$。**所以生成题的实际可行规模很小**——这也是为什么 LeetCode 上 95 题的 `n` 上限只有 8。**理解了"输出爆炸"，你就明白为什么这类题的规模上界如此保守。**

### 7.2 如何验证生成题

生成题的验证，比计数题更难——因为你不能只对"个数"，还要对"每一棵都合法、且互不重复"。三个验证维度：

**维度一，个数对不对。** 生成结果的数量应当等于 $C_n$（或题面给定的数量）。**个数错了，说明基准情况或笛卡尔积有问题。**

**维度二，每棵是否合法 BST。** 对每棵生成的树，跑一次 Validate BST（第 06 篇）即可。**这一步能抓住"根值选错""左右挂反"这类错误。**

**维度三，有没有重复。** 用"树的序列化字符串"（第 01 篇）作为指纹，放进一个集合，检查有没有重复。**这一步能抓住"基准情况返回 `{nil}` 时处理不当"导致的重复或遗漏。**

**这三个维度，恰好对应生成题的三类 bug：数量错、结构错、重复/遗漏。**

### 7.3 一个实用的调试顺序

生成题调试，建议按"先验个数、再验结构、最后验去重"的顺序：

1. **先用 `n = 1, 2, 3` 手算个数**——确认基准与递推；
2. **再用一个 Validate BST 检查每棵树**——确认结构；
3. **最后用集合去重**——确认没有重复。

**"先验个数"最重要**——因为个数错了，说明问题出在"递归的骨架"（基准或组合），而不在"细节"。**先用最简单的方式定位"哪一层出了问题"，比逐棵树 debug 高效得多。**

> [!note] 生成题与"输出敏感"的普遍性
> "输出敏感"不只出现在生成题里——**排序问题（输出是 $n$ 个数的排列）、图的所有路径、字符串的所有子序列，都属于这一类。** 它们的共同点是"答案本身很大"，因此复杂度下界由输出规模决定。**面试中若能主动指出"这道题的复杂度下界是输出规模"，会显得你对复杂度有更深的理解。**

### 7.4 从"计数"到"生成"：一个通用的对照

96（计数）与 95（生成）的对照，可以推广成一条通用经验：

| 目标 | 核心动作 | 复杂度 |
|------|---------|--------|
| 计数 | 子问题结果**相乘再求和** | 多项式 |
| 生成 | 子问题结果**做笛卡尔积** | 输出敏感 |

**"计数"是把组合抽象成数字，"生成"是把数字展开成组合。** 很多问题都有这两副面孔（如"有多少种走法"vs"列出所有走法"），**它们的递推结构相同，只是"运算"从乘法变成了笛卡尔积。** 理解了这一对照，你面对"计数/生成"的姊妹题时，就能直接迁移思路。

## 第 8 章 分治、动态规划与记忆化：三种视角看同一题

96 题可以用三种视角来理解——**分治、动态规划、记忆化搜索**。理清它们的关系，能帮你看清"这些方法其实是一回事"。

### 8.1 分治视角

**分治视角**：`numTrees(n)` 的问题，被拆成"选根 `i`、左子树 `i-1` 个、右子树 `n-i` 个"——**这是标准的"分而治之"**。分治的三步是"分解、解决、合并"：分解成左右子问题、递归解决、把结果相乘再求和。

### 8.2 动态规划视角

**动态规划视角**：注意到"左子树 `i-1` 个"与"右子树 `n-i` 个"这两个子问题**会被反复用到**（不同的根对应不同的 `(i-1, n-i)` 组合，但很多组合重复）。于是**自底向上**地算 `dp[0..n]`，避免重复计算。

**分治与 DP 的区别，就在"是否重复子问题"**：分治不关心重复（它假设子问题独立），DP 专门利用重复（它把子问题的解缓存起来）。**96 题之所以是 DP，正是因为它有大量重复子问题**——例如 `numTrees(3)` 会用到 `numTrees(2)` 两次。

### 8.3 记忆化搜索视角

**记忆化搜索**：**写成递归（分治的形式），但用一个数组缓存算过的结果**——这是"分治 + 缓存"，本质上等价于 DP。

```go
func numTreesMemo(n int) int {
    memo := make([]int, n+1)
    var count func(k int) int
    count = func(k int) int {
        if k <= 1 {
            return 1
        }
        if memo[k] != 0 {
            return memo[k] // 命中缓存
        }
        total := 0
        for i := 1; i <= k; i++ {
            total += count(i-1) * count(k-i)
        }
        memo[k] = total
        return total
    }
    return count(n)
}
```

**记忆化搜索与自底向上 DP，是"同一算法的两种写法"**——一个"从大往小递归、顺带缓存"，一个"从小往大递推"。**它们的复杂度相同，取舍只在"可读性"与"是否容易写对转移顺序"。**

### 8.4 三种视角的对照

| 视角 | 写法 | 何时用 |
|------|------|--------|
| 分治 | 纯递归，不缓存 | 子问题不重复 |
| 记忆化 | 递归 + 缓存 | 子问题重复，但递归更直观 |
| 动态规划 | 自底向上递推 | 子问题重复，且转移顺序清晰 |

**这张表的落点是"子问题是否重复"**——这是选择分治还是 DP 的分水岭。**而记忆化则是"介于两者之间"的桥梁**：它保留了分治的递归形式，又获得了 DP 的效率。

> [!info] 分治、DP、记忆化：一个统一的理解
> 很多人把它们当成"三种不同的方法"，其实**它们是同一件事的三个侧面**：
> - **分治**是"思想"（把问题拆成子问题）；
> - **记忆化**是"分治 + 缓存"（避免重复）；
> - **动态规划**是"记忆化的自底向上版"（把递归改成递推）。
>
> **理解了这层关系，你就不会再纠结"这道题是分治还是 DP"——因为答案往往是"都是"。** 真正要问的是"子问题重不重复"，而不是"它属于哪个标签"。

### 8.5 面试追问

**追问一："96 题为什么是 DP 而不是纯分治？"** 答：因为有大量重复子问题（`numTrees(k)` 被反复调用），DP 能缓存它们。

**追问二："95 题能用 DP 吗？"** 答：生成题的"子问题结果"是一组树而非一个数字，缓存它们意义不大（且内存爆炸），所以用"分治 + 记忆化"反而不划算——**直接分治更合适。**

**追问三："Catalan 数还有别求法吗？"** 答：可以用通项公式 $C_n = \frac{1}{n+1}\binom{2n}{n}$，时间 $O(n)$，但涉及大数，`n` 稍大就溢出。

**追问四："为什么生成题（95）的规模上界这么小？"** 答：因为输出规模是 $C_n$（指数增长），`n=8` 时已有 1430 棵，`n` 再大输出就爆炸了。

**追问五："95 题的空区间为什么返回 `{nil}`？"** 答：因为空树是一种合法结构，需要参与上层的笛卡尔积组合；返回空切片会导致"一侧为空"的结构被漏掉。

### 8.6 一个跨专题的落点

**"分治、DP、记忆化是同一件事"这一理解，是跨专题的**——它连接了本专栏（树形结构）与"动态规划专栏""分治与贪心专栏"。**理解了它，你会发现：树形 DP、区间 DP、线性 DP，本质上都是"把问题拆成子问题、用子问题的解组合出大问题的解"。** 区别只在"子问题的形态"（左右子树 / 区间 / 前缀）与"是否重复"。**这，正是本专栏留给你的、可以迁移到整个算法体系的思维方式。**

## 第 9 章 生成题的自查清单与落点

### 9.1 一份自查清单

| 检查项 | 对应问题 |
|--------|---------|
| `dp[0] = 1`（空树算一种） | 递推全为 0 |
| 95 空区间返回 `{nil}` | 漏掉"一侧为空" |
| "先乘后加"（左右乘、根加） | 组合逻辑 |
| 894 排除偶数节点 | 满二叉树节点数为奇 |
| 生成题的规模上界 | 输出爆炸 |
| 是否用了笛卡尔积（而非简单拼接） | 漏组合 |

### 9.2 落点

**生成专题的落点，是"选根视角"与"左右独立"**——**选根后左右取值范围唯一确定、互不干扰，于是"计数用乘法、生成用笛卡尔积"。** 这个视角把 96、95、894 统一成了一件事。

**而更深一层的收获，是"Catalan 结构识别"这一能力**——**凡是能按"选一个分割点、左右独立"拆开的问题，其计数往往就是 Catalan 数**（括号、BST、满二叉树、多边形三角划分）。**能把新题套进这个形状，比记住"哪些题是 Catalan"有用得多。**

> [!info] 一句话带走
> 如果只能带走一句话，那就是：**"选一个分割点、左右独立——这是 Catalan 结构，也是分治生成的全部。"** 括号、BST、满二叉树、多边形划分，都是它的实例。**记住这个形状，你就能一眼判断"这题是不是 Catalan 结构"。**

### 9.3 从"计数"到"组合数学"

**96 题的答案（Catalan 数）来自组合数学**——**这类"结构计数"问题，本质上是"组合数学在数据结构上的应用"。** 除了 Catalan 数，还有 Stirling 数（划分计数）、Fibonacci 数（递推计数）、Bell 数（集合划分计数）等。

**它们的共同点是"用递推关系描述'组合结构'的计数"**——而"递推关系"的形态，恰好对应"结构如何被拆解"。**理解了这一点，你就把"算法里的计数题"与"组合数学"联系了起来**——**很多"看起来要 DP"的计数题，其实是某个已知的组合数。**

**这也是为什么"识别 Catalan 结构"如此重要**——**它能让你用"组合数学的已知结论"，直接跳过"从零推导 DP"。** 在面试里，能认出"这是 Catalan 数"并说出通项，往往是一个漂亮的加分项。

---

### 9.4 一个值得记住的边界

**"空树算不算一种结构"是计数题的第一个分歧点。** 96 题里 `dp[0] = 1`（空树算一种），95 题里空区间返回 `{nil}`（空树是一种可能）。**这个"空也算一种"的约定，正是 Catalan 数从 $C_0 = 1$ 开始的原因。** 若把空当成"零种"，递推就会全为 0。**所以"空是否算一种"，必须在一开始就定清楚。**

**最后补充一点**：生成题的规模上界由"输出规模"决定，面试中若面试官问"`n` 很大怎么办"，正确答案是"生成全部结构本身不可行"，而非"优化算法"——**因为任何算法都至少要把答案写出来。**

**再补充一点**：若面试官只要求"统计数量、不生成结构"，就用 96 的递推（$O(n^2)$）；只有要求"生成结构"时才用 95。**分清"计数"与"生成"，是这类题的第一步。** 本题的 96 是计数、95 是生成——**同一个"选根"内核，两种不同的输出。** 计数把组合压成一个数字，生成把数字展成一组组合——**它们互为逆操作。**

## 小结

本篇用两道题（加一道延伸）把"BST 计数与生成"讲透。核心只有一个视角——**选根之后，左右子树的取值范围（或节点数）被唯一确定，问题拆成两个独立的子问题**。计数题（96）把"独立组合"抽象成"相乘再求和"，得到 Catalan 数；生成题（95）把它具体成"笛卡尔积"，并用"空区间返回 `{nil}`"这一细节保证不漏结构；延伸题（894）则把"按值拆"换成"按节点数拆"，展示同一形态的另一副面孔。

贯穿全篇的核心认知有两条。其一，**"选一个分割点、左右独立"是 Catalan 结构的共同形态**——凡是能这样拆的结构，其计数往往就是 Catalan 数。其二，**递归生成题的基准情况要返回"一个合法结果"而非"零个结果"**——空树也是一种可能，漏掉它就会静默丢解。**把这两条握住，你面对任何"枚举所有结构"的题，都有了拆解与验证的起点。**

下一篇 [[08 有序序列转平衡搜索树：数组与链表两种输入]] 会把视角从"枚举结构"切到"构造特定结构"——有序数组转平衡 BST 看似简单，真正值得讲的是"为什么取中点能保证平衡"；而有序链表转 BST 的难点，在于链表不支持随机访问。
