# 二叉树重建：前序+中序、后序+中序的构造逻辑

## 摘要

二叉树重建题是遍历专题之后最自然的进阶。LeetCode 105 和 106 表面上只是输入两组遍历数组，输出一棵树，真正考察的是你是否理解：根节点在不同遍历中的位置决定了“谁先确定根”，而中序遍历决定了“左子树和右子树的边界在哪里”。本文会系统讲清楚为什么没有中序就很难唯一重建，为什么数组切片思路容易写乱，以及如何用区间下标和哈希表把复杂度压到 $O(n)$。

---

## 第 1 章 为什么重建必须依赖中序

### 1.1 前序和后序各自告诉了什么

- 前序：根、左、右，意味着第一个元素一定是根
- 后序：左、右、根，意味着最后一个元素一定是根
- 中序：左、根、右，意味着根节点左边全属于左子树，右边全属于右子树

也就是说：

- 前序或后序负责“找到根”
- 中序负责“切分左右子树范围”

如果没有中序，你只能知道根是谁，却很难知道左子树到底有多大。

### 1.2 为什么“前序 + 后序”通常不能唯一确定

举一个最简单的反例：

```text
前序: [1,2]
后序: [2,1]
```

这既可能是：

```text
  1
 /
2
```

也可能是：

```text
1
 \
  2
```

根和孩子都能对上，但结构不唯一。这说明中序在“左右边界判定”中不可替代。

## 第 2 章 LeetCode 105：前序 + 中序构造

### 2.1 递归切分逻辑

前序第一个元素一定是根。设 `preorder[preLeft]` 是当前根值，在中序里找到它的位置 `index` 后：

- `inLeft .. index - 1` 是左子树
- `index + 1 .. inRight` 是右子树

左子树节点数是：`leftSize = index - inLeft`

于是前序区间也能对应切开：

- 左子树前序区间：`preLeft + 1 .. preLeft + leftSize`
- 右子树前序区间：`preLeft + leftSize + 1 .. preRight`

### 2.2 代码实现

```java
public TreeNode buildTree(int[] preorder, int[] inorder) {
    Map<Integer, Integer> indexMap = new HashMap<>();
    for (int i = 0; i < inorder.length; i++) {
        indexMap.put(inorder[i], i);
    }
    return build(preorder, 0, preorder.length - 1,
                 inorder, 0, inorder.length - 1,
                 indexMap);
}

private TreeNode build(int[] preorder, int preLeft, int preRight,
                       int[] inorder, int inLeft, int inRight,
                       Map<Integer, Integer> indexMap) {
    if (preLeft > preRight) {
        return null;
    }

    int rootVal = preorder[preLeft];
    TreeNode root = new TreeNode(rootVal);
    int index = indexMap.get(rootVal);
    int leftSize = index - inLeft;

    root.left = build(preorder, preLeft + 1, preLeft + leftSize,
                      inorder, inLeft, index - 1, indexMap);
    root.right = build(preorder, preLeft + leftSize + 1, preRight,
                       inorder, index + 1, inRight, indexMap);
    return root;
}
```

### 2.3 为什么不要直接切数组

很多人会写成 `Arrays.copyOfRange` 来切子数组。这样逻辑看起来直观，但每层递归都复制数组，时间和空间都会恶化。对构造题来说，**传区间边界而不是传切片数组** 是更稳的工程写法。

## 第 3 章 LeetCode 106：中序 + 后序构造

### 3.1 与 105 的差异只在根的位置

后序的最后一个元素才是根，所以当前根值是 `postorder[postRight]`。拿到中序里的位置 `index` 后：

- 左子树大小仍然是 `leftSize = index - inLeft`
- 右子树大小是 `rightSize = inRight - index`

于是后序区间可以这样切：

- 左子树后序区间：`postLeft .. postLeft + leftSize - 1`
- 右子树后序区间：`postLeft + leftSize .. postRight - 1`

### 3.2 代码实现

```java
public TreeNode buildTree(int[] inorder, int[] postorder) {
    Map<Integer, Integer> indexMap = new HashMap<>();
    for (int i = 0; i < inorder.length; i++) {
        indexMap.put(inorder[i], i);
    }
    return build(inorder, 0, inorder.length - 1,
                 postorder, 0, postorder.length - 1,
                 indexMap);
}

private TreeNode build(int[] inorder, int inLeft, int inRight,
                       int[] postorder, int postLeft, int postRight,
                       Map<Integer, Integer> indexMap) {
    if (inLeft > inRight) {
        return null;
    }

    int rootVal = postorder[postRight];
    TreeNode root = new TreeNode(rootVal);
    int index = indexMap.get(rootVal);
    int leftSize = index - inLeft;

    root.left = build(inorder, inLeft, index - 1,
                      postorder, postLeft, postLeft + leftSize - 1,
                      indexMap);
    root.right = build(inorder, index + 1, inRight,
                       postorder, postLeft + leftSize, postRight - 1,
                       indexMap);
    return root;
}
```

### 3.3 容易错的地方

- 左子树区间长度算错一位
- 把后序右子树区间尾部仍然写成 `postRight`
- 递归终止条件写成 `==` 而不是统一的 `>`

这类题最稳的方式不是背公式，而是每次都明确“当前根占掉一个位置，左子树大小是多少”。

## 第 4 章 两道题的统一抽象

| 题目 | 根节点位置 | 中序作用 | 关键公式 |
|------|------------|----------|----------|
| 105 | 前序头部 | 划分左右区间 | `leftSize = index - inLeft` |
| 106 | 后序尾部 | 划分左右区间 | `leftSize = index - inLeft` |

你会发现真正没变的是中序的边界作用，变的只是“根从哪里拿”。

> [!info] 重建题的核心不是遍历顺序，而是区间映射
> 一旦你能把“当前根值 -> 中序切分点 -> 左右子树长度 -> 另一个数组中的对应区间”这条链条说完整，代码基本不会出错。
