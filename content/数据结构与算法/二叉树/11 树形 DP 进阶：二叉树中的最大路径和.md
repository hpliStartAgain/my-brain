# 树形 DP 进阶：二叉树中的最大路径和

**摘要：**

LeetCode 124（二叉树中的最大路径和）是本专栏的收束，也是树形 DP 的标准难题。它训练的是树题里最关键、也最容易混淆的一层抽象——**区分"对父节点可贡献的值"与"当前节点作为路径拐点时的最优值"**。前者必须"只能选一边"（因为路径经过父节点后只能往一个方向延伸），后者则"两边都可以要"（因为拐点是路径的最高点）。**只要把这两类值混在一起，代码就一定错。** 本文用 Go 语言完整实现这道题，逐行解释"为什么要 `max(0, ...)`""为什么返回值只能取一边""为什么全局答案要用外部变量"，并延伸出 LC687（最长同值路径）这一同构变体。作为专栏收束，文末还会把 11 篇的骨架汇总成一张"树题思考框架"，回答"拿到一道树题，我该先想什么"。

## 第 1 章 题目与朴素困难

### 1.1 题目

**LeetCode 124 - Binary Tree Maximum Path Sum**（困难）

路径被定义为一条从树中任意节点出发、沿父节点-子节点连接、达到任意节点的序列。同一个节点在一条路径序列中至多出现一次。路径**至少包含一个节点**，且不一定经过根节点。求路径上各节点值之和的最大值。

```text
输入: root = [1,2,3]        →  输出: 6（路径 2→1→3）
输入: root = [-10,9,20,null,null,15,7]  →  输出: 42（路径 15→20→7）
```

### 1.2 难点在哪

- **路径可能不经过根**（与第 09 篇直径同源）；
- **路径有"形状"**：它可以是一条"直链"（一直向下），也可以是"拐个弯"的（从一个子树上来、经过某节点、再下到另一个子树）；
- **节点值可能为负**，于是"要不要选某段"成了一个决策。

**这三条合起来，让这道题成了树形 DP 的典型。** 要解它，必须先想清"路径在某个节点处有几种走法"。

### 1.3 路径在节点处的两种形态

对任意节点 `node`，一条路径经过它时，只有两种形态：

- **形态 A（拐点）**：路径从 `node` 的左子树上来、经过 `node`、再下到右子树——**`node` 是路径的"最高点"**，左右两边都用到；
- **形态 B（直链）**：路径从 `node` 出发、只向一侧（左或右）延伸——**`node` 是路径的一端**，只用到一边。

**这两种形态，正是"两类值"的来源**：形态 B 对应"对父节点可贡献的值"（父节点只能从这一侧继续往上），形态 A 对应"当前节点作为拐点的最优值"（这是一个可以结算的全局答案）。

## 第 2 章 核心：两类值的区分

### 2.1 定义两类值

- **贡献值 `gain(node)`**：以 `node` 为起点、向下延伸到某一子树的最大路径和——**它是"可以返回给父节点"的值**。因为路径从 `node` 往上经过父节点后，只能选一边继续，所以 `gain(node)` **只能包含一边**。
- **全局答案 `ans`**：所有"以某节点为拐点的路径和"的最大值——**它是"不能返回给父节点、但可以用于结算"的值**。

**关键区别**：`gain` 是"一端"的值（只能选一边），`ans` 是"拐点"的值（两边都要）。

### 2.2 为什么 `gain` 只能选一边

**因为路径是一条"简单路径"——同一个节点至多出现一次。** 若 `gain(node)` 同时包含左右两边，那么当父节点把它接上时，路径就会在 `node` 处"分叉"，而分叉不是一条路径。**所以对父节点可贡献的，只能是"左或右中的一条"。**

### 2.3 为什么 `ans` 要两边都要

**因为当 `node` 作为路径的"最高点"时，路径在它这里"拐弯"——左边上来、右边下去，两边都是路径的一部分。** 此时不需要再往上传，它是一个可以独立结算的完整路径。**所以"拐点值"要把左右都加上。**

## 第 3 章 Go 实现

```go
func maxPathSum(root *TreeNode) int {
    ans := math.MinInt32

    // maxGain 返回"以 node 为起点向下延伸的最大贡献值"
    var maxGain func(node *TreeNode) int
    maxGain = func(node *TreeNode) int {
        if node == nil {
            return 0
        }
        // 负数贡献不如不选（不选即 0），所以用 max(0, ...)
        leftGain := max(0, maxGain(node.Left))
        rightGain := max(0, maxGain(node.Right))

        // 形态 A：以 node 为拐点的路径和（左右都要）
        pathSum := node.Val + leftGain + rightGain
        if pathSum > ans {
            ans = pathSum
        }

        // 形态 B：返回给父节点的贡献值（只能选一边）
        return node.Val + max(leftGain, rightGain)
    }

    maxGain(root)
    return ans
}
```

### 3.1 逐行解释三处关键

**关键一：`max(0, maxGain(...))`。** 若某棵子树的贡献值是负的，那么"接上它"只会让路径和更小——**不如不接**。所以取 `max(0, ...)`，表示"要么接、要么不接"。**这是"节点值可能为负"这一条件下的必然处理。**

**关键二：`ans` 用外部变量累积。** 因为"拐点值"（形态 A）不能作为返回值（父节点不能用它），只能通过外部变量记录全局最大。

**关键三：返回值只能选一边。** `node.Val + max(leftGain, rightGain)`——**这正是"形态 B"的落地：给父节点的贡献，只能是一条直链。**

> [!info] 为什么要用 `math.MinInt32` 初始化
> 因为路径**至少包含一个节点**，而节点值可能全为负。若把 `ans` 初始化为 0，那么"全负的树"会错误地返回 0（相当于"空路径"），而正确结果应是"最大的那个负数"。**用 `math.MinInt32` 初始化，保证第一次结算时一定会被更新。** 这是"边界值"类问题的一个常见陷阱——**初始值必须是一个"任何合法答案都能超过"的值。**

### 3.2 手动验证

以 `root = [-10,9,20,null,null,15,7]` 为例：

```text
节点 9：左右 gain 都为 0，pathSum = 9 + 0 + 0 = 9，ans=9；返回 9 + 0 = 9
节点 15：pathSum = 15，ans=15；返回 15
节点 7：pathSum = 7，ans=15；返回 7
节点 20：leftGain = max(0,15)=15，rightGain = max(0,7)=7
         pathSum = 20 + 15 + 7 = 42，ans=42；返回 20 + max(15,7) = 35
节点 -10：leftGain = max(0,9)=9，rightGain = max(0,35)=35
          pathSum = -10 + 9 + 35 = 34，ans 仍为 42；返回 -10 + max(9,35) = 25

最终 ans = 42 ✓
```

**注意节点 `-10` 处的计算**：它的 `pathSum` 是 34（小于 42），所以 `ans` 不变；但它的**返回值 25 会继续往上贡献**——**这正是"拐点值"与"贡献值"分工的体现**：一个是"结算用的全局答案"，一个是"传递用的局部贡献"。

## 第 4 章 延伸：最长同值路径（LeetCode 687）

### 4.1 题目

**LeetCode 687 - Longest Univalue Path**（中等）

给定一个二叉树的根节点，返回最长的路径的长度，该路径中每个节点具有相同的值。这条路径可以不经过根节点。

### 4.2 同构的骨架

**这道题与最大路径和是同构的**——都是"区分'贡献值'与'拐点值'"：

```go
func longestUnivaluePath(root *TreeNode) int {
    ans := 0
    // arrowLen 返回"以 node 为起点、向下同值延伸的最长长度"
    var arrowLen func(node *TreeNode) int
    arrowLen = func(node *TreeNode) int {
        if node == nil {
            return 0
        }
        leftLen := arrowLen(node.Left)
        rightLen := arrowLen(node.Right)

        leftArrow, rightArrow := 0, 0
        if node.Left != nil && node.Left.Val == node.Val {
            leftArrow = leftLen + 1
        }
        if node.Right != nil && node.Right.Val == node.Val {
            rightArrow = rightLen + 1
        }
        // 拐点值：左右都算
        if leftArrow+rightArrow > ans {
            ans = leftArrow + rightArrow
        }
        // 贡献值：只能选一边
        return max(leftArrow, rightArrow)
    }
    arrowLen(root)
    return ans
}
```

**把这道题与最大路径和并排看，会发现它们的骨架一字不差**——都是"左右各算一个贡献、用拐点更新全局、返回时只选一边"。**差别只在"贡献的规则"**：最大路径和用 `max(0, ...)`（负数不接），最长同值路径用"值相等才接"。**这有力地说明：树形 DP 的难点不在骨架，而在"贡献规则"的定义。**

### 4.3 树形 DP 的通用骨架

把 124、687、543（直径）、110（平衡树）放在一起，可以提炼出树形 DP 的通用骨架：

```text
dfs(node):
    1. 递归左右子树，拿到它们的"贡献值"
    2. 用左右贡献，计算"以 node 为拐点"的答案 → 更新全局 ans
    3. 计算"返回给父节点"的贡献值（通常只能选一边）
    4. 返回该贡献值
```

**这四步，几乎覆盖了所有"需要在树上求全局最优"的问题。** 第 2 步对应"结算"，第 3 步对应"传递"——**把这两件事分开，是树形 DP 的第一原则。**

## 第 5 章 专栏收束：拿到一道树题，先想什么

作为整个二叉树专栏的收束，这里把 11 篇的骨架汇总成一套"思考框架"。拿到任何一道树题，按下面的顺序自问：

**第一问：中间状态是"层"还是"路径"？** 决定用 BFS 还是 DFS（第 02 篇）。
- 层 → BFS（层序、右视图、按层连接）；
- 路径 → DFS（路径总和、最大路径和）。

**第二问：节点在哪个"时机"被处理？** 决定用前序、中序还是后序（第 01 篇）。
- 前序：需要把状态带给子节点（路径、序列化）；
- 中序：需要利用有序性（BST 相关）；
- 后序：需要子树结果汇总（深度、平衡、树形 DP）。

**第三问：函数返回什么、父节点需要什么？** 决定函数语义（第 03、11 篇）。
- 只收集序列 → 返回"无"，用闭包累积；
- 需要子树高度/合法性 → 返回该信息；
- 需要"贡献值" → 返回贡献值，同时用全局变量记录"拐点答案"。

**第四问：需要"全局答案"吗？** 决定是否用外部变量。
- 只求"整棵树的某个量" → 返回值可能就够（如最大深度）；
- 求"任意节点/路径的最优" → 往往需要外部变量（如直径、最大路径和）。

**第五问：有没有特殊约束可以利用？** 决定能否"降维"。
- BST → 中序有序，可降成序列问题（第 06 篇）；
- 完美二叉树 → 结构规整，可省掉队列（第 04 篇）。

**这五问，是本专栏留给你的最持久的工具。** 它们不针对任何具体题目，而是"面对陌生树题时的通用提问方式"。

## 第 6 章 树形 DP 的更多变体：带状态机的 DP

最大路径和（124）与最长同值路径（687）是"贡献值 + 拐点值"这一模式。但树形 DP 还有一个更复杂的变体——**"状态机 DP"**：节点有多个状态，父节点的状态约束子节点的状态。本章用两道题展示它。

### 6.1 打家劫舍 III（LeetCode 337）

**题目**：二叉树上的每个节点有一个"金额"。若两个直接相连的节点都被偷，就会触发警报。求在不触发警报的前提下，能偷到的最大金额。

**思路**：每个节点有两种状态——"偷"或"不偷"，且"偷了当前节点"约束"孩子不能偷"。**让递归返回一对值 `(不偷的最大收益, 偷的最大收益)`：**

```go
func rob(root *TreeNode) int {
    var dfs func(node *TreeNode) (int, int) // 返回 (不偷当前, 偷当前)
    dfs = func(node *TreeNode) (int, int) {
        if node == nil {
            return 0, 0
        }
        lNo, lYes := dfs(node.Left)
        rNo, rYes := dfs(node.Right)
        // 不偷当前：孩子可偷可不偷，各取较大
        no := max(lNo, lYes) + max(rNo, rYes)
        // 偷当前：孩子都不能偷
        yes := node.Val + lNo + rNo
        return no, yes
    }
    no, yes := dfs(root)
    return max(no, yes)
}
```

**这道题与最大路径和的区别在于"返回值是一对而非一个"**——因为父节点需要根据"自己偷不偷"来选择孩子的哪个状态。**这正是"状态机 DP"的特征：返回值承载"当前节点的多个状态"，父节点从中选取合适的那个。** 它推广了最大路径和的"贡献值 vs 拐点值"——**当状态多于两种时，返回值就成了一个状态向量。**

### 6.2 监控二叉树（LeetCode 968）

**题目**：在二叉树上放摄像头，每个摄像头能覆盖它自己、父节点、子节点。求覆盖所有节点所需的最少摄像头数。

**思路**：每个节点有三种状态：`0 = 未覆盖`、`1 = 已覆盖（无摄像头）`、`2 = 有摄像头`。**递归返回当前节点的状态，父节点据此决定是否要放摄像头：**

```go
func minCameraCover(root *TreeNode) int {
    ans := 0
    // 返回节点状态：0 未覆盖，1 已覆盖无摄像头，2 有摄像头
    var dfs func(node *TreeNode) int
    dfs = func(node *TreeNode) int {
        if node == nil {
            return 1 // 空节点视为"已覆盖"，不影响父节点决策
        }
        l := dfs(node.Left)
        r := dfs(node.Right)
        // 任一孩子未覆盖 → 当前必须放摄像头
        if l == 0 || r == 0 {
            ans++
            return 2
        }
        // 任一孩子有摄像头 → 当前已被覆盖
        if l == 2 || r == 2 {
            return 1
        }
        // 孩子都已覆盖但无摄像头 → 当前未覆盖，交给父节点处理
        return 0
    }
    if dfs(root) == 0 { // 根节点仍未覆盖，需再放一个
        ans++
    }
    return ans
}
```

**这道题比打家劫舍更复杂——它是"三状态"的 DP，且"根节点的状态需要单独处理"（因为它没有父节点）。** 它展示了树形 DP 的两个要点：**其一，返回值可以是"多状态"；其二，根节点往往需要额外处理**（因为它是唯一没有父节点的节点）。

### 6.3 树形 DP 的三级台阶

把本篇所有树形 DP 题按"返回值复杂度"排一下，会看到一条清晰的三级台阶：

| 级别 | 返回值 | 代表题 |
|------|--------|--------|
| 一级 | 单个数值 | 最大深度（104） |
| 二级 | 数值 + 全局变量 | 直径（543）、最大路径和（124） |
| 三级 | 多状态向量 | 打家劫舍 III（337）、监控二叉树（968） |

**每上一级，返回值承载的信息就更多、父节点的选择就更复杂。** 但无论哪一级，核心骨架都是那四步——**递归左右 → 用左右更新答案 → 计算返回给父节点的值 → 返回**。**理解了这条台阶，你就有了"从简单到复杂"的树形 DP 学习路径。**

> [!note] 树形 DP 与线性 DP 的对照
> 线性 DP（如爬楼梯、背包）的"状态"是"到了第几步"；树形 DP 的"状态"是"当前节点的某个属性"。**但两者的内核一致——都是"用子问题的最优解，组合出当前问题的最优解"。** 区别只在于：线性 DP 的子问题是"前一步"，树形 DP 的子问题是"左右子树"。**理解了这一点，你会发现"树形 DP"并不神秘——它只是把线性 DP 的"顺序结构"换成了"树形结构"。**

## 第 7 章 常见误区与自测方法

### 6.1 四个高频误区

**误区一：把"贡献值"与"拐点值"混为一谈。** 若返回值也把左右都加上，父节点接上后路径就分叉了，结果必然偏大且错误。

**误区二：忘了 `max(0, ...)`。** 节点值为负时，接上负贡献会让路径和变小，必须"要么接、要么不接"。

**误区三：`ans` 初始化为 0。** 全负的树会错误返回 0，应用 `math.MinInt32`。

**误区四：以为路径一定过根。** 与直径同理，路径可能完全落在某棵子树里。

### 6.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `[1,2,3]` | 经典正例（答案 6） |
| `[-3]` | 全负单节点（答案 -3，检验 `ans` 初始化） |
| `[-2,-1]` | 全负（答案 -1） |
| `[-10,9,20,null,null,15,7]` | 常规复杂例（答案 42） |
| `[2,-1]` | 负数贡献的取舍 |

**其中 `[-3]` 与 `[-2,-1]` 最值得测**——它们专治"`ans` 初始化为 0"这一陷阱。**凡是"至少包含一个节点"的题，都要用"全负输入"验证初始值。**

## 第 8 章 树形 DP 的验证与面试表达

### 8.1 必测的边界：全负输入

**树形 DP 最该测的边界，是"全负输入"**——如 `[-3]`、`[-2,-1]`。**它检验"`ans` 的初始值是否正确"。**

- 若 `ans` 初始化为 0，`[-3]` 会错误返回 0（相当于"空路径"）；
- 正确初始化（`math.MinInt32`）才能返回 `-3`。

**这类"初始值"陷阱，是所有"求最值且值可能为负"的问题的共性**——初始值必须是一个"任何合法答案都能超过"的值，而不能是"一个看起来合理的中性值（如 0）"。

### 8.2 另一个必测点：负数贡献的取舍

**测一个"某侧子树贡献为负"的输入**（如 `[2,-1]`）——检验 `max(0, ...)` 是否生效。**若忘了 `max(0, ...)`，路径会"被迫"接上负贡献，结果偏小。**

**"接还是不接"这一决策，是最大路径和的核心**——它体现了"路径可以只要一部分"这一灵活性。**而 `max(0, ...)` 正是这一灵活性的实现。**

### 8.3 面试表达

树形 DP 的面试表达，建议按这个顺序：

1. **先区分两类值**："这个函数返回'给父节点的贡献值'，同时用全局变量记录'以当前节点为拐点的答案'。"
2. **再讲为什么只能选一边**："因为路径不能分叉，父节点只能用一侧。"
3. **然后讲 `max(0, ...)`**："负数贡献不如不接。"
4. **最后讲初始化**："`ans` 用最小整数初始化，因为路径至少含一个节点。"

**第 1 步是关键**——它表明你理解了"贡献值 vs 拐点值"这一区分。**很多人代码写错，正是因为把这两类值混在了一起。**

### 8.4 专栏收束：树题的五问框架

作为整个专栏的收束，这里把"拿到树题先问什么"的五问再强调一次（第 5 章已详述）：

1. **中间状态是"层"还是"路径"？** → BFS 还是 DFS；
2. **节点在哪个"时机"被处理？** → 前序/中序/后序；
3. **函数返回什么、父节点需要什么？** → 递归语义；
4. **需要"全局答案"吗？** → 是否用外部变量；
5. **有没有特殊约束可利用？** → 能否降维。

**这五问不针对任何具体题，而是面对陌生树题时的通用提问方式。** 它们把 11 篇的内容，压缩成了一套"思考流程"——**从"记题型"到"有流程"，这正是本专栏想帮你完成的转变。**

> [!info] 从"解题"到"有一套解题流程"
> 学完一个专题，最有价值的收获不是"会解 N 道题"，而是"**有了一套面对陌生题的流程**"。**题是会变的，流程是可以迁移的。** 二叉树专栏的"五问框架"，就是这样一个流程——它让你在遇到没见过的树题时，不是"回忆类似题"，而是"按流程分析"。**这套流程，才是本专栏真正的交付物。**

### 8.5 从二叉树出发：后续的迁移

**二叉树是"递归结构"的入门模型**，它的思想会一路迁移：

- **图**：把"左右子树"换成"邻居节点"，把"visited"加进去（搜索专栏）；
- **动态规划**：把"树形结构"换成"线性顺序"或"状态空间"（动态规划专栏）；
- **回溯**：把"沿路径携带状态"换成"决策树上的探索"（搜索专栏）；
- **分治**：把"左右独立"推广到"任意划分"（分治与贪心专栏）。

**所以二叉树专栏不是一个孤立专题，而是整个算法体系的"分水岭"**——**它之后的所有递归结构，都只是它的推广。** 理解了这一点，你就明白为什么二叉树值得花这么多篇幅——**它训练的是"递归思维"这一贯穿始终的能力。**

## 第 9 章 树形 DP 的复杂度与跨专题联系

### 9.1 复杂度：为什么是 $O(n)$

**树形 DP 的时间复杂度，通常是 $O(n)$**——因为"每个节点只被访问一次"，而每次访问做的是常数量的工作（比较、相加、取最值）。

**这个"每个节点访问一次"的性质，正是树形 DP 高效的根源。** 它不像某些 DP 需要"枚举状态组合"，而是"顺着树的结构，自底向上算一遍"。**理解了这一点，你就明白为什么"树形 DP 看起来复杂，复杂度却很简单"**——**因为它的"状态转移"被树的结构天然约束住了：每个节点只依赖它的左右子树。**

**空间是 $O(h)$**（递归栈深度）——与树的深度成正比。**对退化成链的树，空间会退化到 $O(n)$**（与第 01 篇"递归的空间代价"同源）。

### 9.2 与线性 DP、区间 DP 的联系

把三种 DP 并排看，会发现它们的骨架一致、只是"子问题形态"不同：

| DP 类型 | 子问题形态 | 转移依赖 |
|---------|-----------|---------|
| 线性 DP | 前缀（前 `i` 个） | 前一个/前几个 |
| 区间 DP | 区间 `[i, j]` | 分割点 `k` |
| 树形 DP | 子树 | 左右子树 |

**三者的共同点是"用子问题的最优解，组合出当前问题的最优解"。** 区别只在"子问题是什么形态"：线性 DP 是"一段前缀"，区间 DP 是"一段区间"，树形 DP 是"一棵子树"。

**所以树形 DP 并不神秘——它只是把线性 DP 的"顺序结构"换成了"树形结构"。** 理解了这一点，你在遇到"树上的最优化"问题时，就能自然地想："这是不是树形 DP？子问题（子树）的最优解如何组合？"

### 9.3 一个统一的理解

**"把大问题拆成子问题、用子问题的解组合出大问题的解"——这是所有 DP（以及分治）的共同内核。** 树形 DP 之所以看起来特殊，是因为它的"子问题"是"子树"这一递归结构。**但一旦你习惯了"树本身就是递归定义的"，树形 DP 就成了"自然而然"的东西。**

**换句话说，树形 DP 的难点不在"DP"，而在"对树的理解"**——只要你清楚"一棵树由根、左子树、右子树组成"，那么"用左右子树的结果算当前节点的结果"就是顺理成章的。**这也是为什么本专栏把树形 DP 放在最后——它需要前面所有篇目（递归语义、后序汇总、返回值设计）的铺垫。**

> [!info] DP 的统一视角
> 线性 DP、区间 DP、树形 DP、状态压缩 DP……它们的名字不同，但内核一致：**"拆子问题 + 组合子解"**。**理解了这一点，你就不会把"DP"当成一堆互不相干的技巧，而是一个统一的思维框架。** 遇到新问题时，你只需问："子问题是什么？如何组合？"——**这两个问题，就是 DP 的全部。**

### 9.4 落点

**树形 DP 专题的落点，是"贡献值 vs 拐点值"这一区分**——它要求你**严格分清"给父节点传递的值"与"当前节点结算的值"**。这个区分，是所有"返回值 + 全局变量"类问题的关键。

**而更深一层的收获，是"从树形结构看 DP"这一视角**——它让你明白，DP 不是"填表格"，而是"用子问题的解组合出大问题的解"，而"子问题的形态"可以是前缀、区间、子树，乃至任意递归结构。**理解了这一点，你就把"树形 DP"与整个 DP 体系联系到了一起。**

**最后，回到本专栏的开篇（第 01 篇）**：二叉树训练的是"**把整体问题拆成左右子问题、并在回溯时汇总信息**"的能力。**树形 DP，正是这项能力的最完整体现**——它把"拆"（递归左右）与"汇总"（组合结果）两件事，做到了一棵树上。**所以本专栏以它收束，恰如其分。**

## 第 10 章 树形 DP 的自查清单与一句话落点

### 10.1 一份自查清单

| 检查项 | 对应问题 |
|--------|---------|
| `ans` 用最小整数初始化 | 全负输入 |
| `max(0, ...)` 是否生效 | 负贡献 |
| 返回值只选一边 | 路径分叉 |
| 拐点值两边都要 | 结算 |
| 根节点是否特殊处理 | 无父节点（968） |
| 返回值是否承载了多状态 | 状态机 DP |

### 10.2 落点

**树形 DP 专题的落点，是"贡献值 vs 拐点值"这一区分**——**前者供传递（只能选一边），后者供结算（两边都要）。** 把两者分开，是树形 DP 的第一原则。

**而更深一层的收获，是"树形 DP 与线性 DP 同源"这一认识**——**它们都是"用子问题的最优解组合出当前问题的最优解"，只是子问题是"子树"而非"前缀"。** 理解了这一点，你就把树形 DP 融入了整个 DP 体系。

> [!info] 一句话带走
> 如果只能带走一句话，那就是：**"树形 DP 的全部，就是分清'给父节点的'与'当前节点结算的'。"** 前者只能选一边（路径不能分叉），后者两边都要（拐点）。**这一句，解释了最大路径和、最长同值路径、直径等一整族题。**

### 10.3 专栏的最终落点

**整个二叉树专栏，最终落在一句话上：把整体问题拆成左右子问题，并在回溯时汇总信息。** 从遍历（何时处理）到判定（语义设计），从重建（区间映射）到 BST（中序有序），从深度（BFS/DFS 取舍）到树形 DP（贡献值 vs 拐点值）——**它们都是这一句话在不同问题上的展开。**

**而这句话，正是"递归思维"的核心。** 二叉树之所以值得花这么多篇幅，不是因为题目多，而是因为**它把"递归思维"压缩到了最清晰的结构上**——让你能专注于"拆与汇总"这件事本身，而不被其他复杂度干扰。**理解了二叉树，你就理解了递归；理解了递归，你就理解了一大半算法。**

## 小结

本篇用最大路径和这道难题，把树形 DP 的核心抽象讲透了——**区分"对父节点可贡献的值"（只能选一边）与"当前节点作为拐点的最优值"（两边都要）**。前者用于传递，后者用于结算；把两者分开，是树形 DP 的第一原则。延伸的 LC687（最长同值路径）与 LC543（直径）证明：树形 DP 的骨架是固定的，难点只在"贡献规则"的定义。

作为专栏收束，本篇还给出了"拿到树题先问什么"的五问框架——**中间状态是层还是路径、节点在哪个时机处理、函数返回什么、需不需要全局答案、有没有约束可利用**。这五问不针对任何具体题，而是面对陌生树题时的通用提问方式。**二叉树专栏真正想留下的，不是 18 道题的解法，而是这套"把整体问题拆成左右子问题、在回溯时汇总信息"的思维方式**——它会一路迁移到图、动态规划、乃至一切递归结构的处理中。
