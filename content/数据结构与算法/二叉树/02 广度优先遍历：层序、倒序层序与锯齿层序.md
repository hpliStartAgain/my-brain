# 广度优先遍历：层序、倒序层序与锯齿层序

**摘要：**

深度优先遍历关注"沿一条路径先走到底"，广度优先遍历（BFS）则关注"按层推进"。这两者的差异，不只是"用栈还是用队列"，而是两种不同的思维模型：DFS 的中间状态是"当前路径"，BFS 的中间状态是"当前层边界"。LeetCode 102、107、103 是二叉树 BFS 的核心入门题，它们看似只是"把节点放进队列"，实则考察的是——**如何清晰地定义"一层"、如何在结果中保留层信息、以及当题目要求倒序或锯齿形输出时，该改遍历过程还是只改写入策略**。本文用 Go 语言完整实现这三道题，把它们抽象成同一个"层序模板"，并追问：为什么每轮要先固定 `size`、为什么"只改写入不改遍历"更稳、以及哪些题天然适合 BFS。这套模板会一路迁移到右视图、层平均值、按层连接 `Next` 指针等大量变体。

---

## 第 1 章 层序遍历为什么不是"简单队列"

### 1.1 真正的问题是"如何切层"

如果只把根节点入队，然后每次弹出一个节点、把左右孩子继续入队，你当然能按"从上到下、从左到右"的顺序看到所有节点。但题目要的不是一个扁平序列，而是：

```text
[
  [第 0 层],
  [第 1 层],
  [第 2 层]
]
```

**所以 BFS 的关键从来不是"队列存在"，而是：在什么时候知道当前这一层结束了。** 队列只是载体，"切层的边界"才是这道题真正的考点。

### 1.2 为什么每轮要先固定 `size`

层序遍历最经典的写法，是在每一轮开始时保存当前队列长度 `size`——**这个 `size` 恰好就是当前层的节点数。**

```go
size := len(queue)
for i := 0; i < size; i++ {
    // 处理当前层的第 i 个节点
}
```

**理由非常朴素**：循环开始前，队列里全是当前层的节点；而当前层节点出队时，会把下一层节点加到队尾。**如果不提前固定 `size`，循环就会"越界"到下一层，把两层混在一起。**

> [!info] "切层"的本质：一个时间点的快照
> `size := len(queue)` 这一句，本质上是**在当前层与下一层之间，取了一个"时间点快照"**——快照之前入队的，都是当前层；快照之后入队的，都是下一层。**这个"在边界处取快照"的思路，是层序题的灵魂**，也是后面右视图、锯齿层序、按层连接等一切变体的共同起点。理解了它，BFS 就再也不是"把节点丢进队列"这么简单了。

## 第 2 章 LeetCode 102：标准层序遍历

### 2.1 题目

**LeetCode 102 - Binary Tree Level Order Traversal**（中等）

给你二叉树的根节点 `root`，返回其节点值的层序遍历（即逐层地、从左到右访问所有节点）。

```text
输入: root = [3,9,20,null,null,15,7]
输出: [[3],[9,20],[15,7]]
```

### 2.2 Go 实现

```go
func levelOrder(root *TreeNode) [][]int {
    var res [][]int
    if root == nil {
        return res
    }
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        size := len(queue) // 固定当前层节点数
        level := make([]int, 0, size)
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:] // 出队
            level = append(level, node.Val)
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
        res = append(res, level)
    }
    return res
}
```

**注意 Go 里用切片当队列**：`queue = append(queue, x)` 入队、`queue[0]` 取队头、`queue = queue[1:]` 出队。**这是最简洁的写法，但有一个隐性代价**——`queue = queue[1:]` 只是移动了切片的起始位置，底层数组不会立即释放。对算法题无碍；若在生产中长期运行，可用环形缓冲区（参见栈与队列专栏第 03 篇）替代。

### 2.3 手动模拟

对下面这棵树：

```text
        3
       / \
      9  20
        /  \
       15   7
```

队列变化如下：

```text
初始: [3]

第 0 层 size=1: 弹出 3，加入 9、20 → 结果 [3]
队列: [9, 20]

第 1 层 size=2: 弹出 9、20，加入 15、7 → 结果 [9, 20]
队列: [15, 7]

第 2 层 size=2: 弹出 15、7 → 结果 [15, 7]
队列: []
```

**这个模板以后会不断出现**：最小深度、右视图、每层平均值、按层连接 `Next` 指针，都可以从它平移过去。

## 第 3 章 LeetCode 107：自底向上的层序遍历

### 3.1 题目

**LeetCode 107 - Binary Tree Level Order Traversal II**（中等）

返回其节点值的自底向上的层序遍历（即从叶子层到根层）。

```text
输入: root = [3,9,20,null,null,15,7]
输出: [[15,7],[9,20],[3]]
```

### 3.2 两种思路

它与 102 的差别只有一点：最终输出从底层到顶层。有两种处理方式：

1. **正常层序遍历，最后整体反转结果**；
2. 每层结果直接头插到结果列表的头部。

从工程可读性出发，第一种更直观。

```go
func levelOrderBottom(root *TreeNode) [][]int {
    res := levelOrder(root) // 复用第 102 题的解法
    // 整体反转
    for i, j := 0, len(res)-1; i < j; i, j = i+1, j-1 {
        res[i], res[j] = res[j], res[i]
    }
    return res
}
```

### 3.3 为什么不需要改 BFS 本身

**因为题目只改了"输出顺序"，没改"访问顺序"。** 访问节点仍然必须从上到下按层推进，只有结果展示反过来而已。

**这个判断很重要**——它能避免你为了迎合输出形式，去破坏原有的清晰遍历逻辑。**"遍历"与"呈现"应当解耦**：遍历负责"以正确的拓扑顺序访问"，呈现负责"以题目要求的形式组织结果"。**把这两件事分开，是层序题乃至所有遍历题的一条通用原则。**

## 第 4 章 LeetCode 103：锯齿层序遍历

### 4.1 题目

**LeetCode 103 - Binary Tree Zigzag Level Order Traversal**（中等）

按锯齿形（Zigzag）顺序返回层序遍历：第 0 层从左到右，第 1 层从右到左，第 2 层从左到右……依次交替。

```text
输入: root = [3,9,20,null,null,15,7]
输出: [[3],[20,9],[15,7]]
```

### 4.2 难点不在队列，而在每层写入方向

这里有两个常见误区：

1. **试图改变孩子入队顺序**——错误，因为这会破坏下一层的拓扑顺序；
2. **试图在奇数层反向遍历队列**——同样错误，因为队列本身没有"反向遍历"的能力。

**实际上都不必要。队列仍然按正常层序维护即可，变化的是每层结果的写入方式。**

### 4.3 用双端队列承载层结果

```go
func zigzagLevelOrder(root *TreeNode) [][]int {
    var res [][]int
    if root == nil {
        return res
    }
    queue := []*TreeNode{root}
    leftToRight := true

    for len(queue) > 0 {
        size := len(queue)
        level := make([]int, size)
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:]
            // 按方向写入：正序写第 i 位，逆序写倒数第 i 位
            if leftToRight {
                level[i] = node.Val
            } else {
                level[size-1-i] = node.Val
            }
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
        res = append(res, level)
        leftToRight = !leftToRight // 切换方向
    }
    return res
}
```

**注意这里的实现技巧**：预分配长度为 `size` 的切片，正序时写入 `level[i]`、逆序时写入 `level[size-1-i]`。**这样"反向"就退化成了一次"下标计算"，而无需真的去反向遍历或反转数组。** 这正是"只改写入、不改遍历"的落地方式。

### 4.4 为什么"只改写入，不改遍历"更稳

因为**节点的真实拓扑顺序没有变**：第 1 层依然应该先处理左孩子、再处理右孩子，只是最终这一层在结果里要从右往左呈现。**把"遍历顺序"和"结果排列"解耦，是层序题很重要的习惯**——它与第 3 章 107 题的"只反转结果、不改遍历"是同一条原则。

## 第 5 章 层序模板的变体家族

掌握了"固定 `size` 切层"这一模板，一大族题都能平移过去。以下变体都只需改动"层内做什么"：

| 题目 | 层内做什么 | 关键点 |
|------|-----------|--------|
| LC 102 层序遍历 | 收集本层所有值 | 基础模板 |
| LC 107 自底向上 | 收集后整体反转 | 只改呈现 |
| LC 103 锯齿层序 | 按方向写入 | 只改写入 |
| LC 199 二叉树的右视图 | 只取本层最后一个 | `size-1` 位置 |
| LC 637 每层平均值 | 累加后除以 `size` | 注意整除/浮点 |
| LC 116/117 填充 `Next` 指针 | 把本层节点横向连起来 | 层内遍历即"横向连接" |
| LC 111 最小深度 | 首次遇到叶子即返回 | BFS 的"提前返回"优势 |

**其中 LC 199（右视图）最值得一看**——它只需在层内循环到 `i == size-1` 时记录一次，就把"每层最右"取了出来：

```go
// 右视图：层内只取最后一个
if i == size-1 {
    res = append(res, node.Val)
}
```

**这行代码的价值，在于它展示了"切层"的威力**——一旦你能精确地界定"一层"，取"每层最右"就成了一件平凡的事。**换句话说，"切层"把"按层聚合"这类问题，从"需要额外记录层号"降级成了"一个 `if` 判断"。**

## 第 6 章 BFS 与 DFS 的边界

### 6.1 哪些题天然适合 BFS

- **最小深度**：第一次遇到叶子节点即可返回（BFS 的"提前返回"是它相对 DFS 的优势）；
- **每层视角问题**：右视图、层平均值、层最大值；
- **横向连接问题**：填充每个节点的下一个右侧节点指针。

### 6.2 哪些题更适合 DFS

- **需要子树返回值汇总的题**（如平衡树、最大路径和）；
- **需要根到叶路径状态的题**（如路径总和）；
- **需要利用后序时机更新全局答案的题**。

> [!warning] BFS 不是 DFS 的"另一种写法"
> BFS 解决的是**分层**问题，DFS 解决的是**分支递归**问题。两者都能遍历整棵树，但**适用的中间状态完全不同**：BFS 的中间状态是"当前层的边界"，DFS 的中间状态是"当前路径"。**把它们当成"同一件事的两种实现"来互相替换，是学树题时最危险的一种误解。** 选择哪一个，取决于你需要的是"层"还是"路径"。

### 6.3 一个判断的口诀

**问自己一句："我需要的中间状态，是'层'还是'路径'？"** 需要"当前层还剩多少节点没处理"（层边界），选 BFS；需要"从根到当前节点经过了哪些"（路径），选 DFS。**这一个问题，几乎能定下绝大多数树题的遍历方式。**

## 第 7 章 常见误区与自测方法

### 7.1 四个高频误区

**误区一：层序循环不固定 `size`，用 `len(queue)` 直接作条件。** 这会让当前层与下一层混在一起，切层失败。

**误区二：锯齿层序去改孩子入队顺序。** 会破坏下一层的拓扑顺序，导致后续层错乱。

**误区三：107 题去反向遍历队列。** 队列没有反向遍历能力，正确做法是"正常遍历、反转结果"。

**误区四：右视图写成"每层第一个"。** 右视图要的是"每层最后一个"（`size-1`），方向写反就错了。

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `nil` | 空树边界 |
| 单节点 `[1]` | 单层 |
| `[1,2,3,4,5,6,7]` | 完全二叉树（层数整齐） |
| `[1,2,null,3,null,4]` | 单边深链（层内只有一个节点） |
| `[1,2,3,null,null,null,7]` | 层内节点数不均 |

**其中"单边深链"最值得测**——它让每层只有一个节点，`size` 恒为 1，最能暴露"切层逻辑"是否正确。**凡是层序题，先用一条左链测一遍，能拦下大量关于 `size` 与边界判断的 bug。**

## 第 8 章 延伸：层序的三大应用场景

层序模板的威力，在于它能支撑一大族"按层"的问题。本章用三个场景展示它的用法。

### 8.1 二叉树的右视图（LeetCode 199）

**题目**：给定一棵二叉树，想象自己站在它的右侧，按从顶部到底部的顺序，返回从右侧所能看到的节点值。

**站在右侧能看到的，就是每一层最右边的那个节点。** 用层序模板，只需在层内循环到 `i == size-1` 时记录：

```go
func rightSideView(root *TreeNode) []int {
    var res []int
    if root == nil {
        return res
    }
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        size := len(queue)
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:]
            if i == size-1 { // 本层最后一个
                res = append(res, node.Val)
            }
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
    }
    return res
}
```

**注意这里有一个常见的误解**：有人以为"右视图 = 一直往右走"。**这是错的**——若某节点只有左孩子，那左孩子也会出现在右视图里（因为它在该层最右）。**右视图的本质是"每层最右"，而非"一路向右"。** 这个区别，只有用层序模板才能干净地处理。

### 8.2 在每个树行中找最大值（LeetCode 515）

**题目**：给定一棵二叉树的根节点，请找出该二叉树中每一层的最大值。

```go
func largestValues(root *TreeNode) []int {
    var res []int
    if root == nil {
        return res
    }
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        size := len(queue)
        maxVal := math.MinInt32
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:]
            if node.Val > maxVal {
                maxVal = node.Val
            }
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
        res = append(res, maxVal)
    }
    return res
}
```

**这道题与右视图、层均值是同一模板**——只是"层内做什么"从"取最后一个"变成了"取最大"。**它们共同说明：层序模板一旦建立，"层内操作"就成了可替换的插件。**

### 8.3 层序序列化（LeetCode 449 的一种实现）

**题目**：设计一个 BST 的序列化与反序列化算法（这里只讨论用层序实现序列化的思路）。

**层序也可以用来序列化**——它比前序序列化更"直观"，但需要处理"尾部空节点"的裁剪：

```go
// 层序序列化（示意）
func serializeLevelOrder(root *TreeNode) string {
    if root == nil {
        return ""
    }
    var sb []string
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        node := queue[0]
        queue = queue[1:]
        if node == nil {
            sb = append(sb, "#")
            continue
        }
        sb = append(sb, strconv.Itoa(node.Val))
        queue = append(queue, node.Left)
        queue = append(queue, node.Right)
    }
    // 实际工程中通常裁掉尾部的连续 "#"，再反序列化
    return strings.Join(sb, ",")
}
```

**层序序列化的特点是"结构信息更直白"**（每两个子节点对应一个父节点），但**代价是"空节点会大量出现"**（尤其是稀疏的树），字符串会很长。**前序序列化（第 01 篇 6.1 节）则更紧凑**——这就是"两种序列化方案"的取舍：**层序直观但冗长，前序紧凑但需要递归还原。**

### 8.4 三个场景的共性

三个场景（右视图、层最大值、层序序列化）的共同点是：**它们都只需要"按层访问"，而层序模板恰好提供了"精确切层"的能力。** 右视图取"层内最后"、层最大值取"层内最大"、层序序列化取"层内逐个"——**同一模板，插件不同。**

## 第 9 章 层序与最短路径：BFS 的另一个主战场

层序遍历是 BFS 在"树"上的应用，而 BFS 真正的主战场，是"**无权图上的最短路径**"。理解这一推广，能帮你把"层序"从一个树题技巧，上升为一个通用算法。

### 9.1 为什么 BFS 能求最短路径

**BFS 按"距离起点的层数"逐层扩展**——第一层是距离 1 的节点、第二层是距离 2 的……于是**第一次访问到某个节点时，走过的步数就是"从起点到它的最短距离"**（因为更短的距离会在更早的层被访问到）。

**这正是"层序"在树上的体现**：树的"层"就是"到根的距离"，而 BFS 按层扩展，等价于"按距离从小到大访问"。

### 9.2 从树到图：加一个 visited

把 BFS 从树推广到图，只需加一件事——**`visited` 标记**。因为图有环，同一个节点可能被多次入队；用 `visited` 保证每个节点只入队一次，BFS 依然成立：

```go
// 图上的 BFS（求从 start 到各点的最短距离）
func bfs(graph [][]int, start int) []int {
    dist := make([]int, len(graph))
    for i := range dist {
        dist[i] = -1 // -1 表示未访问
    }
    dist[start] = 0
    queue := []int{start}
    for len(queue) > 0 {
        u := queue[0]
        queue = queue[1:]
        for _, v := range graph[u] {
            if dist[v] == -1 { // 未访问
                dist[v] = dist[u] + 1
                queue = append(queue, v)
            }
        }
    }
    return dist
}
```

**注意"层"在这里变成了"距离"**——不再需要显式的 `size` 切层，因为 `dist` 数组本身就记录了"每个节点在第几层"。**这是树与图的一个差异：树的层可以由 `size` 切分，图的距离则需要显式记录。**

### 9.3 一个统一的视角

**层序遍历（树）、BFS 最短路径（图）、乃至"多源 BFS""双向 BFS"，本质都是同一个算法**——"用一个队列按层扩展，每层对应一个距离"。**树是图的特例（无环），所以树的层序是图 BFS 的简化版。** 理解了这一点，你面对任何"最短步数""最少操作次数""最小代价（无权）"的问题，都能条件反射地想到 BFS。

> [!info] 从"层序"到"最短路径"：一次视角的升维
> 在树上，"层序"是一个**输出格式**（按层返回节点）；在图上，"BFS"是一个**求解算法**（求最短路径）。**但它们的底层机制完全一致——都是"按距离从小到大扩展"。** 这个例子很好地说明了本专栏反复强调的一件事：**一个看似"格式性"的技巧，在更一般的结构上，往往会显现出它的算法本质。** 学会从"层序"看到"BFS"，你就完成了一次从"记技巧"到"懂算法"的跃迁。

## 第 10 章 层序的复杂度与工程实现

### 10.1 时间与空间

层序遍历的时间是 $O(n)$（每个节点进出队列一次）。**空间则值得细说**：队列的峰值大小，等于"最宽那一层的节点数"——在最坏情况下（如完全二叉树）是 $O(n/2)$，即 $O(n)$。

**注意这里与 DFS 的对比**：DFS 的空间是"树高"$O(h)$，BFS 的空间是"最宽层"$O(w)$。**对一棵又宽又浅的树，BFS 比 DFS 更耗空间；对一棵又窄又深的树，DFS 更耗空间。** 这就是"BFS vs DFS"在空间上的经典权衡——**选择哪一个，取决于你的树是"宽"还是"深"。**

### 10.2 Go 切片当队列的隐性代价

本篇用 `queue = append(queue, x)` 与 `queue = queue[1:]` 实现队列，简洁好用。但它有一个隐性代价：**`queue = queue[1:]` 只是移动了切片的起始位置，底层数组不会收缩**——于是"已经出队的元素"仍占着内存，直到整个队列被回收。

**对算法题无碍**（队列很快就被丢弃），但**在生产代码里长期运行会导致内存膨胀**。**替代方案是环形缓冲区**（栈与队列专栏第 03 篇）：用固定大小的数组 + 取模下标，空间恒定、无隐性增长。**"算法题的简洁写法"与"工程代码的健壮写法"之间的差距，往往就藏在这些细节里。**

### 10.3 BFS 在工程中的样子

BFS 在工程里最常见的形态，是"**无权图上的最短路径**"：

- **社交网络**：两个人之间的"最短好友链"（几度人脉）；
- **网络路由**：在跳数作为代价的场景下找最短路径；
- **游戏 AI**：在格子上找"最少步数"到达目标；
- **依赖解析**：从某个包出发，逐层找出它依赖的所有包。

**这些场景的共同点，是"每一步代价相同"**——而 BFS 恰好保证"第一次访问到某点时的距离就是最短距离"。**若每步代价不同，就必须换成 Dijkstra（带权最短路径）**——那是另一个专栏的话题，但它的思想仍是"按距离从小到大扩展"，只是"距离"由优先队列而非普通队列维护。

> [!info] 从"层"到"距离"：BFS 的本质
> 层序遍历里，"层"就是"到根的距离"。一旦你意识到这一点，BFS 的本质就清楚了——**它是一个"按距离从小到大扩展"的算法**。**树的层序只是它的一个特例（无环、单源）。** 理解了这层抽象，你面对"最少步数""最少操作"这类问题时，就会条件反射地想到 BFS，而无需去回忆"这道题该用层序"。

### 10.4 一个值得记住的对照

| 场景 | 用 BFS | 用 DFS |
|------|--------|--------|
| 最短/最少（无权） | 优（首次到达即最短） | 需走遍所有路径 |
| 按层聚合 | 优（天然分层） | 需额外记录层号 |
| 空间 | 最宽层 $O(w)$ | 树高 $O(h)$ |
| 全局汇总（最值、路径） | 不便 | 优（后序汇总） |

**这张表的核心，仍是那句"最近优先用 BFS，最远汇总用 DFS"。** 它几乎能定下所有树/图遍历题的选型。

## 第 11 章 层序题的面试表达与追问

### 11.1 表达套路

1. **先点出核心**："层序的关键不是队列，而是'在每层边界取快照'——用 `size := len(queue)` 切层。"
2. **给模板**："每轮固定 `size`，处理 `size` 个节点，同时把下一层入队。"
3. **讲清变体**："倒序只改呈现（反转结果），锯齿只改写入（按下标放）。"
4. **说复杂度**："时间 $O(n)$，空间 $O(w)$（最宽层）。"
5. **主动补充**："若求最小深度，BFS 能首次遇到叶子即返回。"

**第 1 步是关键**——它表明你抓住了"切层"这个本质，而非"用了个队列"。

### 11.2 常见追问

**追问一："为什么必须固定 `size`？"** 答：因为当前层节点出队时会加入下一层节点，不固定 `size` 就会把两层混在一起。

**追问二："倒序层序要不要改 BFS？"** 答：不用。访问顺序仍是"从上到下"，只是最后把结果反转。

**追问三："锯齿层序为什么要用双端队列？"** 答：其实不必用双端队列——预分配一个长度 `size` 的数组，正序写 `[i]`、逆序写 `[size-1-i]` 即可。

**追问四："右视图是'每层最后一个'吗？"** 答：是。右视图不等于"一路向右"——某层若只有左孩子，那个左孩子也会出现在右视图里。

**追问五："BFS 和 DFS 的空间谁更省？"** 答：取决于树的形状。BFS 空间是"最宽层"$O(w)$，DFS 是"树高"$O(h)$。**又宽又浅的树，BFS 更费空间；又窄又深的树，DFS 更费空间。**

### 11.3 落点

**层序题的"简单"是它的模板只有五行；"不简单"是它的变体极多**——倒序、锯齿、右视图、层均值、按层连接 `Next`，全都从这个模板长出来。**能不能一眼看出"这是层序的变体"，是熟练与否的分界。** 而这一切的钥匙，就是那一句 `size := len(queue)`——**在边界处取快照。**

> [!info] 一个模板，一族变体
> 层序、右视图、层均值、锯齿、按层连接 `Next`——五道题，一个模板。**这正是"掌握模板"的价值：它不是让你少写几行代码，而是让你在看到新题时，立刻认出"这是哪个模板的变体"。** 算法学习里，"识别模板"的能力，往往比"写出代码"的能力更重要——**因为识别对了，代码只是填空。**

## 第 12 章 层序题的自查清单与落点

### 12.1 一份自查清单

| 检查项 | 对应问题 |
|--------|---------|
| 是否在层内循环前固定 `size` | 层混在一起 |
| 空树是否返回空结果 | 基准情况 |
| 倒序是否只反转结果 | 破坏了遍历逻辑 |
| 锯齿是否只改写入 | 破坏了下一层顺序 |
| 右视图是否取"每层最后" | 误以为是"一路向右" |
| Go 切片队列是否有内存隐患 | `queue[1:]` 不释放 |

**这份清单，覆盖了层序题最常见的 bug。**

### 12.2 落点

**层序专题的落点，是"切层"这一基础操作**——**`size := len(queue)` 这一行，把"按层聚合"这类需求，从"需要额外记录层号"降级成了"一个边界判断"。** 一旦掌握它，右视图、层均值、锯齿、按层连接 `Next` 全都成了"层内操作"的填空。

**更深一层的收获，是"BFS 的本质是按距离扩展"这一抽象**——树的"层"就是"到根的距离"，而 BFS 按层推进，等价于"按距离从小到大访问"。**理解了这一点，你就把"层序"从一个树题技巧，上升成了"无权图最短路径"这一通用算法**（详见第 9 章）。

> [!info] 一个模板，一次抽象
> 层序题的模板只有五行，但它背后藏着两层抽象：**"切层"（用快照划分边界）与"按距离扩展"（BFS 的本质）。** 前者让你能处理所有"按层"的题，后者让你能处理所有"最短距离"的题。**这就是"从具体到抽象"的学习路径——先掌握模板，再理解它背后的抽象，最终用抽象去解决新问题。**

### 12.3 一句话带走

如果只能带走一句话，那就是：**"层序的关键不是队列，而是在每层边界取一个快照。"** 这句话既解释了"为什么必须固定 `size`"，也解释了"为什么它能支撑这么多变体"。**把它记住，你在面对任何"按层"的题时，都会先问一句"我该怎么切这一层"。**

## 小结

本篇把层序遍历从一个"把节点放进队列"的朴素动作，还原成了它的本质——**在每层边界处取一个"时间点快照"（`size := len(queue)`）**。一旦能精确地"切层"，102、107、103 乃至右视图、层平均值、按层连接 `Next` 指针，都只是"层内做什么"的不同。而 107 与 103 给出的两条经验——**"只改呈现，不改遍历"**——更是层序题乃至所有遍历题的通用原则。

贯穿全篇的核心认知有两条。其一，**BFS 的中间状态是"层边界"，DFS 的中间状态是"路径"**，两者的适用场景由"你需要层还是路径"决定，不可互相替换。其二，**"切层"是一项可以复用的基础操作**——它把"按层聚合"这类需求，从"需要额外记录层号"降级成了"一个边界判断"。**把这两条握住，你在面对任何"按层"的树题时，都能立刻找到切入点。**
