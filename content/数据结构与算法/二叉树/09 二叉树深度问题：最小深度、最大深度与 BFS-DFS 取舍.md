# 二叉树深度问题：最小深度、最大深度与 BFS-DFS 取舍

**摘要：**

"最大深度"与"最小深度"经常被一起问，但**它们的解题逻辑并不对称**——这正是本篇要讲清的核心。最大深度天然适合 DFS：它是"左右子树深度的最大值 + 1"，一个漂亮的后序汇总。而最小深度藏着一个经典陷阱：**当某个节点只有一个孩子时，不能把"空的那侧"的深度 0 直接取 min**——因为"空"不是"一条更短的路"，而是"根本没有路"。除了这个陷阱，本篇还会讲清"为什么最小深度用 BFS 首次遇到叶子即可返回"以及它相对 DFS 的优势。全文用 Go 语言实现，并补充"树的直径"这一深度类问题的进阶形态。掌握本篇，你会对"BFS 与 DFS 如何按问题性质取舍"有更具体的判断。

## 第 1 章 LeetCode 104：最大深度

### 1.1 题目

**LeetCode 104 - Maximum Depth of Binary Tree**（简单）

给定一个二叉树，找出其最大深度。最大深度是从根节点到最远叶子节点的最长路径上的节点数。

```text
输入: root = [3,9,20,null,null,15,7]  →  输出: 3
```

### 1.2 后序汇总：最大值 + 1

最大深度的定义本身就暗示了递归结构：**以 `root` 为根的树，其最大深度 = 左右子树最大深度的较大者 + 1。**

```go
func maxDepth(root *TreeNode) int {
    if root == nil {
        return 0
    }
    return max(maxDepth(root.Left), maxDepth(root.Right)) + 1
}
```

**这是"后序 + 返回值汇总"的最小模型**——与第 03 篇平衡二叉树、第 11 篇最大路径和是同一骨架。**函数返回"以当前节点为根的子树深度"，父节点取两者较大者再加 1。**

**复杂度**：时间 $O(n)$，空间 $O(h)$（递归栈，$h$ 为树高）。

### 1.3 为什么最大深度天然适合 DFS

因为最大深度是"所有根到叶路径中最长的那条"——**它要比较所有路径，而 DFS 恰好能"走遍每条路径"。** 而且"取最大值"这一操作，在递归返回时天然可以汇总。**用 BFS 也能求最大深度（走到最后一层），但没必要——DFS 更简洁。**

## 第 2 章 LeetCode 111：最小深度（陷阱所在）

### 2.1 题目

**LeetCode 111 - Minimum Depth of Binary Tree**（简单）

给定一个二叉树，找出其最小深度。最小深度是从根节点到最近叶子节点的最短路径上的节点数。

```text
输入: root = [3,9,20,null,null,15,7]  →  输出: 2
输入: root = [1,2]                    →  输出: 2
输入: root = [1,null,2]               →  输出: 2
```

### 2.2 经典陷阱：空子树不能直接取 min

很多人会照抄最大深度的思路，写：

```go
// 错误写法
return min(minDepth(root.Left), minDepth(root.Right)) + 1
```

**这会出错。** 考虑 `root = [1,2]`：根 `1` 只有左孩子 `2`。此时 `minDepth(root.Right) = 0`（右子树为空），于是 `min(2, 0) + 1 = 1`——**但正确答案是 2**，因为"最小深度"要求"到叶子节点"，而根 `1` 本身不是叶子（它有左孩子），真正最近的叶子是节点 `2`。

**根本原因在于**：`minDepth(nil) = 0` 里的那个 `0`，代表的是"空"，而不是"一条长度为 0 的路径"。**当某个节点只有一个孩子时，空的那侧不是"更短的路"，而是"根本没有路"——它不应该参与 min 比较。**

### 2.3 正确写法：区分"只有一个孩子"的情形

```go
func minDepth(root *TreeNode) int {
    if root == nil {
        return 0
    }
    // 只有右孩子：最小深度只能在右子树里找
    if root.Left == nil {
        return minDepth(root.Right) + 1
    }
    // 只有左孩子：最小深度只能在左子树里找
    if root.Right == nil {
        return minDepth(root.Left) + 1
    }
    // 两个孩子都有：取较小的
    return min(minDepth(root.Left), minDepth(root.Right)) + 1
}
```

**这三行分支，正是"最小深度不对称于最大深度"的体现。** 最大深度不需要这些分支（因为"取 max"时，空子树的 0 本来就不会被选中）；而最小深度必须显式处理"单孩子"情形。

> [!warning] 生产避坑：`0` 是"空"还是"长度"？
> 最小深度的陷阱，本质是"`0` 这个返回值有歧义"——它既可能是"空子树的深度"，也可能是"长度为 0 的路径"。**在递归里，一个返回值只应承载一种语义**；一旦它身兼二义，就必然在某些输入下出错。**遇到"取 min 却结果偏小"的 bug，先检查"有没有把'空'误当成'更小'"。**

### 2.4 BFS 解法：首次遇到叶子即可返回

最小深度还有一个 BFS 解法，而且它**在"最小"这个问题上天然更优**：

```go
func minDepthBFS(root *TreeNode) int {
    if root == nil {
        return 0
    }
    queue := []*TreeNode{root}
    depth := 1
    for len(queue) > 0 {
        size := len(queue)
        for i := 0; i < size; i++ {
            node := queue[0]
            queue = queue[1:]
            // 首次遇到叶子，它所在的层就是最小深度
            if node.Left == nil && node.Right == nil {
                return depth
            }
            if node.Left != nil {
                queue = append(queue, node.Left)
            }
            if node.Right != nil {
                queue = append(queue, node.Right)
            }
        }
        depth++
    }
    return depth
}
```

**为什么 BFS 在这里更优？** 因为 BFS 是"按层推进"的——**第一次遇到叶子，就一定是"最近的那个叶子"**，可以立即返回，无需遍历整棵树。而 DFS 必须走遍所有路径才能确定"最短"。

**这揭示了一条取舍规律**：**求"最小/最近"的问题，BFS 往往优于 DFS**（因为 BFS 能"一遇到就返回"）；**求"最大/最远"的问题，DFS 往往更自然**（因为"最大"必须比较所有路径）。**"最近优先"用 BFS，"最远汇总"用 DFS**——这条口诀几乎能定下所有深度类问题的遍历方式。

## 第 3 章 BFS 与 DFS 在深度问题上的取舍

| 问题 | 推荐 | 理由 |
|------|------|------|
| 最大深度 | DFS | 必须比较所有路径，"取 max" 后序汇总自然 |
| 最小深度 | BFS（或带特判的 DFS） | "首次遇到叶子即最近"，可提前返回 |
| 每层视角（右视图、层均值） | BFS | 天然按层 |
| 路径类（路径总和） | DFS | 需要"根到叶"的路径状态 |

**注意"最小深度"一行**——它有两种解法：带特判的 DFS（$O(n)$，但要走遍全树）与 BFS（最坏 $O(n)$，但通常"更早返回"）。**在"最坏情况"下两者都是 $O(n)$；但在"最好情况"下，BFS 可能只访问很少的节点就返回。** 这正是"最近优先用 BFS"的量化体现。

## 第 4 章 延伸：树的直径（LeetCode 543）

### 4.1 题目

**LeetCode 543 - Diameter of Binary Tree**（简单）

给你一棵二叉树的根节点，返回该树的直径。直径是树中任意两个节点之间最长路径的长度（以边数计）。这条路径可能不经过根节点。

### 4.2 思路：深度类问题的"全局最优"版

**直径的关键在于"路径可能不经过根节点"**——它可能完全落在某棵子树里。于是我们不能简单地"从根往下求深度"，而要**对每个节点，计算"以它为拐点的最长路径"（即左深度 + 右深度），并取全局最大。**

```go
func diameterOfBinaryTree(root *TreeNode) int {
    ans := 0
    var depth func(node *TreeNode) int // 返回子树深度
    depth = func(node *TreeNode) int {
        if node == nil {
            return 0
        }
        left := depth(node.Left)
        right := depth(node.Right)
        // 以当前节点为拐点的路径长度 = 左深度 + 右深度
        if left+right > ans {
            ans = left + right
        }
        return max(left, right) + 1 // 返回深度供父节点用
    }
    depth(root)
    return ans
}
```

**这道题的精髓，是"返回值"与"全局答案"的分工**：**函数返回的是"子树深度"（供父节点计算），而"直径"这一全局最优值则用外部变量 `ans` 累积。** 二者不能混为一谈——这正是第 11 篇（最大路径和）要重点讲的那层抽象。

**它是"深度问题"通往"树形 DP"的桥梁**：最大/最小深度只用到"返回值"，而直径同时用到了"返回值"与"全局状态"。**理解了直径，你就为理解最大路径和铺好了路。**

## 第 5 章 延伸：更多深度与最值问题

### 5.1 N 叉树的最大深度（LeetCode 559）

**题目**：给定一个 N 叉树，找到其最大深度。

**思路与二叉树完全一致**——只是"左右子树"变成了"所有孩子"，取最大：

```go
func maxDepthN(root *NNode) int {
    if root == nil {
        return 0
    }
    best := 0
    for _, c := range root.Children {
        if d := maxDepthN(c); d > best {
            best = d
        }
    }
    return best + 1
}
```

**这道题再次验证了"遍历骨架与结构无关"**——把"两个孩子"换成"多个孩子"，逻辑一字不变。**它也从侧面说明：二叉树的最大深度之所以简单，是因为"取 max + 1"这一骨架本就与"孩子的数量"无关。**

### 5.2 节点与其祖先之间的最大差值（LeetCode 1026）

**题目**：给定二叉树的根节点 `root`，找出存在于不同节点 `A` 和 `B` 之间的最大值 `|A.Val - B.Val|`，其中 `A` 是 `B` 的祖先。

**思路**：**这是"前序携带状态"的典型**——沿途维护"从根到当前节点的最小值和最大值"，每到一个节点就用它与这两个极值算差值：

```go
func maxAncestorDiff(root *TreeNode) int {
    ans := 0
    var dfs func(node *TreeNode, minVal, maxVal int)
    dfs = func(node *TreeNode, minVal, maxVal int) {
        if node == nil {
            return
        }
        // 用当前节点与路径上的极值算差值
        if d := abs(node.Val - minVal); d > ans {
            ans = d
        }
        if d := abs(node.Val - maxVal); d > ans {
            ans = d
        }
        // 更新极值，继续向下
        if node.Val < minVal {
            minVal = node.Val
        }
        if node.Val > maxVal {
            maxVal = node.Val
        }
        dfs(node.Left, minVal, maxVal)
        dfs(node.Right, minVal, maxVal)
    }
    dfs(root, root.Val, root.Val)
    return ans
}
```

**这道题与第 10 篇的"好节点计数"（1448）是同一种模式**——都是"沿路径向下携带一个（或几个）状态，在节点处结算"。**它展示了"路径状态"可以是"极值对"，而不只是"和"或"剩余量"。**

### 5.3 二叉树中的最长交错路径（LeetCode 1372）

**题目**：给你一棵二叉树，返回最长交错路径的长度。交错路径是指"从某节点出发，先向左再向右再向左……"交替前进的路径。

**思路**：**树形 DP 的经典变体**——对每个节点，维护"从它出发、以向左/向右开始的最长交错路径长度"，并取全局最大：

```go
func longestZigZag(root *TreeNode) int {
    ans := 0
    // dfs 返回 (从 node 向左开始的最长交错路径, 向右开始的)
    var dfs func(node *TreeNode) (int, int)
    dfs = func(node *TreeNode) (int, int) {
        if node == nil {
            return -1, -1 // -1 表示"无法从此方向出发"
        }
        _, rightLeft := dfs(node.Left)   // 左子树的"向右开始"长度
        leftRight, _ := dfs(node.Right)  // 右子树的"向左开始"长度
        left := rightLeft + 1            // 从 node 向左：接左子树的向右
        right := leftRight + 1           // 从 node 向右：接右子树的向左
        ans = max(ans, max(left, right))
        return left, right
    }
    dfs(root)
    return ans
}
```

**注意这里 `dfs` 返回的是"一对值"（向左、向右各一个）**——因为父节点需要根据"自己往哪个方向走"来选择子树的哪一个返回值。**这是"返回值设计"的一个新变体：当父节点需要"多个方向的贡献"时，返回值就成了一对（或一组）。** 它与第 11 篇"贡献值 vs 拐点值"是同一族问题——**都在问"父节点到底需要什么"。**

### 5.4 三道延伸题的共性

559、1026、1372 三道题，分别展示了深度/最值问题的三种"状态携带"方式：**559 用"多孩子的最大"、1026 用"路径极值对"、1372 用"方向对"。** 它们的共性是：**都是"沿路径携带状态、在节点处结算"**——区别只在"状态是什么"。**这与第 10 篇的路径专题、第 11 篇的树形 DP 完全同源。**

## 第 6 章 常见误区与自测方法

### 5.1 四个高频误区

**误区一：最小深度直接 `min(左, 右) + 1`。** 会漏掉"单孩子节点"的情形（详见第 2.2 节）。

**误区二：把"根不是叶子"这一点忽略。** 最小深度要求"到叶子"，若根只有一边孩子，它自己不是叶子。

**误区三：最大深度用 BFS 绕远路。** 虽然能求，但 DFS 更简洁，没必要。

**误区四：直径题只从根往下求。** 直径可能不经过根，必须对每个节点求"左深度 + 右深度"并取最大。

### 5.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `nil` | 空树（深度 0） |
| `[1]` | 单节点（深度 1） |
| `[1,2]` | 单左孩子（最小深度陷阱） |
| `[1,null,2]` | 单右孩子（陷阱的另一侧） |
| `[1,2,3,4,5]` | 常规情形 |

**其中 `[1,2]` 与 `[1,null,2]` 是最该测的用例**——它们专治"最小深度直接取 min"这个陷阱，且必须**左右各测一次**（因为陷阱在两侧都可能触发）。

## 第 7 章 深度题的验证与面试表达

### 7.1 深度题的验证要点

深度题的验证，关键是"**用手算一棵小树**"——因为深度的定义容易在"单孩子"情形下被误算。

**验证步骤**：

1. **先用单节点树**（深度应为 1）；
2. **再用单孩子树**（`[1,2]` 与 `[1,null,2]`）——这两棵最容易暴露最小深度陷阱；
3. **最后用完全二叉树**（深度应为 $\log_2(n+1)$）。

**"单孩子树"是必测项**——它是"最小深度陷阱"的唯一触发条件。**凡是最小深度题，先用 `[1,2]` 和 `[1,null,2]` 各测一次。**

### 7.2 一个值得强调的对照

**最大深度与最小深度，在"代码对称性"上是一个陷阱**——它们看起来只差一个 `max`/`min`，实际却差了三行特判。**这提醒我们：不要因为两道题"名字对称"就以为"代码也对称"。** 很多算法的"对称外表"下，藏着"不对称的边界"：

- 最大深度 vs 最小深度：最小深度需要处理"单孩子"；
- 前序遍历 vs 后序遍历的迭代：后序需要"反转"；
- 找最大值 vs 找最小值：找最小值可能受"空集"影响。

**遇到"看起来对称"的问题时，先问一句"它们的边界是否也对称"**——这往往就是难点的所在。

### 7.3 面试表达

深度题的面试表达，建议按这个顺序：

1. **先讲遍历选择**："最大深度用 DFS 后序汇总，最小深度用 BFS 更优。"
2. **再讲关键陷阱**："最小深度要注意——单孩子节点不能直接取 min。"
3. **然后讲复杂度**："时间 $O(n)$，空间 $O(h)$（DFS）或 $O(w)$（BFS）。"
4. **主动补充**："BFS 求最小深度能'首次遇到叶子即返回'，通常比 DFS 更快。"

**第 2、4 步是关键**——它们表明你不是在套模板，而是理解了"为什么最小深度与最大深度不一样"。

> [!info] 一道题的价值，常在它的"陷阱"里
> 最小深度这道题本身不难，但它藏着一个经典陷阱。**很多"简单题"之所以被反复考，正是因为它们的陷阱能区分"理解"与"背模板"。** 面试里，能主动指出陷阱（而非踩中它）的候选人，往往能让面试官眼前一亮。**所以，遇到"看起来简单"的题，更要警惕——它的陷阱，可能正是考点。**

### 7.4 深度与"层级结构"的普遍性

**"深度"这一概念，在计算机科学里无处不在**：文件系统的目录深度、HTML 的 DOM 嵌套深度、JSON 的嵌套深度、递归的调用深度、编译器的作用域层级……**它们都面临同一个问题：如何"按层"或"按深度"处理数据。**

**树的最小/最大深度问题，是这类问题的"最小模型"**——理解了它，你就理解了"如何度量嵌套结构的最远/最近距离"。**而它背后"BFS 求最近、DFS 求最远"的取舍，也可以迁移到任何"嵌套结构"的处理上。**

## 第 8 章 深度与平衡树：从"求深度"到"维护深度"

### 8.1 深度是平衡树的"度量"

前面几篇反复用"深度"来判断平衡（110 题）。**而在真正的平衡树（AVL、红黑树）里，"深度"不只是一个被查询的量，更是一个被"维护"的量。**

以 **AVL 树**为例：它要求"任意节点左右子树高度差不超过 1"，一旦插入/删除破坏了这一条件，就通过**旋转**来恢复。旋转的本质，是"**在不破坏 BST 性质的前提下，把较高的子树的一部分挪给较矮的一侧**"——从而让高度重新平衡。

**理解了"深度是平衡树的度量"，你就明白为什么 110 题（判断平衡）值得反复练**——它是 AVL 树"检查是否需要旋转"这一动作的最小模型。**判断平衡 → 若不满足则旋转 → 重新判断**，这正是 AVL 树插入/删除的循环。

### 8.2 为什么工程不用"每次重算深度"

**朴素地在每次插入后"重算整棵树的高度"是 $O(n)$ 的**——这会毁掉 BST 的 $O(\log n)$ 优势。**工程做法是"在每个节点里缓存它的高度"**：插入/删除时，只更新"从修改点到根"这条路径上节点的高度（$O(\log n)$ 个节点），而不重算全树。

**这就是"用空间换时间"的又一体现**——多存一个 `height` 字段，换来"高度更新只走一条路径"。**它也从反面印证了第 03 篇 110 题的教训**：那道题"先算高度再判平衡"会退化到 $O(n^2)$，正是因为"重复计算高度"；而工程上"缓存高度"，恰恰消除了这种重复。

### 8.3 更多深度变体

**单值二叉树（LeetCode 965）**：判断所有节点的值是否相同。这是"前序携带状态"的简单版——沿途比较"当前值是否等于根值"：

```go
func isUnivalTree(root *TreeNode) bool {
    if root == nil {
        return true
    }
    if root.Left != nil && root.Left.Val != root.Val {
        return false
    }
    if root.Right != nil && root.Right.Val != root.Val {
        return false
    }
    return isUnivalTree(root.Left) && isUnivalTree(root.Right)
}
```

**从根到叶的二进制数之和（LeetCode 1022）**：与第 10 篇的 129 题同构——沿路径累积"二进制数字"，到叶子结算：

```go
func sumRootToLeaf(root *TreeNode) int {
    var dfs func(node *TreeNode, cur int) int
    dfs = func(node *TreeNode, cur int) int {
        if node == nil {
            return 0
        }
        cur = cur*2 + node.Val // 累积二进制位
        if node.Left == nil && node.Right == nil {
            return cur
        }
        return dfs(node.Left, cur) + dfs(node.Right, cur)
    }
    return dfs(root, 0)
}
```

**这两道题分别展示了"深度/路径问题的两种携带状态"**——965 携带"根值"（用于比较），1022 携带"累积数字"（用于结算）。**它们与第 10 篇的路径专题完全同源。**

### 8.4 深度问题的面试追问

**追问一："最大深度和最小深度为什么不对称？"** 答：因为"取 max"时，空子树的 0 不会被选中（不影响结果）；而"取 min"时，空子树的 0 会错误地"变小"结果——所以最小深度必须显式排除单孩子情形。

**追问二："求深度用 BFS 还是 DFS？"** 答：最大深度用 DFS（后序汇总自然）；最小深度用 BFS（首次遇到叶子即返回，更优）。

**追问三："如何判断一棵树是否平衡？"** 答：用"后序返回高度 + 失败哨兵"，一次遍历完成（110 题）。

**追问四："平衡树的深度为什么是 $O(\log n)$？"** 答：因为"左右子树高度差不超过 1"这一约束，使得每往下一层，节点数的规模至多翻倍——反推之，深度至多 $O(\log n)$。

> [!info] 从"求深度"到"理解对数复杂度"
> 深度问题的深层价值，在于它连接了"**树高**"与"**对数复杂度**"这两个概念。**平衡树的 $O(\log n)$ 查找，本质上就是"树高为 $O(\log n)$"**；而二分查找的 $O(\log n)$，也对应着"一棵隐式的平衡判定树"。**理解了"树高 = 对数复杂度"，你就把"平衡"与"高效"这两件事，从直觉上升到了可证明的联系。**

### 8.5 一个跨领域的对照

**"深度"这一概念，在计算机科学里几乎无处不在**——它度量的是"**嵌套的层数**"。而"嵌套层数"直接决定了许多算法的复杂度：

- 递归的调用深度 → 栈空间；
- 树的深度 → 查找复杂度；
- 目录的嵌套深度 → 文件遍历的路径长度；
- JSON/XML 的嵌套深度 → 解析器的栈需求。

**它们共享同一个结论：深度决定资源。** 所以"**如何控制深度**"（平衡树、迭代代替递归、扁平化嵌套）成了一个反复出现的工程命题。**二叉树的最小/最大深度问题，正是这个命题的最小模型**——理解了它，你就理解了"为什么工程上如此在意'嵌套的层数'"。

## 第 9 章 深度题的面试追问与落点

### 9.1 常见追问

**追问一："最小深度为什么不能用 `min(左, 右) + 1`？"** 答：当某节点只有一个孩子时，空的那侧返回 0，会被 `min` 选中，得出错误的偏小结果。

**追问二："BFS 求最小深度为什么更优？"** 答：BFS 按层推进，首次遇到叶子即为最近叶子，可以提前返回，无需遍历全树。

**追问三："树的直径为什么不等于'最大深度 × 2'？"** 答：因为直径可能不经过根——它可能完全落在某棵子树里。必须对每个节点求"左深度 + 右深度"并取最大。

**追问四："深度问题该用 DFS 还是 BFS？"** 答：最大深度用 DFS（后序汇总自然）；最小深度用 BFS（首次遇到叶子即返回）；每层视角用 BFS。

**追问五："递归求深度的空间是多少？"** 答：$O(h)$，最坏（退化成链）是 $O(n)$，可能栈溢出。

### 9.2 一份自查清单

| 检查项 | 对应问题 |
|--------|---------|
| 最小深度是否处理了单孩子 | 经典陷阱 |
| 直径是否"对每个节点"求 | 路径不过根 |
| 叶子判定是否"左右都空" | 单孩子误判 |
| 空树是否返回 0 | 基准情况 |
| 深度题是否选了合适的遍历 | BFS/DFS 取舍 |

### 9.3 落点

**深度专题的落点，是"最近优先用 BFS、最远汇总用 DFS"这条口诀**，以及"**一个递归返回值只应承载一种语义**"这一纪律（最小深度陷阱的根源）。

**更深一层的收获，是"深度 = 嵌套层数"这一抽象**——它把"树高""递归栈深""目录层级""JSON 嵌套"统一成了同一个概念，也解释了"为什么深度决定资源"。**理解了这一点，你就把"树的深度"从一个具体问题，上升成了"嵌套结构"这一更普遍的主题。**

> [!info] 从"一道深度题"到"嵌套结构"
> 最大深度、最小深度、直径、平衡判定——它们都围绕"深度"这一概念。**而"深度"的本质，是"嵌套的层数"。** 一旦这样理解，你就能把树题里的"深度"，与文件系统、JSON、递归调用等场景里的"嵌套"联系起来。**这种"从一个具体问题，上升到一类普遍概念"的能力，正是本专栏反复训练的。**

### 9.4 一个值得记住的对照

**最大深度与最小深度的"不对称"，是一个极好的教学案例**——它告诉我们：**"看起来对称的两个问题，边界可能并不对称"。** 类似的例子还有：

- 前序迭代 vs 后序迭代：后序需要"反转"；
- 找最大值 vs 找最小值：找最小值要处理"空集"；
- 升序数组 vs 降序数组：二分的方向相反。

**遇到"对称"的问题，先问一句"边界是否也对称"**——这往往就是难点的所在。**深度专题用一道"最小深度"，把这个教训讲得清清楚楚。**

---

### 9.5 一个值得记住的边界

**"空树算不算深度 0"是深度题的第一个约定。** 本篇约定 `maxDepth(nil) = 0`、`minDepth(nil) = 0`。**但请注意：这个"0"在最大深度里无害（不会被 max 选中），在最小深度里却会引发歧义**（被 min 选中）。**同一个"空树 = 0"的约定，在两道题里的效果截然相反**——这正是最小深度陷阱的根源。

**这提醒我们：一个约定的"合理性"，取决于它被用在哪里。** 同一个 `0`，在"取 max"的语境下是安全的，在"取 min"的语境下却是危险的。**遇到"看起来合理、结果却错"的 bug，先检查"某个约定在当前语境下是否仍成立"。**

**最后补充一点**：深度题的递归空间是 $O(h)$，对"可能退化成链"的输入（如按有序顺序插入的 BST），递归可能栈溢出——**此时应改用 BFS 或迭代 DFS，把空间从"调用栈"转到"堆上的显式结构"。**

**再补充一点**：BFS 求最大深度也可以——只需在每层结束时更新深度，走完最后一层即为最大深度。**但它比 DFS 多用了 $O(w)$ 的队列空间，所以在"只求最大深度"时，DFS 仍是更简洁的选择。** 因为 BFS 求最大深度必须走完所有层，无法像求最小深度那样"首次遇到叶子即返回"——**"能否提前返回"，正是 BFS 在"最近问题"上的核心优势。** 这也是为什么"最少步数""最短路径"这类问题，几乎都用 BFS 而不是 DFS——**因为它们的答案一旦出现，就可以立即返回，无需探索完整个空间。** 这也就是"最近优先"这四个字的全部含义所在。

## 小结

本篇用"最大深度 vs 最小深度"这一对问题，讲清了深度类问题的核心：**最大深度是"取 max + 1"的后序汇总，天然对称、无需特判；最小深度则必须警惕"空子树不能直接取 min"这一陷阱，且 BFS 往往比 DFS 更优**。延伸的"树的直径"进一步展示了"返回值供父节点用、全局答案用外部变量"这一分工——它是通往树形 DP 的桥梁。

贯穿全篇的核心认知有两条。其一，**"最近优先用 BFS，最远汇总用 DFS"**——这条口诀几乎能定下所有深度类问题的遍历方式。其二，**一个递归返回值只应承载一种语义**——最小深度的陷阱，本质是 `0` 身兼"空"与"长度"二义。**把这两条握住，你面对任何深度类或"最值类"的树题，都能先判断遍历方式、再检查语义歧义。**
