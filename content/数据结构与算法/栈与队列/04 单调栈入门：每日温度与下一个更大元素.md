# 单调栈入门：每日温度与下一个更大元素

**摘要：**

单调栈（Monotonic Stack）是本专栏最重要的技术，也是算法面试中"性价比"最高的知识点之一——模板固定、代码量少，却能解决一大类"下一个更大/更小元素""左右边界"的范围查询问题。它之所以让人初见时感到"巧妙得不像话"，是因为它把"等待未来的某个事件"这一时间上的不确定，转化成了一次简单的栈操作。本文通过三道题逐层建立单调栈的直觉：LeetCode 739（每日温度）建立"维护递减栈、遇到更大元素即结算"的核心范式；LeetCode 496（下一个更大元素 I）引入"两数组映射"的变体；LeetCode 503（下一个更大元素 II）引入"循环数组"的处理技巧。三题一气呵成，彻底打通单调栈的基础用法。本文用 Go 语言完整实现，并逐层追问：为什么"悬而未决"的元素要用栈保存、为什么总复杂度是 $O(n)$、循环数组为什么要遍历两遍。

## 第 1 章 单调栈的直觉来源

### 1.1 从朴素暴力说起

以 LeetCode 739 为例：给定每日气温 `temperatures`，返回 `answer[i]` 表示第 `i` 天之后还需等几天才能遇到更高气温（不存在则为 0）。

```text
temperatures = [73,74,75,71,69,72,76,73]
answer       = [ 1, 1, 4, 2, 1, 1, 0, 0]
```

朴素解法是：对每天 `i`，向右扫描找到第一个 `temperatures[j] > temperatures[i]`，则 `answer[i] = j - i`。时间 $O(n^2)$，$n = 10^5$ 时必然超时。

### 1.2 核心洞察：什么时候才能确定答案

这道题的本质是：**对每个元素 `i`，找到它右边第一个比它大的元素的位置。**

关键问题在于——**元素 `i` 的答案，要到什么时候才能确定？** 答案是：**当我们第一次遇到一个比它更大的元素时。** 在那之前，元素 `i` 是"悬而未决"的，它的答案还藏在未来。

于是问题的形态变得清晰了：我们需要一个容器，用来**暂存那些"还没等到答案"的元素**；当未来某个更大的元素出现时，从这个容器里"结算"一批等待者。

**该用什么容器？答案是栈。** 理由在于：**越晚加入的元素，其位置越靠右，越容易先遇到更大的值，也就越应该先被结算。** 这正是 LIFO 的语义——**最近等待的，最先被满足**。

用一个生活场景类比：设想一群人排队等待"第一个比自己高的人"出现。队伍里的人按到达顺序等待，但每当一个高个子走过来，他能"结清"的往往是**队伍最前面那批恰好比他矮的人**——而离得最近的等待者，最容易先被结清。**栈天然地让"最近的等待者"站在最前面，随时准备被结算。**

### 1.3 单调栈的规则

把上面的直觉写成规则，就得到了**单调递减栈**（从栈底到栈顶单调递减，用于求"下一个更大元素"）：

1. 遍历到元素 `i` 时，不断弹出栈中所有**小于** `temperatures[i]` 的元素——每弹出一个，它的答案就是 `i`（因为它终于等到了第一个比它大的元素）；
2. 把 `i` 压入栈。

遍历结束后，栈中剩余的元素就是"找不到更大值"的，答案为 0。**栈中始终保持"从底到顶单调递减"，这正是"单调栈"这个名字的由来。**

## 第 2 章 LeetCode 739：每日温度

### 2.1 题目

**LeetCode 739 - Daily Temperatures**（中等）

给定每日气温数组 `temperatures`，返回 `answer[i]` 为第 `i` 天后至少等几天才能看到更高气温；若之后都不会升高，该位置为 0。

```text
输入: [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]
```

### 2.2 Go 实现

```go
func dailyTemperatures(temperatures []int) []int {
    n := len(temperatures)
    answer := make([]int, n) // 默认 0，对应"找不到更大值"
    stack := []int{}         // 单调递减栈，存"悬而未决"的下标

    for i := 0; i < n; i++ {
        // 当前温度高于栈顶温度 → 栈顶元素等到了它的"下一个更大值"
        for len(stack) > 0 && temperatures[i] > temperatures[stack[len(stack)-1]] {
            prev := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            answer[prev] = i - prev // 等待的天数
        }
        stack = append(stack, i) // 压入下标（注意：不是温度）
    }
    return answer
}
```

**注意栈里存的是下标而非温度。** 因为要计算"等待的天数"（`i - prev`），下标是必需的信息。**这与第 01 篇"栈里存什么由弹栈时的计算决定"是同一条原则**——这里要算位置差，所以存下标。

### 2.3 逐步模拟

```text
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
indices        [ 0,  1,  2,  3,  4,  5,  6,  7]

i=0, t=73: 栈空，压入 0 → stack=[0]
i=1, t=74: 74>73 → 弹出 0，answer[0]=1-0=1；栈空，压入 1 → stack=[1]
i=2, t=75: 75>74 → 弹出 1，answer[1]=2-1=1；压入 2 → stack=[2]
i=3, t=71: 71<75，不弹，压入 3 → stack=[2,3]
i=4, t=69: 69<71，不弹，压入 4 → stack=[2,3,4]
i=5, t=72:
  72>69 → 弹出 4，answer[4]=5-4=1
  72>71 → 弹出 3，answer[3]=5-3=2
  72<75，停止；压入 5 → stack=[2,5]
i=6, t=76:
  76>72 → 弹出 5，answer[5]=6-5=1
  76>75 → 弹出 2，answer[2]=6-2=4
  栈空，压入 6 → stack=[6]
i=7, t=73: 73<76，压入 7 → stack=[6,7]

遍历结束，stack=[6,7]，answer[6]=answer[7]=0（保持默认）
最终: [1,1,4,2,1,1,0,0] ✓
```

**注意 i=5 时的连锁弹出**：`72` 一次弹出了 `69` 和 `71` 两个元素。**这正是单调栈的精妙——一个新元素可以一次性"结清"它前面所有比它小的等待者，而不必逐个扫描。**

### 2.4 为什么总复杂度是 $O(n)$

一个常见的困惑：内层 `while` 循环看起来可能执行很多次，为什么总时间仍是 $O(n)$？

**关键在于"每个元素最多被压栈一次、弹栈一次"。** 内层 `while` 的每一次执行，都对应着一次弹出；而整个过程中弹出总数不超过入栈总数，即不超过 $n$。于是外层循环 $n$ 次、内层累计 $n$ 次，总操作数是 $O(n)$。

**这是摊还分析的又一次现身**——与线性表专栏里动态数组扩容、第 03 篇双栈队列的搬移分析同出一辙。**看到嵌套循环就断言 $O(n^2)$ 是危险的；真正决定复杂度的，是每个元素在全部循环中被访问的总次数。**

## 第 3 章 LeetCode 496：下一个更大元素 I

### 3.1 题目

**LeetCode 496 - Next Greater Element I**（简单）

给你两个**无重复元素**的数组 `nums1` 与 `nums2`，`nums1` 是 `nums2` 的子集。找出 `nums1` 中每个元素在 `nums2` 中的下一个更大值（右侧第一个更大的元素），不存在则输出 -1。

```text
输入: nums1 = [4,1,2], nums2 = [1,3,4,2]
输出: [-1,3,-1]
```

### 3.2 思路：先建表，再查表

暴力做法是：对 `nums1` 的每个元素，在 `nums2` 中定位它，再向右扫描找更大值，时间 $O(m \cdot n)$。

**优化思路是"预处理 + 查表"**：先对 `nums2` 整体跑一次单调栈，求出 `nums2` 中每个元素的"下一个更大元素"，结果存入哈希表（`值 → 下一个更大值`）；再遍历 `nums1`，直接从哈希表查询即可。

**这道题引入了一个新的变体要素——"映射"。** 单调栈本身只负责在 `nums2` 上求答案，而"如何把答案映射回 `nums1`"则交给哈希表。**把"求答案"与"映射答案"分成两步，是这类"子集查询"问题的通用手法。**

```go
func nextGreaterElement(nums1, nums2 []int) []int {
    // 第一步：对 nums2 用单调栈，建立 值 → 下一个更大值 的映射
    nextGreater := map[int]int{}
    stack := []int{} // 元素无重复，可直接存值
    for _, num := range nums2 {
        for len(stack) > 0 && num > stack[len(stack)-1] {
            nextGreater[stack[len(stack)-1]] = num
            stack = stack[:len(stack)-1]
        }
        stack = append(stack, num)
    }
    // 第二步：查表
    res := make([]int, len(nums1))
    for i, v := range nums1 {
        if g, ok := nextGreater[v]; ok {
            res[i] = g
        } else {
            res[i] = -1 // 栈中剩余元素没有更大值
        }
    }
    return res
}
```

**为什么这里可以存值而非下标？** 因为 `nums2` 元素**无重复**，值本身就能唯一标识一个元素；而且题目要的是"更大值"而非"位置差"。**存值还是存下标，取决于两个条件：元素是否可能重复、以及弹栈时需要什么信息。** 一旦有重复元素，就必须存下标（否则无法区分）。

**手动验证** `nums2 = [1,3,4,2]`：

```text
num=1: 栈空，压 1 → stack=[1]
num=3: 3>1 → 弹 1，nextGreater[1]=3；压 3 → stack=[3]
num=4: 4>3 → 弹 3，nextGreater[3]=4；压 4 → stack=[4]
num=2: 2<4 → 压 2 → stack=[4,2]
遍历结束，栈中 [4,2] 均无更大值

nextGreater = {1:3, 3:4}
查询 nums1=[4,1,2]: 4→-1，1→3，2→-1 ✓
```

**复杂度**：时间 $O(m + n)$，空间 $O(n)$。

## 第 4 章 LeetCode 503：下一个更大元素 II（循环数组）

### 4.1 题目

**LeetCode 503 - Next Greater Element II**（中等）

给定一个**循环数组** `nums`（最后一个元素的下一个是第一个元素），返回每个元素的下一个更大元素。

```text
输入: nums = [1,2,1]
输出: [2,-1,2]
```

### 4.2 处理循环数组：遍历两遍

循环数组问题的标准处理方式是**遍历两遍**（等价于把数组长度视为 `2n`，下标用取模 `% n` 处理）。

**直觉是这样的**：在循环数组中，任何元素最多向右看 `n - 1` 步就能找到下一个更大元素，或确认不存在。**遍历两遍，第一遍处理"右边"的更大值，第二遍处理"绕回来"的更大值**——对第一遍中"悬而未决"的元素来说，第二遍给了它们一次"从数组开头绕回来"的机会。

```go
func nextGreaterElements(nums []int) []int {
    n := len(nums)
    res := make([]int, n)
    for i := range res {
        res[i] = -1 // 默认找不到更大值
    }
    stack := []int{}

    for i := 0; i < 2*n; i++ { // 遍历 2n 次，模拟循环
        idx := i % n
        for len(stack) > 0 && nums[idx] > nums[stack[len(stack)-1]] {
            res[stack[len(stack)-1]] = nums[idx]
            stack = stack[:len(stack)-1]
        }
        if i < n { // 只在第一遍压栈，避免同一元素被压两次
            stack = append(stack, idx)
        }
    }
    return res
}
```

**手动验证** `nums = [1,2,1]`：

```text
res 初始: [-1,-1,-1]

i=0, idx=0, num=1: 栈空，压 0 → stack=[0]
i=1, idx=1, num=2: 2>1 → 弹 0，res[0]=2；压 1 → stack=[1]
i=2, idx=2, num=1: 1<2，压 2 → stack=[1,2]

i=3, idx=0, num=1: nums[stack顶=2]=1，1 不严格大于 1 → 不弹；i>=n 不压
i=4, idx=1, num=2: nums[stack顶=2]=1，2>1 → 弹 2，res[2]=2
                   再比 nums[stack顶=1]=2，2 不严格大于 2 → 不弹；i>=n 不压
i=5, idx=2, num=1: 1<2，不弹；i>=n 不压

栈中剩余 [1]，res[1] 保持 -1
最终: [2,-1,2] ✓
```

> [!note] 为什么第二遍不压栈
> 第二遍的目的是让第一遍"悬而未决"的元素有机会找到绕回来的更大值。第一遍已压入的下标，在第二遍中只需被弹出（结算），**若再压一次，同一元素就会被重复结算，`res` 会被错误覆盖。** 所以 `if i < n` 这个条件不能省——它保证每个元素只入栈一次。

### 4.3 另一种写法：两个独立的循环

若觉得 `2n` 加取模不直观，也可以写成两个独立的 `for` 循环——第一遍正常单调栈，第二遍只负责"处理绕回来"（只弹不压）：

```go
func nextGreaterElements2(nums []int) []int {
    n := len(nums)
    res := make([]int, n)
    for i := range res {
        res[i] = -1
    }
    stack := []int{}

    for i := 0; i < n; i++ { // 第一遍：正常单调栈
        for len(stack) > 0 && nums[i] > nums[stack[len(stack)-1]] {
            res[stack[len(stack)-1]] = nums[i]
            stack = stack[:len(stack)-1]
        }
        stack = append(stack, i)
    }
    for i := 0; i < n; i++ { // 第二遍：只弹不压
        for len(stack) > 0 && nums[i] > nums[stack[len(stack)-1]] {
            res[stack[len(stack)-1]] = nums[i]
            stack = stack[:len(stack)-1]
        }
    }
    return res
}
```

两种写法完全等价。**前者更紧凑（一个循环 + 取模），后者更直白（两个循环各司其职）——取舍在"紧凑"与"可读"之间，与第 12 篇反转链表的迭代/递归取舍同源。**

**复杂度**：时间 $O(n)$（每个元素最多入栈一次、弹栈一次），空间 $O(n)$。

## 第 5 章 单调栈的统一模板与变体

### 5.1 问题类型识别

单调栈适用于这样的特征：**对数组中每个元素，找到右边（或左边）第一个满足某种大小关系的元素。**

| 问题类型 | 栈的类型（底→顶） | 弹栈条件 |
|---------|-----------------|---------|
| 下一个更大元素 | 单调递减 | 当前元素 > 栈顶元素 |
| 下一个更小元素 | 单调递增 | 当前元素 < 栈顶元素 |
| 上一个更大元素（向左找） | 单调递减 | 从右向左遍历 |
| 左右两侧边界（同时） | 视题意 | 弹栈时同时确定左右边界 |

### 5.2 通用模板

```go
// 求每个元素的"下一个更大元素"（单调递减栈）
stack := []int{}
for i := 0; i < n; i++ {
    for len(stack) > 0 && nums[i] > nums[stack[len(stack)-1]] {
        idx := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        // 结算 idx：它的下一个更大值是 nums[i]，位置差是 i - idx
        result[idx] = /* 视题意 */
    }
    stack = append(stack, i)
}
// 栈中剩余元素找不到更大值，按题意处理（0 或 -1）
```

**这个模板的三处"旋钮"值得记住**：① 存值还是存下标（取决于元素是否重复、以及需要什么信息）；② 弹栈条件用 `>` 还是 `<`（决定求"更大"还是"更小"）；③ 结算时怎么用 `i` 和 `idx`（决定求的是值、还是距离、还是面积）。

### 5.3 变体快查

| 变体 | 修改点 |
|------|--------|
| 存值而非下标 | 无重复元素时可存值；有重复必须存下标 |
| 循环数组 | 遍历 `2n`，下标 `% n`；或两个独立循环 |
| 从右往左扫描 | 遍历方向反转，用于求"上一个更大" |
| 求左右两侧边界（第 05 篇） | 两次扫描，或弹栈时同时确定左右边界 |

## 第 6 章 延伸：单调栈的更多面孔

### 6.1 商品折扣后的最终价格（LeetCode 1475）

**题目**：给你一个数组 `prices`，对每个商品，找出它右边第一个价格不大于它的商品，用那个价格作为折扣。若不存在，则不打折。返回最终价格。

这道题就是"下一个更小或相等元素"——**只需把模板里的 `>` 换成 `>=`**：

```go
func finalPrices(prices []int) []int {
    n := len(prices)
    res := make([]int, n)
    copy(res, prices)
    stack := []int{}
    for i := 0; i < n; i++ {
        // 找右边第一个"不大于"当前价格的商品
        for len(stack) > 0 && prices[i] <= prices[stack[len(stack)-1]] {
            idx := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            res[idx] = prices[idx] - prices[i] // 打折
        }
        stack = append(stack, i)
    }
    return res
}
```

**这道题说明：单调栈的"更大"与"更小"，只差一个比较符号。** 把模板的旋钮②（弹栈条件）转一下，题目就从"下一个更大"变成了"下一个更小"。

### 6.2 股票价格跨度（LeetCode 901）

**题目**：设计一个 `StockSpanner`，每次输入当天股价，返回"今天为止，连续多少个交易日股价不高于今天"。

这道题是"**向左**找下一个更大元素"——需要把遍历方向反过来（或等价地，维护一个单调递减栈，新元素弹出所有小于等于它的元素，跨度 = 当前下标 − 弹出后栈顶的下标）：

```go
type StockSpanner struct {
    prices []int
    stack  []int // 单调递减栈，存下标
}

func (s *StockSpanner) Next(price int) int {
    i := len(s.prices)
    s.prices = append(s.prices, price)
    for len(s.stack) > 0 && s.prices[s.stack[len(s.stack)-1]] <= price {
        s.stack = s.stack[:len(s.stack)-1]
    }
    span := i + 1
    if len(s.stack) > 0 {
        span = i - s.stack[len(s.stack)-1]
    }
    s.stack = append(s.stack, i)
    return span
}
```

**这道题与第 739 题的差别在于"结算时机"**：739 题是"新元素结算旧元素"（弹出时结算被弹出的），901 题是"新元素结算自己"（用弹出后的栈顶算自己的跨度）。**同一个单调栈，结算对象不同，答案就不同——这提示我们：单调栈的模板虽固定，但"谁来结算、结算什么"是每道题真正需要想清楚的地方。**

### 6.3 链表中的下一个更大节点（LeetCode 1019）

**题目**：给定一个链表，返回每个节点的下一个更大值。

这道题把单调栈从数组搬到了链表——**做法完全一样，只是把"下标"换成了"节点指针"，把"数组访问"换成了"遍历链表"**：

```go
func nextLargerNodes(head *ListNode) []int {
    var vals []int
    for node := head; node != nil; node = node.Next {
        vals = append(vals, node.Val)
    }
    res := make([]int, len(vals))
    stack := []int{}
    for i := 0; i < len(vals); i++ {
        for len(stack) > 0 && vals[i] > vals[stack[len(stack)-1]] {
            res[stack[len(stack)-1]] = vals[i]
            stack = stack[:len(stack)-1]
        }
        stack = append(stack, i)
    }
    return res
}
```

**这道题有力地说明：单调栈依赖的从来不是"数组"这个载体，而是"元素之间存在顺序"这一性质。** 链表同样有顺序，所以单调栈照用不误——**只需先把链表的值读进一个数组，或直接在下标上操作。**

### 6.4 三道延伸题给我们的

三道题分别展示了单调栈的三种"变形"：1475 改比较符号（更大→更小），901 改结算对象（结算别人→结算自己），1019 改数据载体（数组→链表）。**它们共同印证了第 5 章那张"旋钮表"的价值：单调栈的模板是固定的，题目之间的差异，全在那三处旋钮上。** 把这三处想清楚，你就能把单调栈迁移到几乎所有"范围最值"类问题上。

## 第 7 章 常见误区与自测方法

### 7.1 四个高频误区

**误区一：栈里存了温度而非下标。** 求"等待天数"需要位置差，必须存下标。

**误区二：循环数组（503）第二遍还压栈。** 会导致同一元素被重复结算，`res` 被错误覆盖。

**误区三：用 `<` 还是 `<=` 搞不清。** 求"严格更大"用 `>`；若题目允许"相等也算"，则要用 `>=`（如 1475 的"不大于"）。**符号的选择，取决于题目对"更大"的定义是否严格。**

**误区四：忘记处理栈中剩余元素。** 遍历结束后栈里还有"找不到更大值"的元素，需要按题意赋 0 或 -1。

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `[1,1,1]` | 相等元素（严格/非严格的边界） |
| `[5,4,3,2,1]` | 单调递减（全部找不到更大值） |
| `[1,2,3,4,5]` | 单调递增（全部立即结算） |
| `[2,1,2]`（503） | 循环数组的绕回 |

**其中 `[1,1,1]` 最能暴露"严格性"的 bug**：若题目要求"严格更大"，相等的元素之间不应互相结算；若用了 `>=` 就会出错。**凡是涉及"更大/更小"，都先问一句"相等算不算"，再决定用 `>` 还是 `>=`。**

## 第 8 章 单调栈的另一种用法：构造字典序最小的序列

前面几道题的单调栈，都是"求答案"——找下一个更大元素、算距离。但单调栈还有另一种截然不同的用法：**构造一个满足约束的、字典序最小的序列**。这类题在面试里同样高频，思路却别有一番风味。

### 8.1 移掉 K 位数字（LeetCode 402）

**题目**：给定一个以字符串表示的非负整数 `num` 和一个整数 `k`，移除这个数中的 `k` 位数字，使得剩下的数字最小。

**关键观察**：要"剩下的数字最小"，本质上是要让高位尽可能小。**从左往右扫描时，一旦发现"当前数字比前一位小"，就应该把前一位删掉**——因为删掉那个较大的前位、让当前较小的数字顶上来，会让整个数变小。这正是单调栈的动作：

```go
func removeKdigits(num string, k int) string {
    stack := []byte{}
    for i := 0; i < len(num); i++ {
        // 当前数字更小，且还有删除名额 → 弹出栈顶（删掉较大的前位）
        for k > 0 && len(stack) > 0 && stack[len(stack)-1] > num[i] {
            stack = stack[:len(stack)-1]
            k--
        }
        stack = append(stack, num[i])
    }
    // 若还有剩余删除名额，从末尾删（此时栈是单调不减的）
    stack = stack[:len(stack)-k]
    // 去掉前导 0
    i := 0
    for i < len(stack) && stack[i] == '0' {
        i++
    }
    if i == len(stack) {
        return "0"
    }
    return string(stack[i:])
}
```

**这道题的栈是"单调不减栈"**——弹出条件不是"当前更大"，而是"当前更小"（且还有删除名额）。**它把单调栈从"找答案"变成了"做选择"**：每次弹栈，都是在做一次"删掉谁"的贪心决策。**这类"用单调栈做贪心选择"的题，是单调栈的一个重要分支。**

### 8.2 去除重复字母（LeetCode 316）

**题目**：给你一个字符串，去除重复字母，使每个字母只出现一次，且结果字典序最小。

**思路**：这题比 402 更绕，因为它有两个约束——"每个字母只出现一次"与"字典序最小"。做法仍是单调栈，但弹栈条件多了一层判断：**只有当"栈顶字母在当前位置之后还会再出现"时，才敢把它弹掉**（否则弹了就永远缺了这个字母）。

```go
func removeDuplicateLetters(s string) string {
    last := [26]int{} // 每个字母最后出现的位置
    for i := 0; i < len(s); i++ {
        last[s[i]-'a'] = i
    }
    used := [26]bool{}
    stack := []byte{}
    for i := 0; i < len(s); i++ {
        c := s[i]
        if used[c-'a'] {
            continue // 已在栈中，跳过
        }
        // 栈顶更大、且之后还会出现 → 弹出
        for len(stack) > 0 && stack[len(stack)-1] > c && last[stack[len(stack)-1]-'a'] > i {
            used[stack[len(stack)-1]-'a'] = false
            stack = stack[:len(stack)-1]
        }
        stack = append(stack, c)
        used[c-'a'] = true
    }
    return string(stack)
}
```

**这道题展示了单调栈的一个更高阶的用法：弹栈条件不再是单一的比较，而是"比较 + 一个额外的可行性约束"。** 这提示我们：**单调栈的骨架是固定的（单调 + 弹栈），但"何时允许弹栈"这一条件，可以叠加任意多的约束**——只要每次弹栈都是"安全的"（不会破坏最终结果的可行性）。

### 8.3 两类单调栈的对照

把第 4 章与本章的两类用法并排看，会看到单调栈的两副面孔：

| 类型 | 目标 | 弹栈条件 | 代表题 |
|------|------|---------|--------|
| 求答案型 | 找下一个更大/更小元素、算距离/面积 | 当前元素与栈顶的大小关系 | 739、496、503、84 |
| 做选择型 | 构造字典序最小的序列 | 大小关系 + 额外约束 | 402、316 |

**求答案型的单调栈，弹栈是"因为已经不需要它了"；做选择型的单调栈，弹栈是"因为现在删掉它更好"。** 前者是被动的（答案已定），后者是主动的（贪心选择）。**理解了这两类，你对单调栈的认识就完整了——它不只是一个"查询工具"，也是一个"构造工具"。**

### 8.4 一个"不能用单调栈"的反例

需要提醒的是，单调栈并非万能。**它的前提是"存在某种单调性，使得一旦某元素被处理，就再也不会影响后续"。** 若问题不满足这个前提，单调栈就会失效。

例如"求数组中所有元素的中位数"——中位数不满足"某个元素一旦确定就不影响后续"的性质（新元素可能改变中位数），因此无法用单调栈维护。**这类问题需要别的结构（如两个堆）。判断"能不能用单调栈"，本质就是问"这里有没有可利用的单调性"。**

## 第 9 章 单调栈的面试表达与常见追问

### 9.1 如何讲清一道单调栈题

单调栈的代码很短，但面试官真正想听的，是**"为什么可以弹栈"**。建议这样组织表达：

1. **点明本质**："这题要的是'下一个更大元素'，本质是对每个元素找右边第一个比它大的位置。"
2. **说清"悬而未决"**："一个元素的答案，要等到第一次遇到比它大的元素才确定；在那之前它是'悬而未决'的。"
3. **解释为何用栈**："越晚加入的元素越靠右、越容易先遇到更大值，所以用栈——最近等待的最先被满足。"
4. **给出模板**："遍历时不断弹出栈中比当前小的元素（它们找到了答案），再把当前下标压栈。"
5. **交代复杂度**："每个元素至多进出栈一次，总时间 $O(n)$。"

**第 3 步是分水岭**——它解释了"为什么偏偏是栈"，而不是"我背了这个模板"。

### 9.2 三类常见追问

**追问一："为什么总复杂度是 $O(n)$，而不是 $O(n^2)$？"** 答：内层 `while` 每次执行都对应一次弹出，而弹出总数不超过入栈总数 $n$。**"每个元素进出各一次"这一论点，是回答所有单调栈复杂度问题的标准答案。**

**追问二："栈里该存值还是存下标？"** 答：取决于弹栈时要算什么。要算距离/位置差，必须存下标；无重复元素且只要值，可以存值。**有重复元素时，必须存下标**（否则无法区分）。

**追问三："相等元素算不算'更大'？"** 答：取决于题意。求"严格更大"用 `>`；若"相等也算满足"则用 `>=`。**先问清题意对'更大'的定义是否严格，再决定符号。**

### 9.3 一个贯穿的落点

单调栈之所以在面试中"性价比"极高，是因为它**模板固定、变体丰富、且能覆盖大量'范围最值'问题**。但真正拉开差距的，不是会不会写模板，而是**能不能把"为什么可以弹栈"讲清楚**。

**这类"丢弃型"算法的正确性，全都系于那个"丢弃判据"**——单调栈的判据是"遇到更大/更小者即可结算"，单调队列的判据是"被右边更大者盖住即可丢弃"。**面试时若能主动把判据说出来，就等于向面试官证明了你不是在背模板。** 这与第 06 篇反复强调的"讲清为什么可以丢"是同一个要求。

## 小结

本篇用三道题打通了单调栈的基础用法。LeetCode 739 建立了核心范式——**把"等待未来的更大值"这一时间上的不确定，转化成"用栈暂存悬而未决者、遇更大者即结算"**，其 $O(n)$ 复杂度由"每个元素至多进出栈一次"保证；LeetCode 496 引入"先建表、再查表"的两步法，处理子集查询的映射问题；LeetCode 503 则用"遍历两遍"化解循环数组的绕回。延伸的三道题进一步说明：单调栈的模板是固定的，差异全在"比较符号""结算对象""数据载体"这三处旋钮上。

贯穿全篇的核心认知有两条。其一，**单调栈的本质，是用"单调性"保证"一旦某元素被弹出，它就再也不会影响后续"**——这份"一次性"正是 $O(n)$ 的根据。其二，**栈里存什么、何时弹、弹后怎么算，是解每一道单调栈题必须想清的三件事**，而它们都可以从题目的"要什么答案"倒推出来。**把这两条记住，单调栈就不再是一段需要背诵的模板，而是一种可以现场推导的思维。**

### 一句话带走

如果只能带走一句话，那就是：**"单调栈的本质，是用'单调性'保证'一旦弹出，就再不必回头'。"** 这份"一次性"，正是 $O(n)$ 的根据，也是它区别于朴素枚举的关键。**当你遇到"对每个元素找右边/左边第一个满足某条件的元素"这类问题时，先问一句"这个条件有没有单调性"，单调栈就会自己浮现。**
