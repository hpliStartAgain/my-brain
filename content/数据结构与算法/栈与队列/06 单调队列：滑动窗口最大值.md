# 单调队列：滑动窗口最大值

**摘要：**

单调队列（Monotonic Deque）是在双端队列（Deque）上施加单调性约束的数据结构，专为"滑动窗口内的极值"而生。它的精妙之处在于一句可证明的洞察：**窗口内若有两个元素 `i < j` 且 `nums[i] <= nums[j]`，那么 `i` 永远不可能成为任何包含 `j` 的窗口的最大值**——于是 `i` 可以被安全丢弃。正是这句"可丢弃"的判定，把每次查询最值的 $O(k)$ 压到了 $O(1)$，让整道题从 $O(nk)$ 降到 $O(n)$。本文以 LeetCode 239（Sliding Window Maximum）为核心，先对比暴力与堆两种朴素方案，再完整推导单调队列的操作规则与实现；随后辨析单调队列与单调栈的异同，并展示它在 DP 优化中的应用（跳跃游戏 VI）；最后给出几道延伸题与面试表达套路。本文用 Go 语言完整实现，并逐层追问：为什么被"盖住"的元素可以丢、为什么要用双端队列、以及 `<=` 与 `<` 之争的本质。

## 第 1 章 问题与朴素思路

### 1.1 题目

**LeetCode 239 - Sliding Window Maximum**（困难）

给你一个整数数组 `nums` 和一个大小为 `k` 的滑动窗口，窗口从最左滑到最右，每次右移一位。返回每个窗口位置的最大值。

```text
输入: nums = [1,3,-1,-3,5,3,6,7], k = 3
输出: [3,3,5,5,6,7]

窗口位置                最大值
[1  3  -1] -3  5  3  6  7   →  3
 1 [3  -1  -3] 5  3  6  7   →  3
 1  3 [-1  -3  5] 3  6  7   →  5
 1  3  -1 [-3  5  3] 6  7   →  5
 1  3  -1  -3 [5  3  6] 7   →  6
 1  3  -1  -3  5 [3  6  7]  →  7
```

### 1.2 暴力 $O(nk)$

最直接的做法：每次窗口移动后，线性扫描窗口内 `k` 个元素找最大值。时间 $O(nk)$，$n = 10^5$、$k = 10^4$ 时接近 $10^9$ 次操作，必然超时。

### 1.3 堆方案 $O(n \log k)$

维护一个大小为 `k` 的最大堆：每次滑动时加入新元素，查询堆顶即为最大值。但标准堆**不支持 $O(1)$ 删除任意元素**（只能删堆顶），于是需要一个技巧——**惰性删除（lazy deletion）**：堆里存 `(值, 下标)` 对，每次 `peek` 时检查堆顶的下标是否还在窗口内，若已滑出就弹出，直到堆顶在窗口内为止。

```go
// 堆 + 惰性删除（示意）
// 用 container/heap 实现一个按值降序的最大堆
```

时间 $O(n \log n)$（堆中可能堆积 $O(n)$ 个待惰性删除的元素），空间 $O(n)$。**它能通过评测，却不是最优解。** 它暴露了一个信号：既然"查询最值"只需要堆顶，而我们却在维护一整堆可能永远用不上的元素，那么**一定有一部分元素是"多余"的**——这正是单调队列的切入口。

## 第 2 章 单调队列：$O(n)$ 的最优解

### 2.1 核心洞察：哪些元素可以被丢弃

**关键观察**：若窗口内有两个元素，位置 `i < j` 且 `nums[i] <= nums[j]`，那么 **`i` 永远不可能成为任何包含 `j` 的窗口的最大值**。

**为什么？** 因为 `j` 在 `i` 右边、且值不小于 `i`，所以 `j` 会比 `i` 更晚离开窗口；在 `i` 还留在窗口里的所有时刻，`j` 也一定还在窗口里，而且 `j` 的值不更小。于是只要 `j` 在，`i` 就永远当不成最大值——**`i` 是被 `j` "盖住"的，可以安全丢弃。**

**这一句判定，就是单调队列的全部秘密。** 它把"维护窗口内所有元素"这一冗余工作，削减成了"只维护那些没有被右边更大元素盖住的元素"——而这些元素恰好构成一个单调递减的序列。

于是数据结构浮现了：**一个从头到尾单调递减的双端队列**，队头始终是当前窗口的最大值。

### 2.2 操作规则

- **入队**（新元素 `nums[i]` 进窗）：从**队尾**移除所有小于等于 `nums[i]` 的元素（它们被 `nums[i]` 永久盖住），再把 `i` 加入队尾。
- **出队**（窗口左端元素离开）：检查队头下标是否已滑出窗口（`deque[0] <= i - k`），若是，从**队头**移除。
- **查询**：队头下标对应的值即为当前窗口最大值。

**注意这里同时用到了队列的两端**：从队尾删"被盖住的"，从队头删"过期的"。**这正是必须用双端队列（Deque）的原因**——普通队列只能一端进出，栈只能一端进出，都不够用。

### 2.3 Go 实现

```go
func maxSlidingWindow(nums []int, k int) []int {
    n := len(nums)
    result := make([]int, n-k+1)
    deque := []int{} // 存下标，其对应值从队头到队尾单调递减

    for i := 0; i < n; i++ {
        // 1. 从队尾移除所有值 <= nums[i] 的下标（被 nums[i] 盖住）
        for len(deque) > 0 && nums[deque[len(deque)-1]] <= nums[i] {
            deque = deque[:len(deque)-1]
        }
        // 2. 当前下标入队
        deque = append(deque, i)
        // 3. 从队头移除已滑出窗口的下标
        if deque[0] <= i-k {
            deque = deque[1:]
        }
        // 4. 窗口填满后，队头即最大值
        if i >= k-1 {
            result[i-k+1] = nums[deque[0]]
        }
    }
    return result
}
```

### 2.4 逐步模拟

```text
nums = [1,3,-1,-3,5,3,6,7], k=3
deque 存下标，队头在左

i=0, nums[0]=1: 队列空 → 入队 → deque=[0]；未满窗
i=1, nums[1]=3: nums[0]=1 <= 3 → 移除 0；入队 1 → deque=[1]；未满窗
i=2, nums[2]=-1: nums[1]=3 > -1 → 不移除；入队 2 → deque=[1,2]
                 i>=2 → result[0]=nums[1]=3 ✓
i=3, nums[3]=-3: nums[2]=-1 > -3 → 不移除；入队 3 → deque=[1,2,3]
                 队头 1 <= 3-3=0? 否 → result[1]=nums[1]=3 ✓
i=4, nums[4]=5: nums[3]=-3<=5 移除3；nums[2]=-1<=5 移除2；nums[1]=3<=5 移除1
                 入队 4 → deque=[4]；队头 4<=4-3=1? 否 → result[2]=nums[4]=5 ✓
i=5, nums[5]=3: nums[4]=5 > 3 → 不移除；入队 5 → deque=[4,5]
                 队头 4<=5-3=2? 否 → result[3]=nums[4]=5 ✓
i=6, nums[6]=6: nums[5]=3<=6 移除5；nums[4]=5<=6 移除4；入队 6 → deque=[6]
                 队头 6<=6-3=3? 否 → result[4]=nums[6]=6 ✓
i=7, nums[7]=7: nums[6]=6<=7 移除6；入队 7 → deque=[7]
                 队头 7<=7-3=4? 否 → result[5]=nums[7]=7 ✓

最终: [3,3,5,5,6,7] ✓
```

**注意 i=4 时的连锁清理**：`5` 一次就把队尾的 `-3`、`-1`、`3` 全部盖住并移除。**这正是单调队列的高效所在——一个新元素可以一次性丢弃它左边所有不大于它的元素，而不必逐个保留。**

### 2.5 复杂度：为什么是 $O(n)$

**时间 $O(n)$**：每个元素最多入队一次（`append`），被弹出一次（要么在队尾被"盖住"时弹出，要么在队头因过期弹出）。内层 `for` 虽然可能多次执行，但总弹出次数不超过 $n$。于是外层 $n$ 次、内层累计 $n$ 次，总操作数是 $O(n)$——**又是一次摊还分析**，与第 04、05 篇的单调栈分析同源。

**空间 $O(k)$**：队列中最多同时存在 `k` 个元素（窗口大小）。

**三种方案对照**：

| 方案 | 时间 | 空间 | 实现复杂度 |
|------|------|------|----------|
| 暴力 | $O(nk)$ | $O(1)$ | 简单 |
| 堆 + 惰性删除 | $O(n \log n)$ | $O(n)$ | 中等 |
| 单调队列 | $O(n)$ | $O(k)$ | 中等 |

**单调队列之所以完胜堆**，是因为它丢弃了"永远用不上"的元素——**堆保留了所有元素（哪怕它们永远当不成最大值），而单调队列只保留那些"可能成为最大值"的候选。** 这一句"只保留候选"，正是 $O(n \log n)$ 到 $O(n)$ 的关键。

## 第 3 章 单调队列 vs 单调栈

单调栈与单调队列形似，解决的问题却不同，值得逐项对照：

| 特性 | 单调栈 | 单调队列 |
|------|--------|---------|
| 底层结构 | 栈（一端进出） | 双端队列（两端都可操作） |
| 解决的问题 | "下一个更大/更小元素"、前后边界 | "窗口内的极值" |
| 元素的生命周期 | 弹出后永久消失 | 因"超出窗口"或"被盖住"而消失 |
| 主要操作 | 从同一端入栈和弹栈 | 从队尾入队、从队尾或队头弹出 |

**关键区别在于"从两端操作"**：单调队列既要从**队尾**删除被新元素盖住的旧元素（维护单调性），又要从**队头**删除滑出窗口的过期元素（维护窗口范围）。**正是这个"两端"的需求，逼出了双端队列。**

> [!note] 一个统一的视角
> 单调栈与单调队列，其实都是"**用单调性维持一个候选集**"——只不过单调栈的候选集是"等待未来答案的元素"，单调队列的候选集是"当前窗口内可能成为极值的元素"。**它们丢弃元素的判据不同（栈看'有没有遇到更大/更小'，队列看'有没有被右边更大的盖住'），但底层逻辑一致：单调性保证'一旦丢弃，就不必回头'。** 理解了这个统一视角，你就不会把它们当成两个孤立的技巧。

## 第 4 章 单调队列优化 DP

### 4.1 一个更深的用途

单调队列最重要的进阶应用，是**优化动态规划**。当 DP 的转移方程里，某个维度的转移是从"一段连续下标的最值"推导而来时，单调队列可以把这步 $O(k)$ 的转移优化到 $O(1)$，总复杂度从 $O(nk)$ 降到 $O(n)$。

**典型例子：跳跃游戏 VI（LeetCode 1696）**。给定数组 `nums` 与最大步长 `k`，从下标 0 出发，每次可向前跳 1 到 `k` 步，求到达末尾能获得的最大分数。转移方程是：

$$dp[i] = nums[i] + \max_{i-k \le j < i} dp[j]$$

**注意这个 `max` 的范围**——它是"过去 `k` 步内的 `dp` 最大值"，正是**滑动窗口最大值**的结构。于是可以用单调队列维护 `dp[j]` 的窗口最大值。

```go
func maxResult(nums []int, k int) int {
    n := len(nums)
    dp := make([]int, n)
    dp[0] = nums[0]
    deque := []int{0} // 存下标，对应 dp 值单调递减

    for i := 1; i < n; i++ {
        // 移除超出 k 步范围的队头
        for len(deque) > 0 && deque[0] < i-k {
            deque = deque[1:]
        }
        // 队头即过去 k 步内 dp 最大值的下标
        dp[i] = nums[i] + dp[deque[0]]
        // 维护单调递减队列
        for len(deque) > 0 && dp[deque[len(deque)-1]] <= dp[i] {
            deque = deque[:len(deque)-1]
        }
        deque = append(deque, i)
    }
    return dp[n-1]
}
```

**这道题的启示很大**：单调队列不只是"求滑动窗口最大值"这一道题的工具，它是**一类 DP 优化的通用手段**——只要转移里出现"区间最值"，就有单调队列的用武之地。**这把单调队列从"一道题的技巧"提升成了"一种优化模式"。**

### 4.2 相关变体

| 题目 | 变体 | 核心修改 |
|------|------|---------|
| LeetCode 239（本题） | 滑动窗口最大值 | 标准模板 |
| LeetCode 1696（Jump Game VI） | DP 优化 | 单调队列维护 DP 值 |
| LeetCode 862（和至少为 K 的最短子数组） | 前缀和 + 单调队列 | 用单调**递增**队列找最小前缀和 |
| LeetCode 1438（绝对差不超过限制的最长连续子数组） | 双单调队列 | 同时维护窗口最大值与最小值 |

**注意 862 与 1438 的变体方向**：862 用的是单调**递增**队列（因为要的是最小前缀和），1438 则要**同时**维护最大值与最小值两条队列。**它们说明"单调递减"只是求最大值的特例——把比较方向反过来，就能求最小值。**

## 第 5 章 延伸：单调队列的更多面孔

### 5.1 和至少为 K 的最短子数组（LeetCode 862）

**题目**：给定整数数组 `nums` 和整数 `k`，找出和为至少 `k` 的最短非空子数组的长度。

**思路**：先用前缀和 `prefix[i]` 表示前 `i` 个元素之和，则"子数组 `[j+1, i]` 的和"是 `prefix[i] - prefix[j]`，条件变成 `prefix[i] - prefix[j] >= k`，即 `prefix[j] <= prefix[i] - k`。要"最短"，就希望在满足条件的 `j` 中取最大的那个。用**单调递增队列**维护前缀和的下标，队头即"最小的前缀和"，配合滑动窗口处理：

```go
func shortestSubarray(nums []int, k int) int {
    n := len(nums)
    prefix := make([]int, n+1)
    for i, v := range nums {
        prefix[i+1] = prefix[i] + v
    }
    deque := []int{} // 单调递增队列，存前缀和下标
    minLen := n + 1
    for i := 0; i <= n; i++ {
        // 队头若满足条件，更新答案并从队头移除（它已不可能更优）
        for len(deque) > 0 && prefix[i]-prefix[deque[0]] >= k {
            if i-deque[0] < minLen {
                minLen = i - deque[0]
            }
            deque = deque[1:]
        }
        // 维护单调递增
        for len(deque) > 0 && prefix[deque[len(deque)-1]] >= prefix[i] {
            deque = deque[:len(deque)-1]
        }
        deque = append(deque, i)
    }
    if minLen == n+1 {
        return -1
    }
    return minLen
}
```

**这道题是"单调队列 + 前缀和"的组合**，也是"队列求最小值"的范例——把第 239 题的比较方向反过来即可。**它把单调队列从"窗口内元素"扩展到了"前缀和序列"，展示了一个数据结构可以被应用在多么抽象的对象上。**

### 5.2 绝对差不超过限制的最长连续子数组（LeetCode 1438）

**题目**：给定数组 `nums` 和整数 `limit`，返回最长连续子数组的长度，使该子数组内任意两个元素的绝对差不超过 `limit`。等价于"最大值 − 最小值 ≤ limit"。

**思路**：维护一个滑动窗口，同时用**两条单调队列**——一条维护窗口最大值、一条维护窗口最小值。当 `max - min > limit` 时收缩左边界，否则扩展右边界。

```go
func longestSubarray(nums []int, limit int) int {
    var maxD, minD []int // maxD 递减（求最大），minD 递增（求最小）
    left, best := 0, 0
    for right := 0; right < len(nums); right++ {
        for len(maxD) > 0 && nums[maxD[len(maxD)-1]] <= nums[right] {
            maxD = maxD[:len(maxD)-1]
        }
        maxD = append(maxD, right)
        for len(minD) > 0 && nums[minD[len(minD)-1]] >= nums[right] {
            minD = minD[:len(minD)-1]
        }
        minD = append(minD, right)

        // 收缩窗口直到满足限制
        for nums[maxD[0]]-nums[minD[0]] > limit {
            left++
            if maxD[0] < left {
                maxD = maxD[1:]
            }
            if minD[0] < left {
                minD = minD[1:]
            }
        }
        if right-left+1 > best {
            best = right - left + 1
        }
    }
    return best
}
```

**"双单调队列"是本题的亮点**——它说明单调队列可以"成对使用"：一条管最大值、一条管最小值，两者协同维护窗口的合法性。**这与第 02 篇"辅助结构同步追踪"是同一思路，只是这里的辅助结构变成了两条队列。**

### 5.3 环形子数组的最大和（LeetCode 918）

**题目**：给定一个环形整数数组，返回非空子数组的最大和。

**思路**：环形子数组的最大和有两种情况——要么就是普通子数组的最大和（用 Kadane 算法求），要么是"跨越首尾"的情况，即"总和 − 中间一段的最小子数组和"。后者需要用**单调队列**或 Kadane 变体求最小子数组和。

```go
func maxSubarraySumCircular(nums []int) int {
    total, maxSum, minSum := 0, nums[0], nums[0]
    curMax, curMin := 0, 0
    for _, v := range nums {
        total += v
        curMax = max(v, curMax+v)
        maxSum = max(maxSum, curMax)
        curMin = min(v, curMin+v)
        minSum = min(minSum, curMin)
    }
    if maxSum < 0 {
        return maxSum // 全为负，不能取"总和 - 最小子数组"（会取空）
    }
    return max(total-minSum, maxSum)
}
```

**这道题不直接使用单调队列，而是用 Kadane 算法**——把它列在这里，是为了说明一个判断：**"环形数组"并不必然用单调队列，只有当问题涉及"区间最值"时才用。** 判断的标准，仍然是"转移里有没有区间最值"，而非"是不是环形"。

### 5.4 三道延伸题给我们的

三道题展示了单调队列的三种扩展方向：862 把比较方向反过来（求最小前缀和），1438 把队列成对使用（同时管最大最小），918 则提示"环形"不必然用单调队列。**它们与第 4 章的 DP 优化合起来说明：单调队列是一个"可迁移的模式"，它的应用范围远不止"滑动窗口最大值"这一道题。**

## 第 6 章 实战细节与面试表达

### 6.1 入队条件：`<=` 还是 `<`

清理队尾时用的是 `nums[队尾] <= nums[i]`（`<=`）而非 `<`。**为什么用 `<=`？** 若有相等的元素，保留**更新的**（更靠右的）下标更好——因为更旧的下标会更快滑出窗口，留着没有价值。用 `<` 也能得到正确答案（队头仍是最大值），只是队列里会多留一些冗余元素。

**一句话总结：`<=` 让队列"更干净"，`<` 让队列"更保守"，两者都不影响正确性。** 面试中写 `<=` 更规范。

### 6.2 出队检查的时机

代码里是"**先入队（队尾），再检查出队（队头）**"。这个顺序让职责分离得最清晰——入队时处理"单调性维护"，检查队头时处理"窗口过期"。**若先检查队头再入队，结果一样，但"先入后检"读起来更顺。**

### 6.3 面试表达：讲清"为什么可以丢"

单调队列是"信息量大、代码很短"的类型，面试官最想听到的，是**为什么某些元素可以被丢弃**。建议这样表述：

> "如果一个元素在窗口里，它右边有一个值不小于它的元素，那么这个左边的元素永远不可能是任何包含右边那个元素的窗口的最大值——因为右边元素更靠右、会更晚离开窗口，在此之前每个包含左边元素的窗口也必然包含右边元素，而右边元素的值不更小。所以左边元素可以安全丢弃。"

**这段话讲清了"为什么丢弃是安全的"，是区分"背模板"与"真理解"的关键。** 一段单调队列的代码只有十几行，但若讲不出这句"为什么"，面试官就无法确认你理解了它的正确性依据。

> [!note] 一个通用的表达套路
> 凡是"丢弃型"的算法（单调栈、单调队列、贪心的剪枝、并查集的路径压缩），面试时都应准备好一句"**为什么丢掉它不影响答案**"。**这类算法的正确性，全都系于那个'丢弃判据'——能把判据讲清楚，就等于把算法讲清楚了。** 这比背诵代码更能体现理解深度，也更接近"真正掌握"。**

## 第 7 章 延伸：单调队列优化 DP 的更多实例

第 4 章的跳跃游戏 VI 只是"单调队列优化 DP"的一个样本。本章再给两道题，它们把这一模式应用到了更复杂的转移方程上，能帮你把"识别区间最值"的直觉练得更准。

### 7.1 带限制的子序列和（LeetCode 1425）

**题目**：给定数组 `nums` 和整数 `k`，求一个非空子序列的最大和，要求子序列中任意两个相邻元素的下标之差不超过 `k`。

**转移方程**：设 `dp[i]` 表示"以 `nums[i]` 结尾的最大子序列和"，则

$$dp[i] = nums[i] + \max\left(0,\ \max_{i-k \le j < i} dp[j]\right)$$

**注意这个 `max(0, ...)`**：它表示"可以接上前面的最优子序列（若为正），也可以从 `i` 重新开始"。而那个 `max(dp[j])` 的范围正是"过去 `k` 步"——又是滑动窗口最大值，用单调队列维护。

```go
func constrainedSubsetSum(nums []int, k int) int {
    n := len(nums)
    dp := make([]int, n)
    deque := []int{} // 存下标，对应 dp 值单调递减
    ans := nums[0]

    for i := 0; i < n; i++ {
        // 移除超出 k 步范围的队头
        for len(deque) > 0 && deque[0] < i-k {
            deque = deque[1:]
        }
        dp[i] = nums[i]
        if len(deque) > 0 && dp[deque[0]] > 0 {
            dp[i] += dp[deque[0]] // 接上过去 k 步内的最优
        }
        // 维护单调递减
        for len(deque) > 0 && dp[deque[len(deque)-1]] <= dp[i] {
            deque = deque[:len(deque)-1]
        }
        deque = append(deque, i)
        if dp[i] > ans {
            ans = dp[i]
        }
    }
    return ans
}
```

**与跳跃游戏 VI 的差别，只在转移方程里多了个 `max(0, ...)`**——但"用单调队列维护过去 k 步的最值"这一骨架完全一致。**这说明：单调队列优化 DP 的适用范围，只取决于"转移里有没有区间最值"，而与转移方程的具体形式无关。**

### 7.2 满足不等式的最大值（LeetCode 1499）

**题目**：给你一个数组 `points`（按横坐标 `x` 升序，每点形如 `[x, y]`）和整数 `k`，求满足 `|xi - xj| <= k` 的 `yi + yj + |xi - xj|` 的最大值。

**关键变形**：因为 `points` 已按 `x` 升序，设 `i > j`，则 `|xi - xj| = xi - xj`，于是目标式变成：

$$yi + yj + xi - xj = (yi + xi) + (yj - xj)$$

**这样就把"两点耦合"的式子，拆成了"当前点的一项"加"过去某点的一项"**——对每个 `i`，我们要在满足 `xi - xj <= k` 的 `j` 中，找 `(yj - xj)` 的最大值。**又是区间最值。** 用单调队列维护 `(y - x)` 的滑动窗口最大值：

```go
func findMaxValueOfEquation(points [][]int, k int) int {
    deque := []int{} // 存下标，维护 (y-x) 单调递减
    ans := math.MinInt32

    for i, p := range points {
        x, y := p[0], p[1]
        // 移除 x 距离超过 k 的队头
        for len(deque) > 0 && x-points[deque[0]][0] > k {
            deque = deque[1:]
        }
        // 队头即 (y-x) 最大的那个 j
        if len(deque) > 0 {
            j := deque[0]
            val := y + x + points[j][1] - points[j][0]
            if val > ans {
                ans = val
            }
        }
        // 维护 (y-x) 单调递减
        cur := y - x
        for len(deque) > 0 && points[deque[len(deque)-1]][1]-points[deque[len(deque)-1]][0] <= cur {
            deque = deque[:len(deque)-1]
        }
        deque = append(deque, i)
    }
    return ans
}
```

**这道题的关键，是"先把目标式变形，把耦合项拆开"**：`yi + yj + |xi - xj|` 里 `i` 和 `j` 是耦合的，直接看无从下手；一旦利用"`x` 已升序"把它拆成 `(yi + xi) + (yj - xj)`，就立刻显出了"对当前 `i`，在窗口内找 `(yj - xj)` 最大"的结构。**"先变形、再识别区间最值"，是应用单调队列优化 DP 的第一步——很多时候，难点不在单调队列本身，而在于能否把式子整理成"区间最值"的样子。**

### 7.3 三道 DP 题的共同骨架

把跳跃游戏 VI、带限制的子序列和、满足不等式的最大值三道题并排，会发现它们共享同一副骨架：

```text
for i in range(n):
    1. 清理队头：移除超出窗口范围的元素
    2. 用队头（窗口最值）更新 dp[i] 或答案
    3. 维护单调性：从队尾移除被 nums[i] 盖住的元素
    4. 把 i 入队
```

**"清头 → 用最值 → 维护尾 → 入队"这四步，就是单调队列优化 DP 的固定模板。** 三道题的差异，全在"窗口范围怎么定义""用队头算的是什么"这两点上。**把这四步背下来，再遇到"转移里有区间最值"的题，你就能直接套用。**

> [!info] 一个识别的信号
> 什么时候该想到"用单调队列优化 DP"？**当转移方程里出现 `max`/`min`，且其作用范围是一段"连续的下标区间"时。** 例如 `max(dp[j]) for i-k <= j < i`（窗口）、`max(yj - xj) for xi - xj <= k`（变形的窗口）。**"区间 + 最值"这两个信号同时出现，单调队列几乎就是标准答案。**

## 第 8 章 常见误区与自测方法

### 8.1 四个高频误区

**误区一：出队检查漏掉。** 只做了"维护单调性"（清队尾），忘了"清理过期元素"（清队头），导致队头可能指向已滑出窗口的下标。**这是单调队列最常见、也最致命的 bug。**

**误区二：清理队尾用 `<=` 还是 `<` 犹豫不决。** 两者都不影响正确性（队头仍是最大值），但 `<=` 更干净（不留冗余）。**若纠结，选 `<=`。**

**误区三：窗口大小 `k` 与下标关系搞错。** 队头过期条件是 `deque[0] <= i - k`（不是 `< i - k`）。**用 `k = 1` 这个最简用例一测便知**——此时每个窗口只有一个元素，`deque[0]` 必须恰好等于 `i`。

**误区四：在 DP 优化里忘了 `max(0, ...)`。** 如第 7 章带限制的子序列和，"可以从头开始"这一分支若漏掉，答案会偏小。

### 8.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `nums = [1], k = 1` | 最简窗口 |
| `nums = [1,2,3,4], k = 1` | 每个窗口一个元素 |
| `nums = [4,3,2,1], k = 2` | 单调递减（队尾从不清理） |
| `nums = [1,2,3,4], k = 2` | 单调递增（每次清空队尾） |

**其中 `k = 1` 是最该测的用例**——它把"队头过期判断"压到最简：每个窗口只含当前元素，队头必须恰好是 `i`。**若 `deque[0] <= i - k` 写成了别的形式，这个用例会立刻暴露。**

### 8.3 单调队列与其他结构的对照

| 结构 | 能回答的问题 | 代价 |
|------|-------------|------|
| 单调队列 | 窗口内的最大/最小值 | $O(n)$ 时间、$O(k)$ 空间 |
| 最大堆 | 全局（或带惰性删除的窗口）最值 | $O(n \log n)$ 时间、$O(n)$ 空间 |
| 有序集合（平衡树） | 窗口内任意次序统计量 | $O(n \log k)$ 时间 |
| 稀疏表（Sparse Table） | 静态区间的极值 | $O(n \log n)$ 预处理、$O(1)$ 查询 |

**单调队列的独特价值，在于它是"动态窗口最值"的 $O(1)$ 单次查询最优解**——窗口在移动（动态），而它仍能维持 $O(1)$ 的查询。**静态区间最值可以用稀疏表，动态窗口最值则非单调队列莫属。** 理解这个分工，你就明白为什么单调队列值得单独成为一个知识点。

## 小结

本篇用一道题（滑动窗口最大值）把单调队列讲透。它的突破口是一句可证明的洞察——**窗口内被右边更大元素"盖住"的元素，永远当不成最大值，可以安全丢弃**；这句话把"维护窗口内所有元素"削减为"只维护单调递减的候选集"，从而把查询最值降到 $O(1)$。单调队列与单调栈的最大区别，在于它需要**从两端操作**（队尾删被盖住的、队头删过期的），这正是双端队列存在的理由。第 4 章进一步展示了它在 DP 优化中的威力——凡是转移里出现"区间最值"，都可以用单调队列把 $O(k)$ 降到 $O(1)$。

贯穿全篇的核心认知有两条。其一，**单调队列的本质是"用单调性维持一个候选集"**，而"丢弃判据"决定了它的正确性——把判据讲清，算法就讲清了。其二，**它是一个可迁移的优化模式，而非一道题的技巧**——从滑动窗口最大值，到 DP 优化，再到前缀和上的应用，它的身影随处可见。**把"区间最值"识别为"该请出单调队列"的信号，你就掌握了一件真正的通用工具。**

### 一句话带走

如果只能带走一句话，那就是：**"单调队列的正确性，全系于那句'为什么可以丢'。"** 被右边更大元素盖住的元素，永远当不成最大值——把这句判据讲清楚，就等于把整个算法讲清楚了。**凡是"丢弃型"的算法（单调栈、单调队列、剪枝），都应当准备好这样一句判据；它是区分"背模板"与"真理解"的唯一标尺。** 更进一步，**当你能为一道题独立地"发明"出它的丢弃判据时，你就不再需要记忆任何模板——因为模板本就是判据的副产品。**

> [!note] 为什么不用平衡树（有序集合）
> 维护"窗口内最值"，理论上也可以用平衡树或有序集合（$O(n \log k)$）。**但单调队列做到了 $O(n)$——省下的正是那一个 $\log$。** 为什么能省？因为单调队列丢弃了"永远不会成为最值"的元素，把候选集压到了最小；而平衡树保留了所有元素，只是为了能回答"任意次序统计量"这类更一般的问题。**当需求只是"最值"而非"任意排名"时，单调队列就是那个"刚好够用"的更优解。** 这又是"为需求匹配结构"的一个例证——**需求越具体，能用的结构就越轻；需求越泛化，结构就越重。**
