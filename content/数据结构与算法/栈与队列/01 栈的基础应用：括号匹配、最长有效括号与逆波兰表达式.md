# 栈的基础应用：括号匹配、最长有效括号与逆波兰表达式

**摘要：**

栈（Stack）是线性表的一种"被约束"的形态——它只允许在一端进出，看似比数组、链表更加受限，却恰恰因为这份受限，天然适配了一整类"最近优先"的问题：撤销最近的操作、闭合最近的括号、计算最近的两个操作数。本文以三道经典题切入：LeetCode 20（有效的括号）建立"符号匹配"的基本范式，LeetCode 32（最长有效括号）示范"从字符栈升级为下标栈"这一关键跃迁，LeetCode 150（逆波兰表达式求值）则展示栈在表达式计算中的教科书级应用。三题难度递进，覆盖了栈在工程中最常见的两类用途——**符号匹配与表达式计算**。本文不止给出代码，更逐层追问：为什么括号问题必然要用栈、为什么第 32 题要压下标而不是字符、哨兵究竟在扮演什么角色、以及逆波兰表达式凭什么能"无需括号"。示例代码统一使用 Go。

---

## 第 1 章 栈：一种被约束成全能的线性表

### 1.1 栈的本质

栈是一种线性数据结构，核心操作只有三个：

- `push(x)`：把元素 `x` 压入栈顶；
- `pop()`：移除并返回栈顶元素；
- `peek()`：查看栈顶元素但不移除。

约束只有一条：**只能从一端（栈顶）进出**。这条约束看起来是种限制——数组能随机访问，链表能在中间插入，栈却什么都不行。**但恰恰是这份"什么都不行"，让栈天然匹配了一整类"最近优先"的需求**：

- **函数调用栈**：每次调用把栈帧压入，返回时弹出——"最近调用的函数最先返回"；
- **编辑器撤销**：`Ctrl+Z` 撤销的是最近一次操作；
- **编译器括号匹配**：最近打开的括号最先被闭合；
- **深度优先搜索**：递归的本质就是借助调用栈。

**这四件事的共同点，是"后进先出"（LIFO，Last In First Out）。** 栈之所以适配它们，不是因为栈功能多，而是因为**这些问题的内在顺序恰好是 LIFO**。理解这一点，比记住"括号匹配用栈"重要得多——**当你在题目里发现"最近出现的东西要先被处理"，栈就会自己浮现在脑海里。**

### 1.2 Go 里的栈

Go 没有内置的栈类型，但切片（slice）就是最自然的栈：**把切片末尾当作栈顶**，三个操作都是 $O(1)$。

```go
stack := []int{}
stack = append(stack, 1)          // push：压入
top := stack[len(stack)-1]        // peek：查看栈顶
stack = stack[:len(stack)-1]      // pop：弹出（丢掉末尾元素）
empty := len(stack) == 0          // isEmpty
```

**为什么用切片而不用双向链表？** 因为栈只在一端操作，切片尾部恰好就是那一端，无需任何额外结构；而且切片底层是连续内存，缓存友好（呼应线性表专栏第 01 篇对缓存局部性的讨论）。`container/list` 虽然也能当栈用，但每个元素都要分配一个节点，常数更大，得不偿失。

> [!note] 切片当栈的一个约定
> `stack = stack[:len(stack)-1]` 只是移动了切片的长度，底层数组的元素并没有被清零——若元素是引用类型，这会短暂地让对象无法被回收。在算法题里无碍；但若在生产代码里长期持有大对象，可先 `stack[len(stack)-1] = zero` 再收缩长度。**这类"内存泄漏"细节，是"会写算法"与"会写生产代码"之间的一层分野。**

## 第 2 章 LeetCode 20：有效的括号

### 2.1 题目

**LeetCode 20 - Valid Parentheses**（简单）

给定一个只包含 `(`、`)`、`{`、`}`、`[`、`]` 的字符串 `s`，判断字符串是否有效。有效需满足：左括号必须以相同类型、正确顺序闭合，每个右括号都有对应的同类型左括号。

```text
输入: "()"      → true
输入: "()[]{}"  → true
输入: "(]"      → false
输入: "([)]"    → false
输入: "{[]}"    → true
输入: "["       → false（未闭合）
```

### 2.2 为什么栈是必然选择

括号匹配有一条核心性质：**最近打开的括号最先被闭合。** 以 `"{[()]}"` 为例，`(` 是最后打开的，却要先与 `)` 闭合；`{` 是最先打开的，却要等到最后才闭合。这正是 LIFO 的语义。

把处理过程走一遍：

```text
i=0: '{' → 压栈 → 栈: ['{']
i=1: '[' → 压栈 → 栈: ['{', '[']
i=2: '(' → 压栈 → 栈: ['{', '[', '(']
i=3: ')' → 与栈顶 '(' 匹配，弹栈 → 栈: ['{', '[']
i=4: ']' → 与栈顶 '[' 匹配，弹栈 → 栈: ['{']
i=5: '}' → 与栈顶 '{' 匹配，弹栈 → 栈: []
最终栈为空 → true
```

**任何一步"栈顶与当前右括号不匹配"，或者遍历结束"栈不为空"，都是无效。** 这两条判断，恰好对应了括号无效的两种成因：类型不匹配、数量不匹配。

### 2.3 Go 实现

```go
func isValid(s string) bool {
    stack := make([]byte, 0, len(s))
    // 右括号 → 对应的左括号
    pairs := map[byte]byte{')': '(', ']': '[', '}': '{'}

    for i := 0; i < len(s); i++ {
        c := s[i]
        if c == '(' || c == '[' || c == '{' {
            stack = append(stack, c) // 左括号：压栈
        } else {
            // 右括号：栈空或栈顶不匹配，即无效
            if len(stack) == 0 || stack[len(stack)-1] != pairs[c] {
                return false
            }
            stack = stack[:len(stack)-1] // 匹配成功，弹栈
        }
    }
    return len(stack) == 0 // 全部匹配完，栈应为空
}
```

**两个必须处理的边界**：其一，遇到右括号时栈已空（如 `")"`），说明右括号多余，直接返回 `false`；其二，遍历结束后栈非空（如 `"((("`），说明左括号多余，由最后的 `len(stack) == 0` 兜住。**把这两个边界分别"卡"在循环内部和循环之后，是括号题最简洁的写法。**

**复杂度**：时间 $O(n)$，空间 $O(n)$（最坏情况全是左括号，栈深为 $n$）。

## 第 3 章 LeetCode 32：最长有效括号

### 3.1 题目

**LeetCode 32 - Longest Valid Parentheses**（困难）

给你一个只含 `(` 和 `)` 的字符串，找出最长有效（格式正确且连续）括号子串的长度。

```text
输入: s = "(()"     → 输出: 2（最长有效子串 "()"）
输入: s = ")()())"  → 输出: 4（最长有效子串 "()()"）
输入: s = ""        → 输出: 0
```

### 3.2 关键跃迁：从字符栈到下标栈

第 20 题压入的是**字符**，因为判"是否匹配"只需知道类型。但第 32 题要求的是**长度**——长度是位置的差值，与字符本身无关。**于是栈里该存的，就从"字符"换成了"下标"。**

这是一次看似微小、实则关键的跃迁。**它揭示了一个通用经验：栈里存什么，取决于"弹栈时你需要什么信息"**——需要类型就存字符，需要位置就存下标，需要值就存值。**栈的内容永远服务于"弹栈那一刻要做的计算"。**

### 3.3 哨兵：一个"未匹配区域起点"的锚

除了存下标，第 32 题还引入了一个精妙的设计——**栈底始终保留一个"哨兵下标"**，它代表"上一个未被匹配的右括号的位置"（初始时压入 `-1`，代表虚拟的起点）。

它的作用，是在完成一次匹配后，能立刻算出当前有效子串的长度：**`当前下标 - 栈顶下标`**。因为栈顶此刻要么是哨兵（上一段未匹配区域的边界），要么是一个尚未被匹配的左括号——无论哪种，它都是"当前有效子串左边界的前一个位置"。

以 `s = ")()()"` 为例：

```text
初始栈: [-1]（哨兵）

i=0, ')': 弹出哨兵 -1，栈空 → 说明这是孤立右括号，压入 0 作为新哨兵
          栈: [0]
i=1, '(': 压入 1
          栈: [0, 1]
i=2, ')': 弹出 1，栈顶为 0（哨兵），栈非空
          有效长度 = 2 - 0 = 2，maxLen = 2
          栈: [0]
i=3, '(': 压入 3
          栈: [0, 3]
i=4, ')': 弹出 3，栈顶为 0
          有效长度 = 4 - 0 = 4，maxLen = 4
          栈: [0]

结果: 4 ✓
```

### 3.4 规则与代码

把上面的过程归纳成两条规则：

- 遇到 `(`：压入它的下标；
- 遇到 `)`：先弹出栈顶；**若弹出后栈空**，说明这个 `)` 是孤立的，把它的下标压入作为新哨兵；**若弹出后栈非空**，则用 `i - 栈顶下标` 更新最大长度。

```go
func longestValidParentheses(s string) int {
    stack := []int{-1} // 初始哨兵：未匹配区域的起点
    maxLen := 0

    for i := 0; i < len(s); i++ {
        if s[i] == '(' {
            stack = append(stack, i)
        } else {
            stack = stack[:len(stack)-1] // 弹出栈顶（匹配的左括号，或哨兵）
            if len(stack) == 0 {
                stack = append(stack, i) // 孤立右括号成为新哨兵
            } else if d := i - stack[len(stack)-1]; d > maxLen {
                maxLen = d
            }
        }
    }
    return maxLen
}
```

**手动验证** `s = "(()"`：

```text
栈初始: [-1]
i=0, '(': 压入 0 → [-1, 0]
i=1, '(': 压入 1 → [-1, 0, 1]
i=2, ')': 弹出 1 → [-1, 0]；栈非空，长度 = 2 - 0 = 2
结果: 2 ✓
```

**复杂度**：时间 $O(n)$（每个下标至多进出栈一次），空间 $O(n)$。

### 3.5 另两种解法与取舍

这道题有三种主流解法，值得对照：

**方法二，动态规划。** 定义 `dp[i]` 为"以 `s[i]` 结尾的最长有效括号长度"，分情况转移：若 `s[i] == ')'` 且 `s[i-1] == '('`，则 `dp[i] = dp[i-2] + 2`；若 `s[i-1] == ')'`，则向前跨过 `dp[i-1]` 找配对字符。时间 $O(n)$、空间 $O(n)$，但转移的边界条件复杂，容易写错。

**方法三，双向计数。** 从左到右、从右到左各扫一遍，分别统计左右括号数量，相等时更新长度。空间 $O(1)$，但需要处理"左括号过多"和"右括号过多"两种失效情形，细节最多。

| 方法 | 时间 | 空间 | 直觉难度 |
|------|------|------|---------|
| 下标栈 | $O(n)$ | $O(n)$ | 中 |
| 动态规划 | $O(n)$ | $O(n)$ | 高 |
| 双向计数 | $O(n)$ | $O(1)$ | 高 |

**面试推荐下标栈**：思路最清晰、最容易讲明白，实现也不易出错。**空间更优的"双向计数"适合作为加分项提及，但不必作为首选——因为在面试里，"讲得清"往往比"空间省一格"更重要。**

## 第 4 章 LeetCode 150：逆波兰表达式求值

### 4.1 什么是逆波兰表达式

**逆波兰表达式**（Reverse Polish Notation，RPN）又称后缀表达式——运算符放在两个操作数的**后面**，而非中间。

```text
中缀: 3 + 4                → 后缀: 3 4 +
中缀: (2 + 3) * 4          → 后缀: 2 3 + 4 *
中缀: 5 - (1 + 2) * 4 + 3  → 后缀: 5 1 2 + 4 * - 3 +
```

**逆波兰表达式最大的优势，是不需要括号。** 因为运算符直接作用于它前面紧邻的两个操作数，优先级由运算符的位置天然决定。这是 HP 计算器在 1970 年代的设计选择——至今部分 HP 科学计算器仍默认 RPN 输入。

### 4.2 题目

**LeetCode 150 - Evaluate Reverse Polish Notation**（中等）

根据逆波兰表示法求表达式的值。有效算符包括 `+`、`-`、`*`、`/`，除法向零截断。

```text
输入: ["2","1","+","3","*"]  → 输出: 9（((2+1)*3)）
输入: ["4","13","5","/","+"] → 输出: 6（(4+(13/5))）
```

### 4.3 求值算法

逆波兰求值是栈的教科书级应用：

- 遇到**数字**：压栈；
- 遇到**运算符**：弹出两个操作数，计算结果，再把结果压栈；
- 最终栈中唯一剩下的元素就是答案。

```go
func evalRPN(tokens []string) int {
    stack := []int{}

    for _, tok := range tokens {
        switch tok {
        case "+", "-", "*", "/":
            b := stack[len(stack)-1] // 右操作数（后入栈）
            a := stack[len(stack)-2] // 左操作数（先入栈）
            stack = stack[:len(stack)-2]
            var r int
            switch tok {
            case "+":
                r = a + b
            case "-":
                r = a - b
            case "*":
                r = a * b
            case "/":
                r = a / b // Go 整数除法向零截断，与题意一致
            }
            stack = append(stack, r)
        default:
            n, _ := strconv.Atoi(tok)
            stack = append(stack, n)
        }
    }
    return stack[0]
}
```

> [!warning] 生产避坑：弹出顺序决定减法与除法的正确性
> 弹栈顺序是先右后左：先弹出的是**右操作数** `b`，后弹出的是**左操作数** `a`。减法和除法是非交换的（`a - b ≠ b - a`、`a / b ≠ b / a`），顺序写反就会得到错误答案。
>
> 例：`["5", "3", "-"]` 的预期是 `5 - 3 = 2`——先弹 `b = 3`、再弹 `a = 5`，算 `a - b`，正确。若写成 `b - a`，就会得到 `-2`。**这类"顺序反了"的 bug 在测试用例里未必暴露（若操作数恰好相等），却在真实输入下必然出错。**

**手动验证** `["4","13","5","/","+"]`：

```text
"4"  → stack: [4]
"13" → stack: [4, 13]
"5"  → stack: [4, 13, 5]
"/"  → b=5, a=13, 13/5=2 → stack: [4, 2]
"+"  → b=2, a=4, 4+2=6   → stack: [6]
结果: 6 ✓
```

**复杂度**：时间 $O(n)$，空间 $O(n)$。

### 4.4 逆波兰为什么如此"好算"

中缀表达式求值的困难，全在**运算符优先级**（先乘除后加减）与**括号**（改变优先级）这两件事上。人类读起来很直观，计算机却需要两次扫描，或借助调度场算法（Shunting Yard Algorithm）先把中缀转成后缀。

**逆波兰表达式把优先级的信息，编码进了运算符的位置**——它把"先算什么"这件事从"语义"变成了"顺序"。于是计算机只需从左到右扫一遍、用一个栈就能算完，时间与空间都是线性的。**这也是编译器在生成中间表示（IR）时，常把表达式转成类似后缀形式来处理的原因：位置即优先级，无需反复回看。**

> [!info] 中缀转后缀：调度场算法
> Dijkstra 提出的调度场算法能把中缀表达式转成逆波兰表达式，同样只用 $O(n)$ 时间和一个栈。它的规则是：遇数字直接输出；遇运算符则按优先级弹栈输出，再压入；遇左括号压栈，遇右括号弹出到左括号为止。**第 07 篇的基本计算器（LeetCode 224）的一种解法，正是"先调度场转后缀、再用本篇的 RPN 求值"。** 换句话说，本篇是第 07 篇的前置工具。

## 第 5 章 括号题的通用解题框架

把第 20、32 两题并排看，可以提炼出一套"括号题三问"的框架：

**一问：我需要追踪什么信息？** 决定了栈里存什么。
- 第 20 题只需知道"最近的未匹配左括号是什么类型" → 压**字符**；
- 第 32 题需要知道"匹配发生在哪个位置" → 压**下标**。

**二问：弹栈的时机是什么？** 括号题的弹栈时机高度统一——**遇到右括号时，弹出对应的左括号（或哨兵）**。

**三问：弹栈后如何更新答案？** 决定了题目真正的难点。
- 第 20 题：弹出后判断类型是否匹配；
- 第 32 题：弹出后用"当前下标 − 新栈顶下标"计算长度。

**这三问的价值，是让你在面对陌生的括号变体时，有一个固定的思考起点。** 绝大多数括号题的差别，都落在"一问"（存什么）和"三问"（怎么更新答案）上，而"二问"几乎不变。

### 5.1 表达式求值的栈模式

| 遇到什么 | 操作 |
|---------|------|
| 数字 | 压栈 |
| 双目运算符 | 弹出两个操作数，计算，压入结果 |
| `(` | 压栈（作为特殊标记） |
| `)` | 弹栈直到遇到 `(`，先算出括号内的结果 |

逆波兰表达式已消除了括号，故只需处理"数字"与"运算符"两行；而带括号的中缀求值（第 07 篇）需要额外的 `(`、`)` 逻辑。**"表达式求值"这一类问题，本质上都是在用栈模拟"运算的嵌套结构"。**

## 第 6 章 延伸：括号家族的更多面孔

括号题是一棵枝繁叶茂的家族。补三道同源题，它们都在检验同一件事：**你是否真正掌握了"用栈追踪嵌套结构"这一内核。**

### 6.1 括号生成（LeetCode 22）：回溯而非栈

**题目**：数字 `n` 代表生成括号的对数，设计函数生成所有可能且有效的括号组合。

这道题虽然"关于括号"，却不用栈——它用**回溯**。核心在于两个约束：左括号数量不超过 `n`，且任意前缀中右括号数不超过左括号数。

```go
func generateParenthesis(n int) []string {
    var res []string
    var backtrack func(cur string, open, close int)
    backtrack = func(cur string, open, close int) {
        if len(cur) == 2*n {
            res = append(res, cur)
            return
        }
        if open < n {
            backtrack(cur+"(", open+1, close)
        }
        if close < open {
            backtrack(cur+")", open, close+1)
        }
    }
    backtrack("", 0, 0)
    return res
}
```

**这道题的启示是：并非所有"括号题"都用栈。** 判断标准在于问题的性质——**"验证/计算一个给定串"用栈（因为要追踪嵌套状态），"生成所有合法串"用回溯（因为要枚举状态空间）**。把"括号"这个词当成"必须用栈"的信号，是一种危险的思维定式。

### 6.2 括号的分数（LeetCode 856）：用栈计算嵌套得分

**题目**：给定一个平衡括号字符串，按规则计算它的分数：`()` 得 1 分；`AB` 得 `A + B` 分；`(A)` 得 `2 * A` 分。

这道题用栈计算嵌套的分数，思路干净：遇到 `(` 压入 0 作为"分数占位"；遇到 `)` 弹出栈顶值 `v`，若 `v == 0`（说明是空括号对）则得 1，否则得 `2 * v`，再把它加到新的栈顶（即外层括号的累计分数）。

```go
func scoreOfParentheses(s string) int {
    stack := []int{0} // 栈底放一个 0，代表最外层的累计分数
    for i := 0; i < len(s); i++ {
        if s[i] == '(' {
            stack = append(stack, 0) // 新一层开始
        } else {
            v := stack[len(stack)-1]
            stack = stack[:len(stack)-1] // 弹出内层分数
            if v == 0 {
                v = 1 // 空括号对
            } else {
                v *= 2 // (A) → 2A
            }
            stack[len(stack)-1] += v // 累加到外层
        }
    }
    return stack[0]
}
```

**这道题的价值，在于它把"栈追踪嵌套"这一内核用在了"数值计算"上**——栈的每一层代表一个嵌套深度，弹栈时把内层结果折算后并入外层。**它与第 32 题"压下标、算长度"是同一动作的两种变体：栈承载的，永远是"当前嵌套层的上下文"。**

### 6.3 删除无效的括号（LeetCode 1249）：栈 + 标记

**题目**：给你一个由 `(`、`)` 和小写字母组成的字符串，删除最少数量的无效括号，使结果字符串有效。返回任意一个正确答案。

这道题用栈找出"需要删除的括号下标"：遇到 `(` 压入下标；遇到 `)` 时若有可配对的 `(` 则弹出，否则记录这个 `)` 的下标为"待删"；最后栈里剩下的 `(` 下标也是"待删"。用一个布尔数组标记这些位置，重建成结果字符串即可。

```go
func minRemoveToMakeValid(s string) string {
    stack := []int{}
    remove := make([]bool, len(s))
    for i := 0; i < len(s); i++ {
        switch s[i] {
        case '(':
            stack = append(stack, i)
        case ')':
            if len(stack) > 0 {
                stack = stack[:len(stack)-1] // 配对成功
            } else {
                remove[i] = true // 孤立的右括号，标记删除
            }
        }
    }
    for _, i := range stack {
        remove[i] = true // 未配对的左括号，标记删除
    }
    var b []byte
    for i := 0; i < len(s); i++ {
        if !remove[i] {
            b = append(b, s[i])
        }
    }
    return string(b)
}
```

**这道题展示了"栈 + 标记数组"这一组合**：栈负责判断"哪些括号是多余的"，标记数组负责记录"要删哪些位置"，最后统一重建。**它比第 32 题更直白——因为题目要的是"删掉谁"，而栈恰好能告诉我们"谁没有被匹配"。**

### 6.4 三道延伸题给我们的

三道题与主线两题合起来，构成了括号家族的一张完整图谱：

| 题目 | 内核 | 栈里存什么 |
|------|------|-----------|
| 20 有效括号 | 匹配验证 | 字符 |
| 32 最长有效括号 | 匹配 + 长度 | 下标 + 哨兵 |
| 856 括号的分数 | 嵌套计算 | 分数占位 |
| 1249 删除无效括号 | 匹配 + 标记 | 下标 |
| 22 括号生成 | 枚举生成 | （不用栈，用回溯） |

**它们共同印证了那句话：栈里存什么，取决于弹栈时要算什么。** 而"括号"这个外壳之下，真正被追踪的，永远是"当前嵌套层的上下文"。**理解了这一点，你就不会再被"括号题"这个标签困住。**

## 第 7 章 中缀表达式求值：调度场算法

第 4 章的逆波兰求值之所以简单，是因为优先级已被"编码进位置"。但现实中人写的是**中缀表达式**（`3 + 4 * 2`），计算机要处理它，就得先把优先级"还原"出来。这个还原过程，正是 Dijkstra 的**调度场算法（Shunting Yard Algorithm）**——它同样只用 $O(n)$ 时间和一个栈。

### 7.1 算法规则

调度场算法的目标，是把中缀表达式转成后缀（逆波兰）表达式。规则如下：

- 遇**数字**：直接输出；
- 遇**运算符**：只要栈顶运算符的优先级不低于当前运算符，就弹栈输出；然后压入当前运算符；
- 遇**左括号**：直接压栈；
- 遇**右括号**：不断弹栈输出，直到弹出左括号为止（左括号本身不输出）；
- 结束后：把栈中剩余运算符全部弹出输出。

```go
func infixToPostfix(s string) []string {
    precedence := map[byte]int{'+': 1, '-': 1, '*': 2, '/': 2}
    var output []string
    var ops []byte

    for i := 0; i < len(s); i++ {
        c := s[i]
        switch {
        case c >= '0' && c <= '9':
            // 累积多位数后输出
            j := i
            for j < len(s) && s[j] >= '0' && s[j] <= '9' {
                j++
            }
            output = append(output, s[i:j])
            i = j - 1
        case c == '(':
            ops = append(ops, c)
        case c == ')':
            for len(ops) > 0 && ops[len(ops)-1] != '(' {
                output = append(output, string(ops[len(ops)-1]))
                ops = ops[:len(ops)-1]
            }
            ops = ops[:len(ops)-1] // 弹出左括号
        default: // 运算符
            for len(ops) > 0 && ops[len(ops)-1] != '(' &&
                precedence[ops[len(ops)-1]] >= precedence[c] {
                output = append(output, string(ops[len(ops)-1]))
                ops = ops[:len(ops)-1]
            }
            ops = append(ops, c)
        }
    }
    for len(ops) > 0 {
        output = append(output, string(ops[len(ops)-1]))
        ops = ops[:len(ops)-1]
    }
    return output
}
```

### 7.2 为什么它是对的

**调度场算法的核心思想，是"用栈的先后顺序来模拟优先级"**：优先级高的运算符，会先于优先级低的运算符被输出（因为低优先级的会被高优先级的"压住"）。**换句话说，它把"谁先算"这一语义问题，转化成了"谁先出栈"这一结构问题**——这与逆波兰表达式"把优先级编码进位置"是同一种思路的两种表现。

**把中缀转后缀、再用逆波兰求值，就构成了一条完整的表达式处理链路**：`infixToPostfix(s)` → `evalRPN(tokens)`。第 07 篇的基本计算器，其实也可以用这条链路实现——只是它为了追求 $O(1)$ 的额外空间（而非 $O(n)$ 的输出），选择了"边扫边算"的写法。

> [!info] 调度场与递归下降：两条等价的路
> 处理表达式，除了"调度场 + 逆波兰"这条"先转换、再求值"的路，还有一条"递归下降"的路（第 07 篇 LC772 的写法）——直接按语法层级递归，遇括号就下一层。**两条路都只用 $O(n)$ 时间，区别在于：调度场用"显式栈"管理优先级，递归下降用"调用栈"管理层级。** 这正是"栈 = 显式化的递归调用栈"这一等价关系在表达式求值上的又一次体现。

## 第 8 章 常见误区与自测方法

### 7.1 四个高频误区

**误区一：第 20 题忘了"右括号多余"与"左括号多余"两个边界。** 前者需在循环内检查栈空，后者需在循环后检查栈非空，缺一不可。

**误区二：第 32 题忘了哨兵。** 若初始栈为空、遇到孤立右括号时也不补哨兵，长度计算就失去了左边界，会算出错误结果。

**误区三：第 150 题弹栈顺序写反。** 必须先弹右操作数 `b`、再弹左操作数 `a`，否则减法与除法出错。

**误区四：把"括号题"一律等同于"用栈"。** 如第 22 题（生成）应当用回溯，而非栈。

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `"]"`、`"["` | 第 20 题的两类边界 |
| `")()())"`、`"(()"` | 第 32 题的孤立右括号与未闭合左括号 |
| `"()(()"` | 第 32 题的中段断裂 |
| `["5","3","-"]`、`["4","13","5","/","+"]` | 第 150 题的减法/除法顺序 |

**其中 `"()(()"` 是第 32 题最值得测的用例**：它的答案是 2（前半段 `"()"`），而不是 4——因为中间的 `(` 无法闭合，把字符串切断了。**很多错误写法会把它算成 4，因为它们只统计了总匹配数、忽略了"连续性"这一要求。**

## 小结

本篇以三道题铺开了栈的基础应用。第 20 题建立了"符号匹配"的范式——用栈追踪最近打开的括号；第 32 题完成了从"字符栈"到"下标栈 + 哨兵"的关键跃迁，把"是否匹配"升级为"匹配多长"；第 150 题则用栈演示了表达式求值，并揭示了逆波兰表达式"以位置编码优先级"的巧思。延伸的三道题（括号生成、括号的分数、删除无效括号）进一步说明：**"括号"只是外壳，真正被追踪的，是嵌套层的上下文。**

贯穿全篇的核心认知有两条。其一，**栈里存什么，由弹栈那一刻要做的计算决定**——存字符是为判类型，存下标是为算长度，存分数是为做折算。其二，**栈适配的是"最近优先"这类问题**，而"括号匹配"之所以天然用栈，正是因为它满足"最近打开的括号最先闭合"。**把这两条想通，你在面对陌生的栈题时，就能自己推导出该压什么、何时弹、弹后做什么，而无需去回忆某道题的模板。**

### 8.3 一句话带走

如果只能从本篇带走一句话，那就是：**"栈里存什么，由弹栈那一刻要做的计算决定。"** 第 20 题要判类型，所以存字符；第 32 题要算长度，所以存下标；第 150 题要算结果，所以存数值。**这个原则看似朴素，却能让你在面对任何栈题时，先问自己一句"我弹栈时要用到什么"，从而反推出该往栈里放什么。** 从"记住模板"到"推导模板"，差别就在这一问。**而更进一步——当你能从"要什么答案"反推出"要保存什么状态"时，你其实已经在用"逆向设计"的方式解题了，这比正向地套模板要强大得多。**

下一篇 [[02 栈的设计题：最小栈与用队列模拟栈]] 进入栈的"设计类"题目。LeetCode 155（最小栈）要求在 $O(1)$ 内查询栈中最小值，关键是用一个辅助栈同步追踪最小值；LeetCode 225（用队列实现栈）则考察用 FIFO 模拟 LIFO，理解这道题能加深对两种结构差异的认知。

---

> [!note] 一个容易被忽略的视角
> 本篇的三道题，处理的都是"配对"或"求值"这类**局部可判定**的问题——每个元素是否被匹配、每个位置的水位是多少，都能在"看到某个未来元素"时立刻定下。**这正是栈能发挥作用的场景：局部可判定，意味着"一旦处理完就不必回头"，而这正是 LIFO 所保证的。** 反过来，如果某个元素的答案依赖"尚未出现的全局信息"（如全局中位数），栈就无能为力了。**判断"能不能用栈"，本质就是问"这题的答案是不是局部可判定的"。** 而"局部可判定"这一性质，恰恰来自"元素之间存在明确的先后依赖"——**没有先后依赖的地方，栈也就无从下手。**
