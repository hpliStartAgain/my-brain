# 链表反转艺术：局部反转、k 组翻转与节点交换

**摘要：**

链表反转是面试中最高频的链表操作，没有之一。它之所以重要，是因为它是一块"试金石"——一段三行的反转代码，能同时暴露你对指针顺序、边界处理、以及"改引用而非改数据"这些基本功的掌握程度。本文从反转整个链表（LeetCode 206）的基础模板出发，逐层深入到三种变体：局部反转（LeetCode 92，反转 m 到 n 段）、k 组翻转（LeetCode 25，每 k 个一组，含递归与迭代两种解法）、两两交换（LeetCode 24，k=2 的特例）。这四道题构成一条完整的知识链：206 是地基，92 教你在局部做反转并把两端重新接好，25 是把 92 重复做多次，24 则是 25 的最简特例。理解这条链，就能明白——**所有反转变体的差异，只在"反转哪一段"与"反转后如何衔接两端"这两点上**。本文用 Go 语言完整实现，并逐行解释每处指针操作"为什么这么写"。

---

## 第 1 章 反转链表：基础模板

在接触任何变体之前，必须先把"反转整个链表"（LeetCode 206）练到不假思索。它有两种写法，各有用途。

### 1.1 迭代反转：三指针的舞蹈

**思路**：用三个指针 `prev`、`curr`、`next`，逐节点翻转指向。`prev` 记录已反转部分的头，`curr` 是当前待处理节点，`next` 用来暂存后继。

```go
func reverseList(head *ListNode) *ListNode {
    var prev *ListNode
    curr := head
    for curr != nil {
        next := curr.Next // 先暂存后继：下一步 curr.Next 就要被改写
        curr.Next = prev  // 反转：curr 指向前驱
        prev = curr       // prev 前进
        curr = next       // curr 前进
    }
    return prev // curr 为 nil 时，prev 就是新的头节点
}
```

**逐步演示** `[1,2,3,4,5]`：

```text
初始: prev=nil, curr=1

step1: next=2, 1.Next=nil, prev=1, curr=2
step2: next=3, 2.Next=1,   prev=2, curr=3
step3: next=4, 3.Next=2,   prev=3, curr=4
step4: next=5, 4.Next=3,   prev=4, curr=5
step5: next=nil, 5.Next=4, prev=5, curr=nil

返回 prev=5（新头）→ 5→4→3→2→1→nil ✓
```

**为什么必须先存 `next` 再改写 `curr.Next`？** 这是整段代码唯一的关键点：`curr.Next` 一旦被改成 `prev`，原来指向后继的线索就断了。**若先改写、后保存，后继节点便永久丢失，链表从此断成两截。** 三行操作的顺序，正是被这条约束定死的——**先保存、再改写、最后前进**。

### 1.2 递归反转：从后往前的视角

```go
func reverseListRecursive(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head // 基准情况：空或单节点，直接返回
    }
    newHead := reverseListRecursive(head.Next) // 递归反转后面的部分
    head.Next.Next = head                      // 后继反指回来
    head.Next = nil                            // 断开 head 原有的后继，防止成环
    return newHead
}
```

**递归的理解**：调用 `reverseListRecursive(head.Next)` 之后，`head.Next` 及其后面的部分已经**整体反转完毕**，并返回了新的头 `newHead`。此时 `head.Next` 变成了反转后那段的**末尾节点**（它原来是第二个）。我们只需让这个末尾节点反指回 `head`，再把 `head.Next` 置空，整条链就完成了反转。

**递归与迭代的取舍**：递归代码更短、更接近"分治"的直觉，但空间是 $O(n)$（递归栈）；迭代空间 $O(1)$，是面试更稳妥的选择。**面试时优先写迭代版**，若面试官追问"还有别的写法吗"，再补递归版展示视野。

## 第 2 章 LeetCode 92：反转链表 II（局部反转）

### 2.1 题目

**LeetCode 92 - Reverse Linked List II**（中等）

给你单链表的头指针 `head` 和两个整数 `left`、`right`（`left <= right`），反转从位置 `left` 到位置 `right` 的节点，返回反转后的链表。位置从 1 开始计数。

```text
输入: head = [1,2,3,4,5], left=2, right=4  →  输出: [1,4,3,2,5]
输入: head = [5], left=1, right=1          →  输出: [5]
```

### 2.2 难点不在反转，而在"接回去"

局部反转的**反转动作本身**与第 206 题完全一样；真正的难点在于——**反转完成后，如何把这段反转好的子链，与左右两侧的链表重新接好。** 这需要保存四个"锚点"：

- `pre`：`left` 的前驱节点（反转段左边界之外的那个节点）；
- `start`：反转段的起始节点（第 `left` 个节点，反转后会变成这段的**尾**）；
- `then`：当前准备"摘下来"的节点（遍历游标）；
- `end`：反转段的末尾（第 `right` 个节点，反转后会变成这段的**头**）。

**哑节点在这里的作用**：当 `left == 1` 时，反转段从头节点开始，头节点本身也要被反转，于是"前驱"不存在。哑节点恰好充当这个前驱 `pre`，再次把边界特例抹平（呼应第 10 篇）。

```go
func reverseBetween(head *ListNode, left, right int) *ListNode {
    dummy := &ListNode{Next: head}
    pre := dummy
    // 走到 left-1 位置，即反转段的前驱
    for i := 0; i < left-1; i++ {
        pre = pre.Next
    }
    start := pre.Next   // 反转段第一个节点，反转后成为段尾
    then := start.Next  // 当前待"摘下前插"的节点

    // 执行 right-left 次"头插"操作
    for i := 0; i < right-left; i++ {
        start.Next = then.Next // start 跳过 then
        then.Next = pre.Next   // then 接到反转段当前的头部之前
        pre.Next = then        // pre 指向 then，使 then 成为反转段新头
        then = start.Next      // then 前进到下一个待处理节点
    }
    return dummy.Next
}
```

### 2.3 为什么是"头插法"

这段代码的机理是**头插法**：每次循环把 `start.Next` 指向的那个节点"摘下来"，插到 `pre` 的后面（也就是反转段的头部）。执行 `right - left` 次之后，反转段里原本最靠右的节点被逐个搬到了最左边，整段自然就被翻转了。

**换个角度看**：它不是"就地反转每个节点的指向"，而是"不断把后面的节点搬到前面"。**这种"搬运"而非"翻转"的视角，是局部反转最不容易出错的理解方式**——因为它始终维持着"左边界（pre）不变、右边界（start）不动"这两个锚点，你随时能在脑子里画出当前状态。

**手动演示** `[1,2,3,4,5], left=2, right=4`：

```text
初始: dummy→1→2→3→4→5, pre=1, start=2, then=3

第 1 次：
  start.Next = then.Next = 4   （2 跳过 3，指向 4）
  then.Next = pre.Next = 2     （3 指向 2）
  pre.Next = then = 3          （1 指向 3）
  then = start.Next = 4
  状态: dummy→1→3→2→4→5

第 2 次：
  start.Next = then.Next = 5   （2 跳过 4，指向 5）
  then.Next = pre.Next = 3     （4 指向 3）
  pre.Next = then = 4          （1 指向 4）
  then = start.Next = 5
  状态: dummy→1→4→3→2→5

返回: 1→4→3→2→5 ✓
```

**复杂度**：时间 $O(n)$，空间 $O(1)$。

> [!warning] 生产避坑：四个锚点的顺序不能乱
> 局部反转的每一次循环，四行代码的顺序是**被约束死的**：必须先 `start.Next = then.Next`（把 then 从链上摘下），才能 `then.Next = pre.Next`（给 then 找新位置），再 `pre.Next = then`（把它接上）。若顺序颠倒，比如先写 `pre.Next = then`，那么 `then.Next` 原本要用的那个"反转段当前头部"就已经找不到了。**面试时建议先在纸上画好这四个锚点，再落笔写这四行。**

## 第 3 章 LeetCode 25：K 个一组翻转链表

### 3.1 题目

**LeetCode 25 - Reverse Nodes in k-Group**（困难）

给你链表的头节点 `head`，每 `k` 个节点为一组进行翻转，返回修改后的链表。`k` 是正整数且不超过链表长度。若节点总数不是 `k` 的整数倍，最后剩余的节点保持原有顺序。

```text
输入: head = [1,2,3,4,5], k = 2  →  输出: [2,1,4,3,5]
输入: head = [1,2,3,4,5], k = 3  →  输出: [3,2,1,4,5]
```

### 3.2 核心子问题的分解

**关键观察**：k 组翻转可以分解为两个子问题：

1. **判断剩余节点是否 ≥ k**：若不足 k 个，则不翻转，直接结束；
2. **翻转一组**：对当前 k 个节点执行反转，并把它与前后两组正确衔接。

**这与第 92 题的局部反转其实是同一件事，只是"重复做了多次"。** 抓住这一点，迭代解法的框架就清晰了：用 `prevGroupTail` 记录上一组的尾节点，每轮先探测是否有 k 个节点，有则翻转一组、接好线，再更新 `prevGroupTail`，继续下一轮。

```go
func reverseKGroup(head *ListNode, k int) *ListNode {
    dummy := &ListNode{Next: head}
    prevGroupTail := dummy // 上一组的尾节点

    for {
        // 探测：从 prevGroupTail 出发能否找到第 k 个节点
        kth := getKthNode(prevGroupTail, k)
        if kth == nil {
            break // 不足 k 个，不翻转，结束
        }
        nextGroupHead := kth.Next // 下一组的起点

        // 反转 [prevGroupTail.Next, kth] 这 k 个节点
        prev := nextGroupHead // 反转后的尾巴应指向下一组头
        curr := prevGroupTail.Next
        for curr != nextGroupHead {
            next := curr.Next
            curr.Next = prev
            prev = curr
            curr = next
        }
        // 此时 prev 是翻转后的新头（即原来的 kth）
        newGroupHead := prev
        newGroupTail := prevGroupTail.Next // 原来的组头，翻转后成了组尾

        prevGroupTail.Next = newGroupHead // 上一组尾部接上新组头
        prevGroupTail = newGroupTail      // 更新"上一组尾"为本组尾
    }
    return dummy.Next
}

// 从 node 出发走 k 步，返回第 k 个节点；不足 k 步则返回 nil
func getKthNode(node *ListNode, k int) *ListNode {
    for node != nil && k > 0 {
        node = node.Next
        k--
    }
    return node
}
```

**一个精妙之处**：反转时把 `prev` 初始化为 `nextGroupHead`（下一组的头）而非 `nil`——这样反转结束后，本组的尾节点（原来的组头）的 `Next` 会**自动指向下一组的头**，省去了后续一次显式衔接。**用一个恰当的初值，把"接右端"这件事内化进了反转循环，这是很值得学习的技巧。**

**手动验证** `[1,2,3,4,5], k=2`：

```text
初始: dummy→1→2→3→4→5, prevGroupTail=dummy

第 1 轮:
  getKthNode(dummy, 2) → 2（kth=2），nextGroupHead=3
  反转 1→2（prev 从 3 开始）: 1.Next=3, 2.Next=1 → 新头 2，新尾 1
  dummy.Next = 2, prevGroupTail = 1
  链表: dummy→2→1→3→4→5

第 2 轮:
  getKthNode(1, 2) → 4（kth=4），nextGroupHead=5
  反转 3→4: 3.Next=5, 4.Next=3 → 新头 4，新尾 3
  1.Next = 4, prevGroupTail = 3
  链表: dummy→2→1→4→3→5

第 3 轮:
  getKthNode(3, 2) → nil（不足 2 个），break
返回 2→1→4→3→5 ✓
```

### 3.3 递归解法：更简洁的表达

```go
func reverseKGroupRecursive(head *ListNode, k int) *ListNode {
    // 检查是否有 k 个节点
    node := head
    for i := 0; i < k; i++ {
        if node == nil {
            return head // 不足 k 个，不翻转，原样返回
        }
        node = node.Next
    }
    // node 现在是第 k+1 个节点，即下一组的起点

    // 先递归处理后面的部分
    nextGroupHead := reverseKGroupRecursive(node, k)

    // 再反转当前 k 个节点，prev 初值设为 nextGroupHead 以自动接上后一组
    prev := nextGroupHead
    curr := head
    for i := 0; i < k; i++ {
        next := curr.Next
        curr.Next = prev
        prev = curr
        curr = next
    }
    return prev // 反转后的新头
}
```

**递归的视角很漂亮**：先让"后面的组"各自处理完毕，拿到 `nextGroupHead`；再反转当前这一组，并让本组的尾自动连到 `nextGroupHead`。**这与第 92 题"先处理好局部、再接回两端"是同一思路，只是这里的"后面"是递归处理的。** 时间 $O(n)$，空间 $O(n/k)$（递归栈深度）。

> [!info] 迭代与递归的取舍
> 递归版代码更短、语义更清晰，但空间是 $O(n/k)$；迭代版空间 $O(1)$，是面试更稳妥的选择。**建议先写迭代版（体现工程严谨），若面试官追问"能不能更简洁"，再给递归版（体现思路灵活）。** 反之，若先写递归版，面试官可能会追问"能不能不用递归栈"，反而被动。

## 第 4 章 LeetCode 24：两两交换链表中的节点

### 4.1 题目

**LeetCode 24 - Swap Nodes in Pairs**（中等）

给你一个链表，两两交换其中相邻的节点，返回交换后链表的头节点。必须在不修改节点内部值的前提下完成（即只能进行节点交换）。

```text
输入: head = [1,2,3,4]  →  输出: [2,1,4,3]
输入: head = [1]        →  输出: [1]
```

### 4.2 方法一：迭代（k=2 的特例）

这道题就是第 25 题在 `k=2` 时的特例，只是逻辑更简单，可以单独写出更精简的迭代版：

```go
func swapPairs(head *ListNode) *ListNode {
    dummy := &ListNode{Next: head}
    prev := dummy

    for prev.Next != nil && prev.Next.Next != nil {
        first := prev.Next
        second := prev.Next.Next

        // 交换 first 与 second
        first.Next = second.Next // first 跳过 second
        second.Next = first      // second 指向 first
        prev.Next = second       // prev 指向新头 second

        prev = first // prev 前进到这一对的尾部（交换后 first 成了尾）
    }
    return dummy.Next
}
```

**手动验证** `[1,2,3,4]`：

```text
初始: dummy→1→2→3→4, prev=dummy

第 1 轮: first=1, second=2
  1.Next = 3, 2.Next = 1, dummy.Next = 2
  prev = 1
  链表: dummy→2→1→3→4

第 2 轮: first=3, second=4
  3.Next = nil, 4.Next = 3, 1.Next = 4
  prev = 3
  链表: dummy→2→1→4→3

返回 2→1→4→3 ✓
```

**循环条件 `prev.Next != nil && prev.Next.Next != nil`**：它同时保证了"这一对有两个节点"——若只剩一个节点（`prev.Next.Next == nil`），就不交换，保持原样。

### 4.3 方法二：递归（核心逻辑一行）

```go
func swapPairsRecursive(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head
    }
    second := head.Next
    head.Next = swapPairsRecursive(second.Next) // 递归处理后续
    second.Next = head                          // second 指向 head
    return second                               // second 成为新头
}
```

**递归解法极简**：`head` 与 `second` 交换后，让 `head.Next` 连上"后续部分递归处理的结果"，`second` 成为新的头。**这三行代码几乎是"两两交换"这个问题的直译**——交换当前两个，再递归处理剩下的。它是展示"用递归写出优雅代码"的好机会，但面试时也要能写出迭代版。

## 第 5 章 反转链表的知识体系

### 5.1 反转的本质操作

无论哪一种反转变体，核心都是同一个三步操作（迭代版）：

```go
next := curr.Next // 暂存后继
curr.Next = prev  // 反转指向
prev, curr = curr, next // 双双前进
```

变体题与基础题的差别，**只在两个问题上**：

- **反转哪一段**：206 反转全部；92 反转 m 到 n；25 反转每组 k 个；24 反转每两个；
- **如何衔接两端**：反转完成后，如何把"左侧链表的尾"和"右侧链表的头"正确接上。

**把这两点想清楚，所有反转题都会归约成同一套骨架。** 这也解释了为什么本文的解法都在反复出现"保存前驱 pre""让尾巴指向下一段的头"这类操作——它们处理的正是"衔接两端"这件事。

### 5.2 四道题的关系

```text
          206 反转整个链表（基础）
               ↓
    92 反转 m 到 n（局部版本，学"接两端"）
               ↓
  25 k 组翻转（重复多次局部反转）
               ↓
     24 两两交换（k=2 的特例）
```

**理解了 206，其余三道都只是它的扩展。** 206 教会你"如何翻转一段"，92 教会你"如何把翻好的一段接回去"，25 是"把 92 重复做"，24 则是"最简的特例"。这条从简到繁的路径，也正是学习的顺序。

### 5.3 三处高频陷阱

**陷阱一，改写 `Next` 前忘了保存后继。** 这是所有反转题的共同死因。**口诀：先存 `next`，再改 `curr.Next`。**

**陷阱二，局部反转后忘了把左端接上。** 92、25、24 都必须显式地把"左侧的尾"指向"反转后的新头"，否则反转段就与左侧脱节了。

**陷阱三，末节点的 `Next` 没有置空或正确指向。** 25 题里 `prev` 初值设为 `nextGroupHead` 正是为了避免这个坑；若初值设为 `nil`，则每组的尾巴都会指向 `nil`，需要额外一步修正。**用一个恰当的初值省掉一次修正，是这类题里很实用的小技巧。**

## 第 6 章 递归与迭代：反转题的两种心智模型

本文的每一道题都给出了迭代与递归两种写法。这不是为了凑解法数量，而是因为**它们代表了两种截然不同的思维模型**——看清这一点，你对链表的理解会上一个台阶。

### 6.1 迭代：自底向上的流水线

迭代写法的心智模型是**一条流水线**：`prev`、`curr`、`next` 三个指针像流水线上的工位，每个节点依次经过"暂存—改向—前进"三道工序。它的视角是**局部的**——每一步只关心"当前这个节点如何翻转指向"，不关心后面还有多少节点。

这种模型的优点是**空间恒定**（$O(1)$），且执行过程与链表长度无关地线性推进；缺点是**需要显式维护指针顺序**，一旦三行代码写乱顺序，就会断链。它考验的是"每一步都清醒"的严谨。

### 6.2 递归：自顶向下的分治

递归写法的心智模型是**分治**：先假设"后面的部分已经反转好了"，只处理"当前节点与反转后那一段的连接"。它的视角是**整体的**——每一步都建立在"子问题已解决"的假设之上。

这种模型的优点是**代码极简、语义清晰**，几乎就是问题描述的直译（"交换当前两个，再递归处理剩下的"）；缺点是**空间是 $O(n)$**（递归栈的深度等于链表长度），且对超长链表有栈溢出的风险。

### 6.3 何时该选哪一种

两种模型各有主场，判断依据是**约束**：

| 考量 | 迭代 | 递归 |
|------|------|------|
| 空间约束（要求 $O(1)$） | 优 | 劣（$O(n)$ 栈） |
| 代码简洁度 | 一般 | 优 |
| 超长链表的健壮性 | 优 | 有栈溢出风险 |
| 面试首选的稳妥解 | 优 | 视情况 |

**笔者的建议是：面试时优先写迭代版**（空间更优、更稳健，且展示了工程严谨），若面试官追问"有没有更简洁的写法"，再补递归版展示思路灵活。**反过来——若一上来就写递归，面试官往往会追问"能否不用递归栈"，反而让你陷入被动。**

> [!note] 递归的隐式成本
> 递归写法常给人"代码短就等于好"的错觉，但它把 $O(n)$ 的空间成本**藏进了调用栈里**——代码里看不见，运行时可都在。**评估一个解法时，永远要把"看不见的成本"也算进复杂度**：递归栈、Go 的 `defer`、切片底层数组的隐式扩容，都属于这一类。这种"把隐式成本显式化"的意识，是从"会写代码"迈向"会做工程"的分水岭。

## 第 7 章 延伸：反转家族的更多面孔

"反转一段"这个动作本身很简单，但它能组合出相当丰富的变体。下面三道延伸题，都在检验同一件事：**你是否真正理解了"翻转哪一段 + 如何衔接两端"这一框架。**

### 7.1 反转链表的前 N 个节点

**题目**：给定链表头节点 `head` 和整数 `n`，反转链表的前 `n` 个节点，返回新的头节点（后段保持原样）。

这道题是第 92 题在 `left = 1` 时的特例，但它的递归写法尤其优雅，值得一看：

```go
// reverseN 反转以 head 为起点的前 n 个节点，返回新头
// 借助闭包记录"第 n+1 个节点"，作为反转后尾节点的后继
func reverseN(head *ListNode, n int) *ListNode {
    var successor *ListNode
    var recurse func(node *ListNode, n int) *ListNode
    recurse = func(node *ListNode, n int) *ListNode {
        if n == 1 {
            successor = node.Next // 记录第 n+1 个节点
            return node
        }
        newHead := recurse(node.Next, n-1)
        node.Next.Next = node
        node.Next = successor // 反转后的尾节点接回第 n+1 个节点
        return newHead
    }
    return recurse(head, n)
}
```

**这段代码的价值在于，它把"接右端"这件事显式地表达了出来**——`successor` 就是第 `n+1` 个节点，反转后的尾节点（原来的 `head`）必须接回它。第 25 题里那个"把 `prev` 初值设为 `nextGroupHead`"的技巧，本质上就是在做同一件事，只是换了一种更隐蔽的表达。

### 7.2 反转指定区间并保持其余不变（第 92 题的递归版）

有了"反转前 N 个"的递归模板，第 92 题的递归解法就呼之欲出了——**当 `left == 1` 时，问题退化为"反转前 `right` 个"；否则，递归到 `head.Next`，让区间整体左移一格**：

```go
func reverseBetweenRecursive(head *ListNode, left, right int) *ListNode {
    if left == 1 {
        return reverseN(head, right) // 退化为"反转前 right 个"
    }
    // 区间左移一格：把 head 之后的部分当作新的起点
    head.Next = reverseBetweenRecursive(head.Next, left-1, right-1)
    return head
}
```

**这三行代码几乎是把问题描述直译了一遍**——"若区间从第 1 个节点开始，就是反转前 N 个；否则，保留头节点，让后面那截自己处理"。**递归在这里的价值，是把"区间位置"这一繁琐的坐标计算，转化成了"不断左移一格"的自然递推。** 相比之下，迭代版要显式数 `left-1` 步、维护四个锚点，虽更省空间，却远不如递归版贴合直觉。

### 7.3 交替反转：当"反转哪一段"变得复杂

**题目**：从头开始，每 `k` 个节点反转一次，但方向交替——第一组正序、第二组逆序、第三组正序……（这是一个常见变体）。

这类题的最佳思路，是**把"反转一段"抽成一个独立函数**，然后在主循环里只负责"决定这一段是否反转、以及如何衔接"。例如：

```go
// 主循环骨架（示意）
for prevGroupTail != nil {
    groupHead := prevGroupTail.Next
    groupTail := getKthNode(prevGroupTail, k)
    if groupTail == nil {
        break
    }
    nextHead := groupTail.Next
    var newHead, newTail *ListNode
    if shouldReverse { // 本组需要反转
        newHead, newTail = reverseGroup(groupHead, groupTail, nextHead)
    } else { // 本组保持原样
        newHead, newTail = groupHead, groupTail
    }
    prevGroupTail.Next = newHead
    prevGroupTail = newTail
}
```

**这道题的启示在于：当变体越来越复杂时，正确的应对不是"在一个大循环里塞进所有逻辑"，而是把稳定的部分（反转一段、找第 k 个）抽成独立函数，主循环只保留"决策与衔接"。** 这正是第 01 篇提到的"分拆再合并"心法在反转题上的延伸——**复杂的问题之所以复杂，往往只是因为它把好几个简单步骤缠在了一起；一旦拆开，每一步都平平无奇。**

## 第 8 章 反转题的 bug 全览与自测方法

反转题是链表 bug 的重灾区，把它们集中盘点一遍，比零散地记住若干"注意事项"更有效。

### 8.1 五类高频 bug

**bug 一：改向之前没保存后继。** 表现为链表断成两截，后半段丢失。根因是违背了"先存 `next`、再改 `curr.Next`"的铁律。

**bug 二：循环终止条件写错。** 如把 `curr != nil` 误写成 `curr.Next != nil`，导致最后一个节点没有被反转，或反过来多走一步导致空指针。**这类 bug 的表现是"结果总是差一个节点"。**

**bug 三：局部反转后左端没有接回。** 表现为反转段"飘"了出去，前面的链表与它脱节。根因是漏了 `prev.Next = newHead` 这一步。

**bug 四：末节点的 `Next` 没有正确置空或指向。** 表现为结果链表的末尾多出一个节点、或与前面某处成环（此时遍历会死循环）。

**bug 五：`k` 组翻转中组数或边界计算错误。** 表现为最后一组（不足 k 个）被错误地反转了，或最后一组的尾节点指向了错误的位置。

### 8.2 一套自测清单

写完任何一道反转题，用下面这份清单自测，基本可以拦截上述五类 bug：

| 检查项 | 对应 bug |
|--------|---------|
| 三行核心操作里，`next` 是否最先保存 | bug 一 |
| 空链表、单节点、两节点是否都正确 | bug 二 |
| 反转段的左端是否显式接回了前驱 | bug 三 |
| 反转段的右端是否指向了正确的后继（而非 `nil`） | bug 四 |
| 不足 k 个的尾组是否保持原样 | bug 五 |

### 8.3 用"手工走一遍"代替"调试"

链表题最有效的自测方式，不是写代码去跑，而是**在纸上把三到五个节点手工走一遍**。原因很朴素：链表 bug 几乎全都出在"某一步的指针指向了哪里"，而手工走一遍恰恰能把每一步的指向都写下来、看得见。**如果你不能在纸上把 `[1,2,3]` 反转的过程完整走通，那么代码大概率也是错的。**

> [!note] 一个反直觉的建议
> 很多人遇到链表题的第一反应是"先写代码，跑跑看"。但对链表而言，**先写代码往往比先画图更慢**——因为一旦出 bug，你不得不在脑子里重新推演整个指针状态，成本极高。笔者的建议是反过来：**先花一分钟把节点和箭头画出来，确认每一步的指向，再落笔写代码。** 这多出来的一分钟，通常会省下十分钟的调试。链表题惩罚的从来不是"想得慢"，而是"想得不够细"。

## 第 9 章 面试表达与延伸追问

### 9.1 五步表达法

反转题的表达，可以照下面这条链来讲：

1. **点明本质**："所有反转变体都可以拆成两件事——翻转哪一段、以及如何把两端接回去。"
2. **画图定锚点**："局部反转需要四个锚点：前驱 `pre`、段头 `start`、游标 `then`、段尾。"
3. **讲清顺序**："每次循环先把 `then` 摘下来、再给它找新位置、最后接上——顺序不能乱，因为后一步依赖前一步的结果。"
4. **说明边界**："`left == 1` 时用哑节点充当 `pre`；末节点的 `Next` 要指向正确的后继而非 `nil`。"
5. **补一句优化**："k 组翻转里，把 `prev` 初值设为下一组的头，能省掉一次显式衔接。"

### 9.2 三类常见追问

**追问一："迭代和递归哪个更好？"** 答：迭代空间 $O(1)$、更稳健；递归代码短、更贴近直觉，但空间 $O(n)$、有栈溢出风险。**面试首选迭代，被追问简洁性时再给递归。**

**追问二："能不能不反转节点、只交换 `Val`？"** 答：多数情况下可以（LeetCode 24 明确禁止，但很多变体允许），代价是当节点还带有其他字段（如随机指针、卫星数据）时，交换值会把这些数据也一起搬走，可能不符题意。**"交换节点"与"交换值"的区别，在简单链表上无感，在复杂节点上却是本质的。**

**追问三："k 组翻转能否做到 $O(1)$ 空间？"** 答：迭代版已经是 $O(1)$；递归版是 $O(n/k)$。**所以"能否 $O(1)$"的答案，取决于你选哪种实现——这又是一次"约束决定选型"。**

### 9.3 落点

反转题看似花样繁多，但正如第 5 章所说，它们都归约为"翻转一段 + 衔接两端"两个子问题。**把这两个子问题分别想透，再复杂的变体也只是它们的重新组合。** 面试中，与其死记某道题的解法，不如把这句话讲出来——**它展示的是"看穿共性"的能力，而面试官恰恰最看重这个。**

## 小结

本篇以四道题搭起了"链表反转"这一知识体系。LeetCode 206 是地基，它用三指针迭代和递归两种写法，把"先保存、再改写、后前进"这条铁律刻进肌肉记忆；LeetCode 92 揭示了局部反转的真正难点——不在反转本身，而在"如何把反转好的一段与左右两端重新接好"，四个锚点与哑节点的配合是解题关键；LeetCode 25 把局部反转推广到"重复多次"，其迭代版中"把 `prev` 初值设为下一组的头"这一手，巧妙地把"接右端"内化进了循环；LeetCode 24 则是 k=2 的最简特例。

四题合起来，给出两条可迁移的经验。其一，**一切反转变体都可以归约为"翻转一段 + 衔接两端"两个子问题**——先问"反转哪一段"，再问"如何接回去"，问题就解了一半。其二，**链表反转的全部风险都集中在"指针改写的顺序"上**：先存后继、再接两端、末节点处理干净，这三条守住了，反转题便再没有意外。**链表题的严谨，恰恰体现在这些"顺序不能错"的细节里——它不考验聪明，只考验是否每一步都清醒。**
