# 链表快慢指针：环检测、倒数节点与链表旋转

**摘要：**

快慢指针（Floyd 判圈算法）是链表题里最具代表性的技巧：两个指针以不同速度在同一结构上移动，通过它们的**相对位置关系**反推出链表的结构信息。这套技巧之所以精妙，在于它把"结构判断"这种通常需要额外空间的难题，化解成了两个指针的"赛跑"——空间复杂度因此降到 $O(1)$。本文覆盖四道经典题：LeetCode 141（环路检测）、142（找环入口）、19（删除倒数第 N 个节点）、61（旋转链表）。其中 141 给出判圈的正确性证明，142 给出"头到入口等于相遇点到入口"这一著名结论的完整数学推导，19 展示了"保持固定步距"这一快慢指针的另一种用法，61 则把旋转巧妙地转化为"先成环、再在正确位置断开"。本文用 Go 语言完整实现，并在每道题后交代其背后的不变量与数学依据。

---

## 第 1 章 快慢指针的基本原理

### 1.1 龟兔赛跑

快慢指针（Fast-Slow Pointer），又称龟兔赛跑算法，源自 Floyd 的判圈思想：

- **慢指针（slow）**：每次移动 1 步；
- **快指针（fast）**：每次移动 2 步。

**核心直觉**：如果链表里存在环，那么进入环之后，快指针一定会在某个时刻"追上"慢指针——就像跑道上两位速度不同的运动员，快的那个总会从后面追上并超过慢的。反之，如果链表无环，快指针会率先抵达终点（`fast == nil` 或 `fast.Next == nil`）。

这个直觉之所以可靠，是因为**进入环以后，两个指针都被"困"在同一个有限的圈里**：快指针每轮比慢指针多走 1 步，两者的距离每轮减少 1，终将归零。**"每轮追近一步"这一确定性，是判圈算法成立的根基。**

### 1.2 快慢指针的适用场景

速度差这一简单机制，能派生出相当丰富的一族应用：

| 场景 | 具体应用 |
|------|---------|
| 检测链表是否有环 | LeetCode 141 |
| 找环的入口节点 | LeetCode 142 |
| 找链表中间节点 | 快指针到末尾时，慢指针恰在中间（LeetCode 876） |
| 找倒数第 N 个节点 | 快指针先走 N 步，再同步前进（LeetCode 19） |
| 判断链表是否回文 | 找中点 + 反转后半段（LeetCode 234） |

**把这些场景归拢起来看，快慢指针的本质是"用速度差度量位置"**：快指针到达某个已知位置时，慢指针所处的位置恰好是我们想求的那个。它不是一种"搜索"，而是一种"同步计时"——用快指针的行程，来标定慢指针的坐标。

## 第 2 章 LeetCode 141：环路检测

### 2.1 题目

**LeetCode 141 - Linked List Cycle**（简单）

给定一个链表的头节点 `head`，判断链表中是否有环。若存在某个节点，可以通过连续跟踪 `Next` 指针再次到达，则链表中有环。返回 `true` 或 `false`。

```text
输入: head = [3,2,0,-4], pos = 1（尾部连接到下标 1 的节点）  →  输出: true
输入: head = [1,2], pos = 0                              →  输出: true
输入: head = [1], pos = -1                               →  输出: false
```

### 2.2 解法

```go
func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next      // 慢指针走 1 步
        fast = fast.Next.Next // 快指针走 2 步
        if slow == fast {
            return true // 相遇，说明有环
        }
    }
    return false // fast 到达末尾，无环
}
```

**为什么循环条件是 `fast != nil && fast.Next != nil`？** 因为 `fast` 每轮要走 2 步：先要保证 `fast` 本身不为空（否则无法访问 `fast.Next`），还要保证 `fast.Next` 不为空（否则无法访问 `fast.Next.Next`）。**这两个检查缺一不可**——少了前一个，访问 `fast.Next` 时 panic；少了后一个，访问 `fast.Next.Next` 时 panic。

### 2.3 正确性证明

设链表"无环部分"的长度为 $a$，环的长度为 $c$。

**当慢指针刚进入环时**，它走了 $a$ 步；此时快指针走了 $2a$ 步，它相对环入口的位置是 $(2a - a) \bmod c = a \bmod c$。

**进入环之后**，快指针每轮比慢指针多走 1 步，而两者都待在长度为 $c$ 的环内。快指针与慢指针之间的"距离"（沿环前进方向计算）每轮缩短 1 步，最多经过 $c$ 轮，距离就会归零——即两指针相遇。

**所以：只要存在环，快慢指针必然在环内相遇；若不存在环，快指针必然先到末尾。** 两条路径穷尽了所有可能，算法的正确性由此得证。

**复杂度**：时间 $O(n)$（慢指针最多走 $a + c$ 步），空间 $O(1)$（只用两个指针）。**这正是快慢指针优于哈希表解法之处**——用哈希表记录访问过的节点同样能判圈，但要 $O(n)$ 空间；快慢指针把这个空间省了下来。

## 第 3 章 LeetCode 142：环路入口

### 3.1 题目

**LeetCode 142 - Linked List Cycle II**（中等）

给定一个链表的头节点 `head`，返回链表开始入环的第一个节点；若无环，返回 `nil`。

```text
输入: head = [3,2,0,-4], pos = 1  →  输出: 下标为 1 的节点（值为 2）
```

### 3.2 数学推导

这道题是 141 的升级：不仅要判断有没有环，还要**定位环的入口**。它需要一段漂亮的数学推导。

**设定变量：**

- 头节点到环入口的距离记为 $a$；
- 环入口到"相遇点"的距离记为 $b$；
- 相遇点沿环继续走到环入口的距离记为 $c$；
- 于是环长 $= b + c$。

**相遇时两指针各走了多少？** 慢指针走了 $a + b$；快指针走了 $a + b + k(b+c)$（它在环里多绕了 $k$ 圈，$k \ge 1$）。由于快指针速度是慢指针的两倍：

$$2(a + b) = a + b + k(b + c)$$

化简：

$$a + b = k(b + c) \quad \Longrightarrow \quad a = (k-1)(b + c) + c$$

**关键结论就是最后这个式子：$a = (k-1)(b+c) + c$。** 它说的是：**从链表头走 $a$ 步，与从相遇点走 $c$ 步（再加上绕 $(k-1)$ 圈环），会到达同一个位置——环入口。**

特别地，当 $k = 1$ 时，$a = c$——**头节点到环入口的距离，恰好等于相遇点到环入口的距离。** 这就是那道著名结论的由来。

### 3.3 从结论到算法

这个式子直接翻译成算法：**第一阶段用快慢指针找到相遇点；第二阶段，把一个指针放回链表头，另一个留在相遇点，然后两者以相同的速度（都走 1 步）前进，它们相遇的地方就是环入口。**

为什么？因为从头出发的指针走 $a$ 步到达入口，从相遇点出发的指针走 $c$ 步（再绕整数圈）也到达入口，而 $a$ 与 $c$（加上整数圈）是相等的路程——两者必然同时抵达。

```go
func detectCycle(head *ListNode) *ListNode {
    slow, fast := head, head

    // 第一阶段：找相遇点
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            // 第二阶段：一个回到头部，另一个留在相遇点，同速前进
            for slow = head; slow != fast; {
                slow = slow.Next
                fast = fast.Next // 注意：这里 fast 也只走 1 步
            }
            return slow // 相遇处即环入口
        }
    }
    return nil // 无环
}
```

**手动验证** `[3,2,0,-4]`（`-4` 的 `Next` 指回节点 `2`，故环入口是节点 `2`）：

```text
第一阶段：
slow=3, fast=3
step1: slow=2, fast=0
step2: slow=0, fast=2（fast: 0→-4→2）
step3: slow=-4, fast=-4（fast: 2→0→-4）相遇，相遇点在 -4

此时 a=1（3→2，走 1 步到入口），c=1（-4→2，走 1 步到入口），验证 a=c ✓

第二阶段：
slow 重置到 3，fast 留在 -4
step1: slow=2, fast=2 → 相遇，返回节点 2（环入口）✓
```

**复杂度**：时间 $O(n)$，空间 $O(1)$。

> [!note] 记住结论还是记住推导
> 面试中常见的建议是"记住结论"——相遇后把一指针放回头部、同速前进即可。但笔者更建议理解推导，原因有二：其一，理解 $a = (k-1)(b+c) + c$ 之后，即便一时忘了结论，也能在面试现场两分钟内重新推出来；其二，这段推导本身就是展示"能用数学分析算法"的绝佳机会，往往比背出结论更能赢得面试官认可。**能推导的结论，才是真正属于你的结论。**

## 第 4 章 LeetCode 19：删除链表的倒数第 N 个节点

### 4.1 题目

**LeetCode 19 - Remove Nth Node From End of List**（中等）

给你一个链表，删除链表的倒数第 `n` 个节点，并返回链表的头节点。

```text
输入: head = [1,2,3,4,5], n = 2  →  输出: [1,2,3,5]
输入: head = [1], n = 1          →  输出: []
输入: head = [1,2], n = 1        →  输出: [1]
```

### 4.2 从两遍扫描到一遍扫描

**朴素思路**：先遍历一遍求链表长度 $L$，则目标节点是正数第 $L-n+1$ 个，再遍历一遍找到它。这需要两遍扫描。

**快慢指针（一遍扫描）**：让快指针先走 `n+1` 步，随后快慢同步前进。当快指针走到 `nil` 时，慢指针恰好停在**目标节点的前驱**上，于是可以执行删除。

**为什么要先走 `n+1` 步，而不是 `n` 步？** 因为删除一个节点，需要先拿到它的**前驱**（才能写 `prev.Next = prev.Next.Next`）。让快指针多走一步，正是为了让"快指针到末尾"这个时刻，慢指针停在目标节点之前一格。**这里的 `+1` 不是随意的偏移，而是"我们要操作的是前驱而非节点本身"这一需求的直接翻译。**

```go
func removeNthFromEnd(head *ListNode, n int) *ListNode {
    dummy := &ListNode{Next: head} // 哑节点，统一删除头节点的情况
    fast, slow := dummy, dummy

    // fast 先走 n+1 步，使 slow 最终停在目标节点的前驱
    for i := 0; i <= n; i++ {
        fast = fast.Next
    }
    // 同步前进，直到 fast 抵达末尾
    for fast != nil {
        fast = fast.Next
        slow = slow.Next
    }
    // slow 现在位于目标节点的前驱
    slow.Next = slow.Next.Next
    return dummy.Next
}
```

**手动验证** `[1,2,3,4,5], n=2`（删除节点 4）：

```text
dummy→1→2→3→4→5→nil

fast 先走 n+1=3 步：dummy→1→2→3，fast=3，slow=dummy
同步前进：
  fast=4, slow=1
  fast=5, slow=2
  fast=nil, slow=3
slow=3 是节点 4 的前驱 → 3.Next = 3.Next.Next = 5
结果: dummy→1→2→3→5 ✓
```

**边界验证** `[1], n=1`（删除头节点）：fast 先走 2 步到 `nil`，同步循环不执行，slow 停在 dummy，`dummy.Next = dummy.Next.Next = nil`，返回 `nil`。**这里哑节点再次立功**——删头节点与删中间节点走的是同一套代码，没有任何特判。

**复杂度**：时间 $O(n)$（一遍扫描），空间 $O(1)$。

> [!info] 快慢指针的两种"用法"
> 对比一下本章与上一章：142 题的快慢指针靠**速度差**（2 步 vs 1 步）制造相遇；19 题的快慢指针靠**固定步距**（先走 n+1 步，再同速）来定位倒数位置。**同叫"快慢指针"，机理其实不同**——前者是"变速"，后者是"错位起跑"。抓住这一点，就不会把它们混为一谈。

## 第 5 章 LeetCode 61：旋转链表

### 5.1 题目

**LeetCode 61 - Rotate List**（中等）

给你一个链表的头节点 `head`，将链表每个节点向右移动 `k` 个位置。

```text
输入: head = [1,2,3,4,5], k = 2  →  输出: [4,5,1,2,3]
输入: head = [0,1,2], k = 4      →  输出: [2,0,1]
```

### 5.2 分析：旋转等于"先成环、再断开"

**理解旋转**：向右移动 `k` 位，等价于把链表末尾的 `k` 个节点整体搬到头部。例如 `[1,2,3,4,5], k=2`，把后两个节点 `[4,5]` 搬到最前面，得到 `[4,5,1,2,3]`。

**实现步骤：**

1. 遍历求链表长度 `len`，同时找到末尾节点 `tail`；
2. 把 `tail.Next` 接到 `head`，先**人为成环**；
3. 计算新头节点的位置——它是正数第 `len - k%len` 个节点；
4. 在新头节点的**前驱**处断开环，返回新头。

**"先成环、再断开"这一手法的妙处在于**：旋转本是一场"头尾搬家"，直接搬容易把引用关系弄乱；而先把它接成环，环上的每个节点地位平等，只需找准断点、一刀切开即可。**把"移动"转化为"在一个环上重新选择起点"，思路一下子就干净了。**

```go
func rotateRight(head *ListNode, k int) *ListNode {
    if head == nil || head.Next == nil || k == 0 {
        return head
    }
    // 第一步：求长度，找尾节点
    length := 1
    tail := head
    for tail.Next != nil {
        tail = tail.Next
        length++
    }
    // 第二步：k 对长度取模（旋转 length 次等于没旋转）
    k %= length
    if k == 0 {
        return head
    }
    // 第三步：成环
    tail.Next = head
    // 第四步：找新尾节点（正数第 length-k 个），即新头的前驱
    newTail := head
    for i := 0; i < length-k-1; i++ {
        newTail = newTail.Next
    }
    newHead := newTail.Next
    // 第五步：断开环
    newTail.Next = nil
    return newHead
}
```

**手动验证** `[1,2,3,4,5], k=2`：

```text
length=5, tail=5, k=2%5=2
成环: 5.Next=1 → 1→2→3→4→5→1→...
新头是第 5-2=3 个节点（即 4）；newTail 走 length-k-1=2 步：
  初始 newTail=1 → 走1步=2 → 走2步=3
newHead = 3.Next = 4，newTail.Next = nil
返回 4→5→1→2→3 ✓
```

**复杂度**：时间 $O(n)$（两次线性扫描），空间 $O(1)$。

> [!warning] 生产避坑：别忘了 `k %= length` 与 `k == 0` 特判
> 当 `k` 是链表长度的整数倍时，旋转等价于不动，链表结构应当原样返回。如果代码里已经**成环**却忘了对 `k == 0` 特判，就会返回一条带环的链表——后续任何遍历都会陷入死循环。**"先成环"这一手法虽然干净，但它把'链表是否成环'的责任推给了后续的'断开'步骤**：务必保证每一条路径都执行了断开，或提前对无需旋转的情况返回。

## 第 6 章 找中点：快慢指针的另一个经典用法

在进入模式总结前，补一个快慢指针的经典应用——**找链表中点**（LeetCode 876），它是第 13 篇"重排链表"的前置步骤。

思路极为简洁：慢指针走 1 步、快指针走 2 步，快指针到末尾时，慢指针恰好落在中间。

```go
func middleNode(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    return slow
}
```

**为什么慢指针恰好在中点？** 因为当快指针走了 $2m$ 步到达末尾时，慢指针恰好走了 $m$ 步——而 $2m$ 步正是"到末尾"的距离，$m$ 步便落在一半处。**这又是"用速度差度量位置"的同一套逻辑**：快指针的行程充当了"整段长度"的标尺，慢指针的行程自然就是它的一半。

**边界细节**：当节点数为偶数时，这段代码返回的是**靠右**的那个中点（例如 `[1,2,3,4]` 返回节点 `3`）。这一点在重排链表里很关键——有时需要靠左的中点，就得调整循环条件。**"中点"在偶数长度下并不唯一，用之前必须确认题目要的是哪一个。**

## 第 7 章 快慢指针的模式总结

四道题展示了快慢指针在不同场景下的变形，也暴露了它其实有"两种机理"：

| 题目 | 快慢指针变体 | 关键设计 |
|------|-------------|---------|
| 141 环检测 | 快走 2 步、慢走 1 步 | 有环则必相遇 |
| 142 环入口 | 先变速找相遇，再同速找入口 | 相遇后重置一个到头部 |
| 19 倒数第 N 个 | 快先走 N+1 步，再同速 | 维持固定的 N+1 步间距 |
| 61 旋转链表 | 转化为"成环再断开" | 不是严格的快慢指针 |
| 876 找中点 | 快走 2 步、慢走 1 步 | 快指针充当长度标尺 |

> [!note] 61 题不是严格的快慢指针
> 旋转链表的核心技巧是"成环再断"，而非快慢指针。它之所以与本篇同列，是因为它同样考察**链表结构理解与边界处理**，是快慢指针系列之后的一道综合练习。**把它当作"披着快慢指针外衣的结构题"来看，就不会困惑于"它的快慢指针在哪里"。**

**把这一族技巧抽象到底层，其实只有一条主线：通过让两个指针以某种已知的"相对运动"前进，来反推出结构信息。** 相对运动可以是速度差（141、142、876），也可以是固定错位（19），甚至可以是"先人为构造一个环再重新定位"（61）。抓住了"相对运动 → 结构信息"这条主线，再遇到陌生的链表结构题，你就能主动去想：我能不能用两个指针的相对位置，把想求的那个量标定出来？

## 第 8 章 延伸：快慢指针走出链表

快慢指针并非链表专属。本章看三道题，它们要么把双指针用于链表结构之外，要么把"判圈"的思想迁移到数组上——这些延伸能让你更清楚地看到：**快慢指针的本质是一种通用的"相对运动"思维，与数据结构的形态无关。**

### 8.1 相交链表（LeetCode 160）：走对方的长度

**题目**：给你两个单链表的头节点，判断它们是否相交，若相交返回相交的起始节点。

朴素做法是求两条链表的长度差，再让长的那条先走差值步——但这需要先各遍历一遍求长度。有一个更优雅的双指针写法：**让两个指针分别从两条链表的头出发，同步前进；走到末尾后，转而从另一条链表的头继续走。** 若两链表相交，它们必然在相交点相遇。

```go
func getIntersectionNode(headA, headB *ListNode) *ListNode {
    a, b := headA, headB
    for a != b {
        if a == nil {
            a = headB // A 走完了，转去走 B
        } else {
            a = a.Next
        }
        if b == nil {
            b = headA // B 走完了，转去走 A
        } else {
            b = b.Next
        }
    }
    return a // 相交点，或同时为 nil（不相交）
}
```

**为什么"走对方的长度"一定有效？** 设 A 的独有段长 $a$、B 的独有段长 $b$、公共段长 $c$。指针 `a` 走的路径是"A 全程 + B 独有段" $= a + c + b$；指针 `b` 走的路径是"B 全程 + A 独有段" $= b + c + a$。**两者路程相等，因此若相交，它们必然同时抵达相交点；若不相交，则同时抵达 `nil`。** 这里没有"快慢"之分（两指针同速），靠的是**路程的对称构造**——它再次印证了那条主线：**通过设计两个指针的相对运动，来反推结构信息。**

### 8.2 寻找重复数（LeetCode 287）：数组上的判圈

**题目**：给定一个包含 $n+1$ 个整数的数组，其数字都在 $[1, n]$ 范围内。只有一个数字重复出现（可能不止一次），找出这个重复的数字。要求不修改数组、只用 $O(1)$ 额外空间。

这道题看似与链表无关，却可以用 Floyd 判圈算法解——**关键是把数组看作一个"隐式的链表"**：把下标 `i` 视为节点，把 `nums[i]` 视为"节点 `i` 指向的下一个节点"。由于数字范围是 $[1, n]$、数组长度是 $n+1$，这个映射必然存在环，而**环的入口恰好就是那个重复的数字**。

```go
func findDuplicate(nums []int) int {
    // 把数组视为隐式链表：i → nums[i]
    slow, fast := nums[0], nums[nums[0]]
    for slow != fast {
        slow = nums[slow]
        fast = nums[nums[fast]]
    }
    // 找环入口（与第 142 题完全一致）
    slow = 0
    for slow != fast {
        slow = nums[slow]
        fast = nums[fast]
    }
    return slow
}
```

**这道题的精妙，全在"把数组映射成链表"这一转换上。** 一旦转换完成，它就是第 142 题的原样复制——找环、找入口，一字不差。**它有力地说明：判圈算法的适用对象不是"链表"这个数据结构，而是"每个节点只有一个后继"这一映射性质。** 数组下标到值的映射恰好满足这个性质，于是判圈算法照用不误。**看清一个算法真正依赖的性质，比记住它"用于哪种结构"重要得多。**

### 8.3 快乐数（LeetCode 202）：隐式链表的又一场合

**题目**：判断一个数是否为"快乐数"。定义：反复把该数替换为"它各位数字的平方和"，若最终变为 1，则是快乐数；若陷入不包含 1 的循环，则不是。

这道题的"隐式链表"更隐蔽：**把每个数看作节点，把"它的各位平方和"看作它的后继。** 于是"是否为快乐数"就变成了"这条链最终抵达 1，还是进入一个环"——又是判圈。

```go
func isHappy(n int) bool {
    squareSum := func(x int) int {
        s := 0
        for x > 0 {
            d := x % 10
            s += d * d
            x /= 10
        }
        return s
    }
    slow, fast := n, squareSum(n)
    for fast != 1 && slow != fast {
        slow = squareSum(slow)
        fast = squareSum(squareSum(fast))
    }
    return fast == 1
}
```

**三道延伸题放在一起看，会发现判圈算法几乎是"万能"的**——只要问题的状态转移满足"每个状态只有一个后继"，且状态空间有限（必然要么终止、要么成环），就可以用快慢指针在 $O(1)$ 空间内判定。**这正是"看穿问题的抽象结构"带来的力量：表面上三道毫不相干的题（链表相交、数组找重复、数字迭代），在抽象层面竟是同一个问题。**

## 第 9 章 常见误区与自测方法

### 9.1 四个高频误区

**误区一：判圈循环条件写成 `fast != nil`。** 必须同时检查 `fast != nil && fast.Next != nil`，否则访问 `fast.Next.Next` 会 panic。

**误区二：142 题第二阶段把 `fast` 仍按 2 步前进。** 找环入口时两指针必须**同速**（都走 1 步），否则永远无法在入口相遇。

**误区三：19 题让快指针先走 `n` 步。** 应当先走 `n+1` 步，才能让慢指针停在目标节点的**前驱**。

**误区四：61 题忘记处理 `k % len == 0`。** 此时链表无需旋转，但代码若已"成环"，不特判就会返回一条带环的链表。

### 9.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| 无环链表 `[1,2,3]` | 141 的"无环"分支 |
| 自环单节点 `[1]`（`next` 指自己） | 环长为 1 的退化 |
| `[1,2], n=1` / `[1], n=1` | 19 的头尾边界 |
| `k` 为链表长度整数倍 | 61 的回绕特判 |

**尤其要构造"环长为 1"与"`k` 为长度整数倍"这两个极端**：它们分别是判圈与旋转的退化边界，很多写法只在这类输入下暴露问题。

## 第 10 章 复杂度分析与常见追问

### 10.1 快慢指针的复杂度为什么是 $O(n)$

一个常见的困惑：判圈时快指针走了 2 倍的路，会不会变成 $O(2n)$ 甚至更高？

**不会——渐进复杂度只关心量级，$O(2n) = O(n)$。** 更严格地说，当慢指针进入环后，快指针最多再走 $c$ 步（环长）就能追上它，因此总步数是 $O(a + c) = O(n)$。**关键在于"每个节点被访问的次数有上界"，而不在于"总共走了多少步"。**

找环入口时也是同理：第一阶段 $O(n)$，第二阶段两指针各走 $O(n)$，总计仍是 $O(n)$。**"多趟线性扫描相加"依然是线性**，这与第 04 篇里"外层 $n$ 次、内层累计 $n$ 次"的均摊分析是同一种算法。

### 10.2 三类常见追问

**追问一："判圈除了快慢指针，还有什么方法？"** 答：哈希表记录访问过的节点，首次遇到重复即判圈——时间同为 $O(n)$，但空间 $O(n)$。快慢指针的价值正是**把空间压到 $O(1)$**。此外，若允许修改链表，也可以给访问过的节点打标记。

**追问二："快指针每次走 3 步，还能判圈吗？"** 答：能，只要速度差与环长的最大公约数合适。走 2 步时速度差是 1，无论环长多少都能追上；走 3 步时速度差是 2，若环长为偶数，可能出现"快指针总是跳过慢指针"而永不相遇的情形。**速度差与环长的关系，是判圈能否成立的隐藏条件。**

**追问三："142 题的结论 $a = c$ 依赖速度比是 2:1，换成别的比例还成立吗？"** 答：不成立。$a = (k-1)(b+c)+c$ 这个式子是由 $2(a+b) = a+b+k(b+c)$ 推出的，若速度比改变，等式改变，结论也随之改变。**这提醒我们：所有"看起来简洁的结论"，背后都挂着一组前提假设；换掉假设，结论就要重推。**

### 10.3 一个贯穿的落点

快慢指针这一族技巧，最终都落回同一个抽象：**用两个指针的相对运动，去标定一个未知的结构量。** 无论是环的存在性、环的位置、倒数第 N 个的位置、中点、还是两链表的交点，本质都是在回答"当指针 A 到达某个已知位置时，指针 B 在哪里"。

**把问题转化成"相对位置的度量"，是快慢指针留给我们最持久的思维方式。** 当你遇到一个"需要定位某个结构位置、却又不允许额外空间"的问题时，不妨先问一句：**我能不能让两个指针按某种已知的相对运动前进，把想求的位置'量'出来？**

### 10.4 留一道自测题

142 题中，若链表实际无环，第二阶段的循环会怎样？答案是——第一阶段就因 `fast == nil`（或 `fast.Next == nil`）退出，直接返回 `nil`，根本不会进入第二阶段。

**这类"假设前提不成立"的追问，能帮你确认自己写的每个分支都被想到了。** 很多链表题的 bug，恰恰藏在"主路径想清楚了、边界分支却漏了"的地方。**写完之后主动问一句"如果这里没有环/这里是空/这里只剩一个节点，会怎样"，往往比再读三遍代码更有用。**

## 小结

本篇以四道题把快慢指针这条主线铺展开来。LeetCode 141 用速度差判圈，其正确性建立在"进入环后每轮追近一步"的确定性上；LeetCode 142 用一段 $a = (k-1)(b+c) + c$ 的推导，得出了"头到入口等于相遇点到入口"这一著名结论，并把"找入口"变成了"两指针同速相遇"；LeetCode 19 用"快指针先走 n+1 步"的错位手法，一遍扫描即定位到目标节点的前驱；LeetCode 61 则把旋转转化为"先成环、再断开"，展示了结构类问题的另一种解法范式。补充的找中点（876），则是第 13 篇重排链表的前置工具。

四题合起来，给出两条可迁移的经验。其一，**快慢指针的本质是"用相对运动标定位置"**，它并不神秘——只要想清楚"两个指针的相对关系对应着什么结构信息"，很多题都能自己推出来。其二，**看似同名的技巧可能有不同机理**：变速与错位都叫"快慢指针"，但一个靠速度差、一个靠固定间距，混为一谈就会在变体题上卡壳。**给技巧起个准确的名字、弄清它的机理，比记住它的形式更重要。**

下一篇 [[12 链表反转艺术：局部反转、k 组翻转与节点交换]] 将深入链表反转的三种场景：LeetCode 92（反转 m 到 n 段）、LeetCode 25（每 k 个一组翻转）、LeetCode 24（两两交换）。反转是面试最高频的链表操作，掌握它的迭代与递归两种写法，就能应对大部分反转变体。
