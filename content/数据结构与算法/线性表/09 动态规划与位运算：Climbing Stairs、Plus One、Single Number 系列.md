# 动态规划与位运算：Climbing Stairs、Plus One、Single Number 系列

**摘要：**

本篇是数组专题的收尾，覆盖四道类型迥异却都高频的题：Climbing Stairs（LeetCode 70）、Plus One（LeetCode 66）、Single Number（LeetCode 136）、Single Number II（LeetCode 137）。爬楼梯是动态规划的入门经典，几乎人人会写，但"状态"二字究竟意味着什么、状态转移方程为什么是加法而非乘法，很多人并未真正想清；Plus One 是大数运算的模拟，难点全在连续进位的细节处理；Single Number 系列则把异或运算的性质用到了极致——第一题靠"相同数异或为零"的抵消，第二题靠一个"三进制计数器"，把出现三次的数自动归零。四题背后其实是两种不同的思维方式：DP 用"记录并复用子问题"换取时间，位运算用"数字的二进制结构"换取空间。本文用 Go 语言完整实现，并补上 DP 三要素与位运算工具箱两张速查表。

## 第 1 章 LeetCode 70：爬楼梯与动态规划三要素

### 1.1 题目

**LeetCode 70 - Climbing Stairs**（简单）

你正在爬楼梯，需要 `n` 阶才能到达楼顶，每次可以爬 1 阶或 2 阶。问有多少种不同的方法可以爬到楼顶。

```text
输入: n = 2  →  输出: 2（1+1 或 2）
输入: n = 3  →  输出: 3（1+1+1 或 1+2 或 2+1）
```

### 1.2 从暴力递归到动态规划

先从最朴素的思路出发。要到达第 $n$ 阶，最后一步只可能是两种情况：从第 $n-1$ 阶迈 1 阶上来，或从第 $n-2$ 阶迈 2 阶上来。于是：

$$f(n) = f(n-1) + f(n-2)$$

边界是 $f(1) = 1$（只有一种走法）、$f(2) = 2$（两种走法）。这正是一个 Fibonacci 数列（从 $f(1)=1, f(2)=2$ 起的版本）。

如果直接按这个式子递归，会遇到大量重复计算——$f(n-1)$ 与 $f(n-2)$ 都要用到 $f(n-3)$，$f(n-3)$ 被算了两遍，越往下重复越严重，时间复杂度呈 $O(2^n)$ 爆炸。$n=45$ 时约 $3.5 \times 10^{13}$ 次运算，必然超时。

**优化的切入点，正是这些"被重复计算的子问题"。** 既然同一个 $f(k)$ 会被反复求值，那就把它算一次、存下来，下次直接取用——这就是动态规划（Dynamic Programming）"记忆化"的核心思想。

```go
func climbStairs(n int) int {
    if n <= 2 {
        return n
    }
    dp := make([]int, n+1)
    dp[1], dp[2] = 1, 2
    for i := 3; i <= n; i++ {
        dp[i] = dp[i-1] + dp[i-2] // 状态转移方程
    }
    return dp[n]
}
```

**空间压缩**：注意到 `dp[i]` 只依赖前两个值，整张表其实用不上，两个变量足矣：

```go
func climbStairsCompressed(n int) int {
    if n <= 2 {
        return n
    }
    prev2, prev1 := 1, 2
    for i := 3; i <= n; i++ {
        prev2, prev1 = prev1, prev1+prev2
    }
    return prev1
}
```

时间 $O(n)$，空间 $O(1)$。

### 1.3 动态规划的三要素

爬楼梯虽简单，却完整地展示了 DP 的三要素，值得逐条拆清：

**要素一，状态定义。** 定义 `dp[i]` 为"到达第 `i` 阶的方法数"。**状态定义的措辞极其关键**——它必须让"下一步"能由"上一步"推出。这里选"到达某阶的方法数"而非"走了多少步"，正是因为它天然具有可递推性。

**要素二，状态转移方程。** `dp[i] = dp[i-1] + dp[i-2]`。它的推导用了一个重要视角——**"最后一步的视角"**：不要一上来就想"一共有多少种走法"，而要问"最后一步是哪一种走法，那么在此之前是什么子问题"。最后一步要么从 `i-1` 迈 1 阶来，要么从 `i-2` 迈 2 阶来，这两种情况互斥且穷尽，故方法数相加。

**要素三，边界条件。** `dp[1] = 1, dp[2] = 2`。递推必须有起点，否则会无限回退下去。

> [!note] 为什么状态转移用加法而不是乘法
> 这是 DP 里一个极易混淆的点，值得单独记住：**加法用于"互斥方案的合并"**——到达 `i` 的方法要么经由 `i-1`、要么经由 `i-2`，两者不重叠，数量相加；**乘法用于"独立事件的组合"**——若一个方案要分两个相互独立的步骤，每步各有若干选择，则总方案数是两者之积。判断用加还是乘，只需问一句："这些情况是并列可选，还是必须同时发生？"

### 1.4 变体：每步可走 1、2 或 3 阶

把状态转移方程改成 `dp[i] = dp[i-1] + dp[i-2] + dp[i-3]`，边界再加一个 `dp[3] = 4`（即 1+1+1、1+2、2+1、3），即可支持"每步走 1 至 3 阶"。**代码只改一行，这就是 DP 框架的可扩展性**——一旦状态定义与转移方程想清楚，规则的变化往往只是增删一个加项。

## 第 2 章 LeetCode 66：加一

### 2.1 题目

**LeetCode 66 - Plus One**（简单）

给定一个由整数组成的非空数组所表示的非负整数，在该数的基础上加一。最高位在数组首位，每个元素只存单个数字。除 0 本身外，该整数不会以零开头。

```text
输入: digits = [1,2,3]    →  输出: [1,2,4]
输入: digits = [4,3,2,1]  →  输出: [4,3,2,2]
输入: digits = [9]        →  输出: [1,0]
输入: digits = [9,9,9]    →  输出: [1,0,0,0]
```

### 2.2 进位模拟

这道题考察的是**手工模拟加法进位**的能力，细节全在连续进位的处理上。思路很直白：从最低位（末尾）开始加 1；若该位加完后不超过 9，则直接返回；若该位是 9，则把它置 0 并向高位继续进位。

```go
func plusOne(digits []int) []int {
    for i := len(digits) - 1; i >= 0; i-- {
        if digits[i] < 9 {
            digits[i]++ // 不产生进位，加完即返回
            return digits
        }
        digits[i] = 0 // 当前位是 9，置 0 并向高位进位
    }
    // 走到这里说明所有位都是 9，需要新增一位 1
    // 例如 [9,9,9] → [1,0,0,0]
    result := make([]int, len(digits)+1)
    result[0] = 1 // 首位为 1，其余默认 0
    return result
}
```

**复杂度**：时间 $O(n)$（最坏情况扫描全部位），空间 $O(1)$（不计返回数组）。

### 2.3 细节解析：为什么这样写是对的

循环从 `n-1` 向高位推进：只要某一位不是 9，`digits[i]++` 后立即 `return`——因为此时不会产生进位，更高位完全不受影响，没必要再处理。只有当 `digits[i] == 9` 时，才把它置 0 并继续循环，模拟"向高位进 1"。

如果循环正常跑完而没有 `return`，说明**每一位都经历了"置零"**，整个数组已变成全 0，此时真实的数值是 $10^n$，需要在最前面补一个 1——因此创建一个长度为 `n+1` 的新数组，首位设为 1，其余默认 0。**"循环是否跑完"这一信号，恰好等价于"是否发生全位进位"，代码借它省去了一次专门的标志变量。**

### 2.4 延伸：两个大数相加（LeetCode 415）

Plus One 的更一般版本，是用字符串表示的两个大数相加：

```go
func addStrings(num1, num2 string) string {
    i, j, carry := len(num1)-1, len(num2)-1, 0
    var sb []byte
    for i >= 0 || j >= 0 || carry > 0 {
        a, b := 0, 0
        if i >= 0 {
            a = int(num1[i] - '0')
            i--
        }
        if j >= 0 {
            b = int(num2[j] - '0')
            j--
        }
        sum := a + b + carry
        sb = append(sb, byte('0'+sum%10))
        carry = sum / 10
    }
    // 反转字节切片
    for l, r := 0, len(sb)-1; l < r; l, r = l+1, r-1 {
        sb[l], sb[r] = sb[r], sb[l]
    }
    return string(sb)
}
```

**这个模板值得记住，它是"模拟手工加法"的通用范式**：从低位到高位逐位相加，用 `carry` 记录进位，循环条件把"两个数都遍历完"与"仍有进位"一并纳入，从而自动处理"最高位再进位"这一边界。**注意循环条件里的 `carry > 0`**——它正是那个最容易被遗漏、又必然出现在全 9 情形下的分支。第 13 篇的链表大数加法，会复用同一套骨架。

## 第 3 章 LeetCode 136：只出现一次的数字

### 3.1 题目

**LeetCode 136 - Single Number**（简单）

给定一个非空整数数组，除某个元素只出现**一次**外，其余元素均出现**两次**。找出那个只出现一次的元素。要求线性时间、不使用额外空间。

```text
输入: nums = [2,2,1]      →  输出: 1
输入: nums = [4,1,2,1,2]  →  输出: 4
```

### 3.2 约束如何逼出位运算

"线性时间"排除了排序（$O(n \log n)$），"不使用额外空间"排除了哈希表（$O(n)$ 空间）。两条约束一合围，常规武器全部出局，只剩下一条路——**位运算**。

**关键在于异或（XOR）的三条性质：**

1. `a ^ a = 0`：任何数与自身异或得 0；
2. `a ^ 0 = a`：任何数与 0 异或得自身；
3. 异或满足交换律与结合律。

有了交换律与结合律，就可以把所有元素"打散重组"：成对出现的元素两两抵消成 0，最后只剩下那个落单的元素。

$$\text{result} = a_1 \oplus a_1 \oplus a_2 \oplus a_2 \oplus \cdots \oplus x = 0 \oplus 0 \oplus \cdots \oplus x = x$$

```go
func singleNumber(nums []int) int {
    result := 0
    for _, num := range nums {
        result ^= num
    }
    return result
}
```

三行代码，$O(n)$ 时间，$O(1)$ 空间。**这道题的优雅，正是"约束逼出巧妙解法"的范例**——如果允许额外空间，谁也不会想到异或；恰恰是"不能用额外空间"这一条，把思路推向了对数字二进制结构的利用。

> [!info] 异或的直觉：不进位加法
> 异或可以理解为"不进位的二进制加法"——相同位相加得 0，不同位得 1。从这个角度看，把数组所有元素"不进位地加"起来，每个出现两次的数在每一位上都贡献了偶数个 1（偶数次相加得 0），只有那个只出现一次的数，在其为 1 的位上有奇数个 1，于是结果恰好是它本身。**"成对抵消"这句话，用"奇偶性"来解释会更严谨。**

## 第 4 章 LeetCode 137：只出现一次的数字 II

### 4.1 题目

**LeetCode 137 - Single Number II**（中等）

给定一个整数数组，除某个元素仅出现**一次**外，其余每个元素都恰好出现**三次**。找出那个只出现一次的元素。同样要求线性时间、不使用额外空间。

```text
输入: nums = [2,2,3,2]           →  输出: 3
输入: nums = [0,1,0,1,0,1,99]    →  输出: 99
```

### 4.2 为什么异或不再够用

异或的威力来自"两次抵消"，而这里是三次出现。三个相同数字异或的结果是 `a ^ a ^ a = a`，并不会归零。**抵消的逻辑建立在"出现次数为偶数"这一前提上，一旦次数变成 3，"两次归零"就失效了。** 要解决它，得换一种能"逢三归零"的机制——这就是三进制计数器。

### 4.3 方法一：逐位统计（直观稳妥）

最直接的思路是：**对每一个二进制位，分别统计数组中该位上 1 的个数。** 若某位上 1 的总数是 3 的倍数，说明这一位上的 1 全来自那些出现三次的数；若对 3 取模余 1，说明那个只出现一次的数在该位上是 1。

```go
func singleNumberBitwise(nums []int) int {
    result := 0
    for bit := 0; bit < 32; bit++ {
        sum := 0
        for _, num := range nums {
            sum += (num >> bit) & 1 // 统计第 bit 位上 1 的个数
        }
        if sum%3 == 1 {
            result |= 1 << bit // 目标数在该位上是 1
        }
    }
    return result
}
```

时间 $O(32n) = O(n)$（32 是常数），空间 $O(1)$。**这是最稳妥的解法**：思路一目了然，不易写错，面试时优先给出它。

### 4.4 方法二：三进制计数器（状态机）

更精巧的方案，是用两个变量 `ones`、`twos` 组成一个**按位独立的三进制计数器**：对每一个二进制位，`ones` 记录该位计数对 3 取模为 1 的状态，`twos` 记录取模为 2 的状态。状态转移如下：

| 计数（mod 3） | ones | twos |
|--------------|------|------|
| 0 | 0 | 0 |
| 1 | 1 | 0 |
| 2 | 0 | 1 |
| 3（归零） | 0 | 0 |

**转移方程的推导思路**：遇到新数字 `num` 时，`ones` 与 `twos` 要协同地"加一"。可以分两步看：先让 `ones` 承接那些"原来计数为 0、本次该升到 1"的位；再让 `twos` 承接那些"原来计数为 1、本次该升到 2"的位；同时，凡是计数已经到 2 的位，再遇到 1 就要回到 0。据此写出：

```go
func singleNumberStateMachine(nums []int) int {
    ones, twos := 0, 0
    for _, num := range nums {
        ones = (ones ^ num) & ^twos // 更新 ones，并清除已进入 twos 的位
        twos = (twos ^ num) & ^ones // 更新 twos，并清除刚被 ones 占用的位
    }
    return ones
}
```

**注意 Go 里没有 `~` 一元取反运算符，按位取反用 `^x`（与全 1 异或）表示**，所以上面写的是 `& ^twos`（`^twos` 即 `~twos`）。

### 4.5 用一个小例子把状态机跑一遍

光看公式容易糊涂，用 `nums = [2, 2, 3, 2]` 走一遍，只关注低两位（因为 2 = `10`、3 = `11`，都只用低两位）：

```text
初始:        ones = 00, twos = 00

num = 2(10): ones = (00 ^ 10) & ^00 = 10
             twos = (00 ^ 10) & ^10 = 10 & 01 = 00
             → ones=10, twos=00   （2 出现 1 次）

num = 2(10): ones = (10 ^ 10) & ^00 = 00
             twos = (00 ^ 10) & ^00 = 10
             → ones=00, twos=10   （2 出现 2 次）

num = 3(11): ones = (00 ^ 11) & ^10 = 11 & 01 = 01
             twos = (10 ^ 11) & ^01 = 01 & 10 = 00
             → ones=01, twos=00   （2 出现 2 次归位，3 出现 1 次）

num = 2(10): ones = (01 ^ 10) & ^00 = 11
             twos = (00 ^ 10) & ^11 = 10 & 00 = 00
             → ones=11, twos=00   （3 计满 3 次的部分被抵消）

返回 ones = 11 = 3 ✓
```

**注意第 4 步的结果 `ones = 11`**：低位的 `1` 来自数字 3（它出现 1 次），高位的 `1` 来自数字 2——但 2 出现了 3 次，恰好被计数器归零，所以高位这一位实际上是 3 的贡献……为了让这个例子不至于绕晕，更稳妥的理解是：**`ones` 最终保存的是"每一位上 1 的总数 mod 3 为 1"的那些位**，逐位独立，互不干扰。把每一位单独看，状态机就是一台小小的 mod-3 计数器。

> [!note] 方法二了解即可
> 三进制计数器的推导较为精巧，面试中若一时记不住，**直接用方法一（逐位统计）同样满分**——它思路清晰、不易出错。方法二更适合作为"加分项"，展示你对位运算状态机的理解。**能写对的方法一，永远优于记混的方法二。**

## 第 5 章 位运算工具箱与知识关联

### 5.1 位运算速查表

本篇用到的位运算操作，值得整理成一张随身速查表（Go 语法）：

| 操作 | 语法 | 用途 |
|------|------|------|
| 异或 | `a ^ b` | 相同位为 0、不同位为 1；相同数异或得 0 |
| 与 | `a & b` | 取公共为 1 的位，常用于掩码 |
| 或 | `a \| b` | 取任一为 1 的位 |
| 按位取反 | `^a` | 所有位翻转（Go 无 `~` 一元运算符） |
| 左移 | `a << k` | 相当于乘以 $2^k$ |
| 右移 | `a >> k` | 相当于整除 $2^k$ |
| 取某位 | `(a >> k) & 1` | 判断第 `k` 位是否为 1 |
| 置某位 | `a \| (1 << k)` | 把第 `k` 位置为 1 |

**"按位取反在 Go 里用 `^a`"这一点容易踩坑**：Go 没有 C/Java 那样的 `~` 一元运算符，`^` 既是二元异或、又是一元取反。写 `^twos` 时，`^` 是一元取反；写 `a ^ b` 时，它是二元异或——同一个符号，两种角色，靠是否带操作数来区分。

### 5.2 动态规划的入门路径

爬楼梯是 DP 阶梯的第一级。往后依次是：打家劫舍（一维线性 DP，"选或不选"）、最长公共子序列（二维 DP）、背包问题（经典约束优化），构成一条清晰的进阶路线。**爬楼梯之所以重要，不在于它本身，而在于它是"最后一步的视角"这一 DP 核心思维的最小模型**——把"一共有多少种走法"这种全局问题，转化为"最后一步怎么走、之前的子问题是什么"这种局部递推。

### 5.3 两种思维方式的对照

本篇四道题，其实分属两种思维模式，值得对照记忆：

| 题目 | 思维模式 | 换取的是什么 |
|------|---------|-------------|
| 爬楼梯 | 动态规划 | 用"记录子问题"换取时间（$O(2^n) \to O(n)$） |
| Plus One | 模拟 | 用"逐位进位"换取对大数的处理能力 |
| Single Number I | 位运算 | 用"数字的二进制结构"换取空间（$O(n) \to O(1)$） |
| Single Number II | 位运算 | 用"按位 mod-3 计数"换取空间 |

**动态规划的核心是"记住并复用"，位运算的核心是"看穿二进制结构"。** 两者都能在不增加空间的前提下提升效率，但路径完全不同：前者靠时间换空间的逆向操作（把重复计算省掉），后者靠把问题"下沉"到比特层面。

## 第 6 章 延伸：位运算工具箱的更多应用

异或只是位运算工具箱里的一件。再补三道题，它们分别用到了"与运算消除最低位 1""异或分组""与运算判幂"等技巧，合起来能把这套工具箱补全。

### 6.1 位 1 的个数（LeetCode 191）：`n & (n-1)` 的妙用

**题目**：编写一个函数，输入是一个无符号整数，返回其二进制表达式中数字位数为 1 的个数（汉明重量）。

朴素做法是逐位检查（循环 32 次）。但有一个更巧的写法：**`n & (n-1)` 会把 `n` 最右边的那个 1 变成 0**，于是反复执行这一操作，直到 `n` 变成 0，执行的次数就是 1 的个数。

```go
func hammingWeight(n uint32) int {
    count := 0
    for n != 0 {
        n &= n - 1 // 消去最低位的 1
        count++
    }
    return count
}
```

**为什么 `n & (n-1)` 能消去最低位的 1？** 设 `n` 的二进制形如 `...1000`（最低位的 1 及其后全为 0），则 `n-1` 形如 `...0111`（最低位 1 变 0、其后全变 1）。两者相与，`...1000 & ...0111 = ...0000`——最低位的 1 连同其后所有位一起归零，而更高位保持不变。**这个技巧的价值在于：循环次数不再固定为 32，而是恰好等于 1 的个数**，对稀疏的输入尤其高效。**它也是"看穿二进制结构"的一个典型——一行代码替代了一层循环。**

### 6.2 只出现一次的数字 III（LeetCode 260）：分组异或

**题目**：给定一个整数数组，其中恰好有两个元素只出现一次，其余所有元素都出现两次。找出这两个只出现一次的元素。

这道题把异或的性质又推进了一层。设两个只出现一次的元素为 `a` 和 `b`。**先把整个数组异或起来，得到 `a ^ b`（成对的元素都抵消了）。** 现在的问题变成"如何从 `a ^ b` 里把 `a` 和 `b` 分开"。

关键在于：`a ^ b` 中为 1 的某一位，意味着 `a` 与 `b` 在这一位上必然**不同**（一个 0、一个 1）。于是可以**用这一位作为分组依据**，把数组分成两组：该位为 0 的一组、该位为 1 的一组。这样 `a` 和 `b` 就被分到了不同组，而每组内部的其他元素仍然成对出现——**于是每组各做一次异或，就能分别得到 `a` 和 `b`。**

```go
func singleNumberIII(nums []int) []int {
    // 第一步：整体异或，得到 a ^ b
    xor := 0
    for _, n := range nums {
        xor ^= n
    }
    // 第二步：取 a^b 中最低位的 1 作为分组依据
    diff := xor & (-xor) // 最低位的 1
    // 第三步：按该位分组异或
    a := 0
    for _, n := range nums {
        if n&diff != 0 {
            a ^= n
        }
    }
    return []int{a, a ^ xor} // b = a ^ (a^b)
}
```

**`xor & (-xor)` 是"取最低位 1"的经典写法**（利用补码性质）。**这道题的启示是：异或不仅能"抵消重复"，还能"提取差异"——而一旦差异被提取出来，它又能反过来当作分类的依据。** 这种"先求出差异、再用差异做分组"的两步走，是位运算题里很常见的一类套路。

### 6.3 汉明距离与判断 2 的幂

**汉明距离（LeetCode 461）**：两个整数之间的汉明距离定义为二进制表示中不同位的个数。有了上面的基础，它只需一步：**`x ^ y` 会把不同的位标为 1，再统计 `x ^ y` 中 1 的个数即可。**

```go
func hammingDistance(x, y int) int {
    return bits.OnesCount(uint(x ^ y)) // 或用 6.1 的手写计数
}
```

**判断 2 的幂（LeetCode 231）**：一个数是 2 的幂，当且仅当它的二进制表示中**恰好只有一个 1**。结合 6.1 的技巧，它等价于 `n > 0 && n&(n-1) == 0`——**`n & (n-1)` 消去唯一的那个 1 之后若变成 0，说明原本就只有一个 1。**

```go
func isPowerOfTwo(n int) bool {
    return n > 0 && n&(n-1) == 0
}
```

**这两道题都很短，却精确地展示了位运算的思维特征：把一个"看似需要循环判断"的问题，化归为"一个或两个位运算表达式"。** 这正是位运算最迷人的地方——**它不是在"更快地做同一件事"，而是在"用完全不同的方式描述同一件事"。**

### 6.4 位运算工具箱的总览

把本篇与延伸题的技巧汇总成一张表：

| 技巧 | 表达式 | 用途 |
|------|--------|------|
| 异或抵消 | `a ^ a = 0` | 找出唯一出现一次的元素 |
| 按位计数 | `(n >> k) & 1` | 统计某位的 1 的个数 |
| 消最低位 1 | `n & (n-1)` | 数 1 的个数、判断 2 的幂 |
| 取最低位 1 | `n & (-n)` | 提取差异、分组 |
| 分组异或 | 用某位分组 | 找出两个只出现一次的元素 |
| 掩码 | `n \| (1 << k)` | 集合的位表示（第 07 篇数独） |

**这张表里的每一个技巧，背后都是一条关于二进制结构的洞察，而不是一段需要背诵的代码。** 记表达式容易忘，理解"为什么这个表达式能实现这个效果"却能长久记住——这也是本专栏对待所有技巧的一贯态度。

## 第 7 章 常见误区与自测方法

### 7.1 四个高频误区

**误区一：Single Number II 里对"三次出现"直接套用异或。** 异或的"抵消"依赖出现次数为偶数，三次出现必须改用 mod-3 计数（逐位统计或三进制状态机）。

**误区二：Go 里用 `~` 表示按位取反。** Go 没有 `~` 一元运算符，按位取反要写 `^x`；写成 `~x` 会编译报错。

**误区三：Plus One 忘记"全 9"的边界。** 当所有位都是 9 时，需要在最前面新增一位，返回的数组长度加一。

**误区四：爬楼梯把状态转移写成乘法。** 状态转移是"互斥方案相加"，用加法；乘法只用于"独立事件的组合"。

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `[9]`、`[9,9,9]` | Plus One 的连续进位与全位进位 |
| `[2,2,3,2]` | Single Number II 的三次出现 |
| `n=1` | 爬楼梯的边界 |
| `n=0`、`n=-1` | 位运算题的符号边界 |

**特别提醒"负数"这一边界**：位运算题里，负数的补码表示常让结果出乎意料。**凡是涉及位运算，先在草稿上写出 `-1` 的补码（全 1），再推演代码行为**，能避免一大类"看起来对、其实错"的问题。

## 第 8 章 两条主线的交汇：状态压缩 DP

本篇的前半讲动态规划、后半讲位运算，看似两块内容。但它们在"状态压缩 DP"里交汇——**位运算成了动态规划表达状态的手段**。这是本专栏里"两个看似无关的技巧实为一体"的最佳例证。

### 8.1 问题的由来

有些 DP 问题，其"状态"本身就是一个**集合**。例如"访问过哪些城市"、"选了哪些物品"、"填满了哪些格子"。若用布尔数组表示这个集合，状态空间会膨胀到无法枚举；但如果集合的元素个数不多（不超过 20 左右），就可以**用一个整数的二进制位来表示它**——第 $k$ 位为 1 表示"元素 $k$ 在集合中"。

**这正是第 07 篇数独位掩码的同一思想，只是用在了 DP 的状态定义上。** 集合的"并"变成按位或，"交"变成按位与，"属于"变成按位与判零——集合运算全都被位运算替代，速度极快、空间极小。

### 8.2 一个示意：旅行商问题（TSP）

以经典的旅行商问题为例：给定 $n$ 个城市与两两之间的距离，求从起点出发、访问每个城市恰好一次、再回到起点的最短路径。若 $n \le 20$，可以用状压 DP：

- **状态**：`dp[mask][i]` 表示"已访问的城市集合为 `mask`、当前停在城市 `i`"时的最短路径；
- **转移**：从 `dp[mask][i]` 出发，选择一个尚未访问的城市 `j`（即 `mask` 的第 `j` 位为 0），转移到 `dp[mask | (1<<j)][j]`；
- **答案**：`min(dp[(1<<n)-1][i] + dist[i][起点])`。

```go
// TSP 状压 DP 骨架（示意）
func tsp(dist [][]int) int {
    n := len(dist)
    const inf = 1 << 30
    dp := make([][]int, 1<<n)
    for i := range dp {
        dp[i] = make([]int, n)
        for j := range dp[i] {
            dp[i][j] = inf
        }
    }
    dp[1][0] = 0 // 只访问了城市 0，停在城市 0
    for mask := 1; mask < (1 << n); mask++ {
        for i := 0; i < n; i++ {
            if dp[mask][i] == inf {
                continue
            }
            for j := 0; j < n; j++ {
                if mask&(1<<j) != 0 {
                    continue // j 已访问
                }
                nmask := mask | (1 << j)
                if dp[mask][i]+dist[i][j] < dp[nmask][j] {
                    dp[nmask][j] = dp[mask][i] + dist[i][j]
                }
            }
        }
    }
    ans := inf
    for i := 0; i < n; i++ {
        if dp[(1<<n)-1][i]+dist[i][0] < ans {
            ans = dp[(1<<n)-1][i] + dist[i][0]
        }
    }
    return ans
}
```

**这段代码的复杂度是 $O(2^n \cdot n^2)$**——对 $n \le 20$ 尚可接受，$n$ 再大就爆炸了。**位运算在这里并没有改变问题的组合本质，它只是把"集合状态"这一维度压进了一个整数里，让 DP 得以在有限的状态空间上展开。** 这再次印证了那条朴素的道理：**技巧不改变问题的下界，只改变我们触达它的效率。**

### 8.3 与数独位掩码的呼应

把第 07 篇的 Valid Sudoku 与本章的 TSP 并排看，会发现它们用的是同一个动作——**用整数的位表示一个集合**。区别只在用途：数独里，位掩码用于"快速判断某数字是否出现过"（查重）；TSP 里，位掩码用于"表示 DP 的状态"（枚举子集）。

**"用一个整数表示一个集合"这个动作，一旦被真正理解，就会在完全不同的问题里反复出现。** 它是本篇最想留下的一个"可迁移的小工具"——**当你需要表示一个"元素不多、且只关心存在性"的集合时，第一个念头应该是"能不能用一个整数的位来表示它"。**

## 小结

本篇以四道题收束数组专题。爬楼梯用最简的模型讲清了动态规划的三要素——状态定义、状态转移方程、边界条件，并示范了"最后一步的视角"与空间压缩；Plus One 展示了大数进位模拟的完整套路，其中"循环是否跑完"这一信号被巧妙地用来判断是否发生全位进位；Single Number 两题则把异或的性质层层推进：第一题靠"出现两次即抵消"，第二题则把它升级为"按位 mod-3 计数器"，以应对三次出现的场景。

四题合起来，给出两条可迁移的经验。其一，**动态规划的价值不在"技巧"，而在"视角"**——把"求全局方案数"转化为"问最后一步"，是打开一切 DP 问题的通用钥匙。其二，**当约束把常规武器全部排除时，往往正是位运算登场之时**——Single Number 系列的巧妙，完全是被"$O(1)$ 空间"这一条约束逼出来的。**约束越苛刻，解法越需要下沉到更本质的层面。**

下一篇 [[10 链表基础与哑节点技巧：Remove Duplicates、Partition List]] 将跨出数组，进入链表世界。链表题的核心挑战不是算法复杂度，而是**指针操作的正确性**与**边界条件的处理**。哑节点（Dummy Node）正是应对"头节点可能被删除"这类问题的核心工具，我们将通过删除重复节点与链表分区两道题，建立链表操作的标准范式。
