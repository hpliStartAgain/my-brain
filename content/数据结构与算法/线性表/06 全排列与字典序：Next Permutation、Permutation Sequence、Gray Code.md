# 全排列与字典序：Next Permutation、Permutation Sequence、Gray Code

**摘要：**

前面几篇的数组题，解题的主线是"搜索"与"夹逼"；本篇则转入一个截然不同的方向：**序列的生成与编号**。这里的题目不再需要枚举或回溯，而是要求你看穿排列的数学结构，用几条规律直接"算出"答案。本文覆盖三道题：Next Permutation（LeetCode 31）考察字典序递增的最小改动原则，Permutation Sequence（LeetCode 60）引入阶乘数系，把"第 k 个排列"变成一次"按位权取数"的过程，Gray Code（LeetCode 89）则藏着镜像递推与 `i ^ (i >> 1)` 的优雅变换。三道题表面无关，骨子里却是同一件事——**用对结构的洞察，替代对空间的暴力枚举**。本文会先建立字典序这一全序关系的直觉，再逐题推导算法，用 Go 语言完整实现，并补上康托展开（Cantor Expansion）这一"排列与编号互转"的通法，让整套知识连成一片。

## 第 1 章 字典序：排列之间的全序关系

### 1.1 什么是字典序

**字典序（Lexicographic Order）**是一种排列之间的比较方式，类比字典里单词的排序：先比第一个字符，相同则比第二个，依次类推。以 `[1,2,3]` 的全部排列为例，按字典序从小到大排开便是：

```text
1. [1, 2, 3]
2. [1, 3, 2]
3. [2, 1, 3]
4. [2, 3, 1]
5. [3, 1, 2]
6. [3, 2, 1]
```

从这张表里能读出三条事实：最小的排列是升序 `[1,2,3]`，最大的排列是降序 `[3,2,1]`，而所谓"下一个排列"，就是这张有序表里紧挨在当前排列之后的那一个。**"下一个排列"因此不是一个孤立的概念，而是"字典序这条数轴上，当前点右侧的邻居"。** 把问题放到数轴上看，后面所有算法的动机都会清晰起来。

### 1.2 排列的数量与它的量级意义

$n$ 个互异元素的全排列共有 $n!$ 种。几个常用的值：

| $n$ | $n!$ | 量级 |
|-----|------|------|
| 3 | 6 | 个位 |
| 5 | 120 | 百位 |
| 10 | 3,628,800 | 百万 |
| 13 | ≈ 6.2 × 10⁹ | 超 `int` |
| 20 | ≈ 2.4 × 10¹⁸ | 超 `int64` |

这组数字有一个直接的算法含义：**当 $n$ 稍大，排列总数就爆炸式增长，"生成全部排列再取第 k 个"这类暴力思路必然失效**。$n = 13$ 时排列数已超过 $6 \times 10^9$，任何"逐个生成"的做法都会超时。这正是本篇三道题都要绕开暴力、直奔数学结构的根本原因——**是数量级的压力，把我们从"枚举"逼向了"构造"。**

## 第 2 章 LeetCode 31：下一个排列

### 2.1 题目

**LeetCode 31 - Next Permutation**（中等）

整数数组的**下一个排列**，是指其整数的下一个字典序更大的排列。若不存在下一个更大的排列，则把数组重排为字典序最小的排列（即升序）。要求**原地修改，且只使用常数额外空间**。

```text
输入: nums = [1,2,3]  →  输出: [1,3,2]
输入: nums = [3,2,1]  →  输出: [1,2,3]（已是最大，回到最小）
输入: nums = [1,1,5]  →  输出: [1,5,1]
```

### 2.2 推导：从"最小改动"原则出发

要找到字典序里紧挨着的下一个排列，先问一个更本质的问题：**`[1,2,3]` 的下一个为什么是 `[1,3,2]`，而不是别的？**

对比这两个排列会发现，只有末两位发生了变化（`2,3` 变成了 `3,2`），前缀 `1` 原封不动。这揭示出一条关键原则：**下一个排列应当尽量保留更长的公共前缀，只在尽可能靠后的位置做尽可能小的改动。** 因为改动的位置越靠后、改动幅度越小，得到的新排列与原来的"距离"就越近，也就越可能是"紧挨着的下一个"。

沿着这条原则，算法可以拆成三个步骤：

**第一步，从右向左找第一个"下降位" `i`**，即满足 `nums[i] < nums[i+1]` 的最大的 `i`。为什么要从右向左找？因为要尽量保留长前缀，改动要尽量靠后，所以从最右端开始搜寻第一个"有上升空间"的位置。以 `[1,2,3]` 为例，从右看 `nums[1]=2 < nums[2]=3`，于是 `i = 1`。**如果整个数组严格降序（如 `[3,2,1]`），说明它已是最大排列，不存在下一个，直接把整个数组翻转成升序即可。**

**第二步，在 `i` 右侧找到"比 `nums[i]` 大的最小元素" `nums[j]`。** 注意，由于 `i` 是最右侧的下降位，`i` 右侧的区间 `[i+1, n-1]` 必然是降序的；在降序序列里找"比 `nums[i]` 大的最小值"，只需从右向左扫描，遇到的第一个大于 `nums[i]` 的元素即是。

**第三步，交换 `nums[i]` 与 `nums[j]`，再翻转 `[i+1, n-1]` 区间。** 交换让 `nums[i]` 变成一个"比原来大一点点"的值，实现了位置 `i` 上的最小增幅；而交换之后，`[i+1, n-1]` 仍是降序，把它翻转成升序，就得到了后缀部分的最小排列。两者相合，正是"下一个最小的排列"。

### 2.3 一个完整的例子

以 `[1,3,5,4,2]` 为例：

```text
从右向左找下降位：
  nums[4]=2, nums[3]=4（4>2，不是下降）
  nums[3]=4, nums[2]=5（5>4，不是下降）
  nums[2]=5, nums[1]=3（3<5，是下降）→ i=1

右侧 [5,4,2] 是降序，找比 nums[1]=3 大的最小值：
  从右向左：nums[4]=2（不大于3）→ nums[3]=4（大于3）→ j=3

交换 i=1 与 j=3：[1,4,5,3,2]
翻转 [i+1, end] = [5,3,2] → [2,3,5]
结果：[1,4,2,3,5] ✓
```

验证一下：比 `13542` 大、且最接近的字典序排列确实是 `14235`，正确。

### 2.4 Go 实现

```go
func nextPermutation(nums []int) {
    n := len(nums)
    // 第一步：从右向左找第一个下降位 i，满足 nums[i] < nums[i+1]
    i := n - 2
    for i >= 0 && nums[i] >= nums[i+1] {
        i--
    }
    if i >= 0 {
        // 第二步：在右侧找比 nums[i] 大的最小元素
        j := n - 1
        for nums[j] <= nums[i] {
            j--
        }
        nums[i], nums[j] = nums[j], nums[i] // 交换
    }
    // 第三步：翻转 i+1 到末尾；若 i<0，则翻转整个数组
    reverse(nums, i+1, n-1)
}

func reverse(nums []int, left, right int) {
    for left < right {
        nums[left], nums[right] = nums[right], nums[left]
        left++
        right--
    }
}
```

**复杂度**：时间 $O(n)$（最多两次线性扫描加一次翻转），空间 $O(1)$。

### 2.5 一个值得说明的边界：`i < 0` 时为什么翻转整个数组

当数组严格降序时，第一步找不到下降位，`i` 会停在 `-1`。此时 `if i >= 0` 的分支被跳过，第三步直接执行 `reverse(nums, 0, n-1)`，把整个数组翻转为升序——而这恰好就是"最大排列的下一个排列是最小排列"这条规则。**代码没有为这种情况写任何特判，而是让 `i = -1` 自然地落进第三步，靠"翻转整个数组"一并解决。** 这是把边界情况"内化进主逻辑"的一个漂亮例子，值得在面试中主动指出。

## 第 3 章 LeetCode 60：第 k 个排列

### 3.1 题目

**LeetCode 60 - Permutation Sequence**（困难）

给出集合 `[1,2,...,n]`，其全部 $n!$ 种排列按字典序排列，返回第 `k` 个排列。

```text
输入: n=3, k=3  →  输出: "213"
输入: n=4, k=9  →  输出: "2314"
```

### 3.2 为什么不能反复调用 Next Permutation

最直观的思路是：从最小排列 `[1,2,...,n]` 出发，反复调用上一节的 `nextPermutation`，调用 $k-1$ 次即可。每次 `nextPermutation` 是 $O(n)$，总时间 $O(n \cdot k)$。当 $n \le 9$ 时 $k \le 9! = 362880$，尚能勉强通过；但 $n = 13$ 时 $13! \approx 6 \times 10^9$，必然超时。**问题的规模上限，再一次把"逐次推进"这条路上堵死了。**

真正的出路，是**不生成任何中间排列，直接算出第 `k` 个排列的每一位**。而这需要一个能把"编号"翻译成"排列"的数系——阶乘数系。

### 3.3 阶乘数系：把编号按位权分解

先看一个观察。`n` 个数字的全排列按字典序排开后，可以按首位分成 `n` 组，每组恰好含 $(n-1)!$ 个排列：首位为最小数字的那一组排在最前，首位为次小数字的一组紧随其后，依此类推。于是：

- 第 $1$ 到 $(n-1)!$ 个排列，首位是最小的数字；
- 第 $(n-1)! + 1$ 到 $2 \cdot (n-1)!$ 个排列，首位是第二小的数字；
- ……

据此，**首位数字在"剩余数字列表"中的索引，就是 $\lfloor (k-1) / (n-1)! \rfloor$**。确定首位之后，把 `k` 更新为 $(k-1) \bmod (n-1)!$，再在剩余的 $n-1$ 个数字中，用同样的方式确定第二位，依次递推。

这就是**阶乘数系（Factoradic Number System）**的本质：**用 $(n-1)!, (n-2)!, \ldots, 1!, 0!$ 作为进位单位，对 $k-1$ 做一次"变进制"分解**。它与十进制用 $10^0, 10^1, \ldots$ 作位权是一个道理，只是每一位的权值换成了阶乘。理解了这个类比，就不必去记忆公式——**只要记住"每一位选第几小的数字，取决于 `k-1` 在该位权下的商"**，公式会自己浮现。

### 3.4 手动演算

以 `n=4, k=9`、数字列表 `[1,2,3,4]` 为例，阶乘为 $3!=6,\ 2!=2,\ 1!=1,\ 0!=1$。先把 `k` 转成 0-indexed，即 `k = 8`：

```text
第一位：idx = 8 / 3! = 8 / 6 = 1 → 剩余 [1,2,3,4] 中第 1 个是 2
        更新 k = 8 % 6 = 2，剩余 [1,3,4]

第二位：idx = 2 / 2! = 2 / 2 = 1 → 剩余 [1,3,4] 中第 1 个是 3
        更新 k = 2 % 2 = 0，剩余 [1,4]

第三位：idx = 0 / 1! = 0 / 1 = 0 → 剩余 [1,4] 中第 0 个是 1
        更新 k = 0 % 1 = 0，剩余 [4]

第四位：只剩 [4]，取 4

结果：2314 ✓
```

### 3.5 Go 实现

```go
func getPermutation(n int, k int) string {
    // 预计算阶乘：fact[i] = i!
    fact := make([]int, n)
    fact[0] = 1
    for i := 1; i < n; i++ {
        fact[i] = fact[i-1] * i
    }

    // 剩余可选数字（用切片维护，方便按索引删除）
    digits := make([]int, n)
    for i := 0; i < n; i++ {
        digits[i] = i + 1
    }

    k-- // 转为 0-indexed，便于取商取余
    var sb strings.Builder
    for i := n; i >= 1; i-- {
        idx := k / fact[i-1] // 当前位取剩余数字中的第 idx 个
        sb.WriteByte(byte('0' + digits[idx]))
        digits = append(digits[:idx], digits[idx+1:]...) // 移除已选数字
        k %= fact[i-1]                                    // 更新剩余编号
    }
    return sb.String()
}
```

**复杂度**：时间 $O(n^2)$（每次删除切片元素是 $O(n)$，共 $n$ 次），空间 $O(n)$。相比反复调用 `nextPermutation` 的 $O(n \cdot n!)$，这是质的飞跃。

> [!note] 设计哲学：当"生成"太贵，就改成"计算"
> 从"反复调用下一个排列"到"用阶乘数系直接定位"，这道题的跃迁很有代表性：**当一条路的代价随规模指数级膨胀时，正确的做法往往不是把它优化得更快，而是换一条完全不同、把"枚举"替换为"计算"的路。** 阶乘数系之于排列，正如进制之于整数——一旦找到了合适的"坐标系"，位置就能被直接算出，而不必逐个走过去的。这种"换坐标系"的思路，是算法设计里最激动人心的一类洞察。

## 第 4 章 康托展开：排列与编号的双向映射

### 4.1 从"编号到排列"到"排列到编号"

Permutation Sequence 解决的是"给定编号求排列"。它的逆问题——**给定一个排列，求它在字典序中的编号**——同样常见，答案就是**康托展开（Cantor Expansion）**。两者互为逆运算，合起来构成"排列 ↔ 编号"的双向映射，是很多排列相关问题的通用工具。

### 4.2 康托展开的公式与推导

对一个排列 $a_1 a_2 \ldots a_n$，它在全排列中的排名（从 0 开始）为：

$$X = \sum_{i=1}^{n} c_i \cdot (n-i)!$$

其中 $c_i$ 表示"在 $a_i$ 右侧、比 $a_i$ 小的元素的个数"。这个公式与阶乘数系是同一枚硬币的两面：$c_i$ 恰好就是第 $i$ 位在阶乘数系中的"数字"，而 $(n-i)!$ 是那一位的权值。**换句话说，康托展开就是把一个排列读成它的阶乘数系表示，再把各位乘上权值求和。**

以 `[2,3,1]`（$n=3$）为例：第一位 `2` 右侧有 `1` 个比它小的（`1`），$c_1 = 1$；第二位 `3` 右侧有 `1` 个比它小的（`1`），$c_2 = 1$；第三位 `1` 右侧有 0 个，$c_3 = 0$。于是

$$X = 1 \times 2! + 1 \times 1! + 0 \times 0! = 2 + 1 + 0 = 3$$

即 `[2,3,1]` 的排名是 3（0-indexed），也就是字典序中的第 4 个排列，与第 1 章表格里列出的顺序一致。

**康托展开的价值在于，它把"排列"这种看似无结构的东西，映射成了一个整数**。有了这个映射，判断两个排列谁在前、快速定位某个排列、乃至在搜索中做状态去重，都可以退化为整数运算。

> [!info] 康托展开的复杂度与用途
> 朴素计算 $c_i$ 需要 $O(n^2)$（对每位向右扫描一遍）。若在竞赛或大规模场景中使用，可用树状数组把每位 $c_i$ 的计算降到 $O(\log n)$，整体 $O(n \log n)$。在面试里，掌握朴素版本已足够，重点是理解"排列可被编号"这一思想。

## 第 5 章 LeetCode 89：格雷编码

### 5.1 题目

**LeetCode 89 - Gray Code**（中等）

$n$ 位**格雷码序列**是一个由 $2^n$ 个整数组成的序列，满足：每个整数都在 $[0, 2^n-1]$ 内、第一个是 0、每个整数只出现一次，且**每对相邻整数的二进制表示恰好只有一位不同**（首尾也视为相邻）。返回任意一个有效序列。

```text
输入: n = 2  →  输出: [0,1,3,2]（二进制 00→01→11→10，相邻只差一位）
输入: n = 1  →  输出: [0,1]
```

### 5.2 格雷码的由来与性质

格雷码（Gray Code）由贝尔实验室的工程师 Frank Gray 在 1953 年提出，最初的用途是减少机械式编码器在多位同时翻转时产生的短暂错误状态——**相邻状态只翻转一位，就意味着"过渡瞬间"永远只有确定的一个中间态，不会出现因多位不同步而产生的乱码。** 这个"最小改动"的诉求，与本章 Next Permutation 的"最小改动原则"竟是同一种精神。

格雷码有一个极简的生成公式：

$$G(i) = i \oplus (i \gg 1)$$

其中 $\oplus$ 是异或，$\gg$ 是右移。以 $n=2$ 验证：

```text
i=0: 0 XOR 0 = 0  (00)
i=1: 1 XOR 0 = 1  (01)
i=2: 2 XOR 1 = 3  (11)
i=3: 3 XOR 1 = 2  (10)
```

序列 `[0,1,3,2]` 正是 $n=2$ 的格雷码。

### 5.3 公式从何而来：镜像递推

公式不是凭空掉下来的，它来自格雷码的**镜像递推**结构：

- $n=1$ 时，序列是 `[0, 1]`；
- $n=2$ 时，先把 `[0,1]` 原样保留（最高位补 0），再把它**倒序**并给每个元素最高位补 1，得到 `[11, 10]`，两者拼接为 `[00, 01, 11, 10]`，即 `[0,1,3,2]`；
- $n=3$ 时，依样对 `n=2` 的序列再折叠一次。

这种"镜像折叠"的构造，恰好保证了三条性质：两段接缝处只差最高位一位、每段内部相邻元素只差一位（继承自上一级）、首尾也只差一位。**而 `i ^ (i >> 1)` 正是这一递推过程的闭式表达**——它把"逐层折叠"这一几何操作，压缩成了一次异或运算。

### 5.4 Go 实现

**写法一：直接用公式**，简洁到几乎不像算法：

```go
func grayCode(n int) []int {
    res := make([]int, 0, 1<<n)
    for i := 0; i < (1 << n); i++ {
        res = append(res, i^(i>>1))
    }
    return res
}
```

时间 $O(2^n)$，空间 $O(2^n)$（存储结果）。

**写法二：镜像递推**，如果面试中一时忘了公式，可用它从头构建：

```go
func grayCodeIter(n int) []int {
    res := []int{0} // 0 位格雷码是 [0]
    for i := 0; i < n; i++ {
        size := len(res)
        // 把当前序列倒序，每个元素最高位加 1（即加 2^i）
        for j := size - 1; j >= 0; j-- {
            res = append(res, res[j]+(1<<i))
        }
    }
    return res
}
```

**写法二的好处是过程完全可见**：每一步都能看到序列如何从上一级折叠而来，比公式更容易解释给面试官听。两种写法复杂度相同，取舍在"简洁"与"可解释"之间。

## 第 6 章 三道题的关联与面试策略

### 6.1 共同的底层思想

三道题表面分属不同主题，骨子里却共享一条主线：**用对结构的洞察，替代对空间的暴力枚举。**

| 题目 | 核心数学思想 | 关键操作 |
|------|-------------|----------|
| Next Permutation | 字典序递增的最小改动原则 | 找下降位、找替换位、翻转后缀 |
| Permutation Sequence | 阶乘数系（编号的阶乘分解） | `(k-1) / (n-1)!` 逐位定位 |
| Gray Code | 镜像递推 / `i ^ (i >> 1)` | 直接公式或逐层折叠 |

三题都不需要回溯，也不需要 DFS，而是利用数学结构**直接构造**答案。**这正是它们与前几篇"搜索类"题目的根本分野：前者的解法是"走一步看一步"，后者的解法是"一步算到位"。**

### 6.2 面试应对

- **Next Permutation**：务必记牢三步法（找下降位、找替换位、翻转后缀），它是面试中最可能被考到的一道，也是很多排列相关操作的基础。
- **Permutation Sequence**：理解阶乘数系的"变进制进位"类比，比死记公式更可靠。面试时若一时想不清，可以先画 `n=4` 的分组表格，让规律自己浮现。
- **Gray Code**：能背下 `i ^ (i >> 1)` 最好；记不住就用镜像递推，过程清晰同样得分。若被追问公式由来，用"镜像折叠"来解释。

> [!note] 设计哲学：数学洞察 vs 工程暴力
> 这三道题都有一个能跑通、却难看的暴力解法——反复调用 `next`、生成全部排列再取第 k 个、用 BFS/DFS 构造格雷码。**在真实工程里，能跑通往往就够了；但在面试里，展示数学洞察常常比交出一段暴力代码更能打动人。** 原因不难理解：暴力解法人人都能写，而洞察力是稀缺的。这也提示我们：学习算法时，"做出答案"只是及格线，"看懂结构"才是真正的收获。

### 6.3 与前一章的呼应

值得一提的是，本章的"最小改动"精神在第 05 篇（多指针夹逼）与第 02 篇（原地修改）里也曾反复出现——夹逼时每一步只动一个指针、原地修改时只覆写必要的位置。**"以最小代价逼近目标"，是贯穿整个线性表专栏的一条隐性主线。** 它提醒我们：好的算法，往往不是做了很多事，而是**每一步都只做了必须做的那一点**。

## 第 7 章 常见误区与自测方法

排列类题目的错误往往集中在"边界"和"编号语义"上，把它们集中盘点一遍，比零散记忆更有效。

### 7.1 四个高频误区

**误区一：Next Permutation 找的是"最右的下降位"，而不是"任意一个下降位"。** 若从左向右找第一个下降位，得到的位置会太靠前，改动幅度过大，结果就不再是"下一个"排列，而是"某个更靠后的"排列。**记住"从右向左"这四个字，它是"最小改动"原则的直接体现。**

**误区二：交换后忘了翻转后缀。** 只交换 `nums[i]` 与 `nums[j]` 而不翻转 `[i+1, n-1]`，得到的是"比原来大"的某个排列，但不一定是"紧挨着的下一个"——因为交换后后缀仍是降序（即后缀本身是它那一段的最大排列），必须翻成升序才是最小。

**误区三：Permutation Sequence 忘了把 `k` 转成 0-indexed。** 阶乘数系的推导基于"第 `k-1` 个"（0 起算），若直接用 `k` 参与除法，结果会整体偏后一位。**这类"1-indexed 与 0-indexed 混淆"的 bug，在排列、编号类题目里几乎必然出现一次。**

**误区四：阶乘数组越界。** 预计算 `factorial[i] = i!` 时，若数组长度取 `n` 而非 `n+1`，在某些写法下会越界访问 `factorial[n]`。**建议统一用长度为 `n` 的数组存 `0!` 到 `(n-1)!`，与"每一位的位权是 $(n-i)!$"对齐**，这样下标关系最清晰。

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `[1,2,3]` → `[1,3,2]` | 基础递进 |
| `[3,2,1]` → `[1,2,3]` | 最大排列回绕到最小 |
| `[1,1,5]` → `[1,5,1]` | 含重复元素 |
| `n=1, k=1` | 阶乘数系的退化边界 |
| `n=4, k=24`（最大值） | 编号上界 |

**尤其是 `[3,2,1]` 与 `n=1` 这两个"边界用例"，它们分别是"回绕"与"退化"的代表**，几乎能拦截上述一半的误区。

## 第 8 章 延伸：上一个排列与排列编号的逆向应用

### 8.1 上一个排列

既然有"下一个排列"，自然有"上一个排列"（字典序里紧挨着的前一个）。它的三步法与 Next Permutation 完全对称，只需把"下降位"改成"上升位"、把"找比它大的最小元素"改成"找比它小的最大元素"：

- **第一步**：从右向左找第一个"上升位" `i`，即 `nums[i] > nums[i+1]`；
- **第二步**：在 `i` 右侧找"比 `nums[i]` 小的最大元素" `nums[j]`；
- **第三步**：交换 `i`、`j`，再把 `[i+1, n-1]` 翻转（此时它是升序，翻成降序即得该段的最大排列）。

**"下一个"与"上一个"的对称，本身就是一条有用的记忆锚点**：只要理解了"找边界位 → 换一个更接近的候选 → 把后缀调整成最极端的那一端"这一骨架，正反两个方向都能现场推出来，而无需分别背诵。

### 8.2 排列编号的逆向应用

第 4 章的康托展开解决了"排列 → 编号"，第 3 章的阶乘数系解决了"编号 → 排列"。这对互逆映射组合起来，能解决一类"看似无从下手"的问题——**凡是需要在"排列空间"里做二分、去重或计数的场合，都可以先把它映射成整数，用整数的方法处理，再映射回去。**

举一个直观的例子：如果要在"所有 $n$ 位排列"中找出"字典序第 1000 到 2000 个"，只需把区间端点换算成排列即可，完全不必生成中间那些排列。**这正是"换坐标系"思想的威力：一旦找到合适的映射，原本属于组合空间的难题，就变成了整数区间上的平凡操作。**

### 8.3 与位运算的呼应

本章的格雷码用异或公式 `i ^ (i >> 1)` 生成序列，而第 09 篇会用异或来"成对抵消"。**同一个异或运算，在这里是"构造有序序列"的工具，在那里是"消除重复"的工具。** 这种"同一操作、多种用途"的现象在算法里屡见不鲜，也是把零散技巧串成知识网络的关键——**当你发现两个看似无关的题都在用同一个性质时，你对该性质的理解就深了一层。**

## 第 9 章 排列的另一种生成法：回溯枚举与剪枝

本章的三道题都走"构造"路线——直接算出下一个/第 k 个/格雷码，而不生成中间结果。但排列问题还有另一条经典路线——**回溯枚举（backtracking）**。理解两者的分工，才算真正看清"构造"与"搜索"的边界。

### 9.1 回溯枚举全排列

若题目要求"生成全部 $n!$ 个排列"（LeetCode 46），最自然的写法是回溯：逐位决定放哪个数字，用 `used` 标记已用过的数字。

```go
func permute(nums []int) [][]int {
    var res [][]int
    used := make([]bool, len(nums))
    var path []int
    var backtrack func()
    backtrack = func() {
        if len(path) == len(nums) {
            res = append(res, append([]int(nil), path...))
            return
        }
        for i := 0; i < len(nums); i++ {
            if used[i] {
                continue
            }
            used[i] = true
            path = append(path, nums[i])
            backtrack()
            path = path[:len(path)-1] // 撤销选择
            used[i] = false
        }
    }
    backtrack()
    return res
}
```

**回溯的骨架是"选择—递归—撤销"**：每一层为当前位置挑一个数字，递归处理下一位，返回时把选择撤销、换下一个数字。它遍历的是一棵"排列树"，叶子节点就是全部 $n!$ 个排列。

### 9.2 构造 vs 回溯：何时用哪一个

两条路线的适用场景截然不同：

| 需求 | 推荐路线 | 原因 |
|------|---------|------|
| 生成全部 $n!$ 个排列 | 回溯 | 输出规模本身就是 $n!$，无法避免 |
| 求"下一个"排列 | 构造（三步法） | 只需 $O(n)$，无需生成其他排列 |
| 求"第 k 个"排列 | 构造（阶乘数系） | 直接定位，无需生成前面 $k-1$ 个 |
| 求"任意一个"格雷码序列 | 构造（异或/镜像） | 直接生成，无需搜索 |

**判断标准只有一句话：需要的输出规模有多大。** 若确实要输出 $n!$ 个排列，那 $O(n!)$ 的时间是绕不过去的下界，回溯已是最优；但若只需一个特定排列，"构造"就能把 $O(n!)$ 压到 $O(n)$ 或 $O(n^2)$。**本章的三道题之所以用构造，正是因为它们只需要"某一个"排列，而非"全部"。**

### 9.3 剪枝：回溯的效率来源

回溯本身是"穷举"，但它可以通过**剪枝**提前砍掉不可能的分支。例如生成"不含重复排列"时，若数组有重复元素，可以在每一层跳过"与上一个相同且未使用"的数字：

```go
if i > 0 && nums[i] == nums[i-1] && !used[i-1] {
    continue // 同一层里，跳过与前一位置相同的值
}
```

**这与第 05 篇 k-Sum 的去重是同一思想——"相同的值只让一个代表有机会被选中"。** 剪枝不会改变最坏复杂度，却能在有重复元素时大幅减少实际搜索量。**"构造"用数学直接跳过整个搜索空间，"剪枝"则在搜索中砍掉冗余分支——两者都是在与组合爆炸抗争，只是手段不同。**

## 小结

本篇从"字典序"这一全序关系出发，把排列的生成与编号拆解成三条可推导的规律。Next Permutation 告诉我们，**下一个排列的本质是"保留尽量长的前缀、在尽量靠后的位置做最小改动"**，三步法（找下降位、找替换位、翻转后缀）正是这一原则的直接翻译；Permutation Sequence 引入了阶乘数系，把"第 k 个排列"变成一次按位权取数，绕开了生成全部排列的天价代价；Gray Code 则用镜像递推与 `i ^ (i >> 1)`，示范了如何用一个闭式公式替代逐层构造。补上的康托展开，则把"编号到排列"与"排列到编号"这两个方向补齐，使整块知识闭合。

贯穿三题的核心认知只有一条：**当"枚举"的代价随规模指数级膨胀时，出路往往不是把枚举优化得更快，而是换一个能直接"计算"的坐标系。** 阶乘数系之于排列、异或公式之于格雷码，都是这种"换坐标系"的胜利。在更一般的算法实践中，凡是遇到"生成全部候选太贵"的场合，都值得先问一句：这些候选之间，有没有某种可被编号、可被直接定位的结构？

下一篇 [[07 矩阵数组专题：Rotate Image、Set Matrix Zeroes、Valid Sudoku]] 将进入二维数组的世界。旋转矩阵、置零矩阵与数独校验看似不相关，却都围绕同一个核心问题——**如何在不使用额外空间（或极小额外空间）的前提下，对二维数组进行原地修改**。
