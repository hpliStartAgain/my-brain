# 矩阵数组专题：Rotate Image、Set Matrix Zeroes、Valid Sudoku

**摘要：**

前几篇的数组题都停留在一维世界，本篇则跨入二维数组（矩阵）。载体变了，解题的核心命题却一脉相承：**在额外空间受限的前提下，如何原地完成矩阵变换，以及如何高效地维护多组状态标记**。本文覆盖三道经典题：Rotate Image（LeetCode 48）要我们把矩阵顺时针旋转 90°，看似需要搬动每个元素，实则能被分解成"转置 + 翻转"两步极其简单的原地操作；Set Matrix Zeroes（LeetCode 73）要求把含 0 的行列整体置零，它的精髓在于"用矩阵自己的第一行与第一列充当标记数组"，把空间压到常数级；Valid Sudoku（LeetCode 36）则要同时校验行、列、宫格三重约束，其中宫格编号的坐标映射与位运算压缩都值得细品。三题背后有一条共同的方法论——**把复杂操作分解为简单操作的组合，把临时状态就地藏进输入本身**。本文用 Go 语言完整实现，并补上矩阵遍历的通用模式与几处易错边界。

## 第 1 章 二维数组的坐标变换基础

### 1.1 把旋转看作坐标映射

矩阵题的第一步，往往不是写代码，而是**把"操作"翻译成"坐标映射"**。对于 $n \times n$ 矩阵中坐标为 $(r, c)$ 的元素（`r` 为行、`c` 为列，均从 0 起算），常见的几种变换可以用下面的表统一刻画：

| 变换类型 | 新坐标 | 直觉说明 |
|---------|--------|---------|
| 顺时针旋转 90° | $(c,\ n-1-r)$ | 原来的列变成行，行从下往上变成列 |
| 逆时针旋转 90° | $(n-1-c,\ r)$ | 原来的行变成列，列从右往左变成行 |
| 旋转 180° | $(n-1-r,\ n-1-c)$ | 等价于上下翻转再左右翻转 |
| 主对角线转置 | $(c,\ r)$ | 行列互换 |
| 副对角线转置 | $(n-1-c,\ n-1-r)$ | 行列互换后再双向取反 |

这些公式**不必死记**——只要真正理解其中一个，其余都可以由它组合推导出来。而"组合"这个词，恰恰是本篇全部技巧的钥匙。

### 1.2 关键分解：顺时针 90° = 转置 + 左右翻转

请记住这条恒等式：**顺时针旋转 90°，等价于先沿主对角线转置，再对每一行做左右翻转。**

$$\text{顺时针 90°} = \text{主对角线转置}\ (r,c) \to (c,r) \quad + \quad \text{左右翻转}\ (r,c) \to (r,\ n-1-c)$$

两步复合，$(r,c) \to (c,r) \to (c,\ n-1-r)$，正是顺时针 90° 的坐标变换。

这条分解的价值，怎么强调都不过分：**转置与翻转都可以在原地完成，且每一步都极其简单，于是整个旋转也就成了原地操作。** 如果直接去追踪"每个元素旋转后该落在哪里"，代码会复杂得多，还极容易写错下标。分解之后，复杂的旋转被拆成了两个各自都不费脑子的动作——这正是本章开头所说的"把复杂操作分解为简单操作的组合"。

## 第 2 章 LeetCode 48：旋转图像

### 2.1 题目

**LeetCode 48 - Rotate Image**（中等）

给定一个 $n \times n$ 的二维矩阵 `matrix`，将图像顺时针旋转 90°。**不得使用另一个矩阵，必须在原地旋转。**

```text
输入:                输出:
[[1,2,3],           [[7,4,1],
 [4,5,6],    →       [8,5,2],
 [7,8,9]]            [9,6,3]]
```

### 2.2 解法一：转置 + 翻转

**第一步，沿主对角线转置。** 只遍历上三角（`j` 从 `i+1` 开始），交换 `matrix[i][j]` 与 `matrix[j][i]`：

```text
转置前:        转置后:
1 2 3          1 4 7
4 5 6    →     2 5 8
7 8 9          3 6 9
```

**第二步，每行左右翻转。** 对每一行做对称交换：

```text
转置后:        左右翻转后:
1 4 7          7 4 1
2 5 8    →     8 5 2
3 6 9          9 6 3
```

两步做完，结果正是顺时针 90°。

```go
func rotate(matrix [][]int) {
    n := len(matrix)

    // 第一步：沿主对角线转置，只遍历上三角以避免重复交换
    for i := 0; i < n; i++ {
        for j := i + 1; j < n; j++ {
            matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]
        }
    }

    // 第二步：每行左右翻转
    for i := 0; i < n; i++ {
        left, right := 0, n-1
        for left < right {
            matrix[i][left], matrix[i][right] = matrix[i][right], matrix[i][left]
            left++
            right--
        }
    }
}
```

**复杂度**：时间 $O(n^2)$（每个元素被访问常数次），空间 $O(1)$（全程原地）。

**注意 `j` 从 `i+1` 开始这个细节。** 若从 `j = 0` 开始遍历，就会把每一对元素交换两次——第一次换过去、第二次又换回来，等于白做，甚至因对称位置处理重复而破坏结果。**"只遍历上三角"是转置操作必须记住的边界。**

### 2.3 解法二：四点一组循环交换

另一种思路更为"直白"：把矩阵按层处理，每一层里，四个对称位置的元素构成一个循环，一次性轮转。对于第 `layer` 层（从外往内数），设 `first = layer`、`last = n - 1 - layer`，对 `i` 从 `first` 到 `last - 1`：

```text
四个位置构成循环：
  (first, i)              →  左上
  (i, last)               →  右上
  (last, last - (i-first)) → 右下
  (last - (i-first), first) → 左下
```

```go
func rotateFourWay(matrix [][]int) {
    n := len(matrix)
    for layer := 0; layer < n/2; layer++ {
        first, last := layer, n-1-layer
        for i := first; i < last; i++ {
            offset := i - first
            top := matrix[first][i]                     // 左上，暂存
            matrix[first][i] = matrix[last-offset][first] // 左下 → 左上
            matrix[last-offset][first] = matrix[last][last-offset] // 右下 → 左下
            matrix[last][last-offset] = matrix[i][last]   // 右上 → 右下
            matrix[i][last] = top                         // 暂存 → 右上
        }
    }
}
```

**两种解法的取舍值得玩味。** 解法二代码更长、下标更绕，但它是"一步到位"的旋转；解法一代码更短，靠的是把旋转拆成两个平凡操作的洞察。**笔者的建议是面试时首选解法一**：它更容易解释、更不易写错，而且一旦面试官追问"逆时针怎么转"，你只需把两个步骤的顺序调换（先左右翻转、再转置）即可，而不必重新推导四个坐标。**能靠组合推导出来的东西，就不要再单独记忆——这是本篇反复出现的一条心法。**

### 2.4 变体：逆时针旋转 90°

有了分解视角，逆时针旋转变得唾手可得：它等价于**先上下翻转，再沿主对角线转置**（或等价地，先转置再上下翻转）。

```go
// 上下翻转：交换第 i 行与第 n-1-i 行
for i := 0; i < n/2; i++ {
    matrix[i], matrix[n-1-i] = matrix[n-1-i], matrix[i]
}
// 再做一次主对角线转置（同解法一的第一步）
```

> [!note] 设计哲学：把复杂变换分解为简单操作的组合
> 旋转图像的精妙，全在"分解"二字。直接实现旋转需要追踪每个元素的新落点，逻辑绕、易出错；分解为"转置 + 翻转"后，每一步都简单到不可能写错，还能原地完成。**这种"把复杂操作拆成简单操作的组合"的思路，在算法设计中极为普遍**——它让我们把注意力集中在"如何组合"这一层，而不必去啃"如何一步到位"那块硬骨头。后续第 08 篇的接雨水、第 13 篇的重排链表，都会再次用到这条心法。

## 第 3 章 LeetCode 73：矩阵置零

### 3.1 题目

**LeetCode 73 - Set Matrix Zeroes**（中等）

给定一个 $m \times n$ 的矩阵，若某个元素为 0，则把它所在行与所在列的所有元素都设为 0。**要求使用原地算法。**

```text
输入:              输出:
[[1,1,1],          [[1,0,1],
 [1,0,1],    →      [0,0,0],
 [1,1,1]]           [1,0,1]]
```

题目还给出了一条循序渐进的提示：直观解用 $O(mn)$ 额外空间，简单改进用 $O(m+n)$，能否只用常数空间？这道题因此成了一道**"空间优化"的阶梯题**，三种方案层层递进，很能体现"空间如何一步步被省下来"。

### 3.2 三种方案的进化

**方案一，$O(mn)$ 额外空间。** 复制整个矩阵，再依据原矩阵中 0 的位置在副本上置零。逻辑最简单，代价是整整一个矩阵的额外空间。

**方案二，$O(m+n)$ 额外空间。** 用两个数组 `zeroRows[m]` 与 `zeroCols[n]` 记录"哪些行、哪些列需要置零"，第一遍扫描标记，第二遍扫描置零。

```go
// O(m+n) 方案
zeroRows := make([]bool, m)
zeroCols := make([]bool, n)
for i := 0; i < m; i++ {
    for j := 0; j < n; j++ {
        if matrix[i][j] == 0 {
            zeroRows[i] = true
            zeroCols[j] = true
        }
    }
}
for i := 0; i < m; i++ {
    for j := 0; j < n; j++ {
        if zeroRows[i] || zeroCols[j] {
            matrix[i][j] = 0
        }
    }
}
```

**方案三，$O(1)$ 额外空间——把标记藏进矩阵自己。** 方案二的标记数组，能否就地存放在矩阵本身里？可以：**用第一行充当 `zeroCols`，用第一列充当 `zeroRows`。** 即 `matrix[0][j] == 0` 表示第 `j` 列需要置零，`matrix[i][0] == 0` 表示第 `i` 行需要置零。

但这里冒出一个棘手的重叠问题：`matrix[0][0]` 这个位置，**既属于第一行、又属于第一列**，它到底该表示"第一行需要置零"还是"第一列需要置零"？一个格子装不下两重含义。

解决办法很干净：**让 `matrix[0][0]` 专门负责标记第一列，另用一个布尔变量 `firstRowZero` 记录第一行是否需要置零。** 换句话说，当"就地存储"的容量差一格时，就用一个标量把溢出的那一位单独接住。

### 3.3 $O(1)$ 方案完整实现

```go
func setZeroes(matrix [][]int) {
    m, n := len(matrix), len(matrix[0])

    // 第一步：先记录第一行、第一列自身是否有 0（必须在改动之前记录）
    firstRowZero := false
    for j := 0; j < n; j++ {
        if matrix[0][j] == 0 {
            firstRowZero = true
            break
        }
    }
    firstColZero := false
    for i := 0; i < m; i++ {
        if matrix[i][0] == 0 {
            firstColZero = true
            break
        }
    }

    // 第二步：用第一行/第一列作为标记，扫描内部区域 [1,1]..[m-1,n-1]
    for i := 1; i < m; i++ {
        for j := 1; j < n; j++ {
            if matrix[i][j] == 0 {
                matrix[i][0] = 0 // 标记第 i 行需要置零
                matrix[0][j] = 0 // 标记第 j 列需要置零
            }
        }
    }

    // 第三步：依据标记，置零内部区域
    for i := 1; i < m; i++ {
        for j := 1; j < n; j++ {
            if matrix[i][0] == 0 || matrix[0][j] == 0 {
                matrix[i][j] = 0
            }
        }
    }

    // 第四步：最后处理第一行与第一列（依据第一步记录的状态）
    if firstRowZero {
        for j := 0; j < n; j++ {
            matrix[0][j] = 0
        }
    }
    if firstColZero {
        for i := 0; i < m; i++ {
            matrix[i][0] = 0
        }
    }
}
```

**复杂度**：时间 $O(mn)$，空间 $O(1)$（只用两个布尔变量）。

### 3.4 为什么第一行第一列必须最后处理

这是本方案最容易出错、也最需要想清楚的一点：**第一行与第一列被借去当了"标记数组"，若在置零内部区域之前就把它们本身置零，标记信息就被毁了，后续的置零判断会全部失准。** 所以顺序必须是：先记录它们自身的初始状态，再拿它们标记内部，然后置零内部，**最后**才根据最初记录的状态去处理它们自身。

再深一层，这还牵出一个通用的原则——**"先标记，后修改"**。若扫描到某个 0 就立刻把整行整列置零，那么后续扫描遇到的"被置零的位置"就再也分不清是"它本来就是 0"还是"它是被别的 0 传染的"，置零范围会被错误地放大。**当"修改"会影响"后续判断"时，就必须先把所有判断做完，再统一修改。**

> [!warning] 生产避坑：就地借用状态时的"污染"风险
> "把临时状态藏进输入本身"是一种很优雅的省空间手法，但它有一项隐性风险——**这些被借用的格子，本身也是待处理的数据**。一旦处理顺序没安排对，就会发生"标记污染数据、数据覆盖标记"的连锁错误。防范的办法是固定的三步：**先保存被借用格的原始状态，再使用它们作标记，最后按原始状态收尾。** 这套顺序在 Set Matrix Zeroes 里是这样，在更复杂的原地算法里也是如此。

## 第 4 章 LeetCode 36：有效的数独

### 4.1 题目

**LeetCode 36 - Valid Sudoku**（中等）

判断一个 $9 \times 9$ 的数独是否有效。只需根据规则校验已填入的数字是否有效即可：数字 1-9 在每一**行**只能出现一次、在每一**列**只能出现一次、在每一个 $3 \times 3$ **宫格**内只能出现一次。空白格用 `'.'` 表示。

请注意，题目只要求校验"已填数字是否违反规则"，并不要求数独**可解**——这是一个容易读错的细节。

### 4.2 三重约束与宫格编号

这道题的实质，是同时校验三组独立的"不重复"约束：9 行、9 列、9 个宫格。行列的校验直截了当，难点全在**宫格编号的坐标映射**：如何把位置 $(i, j)$ 映射到它所属的宫格（0-8）？

答案是：

$$\text{boxIdx} = \left\lfloor \frac{i}{3} \right\rfloor \times 3 + \left\lfloor \frac{j}{3} \right\rfloor$$

```text
宫格编号（0-8）：
+---+---+---+
| 0 | 1 | 2 |
+---+---+---+
| 3 | 4 | 5 |
+---+---+---+
| 6 | 7 | 8 |
+---+---+---+

位置 (i=4, j=7)：boxIdx = (4/3)*3 + (7/3) = 1*3 + 2 = 5 ✓
```

**这个公式不需要死记。** 想清楚它即可：行方向上有 3 个宫格带，行号整除 3 得到"行带编号"（0-2）；列方向同理得到"列带编号"（0-2）；把这两个 0-2 的数按"基 3"组合成一个 0-8 的编号，就是 `行带 * 3 + 列带`。**它与十进制用 `十位*10 + 个位` 组合出编号，是同一种思路。**

### 4.3 方案一：三个二维布尔数组

最直观的方案，是用三个 `boolean[9][9]` 分别记录每行、每列、每宫格中哪些数字已经出现过：

```go
func isValidSudoku(board [][]byte) bool {
    var rows, cols, boxes [9][9]bool

    for i := 0; i < 9; i++ {
        for j := 0; j < 9; j++ {
            if board[i][j] == '.' {
                continue
            }
            d := board[i][j] - '1' // 转为 0-indexed：'1'→0，'9'→8
            boxIdx := (i/3)*3 + j/3

            if rows[i][d] || cols[j][d] || boxes[boxIdx][d] {
                return false // 任一维度出现冲突，即无效
            }
            rows[i][d] = true
            cols[j][d] = true
            boxes[boxIdx][d] = true
        }
    }
    return true
}
```

**复杂度**：时间 $O(81) = O(1)$（棋盘固定为 $9 \times 9$），空间 $O(1)$（标记数组大小固定）。**对于固定规模的问题，复杂度都是 $O(1)$**——但分析时按 $O(n^2)$（$n=9$）去想，更有推广价值。

### 4.4 方案二：位运算压缩

方案一用了 `3 × 9 × 9 = 243` 个布尔值。其实每个"某行/列/宫格中哪些数字出现过"的状态，本质上只是一个"1-9 的集合"，用 9 个二进制位就足以表示——于是可以用一个 `int` 的低 9 位来承载：

```go
func isValidSudokuBit(board [][]byte) bool {
    var rowState, colState, boxState [9]int

    for i := 0; i < 9; i++ {
        for j := 0; j < 9; j++ {
            if board[i][j] == '.' {
                continue
            }
            d := board[i][j] - '1'
            bit := 1 << d
            boxIdx := (i/3)*3 + j/3

            if rowState[i]&bit != 0 || colState[j]&bit != 0 || boxState[boxIdx]&bit != 0 {
                return false
            }
            rowState[i] |= bit
            colState[j] |= bit
            boxState[boxIdx] |= bit
        }
    }
    return true
}
```

**位运算版本把空间从 243 个布尔压缩到 27 个 int**，且"检查是否出现"退化为一次按位与、"标记出现"退化为一次按位或，常数更小。在更大的数独（如 $16 \times 16$）里，这种压缩的价值更加明显。

> [!info] 集合的位掩码表示
> "用一个整数的若干位表示一个集合"，是一种极其实用的技巧：第 $k$ 位为 1 表示元素 $k$ 在集合中。于是"判断元素是否存在"= 按位与，"加入元素"= 按位或，"求交并差"= 与或非。当集合的元素取值范围不大（不超过一个机器字的位数）时，位掩码几乎总是比布尔数组或哈希集合更快、更省。第 09 篇讲 Single Number 系列时，还会再次用到它。

## 第 5 章 矩阵操作的通用技巧

### 5.1 几种常用的矩阵遍历模式

矩阵题的遍历顺序本身就是一种信息，值得整理成可复用的模式：

```go
// 模式一：顺序遍历（逐行）
for i := 0; i < m; i++ {
    for j := 0; j < n; j++ {
        process(matrix[i][j])
    }
}

// 模式二：上三角遍历（转置、对称处理）
for i := 0; i < n; i++ {
    for j := i + 1; j < n; j++ { // j 从 i+1 起，跳过对角线
        process(i, j)
    }
}

// 模式三：宫格遍历（数独类）
for boxRow := 0; boxRow < 3; boxRow++ {
    for boxCol := 0; boxCol < 3; boxCol++ {
        for r := 0; r < 3; r++ {
            for c := 0; c < 3; c++ {
                process(boxRow*3+r, boxCol*3+c)
            }
        }
    }
}
```

**模式二的"只走半边"尤其重要**：凡是涉及对称交换的操作（转置、镜像翻转），都必须只遍历一半，否则同一对元素会被处理两次，相互抵消。这与第 02 篇里"原地写回要小心自我覆盖"是同一类边界意识。

### 5.2 "先标记后修改"的适用边界

前文提到的"先标记后修改"原则，并非矩阵题的专利，而是**一切"修改会影响后续判断"的场合**的通则。判断它是否适用，只需问一句：**我正在做的修改，会不会改变我接下来要读的那些值？** 会，就必须先完成全部标记、再统一修改；不会，则可以边扫描边处理。以 Set Matrix Zeroes 为例，正是"置零会污染后续对 0 的判断"，才迫使我们必须把标记与修改分两个阶段完成。

### 5.3 三题的共同方法论

把三道题并排来看，它们的技巧其实共享同一套心法：

| 题目 | 空间目标 | 核心手法 | 方法论 |
|------|---------|---------|--------|
| Rotate Image | $O(1)$ | 转置 + 翻转 | 复杂操作分解为简单操作的组合 |
| Set Matrix Zeroes | $O(1)$ | 借用第一行/列作标记 | 把临时状态就地藏进输入 |
| Valid Sudoku | $O(1)$ | 三组标记 / 位掩码 | 用统一结构承载多组约束 |

**三题的落点，都是"如何用更少的额外空间表达状态"**。旋转题靠分解减少了需要的中间量，置零题靠"就地借用"消掉了标记数组，数独题靠位掩码压缩了标记的粒度。理解了这个统一视角，再遇到二维数组的变体题，你就能主动去问：这里有没有可以组合的简单操作？有没有可以就地借用的格子？有没有可以用更紧凑结构承载的状态？

## 第 6 章 延伸：矩阵遍历与变换的更多面孔

三道主线题之外，还有一批矩阵题值得一并看看。它们的技巧与前三题同源，正好用来检验"是否真的把二维数组的坐标感建立起来了"。

### 6.1 螺旋矩阵（LeetCode 54）：边界收缩

**题目**：给你一个 $m \times n$ 矩阵，按螺旋顺序（顺时针由外向内）返回所有元素。

这道题的核心是**维护四条边界**：上、下、左、右。每遍历完一条边，就把对应的边界向内收缩一格；当任意两条边界交叉时，遍历结束。

```go
func spiralOrder(matrix [][]int) []int {
    if len(matrix) == 0 {
        return nil
    }
    top, bottom := 0, len(matrix)-1
    left, right := 0, len(matrix[0])-1
    var res []int

    for top <= bottom && left <= right {
        // 上边：从左到右
        for j := left; j <= right; j++ {
            res = append(res, matrix[top][j])
        }
        top++
        // 右边：从上到下
        for i := top; i <= bottom; i++ {
            res = append(res, matrix[i][right])
        }
        right--
        // 下边：从右到左（需再次检查边界，避免重复）
        if top <= bottom {
            for j := right; j >= left; j-- {
                res = append(res, matrix[bottom][j])
            }
            bottom--
        }
        // 左边：从下到上（同样需检查）
        if left <= right {
            for i := bottom; i >= top; i-- {
                res = append(res, matrix[i][left])
            }
            left++
        }
    }
    return res
}
```

**这道题最值得琢磨的地方，是下边与左边那两处 `if` 检查。** 当矩阵只剩一行（`top == bottom`）或一列（`left == right`）时，若不检查，同一条边会被遍历两次，产生重复元素。**"遍历四条边时，每一条之前都要重新确认边界没被前一步破坏"**，这是螺旋矩阵最容易出错、也最能体现"边界意识"的地方。它和本篇主线题里"第一行第一列最后处理"是同一种警觉——**矩阵题的错误，几乎全都源于"边界在遍历过程中悄悄变了"。**

### 6.2 矩阵转置（LeetCode 867）：非方阵的处理

**题目**：给你一个二维整数数组 `matrix`，返回它的转置矩阵。

对于**方阵**，转置可以原地完成（只遍历上三角，交换 `(i,j)` 与 `(j,i)`），这正是第 2 章旋转的第一步。但对于**非方阵**（$m \times n$），转置会变成 $n \times m$，形状改变，**无法原地完成**，必须新建一个矩阵：

```go
func transpose(matrix [][]int) [][]int {
    m, n := len(matrix), len(matrix[0])
    res := make([][]int, n)
    for i := range res {
        res[i] = make([]int, m)
    }
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            res[j][i] = matrix[i][j] // 行列互换
        }
    }
    return res
}
```

**为什么方阵能原地、非方阵不能？** 因为原地转置依赖"交换 `(i,j)` 与 `(j,i)`"这一对称操作，而对称的前提是这两个位置**都属于同一个矩阵**——只有方阵才满足"转置后形状不变"。**非方阵一转置，行列数就对调了，原来的内存布局再也装不下新形状，于是原地操作在数学上就不可能。** 这是一个很好的例子：**"能否原地"往往由问题本身的对称性决定，而非技巧高低。**

### 6.3 对角线遍历（LeetCode 498）：坐标变换的练习

**题目**：按对角线顺序遍历矩阵，方向交替（左下→右上、右上→左下）。

这道题的实现可以用"模拟"（按方向走，越界则换向），也可以**用坐标变换**：把所有元素按 `i + j` 分组（同一条对角线上的元素 `i + j` 相等），组内再按方向排序。后者的思路更清晰：

```go
func findDiagonalOrder(matrix [][]int) []int {
    if len(matrix) == 0 {
        return nil
    }
    m, n := len(matrix), len(matrix[0])
    // 按 i+j 分组，共 m+n-1 条对角线
    groups := make([][]int, m+n-1)
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            groups[i+j] = append(groups[i+j], matrix[i][j])
        }
    }
    var res []int
    for d, g := range groups {
        if d%2 == 0 {
            // 偶数对角线：从左下到右上，分组时是正序，需反转
            for k := len(g) - 1; k >= 0; k-- {
                res = append(res, g[k])
            }
        } else {
            res = append(res, g...)
        }
    }
    return res
}
```

**`i + j` 这一坐标变换是关键洞察**：它把"对角线"这一几何概念，变成了一次简单的分组。**矩阵题的一大解题心法，就是找到合适的坐标不变量（`i+j`、`i-j`、`i/3` 等），用它把二维的几何关系翻译成一维的数值关系。** 数独的宫格编号 `(i/3)*3 + j/3`，用的正是同一种思路。

## 第 7 章 常见误区与自测方法

### 7.1 四个高频误区

**误区一：转置时从 `j = 0` 开始遍历。** 这会使得每一对元素被交换两次，等于白做。必须只遍历上三角（`j` 从 `i+1` 起）。

**误区二：置零时忘记先记录第一行/第一列的原始状态。** 若直接拿它们作标记、又在处理内部之前置零它们，标记就被污染了。**牢记"先记录、再借用、最后收尾"这三步顺序。**

**误区三：螺旋矩阵的下边、左边忘了重新检查边界。** 当只剩一行或一列时会产生重复元素。

**误区四：宫格编号公式记成 `i/3 + j/3`。** 漏了乘 3 就会把不同宫格映射到同一个编号上。**理解它是"基 3 组合"（行带 × 3 + 列带）就不会写错。**

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `1×1` 矩阵 | 退化边界 |
| `1×n` / `n×1` 矩阵 | 单行/单列（螺旋、置零的关键边界） |
| 全 0 矩阵 | 置零的极端情形 |
| 首行含 0 的矩阵 | 置零方案三的 `firstRowZero` 分支 |

**其中"单行/单列矩阵"是矩阵题最常被忽略、也最容易翻车的边界**——旋转、螺旋、置零在这类输入下都可能有特殊行为。**每次写完矩阵题，先用一个 `1×n` 的输入在心里过一遍，能拦下相当一部分 bug。**

## 第 8 章 从矩阵到工程：这些技巧的真实身影

### 8.1 图像旋转：不只是面试题

LeetCode 48 的"顺时针旋转 90°"，在图像处理里是一个真实且高频的操作——手机拍照时的方向校正、图片编辑器的"旋转"按钮，背后都是同一个坐标变换。**工业实现当然不会真的逐个像素搬移**（那样太慢），而是利用"转置 + 翻转"这一分解，把两个各自可以高度并行、且缓存友好的操作组合起来。**面试题里的"分解"技巧，在工程里对应的正是"用两个简单操作替代一个复杂操作"的性能考量。**

### 8.2 稀疏矩阵与就地标记

Set Matrix Zeroes 的"用第一行第一列当标记"，本质是一种**就地（in-place）技巧**——把元数据藏进数据本身。这个思想在工程里随处可见：稀疏矩阵存储时，用一个数组记录"非零元素的位置"；图算法里，用节点自身的某个字段标记"是否访问过"；甚至在文件系统里，用 inode 的一部分字段记录状态。

**这类技巧的共同前提是"被借用的格子，其原始值可以被安全地保存与恢复"**——正如本篇反复强调的"先记录、再借用、最后收尾"三步顺序。**一旦这个前提不成立（比如被借用的格子本身就是不可丢失的关键数据），就地标记就无法使用，只能退回额外空间。**

### 8.3 位图：从数独到布隆过滤器

Valid Sudoku 的位掩码方案，用一个 `int` 的低 9 位表示一个"1-9 的集合"。这个思想放大到极致，就是工程里的**位图（Bitmap）**与**布隆过滤器（Bloom Filter）**：

- **位图**：用一个比特表示一个元素是否存在，$n$ 个元素只需 $n$ 比特（而非 $n$ 字节），空间利用率提升 8 倍；
- **布隆过滤器**：用多个哈希函数把元素映射到多个比特位上，以极小的空间回答"某元素是否可能存在"——代价是**存在假阳性（说存在可能其实不存在），但没有假阴性**。

**数独的位掩码，正是"位图"思想在 $9 \times 9$ 尺度上的微缩版。** 理解了"用一个整数的位表示一个集合"，你也就理解了为什么在大数据、数据库、网络路由等场景里，"位图"和"布隆过滤器"会如此常见——**它们都是在用比特的密度，换取空间的极致节省。**

### 8.4 认知落点：空间是可以被"设计"出来的

本篇三道主线题都做到了 $O(1)$ 额外空间，而它们省空间的路径各不相同：旋转靠**分解**（把复杂变换拆成两个简单操作，从而不需要暂存整个矩阵），置零靠**就地借用**（把标记藏进输入），数独靠**压缩表示**（用比特替代布尔）。

**三条路径合起来，揭示了"省空间"这件事的本质：空间不是被'省'出来的，而是被'设计'出来的。** 当你觉得"这里非得用额外空间不可"时，不妨依次问三个问题：这个操作能不能分解？这份状态能不能就地存放？这个表示能不能压缩？**能回答其中任何一个'能'，往往就离 $O(1)$ 空间不远了。**

## 小结

本篇把战场从一维数组搬到二维矩阵，但解题的底层逻辑并未改变——**依然是"在空间受限下，用更聪明的结构表达状态"**。Rotate Image 教会我们，复杂的坐标变换可以被分解为转置与翻转这两个平凡操作的复合，从而轻松实现原地旋转；Set Matrix Zeroes 展示了一条完整的空间优化阶梯（从 $O(mn)$ 到 $O(m+n)$ 再到 $O(1)$），其最后一跃靠的是"把标记数组藏进矩阵自己的第一行与第一列"，代价则是必须处理好"第一行第一列最后处理"这一顺序约束；Valid Sudoku 则示范了如何用三组标记同时承载三重约束，以及如何用位掩码把标记粒度压到极致。

三题合起来，给出两条可迁移的经验。其一，**"分解"是应对复杂操作的通用武器**——把一步到位的难事，拆成几步平凡的易事，代码与正确性都会显著改善。其二，**"就地借用状态"能省空间，但会引入污染风险**，必须辅以"先保存、再借用、后收尾"的固定顺序。这两条经验，在后续章节乃至整个算法生涯里，都会被反复验证。

下一篇 [[08 贪心策略：Trapping Rain Water、Gas Station、Candy]] 将进入贪心算法专题。贪心的核心是"每步做局部最优选择，最终得到全局最优"，但这个结论**需要证明**——不是所有问题都能贪心。本篇三道题各有不同的贪心策略：接雨水用双指针或单调栈，加油站用循环不变量，分发糖果用两遍扫描，我们会在给出解法的同时，交代每种贪心为什么成立。
