# 回文检测：Valid Palindrome 与双指针范式

**摘要：**

回文（Palindrome）是字符串题里最基础的概念之一：一个字符串正读反读相同。LeetCode 125（Valid Palindrome）被标为"简单"，但它恰恰是面试里最容易翻车的一类题——**难点不在算法，而在字符过滤、大小写统一、边界处理这些"工程细节"**。本文以 125 题为切入点，讲清字符串双指针的核心范式：**从两端向中间夹逼，跳过无关字符，忽略大小写比较**。随后把它推广到一整族变体——允许删除一个字符（680）、回文数（9）、以及"只考虑字母""最长回文子串"（第 04 篇）。文中还会讲清一个容易被忽视的细节：**内层跳字符的 `while` 为什么必须带 `left < right` 保护**。全文用 Go 语言实现，并逐层追问：为什么"反转比较"不如双指针、预处理与原地的取舍、以及双指针字符串题的通用框架。

## 第 1 章 回文的定义与判断思路

### 1.1 什么是回文

**回文**（Palindrome）：字符串 `s` 满足 `s[i] == s[n-1-i]`（对所有合法下标 `i`），则称其为回文。直觉上，回文就是"从中间折叠后左右对称"的字符串：`racecar`、`abcba`、`a`（单字符）、`""`（空串）都是回文。

### 1.2 朴素方法：反转比较

最直观的方法是把字符串反转、再与原串比较：

```go
func isPalindromeSimple(s string) bool {
    r := []rune(s)
    for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
        r[i], r[j] = r[j], r[i]
    }
    return string(r) == s
}
```

**这需要 $O(n)$ 额外空间**（新字符串），而且"先全部反转再比较"做了很多不必要的工作——**一旦发现某对字符不同，就可以立即返回，无需反转整串。**

### 1.3 双指针：$O(1)$ 空间的优雅方案

**思路**：从两端各放一个指针，向中间靠拢，每步比较左右字符。若某步不等，立即返回 `false`；若两指针相遇或交叉，说明是回文。

```go
func isPalindromePlain(s string) bool {
    left, right := 0, len(s)-1
    for left < right {
        if s[left] != s[right] {
            return false
        }
        left++
        right--
    }
    return true
}
```

时间 $O(n)$、空间 $O(1)$。**这是字符串回文检测的基础模板**——它的价值在于"边比较边前进"，无需构造任何新串。

> [!info] 双指针的"提前返回"优势
> 双指针相比"反转比较"，有一个被忽视的优势：**它可以提前返回。** 若字符串的前两个字符就不对称，双指针一步就能判定 `false`，而"反转比较"要先反转整串。**对"判定类"问题，"能否提前返回"往往比"渐进复杂度"更能决定实际性能**——这与二叉树专栏第 09 篇"最小深度用 BFS 能提前返回"是同一种思路。

## 第 2 章 LeetCode 125：Valid Palindrome

### 2.1 题目

**LeetCode 125 - Valid Palindrome**（简单）

若将所有大写字符转为小写、并移除所有非字母数字字符之后，短语正读反读相同，则视为回文串。字母和数字都属字母数字字符。

```text
输入: "A man, a plan, a canal: Panama"  → true（清洗后 "amanaplanacanalpanama"）
输入: "race a car"                      → false（清洗后 "raceacar"）
输入: " "                               → true（清洗后为空串，空串是回文）
```

### 2.2 题目的真实考察点

这道题被标为简单，但细节上坑不少：

**坑一，如何判断"字母数字字符"。** 用标准库的 `isalnum` 语义即可；**自己手写时容易漏或多算**（如把下划线、非 ASCII 字符算进去）。

**坑二，空串的处理。** 过滤后为空串时，**空串是回文**（没有任何字符违反对称）。

**坑三，大小写统一。** `'A'` 与 `'a'` 应视为相同。

**坑四，预处理还是原地。** 可以"先清洗成干净串再做双指针"，也可以在双指针过程中"跳过非法字符"。**后者空间更优（$O(1)$）。**

### 2.3 解法一：预处理 + 双指针

先把字符串清洗成只含小写字母数字的干净串，再做标准双指针：

```go
func isPalindromePreprocess(s string) bool {
    var cleaned []byte
    for i := 0; i < len(s); i++ {
        c := s[i]
        if isAlnum(c) {
            cleaned = append(cleaned, toLower(c))
        }
    }
    left, right := 0, len(cleaned)-1
    for left < right {
        if cleaned[left] != cleaned[right] {
            return false
        }
        left++
        right--
    }
    return true
}
```

**复杂度**：时间 $O(n)$，空间 $O(n)$。**代码清晰、逻辑分离，推荐面试首先给出这一版。**

### 2.4 解法二：原地双指针（$O(1)$ 空间）

在双指针过程中，遇到非字母数字字符就跳过，不额外创建字符串：

```go
func isPalindrome(s string) bool {
    left, right := 0, len(s)-1
    for left < right {
        // 左指针跳过非字母数字字符
        for left < right && !isAlnum(s[left]) {
            left++
        }
        // 右指针跳过非字母数字字符
        for left < right && !isAlnum(s[right]) {
            right--
        }
        if toLower(s[left]) != toLower(s[right]) {
            return false
        }
        left++
        right--
    }
    return true
}
```

**关键细节**：**内层 `while` 的条件必须带 `left < right`**——否则当字符串全是非字母数字字符时（如 `" "`），左指针会一路越过右指针，导致**访问越界**。这是本题最容易漏的一处。

**复杂度**：时间 $O(n)$、空间 $O(1)$。

### 2.5 两种解法的权衡

| 维度 | 解法一（预处理） | 解法二（原地） |
|------|----------------|--------------|
| 时间 | $O(n)$ | $O(n)$ |
| 空间 | $O(n)$ | $O(1)$ |
| 代码清晰度 | 高（逻辑分离） | 中（双层循环） |
| 面试建议 | 先展示 | 追问空间优化时给出 |

**先给解法一（清晰），面试官追问"能否不用额外空间"时给解法二**——这样展示了你的解题层次感。**这是本专栏反复推荐的一种表达策略：先给"好懂的"，再给"更优的"。**

## 第 3 章 字符辨别工具的底层逻辑

### 3.1 判断"字母数字字符"

Go 标准库提供 `unicode.IsLetter`、`unicode.IsDigit` 等，但它们按 Unicode 语义（涵盖各国文字）。**算法题里通常只需要 ASCII 语义**，手写更快、更可控：

```go
func isAlnum(c byte) bool {
    return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || (c >= '0' && c <= '9')
}

func toLower(c byte) byte {
    if c >= 'A' && c <= 'Z' {
        return c + 32 // 'a' - 'A' = 32
    }
    return c
}
```

**`'a' - 'A' = 97 - 65 = 32`**，所以 ASCII 范围内"大写转小写"只需加 32。**注意这个技巧只在 ASCII 有效**——对 Unicode 字符（如带重音符号的字母），必须用标准库。

### 3.2 字符比较的三种方式

```go
// 方式一：直接比较 byte
if s[i] == s[j] { /* ... */ }

// 方式二：忽略大小写（推荐）
if toLower(s[i]) == toLower(s[j]) { /* ... */ }

// 方式三：转成字符串再比（不推荐，创建临时对象）
if strings.EqualFold(string(s[i]), string(s[j])) { /* ... */ }
```

**面试中优先用方式二**——它明确表达了"忽略大小写"的意图，且不产生临时对象。

> [!note] Go 里字符串与字节的一个坑
> Go 的 `s[i]` 返回的是 `byte`（一个字节），而不是 `rune`（一个字符）。**对 ASCII 文本，二者一致；但对中文、emoji 等多字节字符，`s[i]` 只是"半个字符"。** 所以"按字符处理"的题（如回文、反转），若输入可能含多字节字符，**必须先转成 `[]rune`**。这是 Go 字符串题最容易踩的坑之一。

## 第 4 章 回文变体题一览

### 4.1 Valid Palindrome II（LeetCode 680）

**题目**：给定一个非空字符串，判断能否在**最多删除一个字符**的情况下使其成为回文。

**思路**：双指针夹逼，**遇到不匹配时，尝试"跳过左字符"或"跳过右字符"两种可能**——只要其中一种能构成回文，就返回 `true`。

```go
func validPalindrome(s string) bool {
    left, right := 0, len(s)-1
    for left < right {
        if s[left] != s[right] {
            // 尝试删左 或 删右
            return isPalindromeRange(s, left+1, right) || isPalindromeRange(s, left, right-1)
        }
        left++
        right--
    }
    return true
}

func isPalindromeRange(s string, left, right int) bool {
    for left < right {
        if s[left] != s[right] {
            return false
        }
        left++
        right--
    }
    return true
}
```

**这道题的洞察是"不匹配时，答案只可能是两种之一"**——因为删除一个字符后要么从左边补、要么从右边补。**它把"枚举所有删除方案"（$O(n^2)$）降成了"只试两种"（$O(n)$）。**

### 4.2 回文数（LeetCode 9）

**题目**：不将整数转为字符串，判断它是否是回文。

**思路**：把数字的**后半段反转**，与前半段比较：

```go
func isPalindromeNum(x int) bool {
    if x < 0 || (x%10 == 0 && x != 0) {
        return false // 负数不是；末位为 0 的非零数也不是（首位不可能为 0）
    }
    reversed := 0
    for x > reversed {
        reversed = reversed*10 + x%10
        x /= 10
    }
    return x == reversed || x == reversed/10 // 偶数位：相等；奇数位：中间位在 reversed 里
}
```

**"只反转一半"是本题的精髓**——它避免了"反转整个数"可能带来的溢出。**这与"双指针只走一半"是同一种思路：只处理必要的一半。**

### 4.3 更多变体

| 题目 | 变体 | 关键点 |
|------|------|--------|
| LC 125 Valid Palindrome | 过滤非字母数字 + 忽略大小写 | 跳字符的边界 |
| LC 680 Valid Palindrome II | 最多删一个字符 | 只试两种删除 |
| LC 9 Palindrome Number | 数字回文（不转字符串） | 只反转一半 |
| LC 234 Palindrome Linked List | 链表回文 | 快慢指针找中点 + 反转后半 |
| LC 5 Longest Palindromic Substring | 最长回文子串 | 中心扩展（第 04 篇） |

**这张表说明：回文家族的共同动作是"从两端向中间比较"，差别只在"数据结构"（字符串/数字/链表）与"约束"（是否允许删、是否要最长）。**

## 第 5 章 双指针字符串范式总结

### 5.1 通用框架

Valid Palindrome 是字符串双指针的最简单例子，其框架在字符串题里极为通用：

```go
left, right := 0, len(s)-1
for left < right {
    // （可选）跳过不需要的字符
    for left < right && skip(s[left]) { left++ }
    for left < right && skip(s[right]) { right-- }

    // 处理当前 left 与 right
    if !match(s[left], s[right]) { return false }

    left++
    right--
}
```

**这个框架几乎能直接套用到所有"对撞双指针"的字符串问题**——回文、反转、比较。**理解它，比记住具体代码更有价值。**

### 5.2 对撞双指针的适用条件

**对撞双指针能成立，依赖"从两端向中间收缩"这一单调性**——它要求"问题的答案能被两端的关系逐步确定"。**对回文，这个关系就是"左右字符是否相等"**；对"两数之和（有序数组）"，是"两端和与目标的大小关系"。

**一旦这个单调性不成立（如数组无序），对撞双指针就失效**——这与线性表专栏第 02 篇"对撞双指针需要有序性"是同一条件。

> [!info] 一个反复出现的判断
> "对撞双指针需要单调性"——这条判断，在线性表专栏（两数之和）、栈与队列专栏（接雨水）与本篇（回文）里反复出现。**它说明：一个技巧的"适用条件"，往往比技巧本身更值得记住。** 记住"什么时候能用"，比记住"怎么写"更有价值——**因为写法是可推导的，而适用条件是判断的前提。**

### 5.3 落点

**回文专题的落点，是"对撞双指针"这一基础范式**，以及"细节处理决定成败"这一工程意识——125 题不难，但"跳字符的边界""空串的处理""大小写统一"这些细节，恰恰是面试里区分"会写"与"写对"的地方。**字符串题的一大特点就是"算法不难、细节很多"**，本篇是这一特点的第一次集中体现。

## 第 6 章 延伸：双指针在字符串上的更多应用

回文检测只是"对撞双指针"在字符串上的第一个例子。本章再给三道题，展示这一范式的更多面孔。

### 6.1 反转字符串（LeetCode 344）

**题目**：编写一个函数，其作用是将输入的字符串反转过来。**要求原地修改输入数组**，不要给另外的数组分配额外空间。

**这是对撞双指针最"纯粹"的形式**——两个指针从两端向中间交换：

```go
func reverseString(s []byte) {
    left, right := 0, len(s)-1
    for left < right {
        s[left], s[right] = s[right], s[left]
        left++
        right--
    }
}
```

**注意这里是"交换"而非"比较"**——回文检测是"比到不等就返回"，反转是"一路交换到底"。**同一套指针运动，用途不同。**

### 6.2 反转字符串中的单词（LeetCode 151）

**题目**：给你一个字符串 `s`，逐个翻转字符串中的所有单词（单词之间可能有多个空格，结果中单词间只保留一个空格）。

**经典解法是"两次反转"**：先把整个字符串反转，再逐个单词反转（因为"整体反转 + 单词反转"等于"单词顺序不变、但每个单词被反转"——两次反转抵消，得到"单词顺序反转"）。

```go
func reverseWords(s string) string {
    words := strings.Fields(s) // 按任意空白切分，自动忽略空串
    for l, r := 0, len(words)-1; l < r; l, r = l+1, r-1 {
        words[l], words[r] = words[r], words[l]
    }
    return strings.Join(words, " ")
}
```

**注意这里用了 `strings.Fields` 而非 `strings.Split(s, " ")`**——因为前者会"按任意空白切分并忽略空串"，恰好处理了"多个空格"这一约束。**这与第 08 篇 Length of Last Word 的"连续分隔符"是同一个坑。**

**这道题的"两次反转"技巧值得记住**——它把"翻转单词顺序"这个看似复杂的操作，拆成了两个"翻转整个序列"的简单操作。**"用两次反转实现一次重排"，是字符串题里一个漂亮的小技巧。**

### 6.3 回文链表（LeetCode 234）

**题目**：判断一个单链表是否是回文。

**思路是"三步组合"**：快慢指针找中点 → 反转后半段 → 逐个比较。**它把本专栏（对撞比较）与线性表专栏（快慢指针、反转）的技巧合了起来：**

```go
func isPalindromeList(head *ListNode) bool {
    // 第一步：快慢指针找中点
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    // 第二步：反转后半段
    var prev *ListNode
    for slow != nil {
        next := slow.Next
        slow.Next = prev
        prev, slow = slow, next
    }
    // 第三步：逐个比较
    left, right := head, prev
    for right != nil {
        if left.Val != right.Val {
            return false
        }
        left, right = left.Next, right.Next
    }
    return true
}
```

**这道题说明：回文检测的"对撞比较"内核，可以迁移到链表上**——只是"从两端向中间"需要先"找到中点"和"反转后半段"。**理解了回文的本质是"两端比较"，你就能把它迁移到任何"可双向访问"的结构上。**

### 6.4 三道延伸题的共性

344、151、234 三道题，都在用"对撞双指针"或"反转"这一族技巧：

| 题目 | 核心动作 | 与回文检测的关系 |
|------|---------|-----------------|
| LC 344 反转字符串 | 两端交换 | 同一套指针运动，用途不同 |
| LC 151 反转单词 | 两次反转 | 反转技巧的组合 |
| LC 234 回文链表 | 中点 + 反转 + 比较 | 回文检测迁移到链表 |

**它们共同说明："对撞双指针"是字符串/序列题的通用基础**——回文、反转、比较，都建立在它之上。**把这个基础打牢，你面对任何"两端处理"的题，都能快速找到切入点。**

## 第 8 章 双指针字符串题的性能与工程考量

### 8.1 字符访问：Go 的 byte vs rune

**Go 的 `s[i]` 返回 `byte`（一个字节），而非 `rune`（一个字符）。** 对纯 ASCII 文本二者一致；但对中文、emoji 等多字节字符，`s[i]` 只是"半个字符"。**凡是"按字符处理"的字符串题（回文、反转、计数），若输入可能含多字节字符，必须先转 `[]rune`。**

```go
r := []rune(s) // 按字符切分
// 之后用 r[i] 访问"第 i 个字符"
```

**这是一个"语言细节影响正确性"的典型**——很多人写回文检测时用 `s[i]`，对 ASCII 正确，一遇中文就错。**面试中若输入含非 ASCII，要主动指出这一点。**

### 8.2 双指针 vs 反转：常数因子与提前返回

第 1 章说过"反转比较"需要 $O(n)$ 空间。但即便不计空间，**双指针还有一个优势——提前返回**：若前两个字符就不对称，双指针一步就能判定，而反转要先反转整串。**对"判定类"问题，"能否提前返回"往往比"渐进复杂度"更能决定实际性能。**

### 8.3 字符串不可变的代价

**在很多语言里，字符串是不可变的**（Java、Go、Python 都是）。这意味着"每次拼接/切片都可能产生新对象"。**本专栏反复出现的"用 `[]byte` 代替字符串拼接"（第 03、05 篇），正是为了规避这一代价。**

**Go 的一个特别之处**：`s[i:j]` 切片**不复制底层数据**，只是创建了一个"指向同一底层数组的新切片头"。**所以 Go 里"切片"很便宜，"拼接"很贵**——这与 Java（`substring` 会复制）不同。

### 8.4 一个可复用的判断

**处理字符串时，先问三个问题**：

1. **输入是否可能含多字节字符？**（是则用 `[]rune`）
2. **是否需要频繁拼接/切片？**（是则用 `[]byte` 或 `strings.Builder`）
3. **能否提前返回？**（能则用"边处理边判定"）

**这三问，能把"字符串处理"的性能与正确性问题，覆盖大半。**

> [!info] 语言细节也是"算法素养"的一部分
> 很多人以为算法题"与语言无关"，其实**语言细节（字符串是否可变、切片是否复制、`byte` 还是 `rune`）会直接影响正确性与性能**。**面试中能主动指出这些细节，说明你不仅"会写算法"，还"懂实现"。** 本专栏每篇都留出一节讲 Go 的字符串细节，正是为了培养这种意识。

## 第 10 章 延伸：回文判定的哈希方法与回文树

### 10.1 用字符串哈希判断回文

**除了双指针，回文还能用"字符串哈希"判断**——对字符串求"正序哈希"与"逆序哈希"，若某段的正序哈希等于逆序哈希，则它是回文。

```go
// 概念示意：用前缀哈希比较 s[l..r] 与其逆序
// hash(s[l..r]) == hash(reverse(s[l..r]))
```

**哈希方法的优势是"$O(1)$ 判断任意子串是否回文"**（预处理 $O(n)$ 后）——**这在"需要反复判断回文"的题里（如第 04 篇的回文分割）非常有用**。代价是"哈希可能冲突"（需要双哈希或验证）。

**它与双指针的取舍**：双指针是"$O(k)$ 判断一段"（$k$ 为段长），哈希是"$O(1)$ 判断一段、但要 $O(n)$ 预处理"。**"判断次数多"时用哈希，"只判断几次"时用双指针。**

### 10.2 回文树（Eertree）

**回文树（Palindromic Tree，又称 Eertree）**是一种专门处理"回文中缀"的数据结构——**它能在 $O(n)$ 时间内，找出一个字符串的所有"本质不同"的回文子串，并统计它们的出现次数。**

**它的结构是"两棵 Trie"**：一棵存偶数长度的回文、一棵存奇数长度的回文，每个节点代表一个"本质不同"的回文。**失配指针（类似 KMP）负责"回文之间的跳转"。**

**回文树是"回文问题"的终极工具**——它把"所有回文子串"这一看似 $O(n^2)$ 的信息，压缩到了 $O(n)$ 的树结构中。**但它的实现复杂，面试中极少要求手写**——了解它的存在与能力即可。

### 10.3 三种回文方法的对照

| 方法 | 预处理 | 单次判断 | 适用 |
|------|--------|---------|------|
| 双指针 | 无 | $O(k)$ | 少量判断 |
| 字符串哈希 | $O(n)$ | $O(1)$（期望） | 大量判断 |
| 回文树 | $O(n)$ | 结构本身即答案 | 所有回文中缀 |

**这张表说明："回文判定"本身是一个可以优化的操作**——从"$O(k)$ 双指针"到"$O(1)$ 哈希"，再到"$O(n)$ 建树"，视需求而定。**这与"字符串匹配"有 KMP/哈希/AC 自动机多种方案是同一种现象：同一个问题，可以有不同层次的工具。**

> [!info] 从"一个技巧"到"一族工具"
> 回文判定看似只是"双指针"，实际上有一族工具——双指针、哈希、回文树，各适合不同场景。**这提示我们：任何一个"基础操作"（判断回文、查找子串、求区间和），都可能有"从简单到高级"的一族工具。** 学算法时，**知道"有哪几种、各适合什么"，比"只会最基础的那种"更有价值**——因为面试与工程都需要"按需选型"。

## 第 12 章 双指针范式的完整总结

### 12.1 双指针在字符串上的三种用法

**本专栏涉及的双指针，可以归为三种**：

- **对撞双指针**：两端向中间收缩——回文（125）、反转（344）；
- **快慢双指针**：同向、速度不同——（主要用于链表，如 234 找中点）；
- **滑动窗口**：同向、左右边界——子串问题（438、3、76）。

**"对撞"与"窗口"是字符串题的两大主力**——**前者处理"两端关系"，后者处理"连续子串"。**

### 12.2 "对撞"的适用条件

**对撞双指针能成立，依赖"从两端向中间收缩"的单调性**——**它要求"答案能被两端的关系逐步确定"。**

- 回文：两端字符是否相等；
- 两数之和（有序）：两端和与目标的大小关系；
- 反转：两端交换（无判定，纯操作）。

**一旦"两端关系"无法逐步确定答案（如无序数组的两数之和），对撞就失效**——**这与线性表专栏"对撞需要有序性"是同一条件。**

### 12.3 一个可复用的框架

**对撞双指针的通用框架**：

```go
left, right := 0, len(s)-1
for left < right {
    for left < right && skip(s[left]) { left++ }   // 可选：跳字符
    for left < right && skip(s[right]) { right-- } // 可选：跳字符
    if !match(s[left], s[right]) { return false }  // 处理当前两端
    left++
    right--
}
```

**这个框架覆盖了回文、反转、比较等所有"对撞"题**——**"跳字符"与"匹配规则"是两个可替换的插件。**

> [!info] 一句话带走
> 如果只能带走一句话，那就是：**"对撞双指针的本质，是'用两端的关系逐步确定答案'——它需要单调性。"** 回文有（两端相等性）、两数之和有（有序性和的大小）、反转没有（纯操作）。**判断"能否对撞"，就是判断"两端关系能否逐步确定答案"。**

## 第 13 章 常见误区与自测方法

### 6.1 四个高频误区

**误区一：跳字符的内层循环不带 `left < right`。** 全非法字符时会越界。

**误区二：忘记大小写统一。** `'A'` 与 `'a'` 会被判为不同。

**误区三：把"空串"判为非回文。** 空串是回文。

**误区四：Go 里按字节处理多字节字符。** 若输入含中文/emoji，`s[i]` 只是半个字符，必须先转 `[]rune`。

### 6.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `""` | 空串 |
| `" "` | 全非法字符（跳字符越界） |
| `"a"` | 单字符 |
| `"A man, a plan, a canal: Panama"` | 常规 |
| `"0P"` | 数字与字母混合 |

**其中 `" "` 最值得测**——它专治"跳字符越界"这一陷阱。**凡是"跳过非法字符"的双指针题，都要用"全非法字符"的输入验证。**

## 第 14 章 一句话带走

**如果只能从本篇带走一句话，那就是：**"字符串题的一大特点，是'算法不难、细节很多'——而细节的核心，是边界。"

**125 题就是第一次集中体现**：跳字符的 `left < right` 保护、空串算回文、大小写统一、Go 的 byte vs rune——**这些都不是"算法难点"，但漏掉任何一个都会错。**

**而"对撞双指针"这一范式，依赖一条前提："两端的关系能逐步确定答案"**——回文有（两端相等性）、两数之和有（有序性）、反转没有（纯操作）。**判断"能否对撞"，就是判断这条前提是否成立。**

> [!note] 一个可复用的判断
> 遇到字符串题，**先问两句**：算法模式是什么（双指针/哈希/DP/状态机）？边界有哪些（空、单、全非法、多字节）？**这两问，能定下字符串题的方向与自查点。**

## 第 15 章 复杂度速查

| 题目 | 时间 | 空间 | 关键点 |
|------|------|------|--------|
| LC 125 Valid Palindrome | $O(n)$ | $O(1)$（原地）/ $O(n)$（预处理） | 跳字符边界 |
| LC 680 Valid Palindrome II | $O(n)$ | $O(1)$ | 只试两种删除 |
| LC 9 Palindrome Number | $O(\log n)$ | $O(1)$ | 只反转一半 |
| LC 234 Palindrome Linked List | $O(n)$ | $O(1)$ | 中点 + 反转 + 比较 |

**"$O(1)$ 空间"是回文题的常见追问**——125 用原地双指针、9 用反转一半、234 用快慢指针 + 反转。**它们都体现了"只处理必要的一半/部分"这一思路。**

> [!note] 一个总体判断
> 遇到"回文"题，**先问"是串/数/链表"**——串用双指针、数用反转一半、链表用中点 + 反转。**载体不同，但内核都是"两端比较"。**

## 小结

本篇以回文检测为切入点，讲清了字符串双指针的核心范式——**从两端向中间夹逼，跳过无关字符，忽略大小写比较**。125 题本身不难，但"跳字符的边界""空串处理""大小写统一"这些细节，恰恰是面试的考察点。变体题（680 允许删一个、9 数字回文）进一步说明：**回文家族的共同动作是"两端比较"，差别只在"数据结构"与"约束"。**

贯穿全篇的核心认知有两条。其一，**"对撞双指针需要单调性"**——这是它成立的适用条件，也是它失效的边界。其二，**字符串题的特点往往是"算法不难、细节很多"**——125 题就是第一次集中体现。**把这两条握住，你面对任何字符串双指针题，都会先判断"能否对撞"、再检查"细节是否周全"。**

下一篇 [[02 字符串搜索：Implement strStr 与 KMP 算法深度解析]] 会深入字符串搜索的经典算法——KMP。Implement strStr（LeetCode 28）的暴力解法是 $O(mn)$，而 KMP 通过预处理模式串的"最长相等前后缀"，把复杂度降到 $O(m+n)$。**理解 `next` 数组的构建原理，是搞懂 KMP 的关键，也是面试中区分"背了答案"与"真正理解"的分水岭。**

**再补充一段落点。** 回文检测是"对撞双指针"在字符串上的第一个例子，也是"边界意识"的第一次集中训练。**它的价值不在"会解这道题"，而在"养成'先列边界、再写代码'的习惯"**——空串、全非法字符、大小写、多字节字符，这些细节在后面的每一篇里都会重现。**把这篇文章的"边界清单"内化，你在整个字符串专栏里都会受益。**

**再看一个更深的落点。** 回文检测用到的"对撞双指针"，是"序列算法"的基础工具之一——**它不只用于字符串，也用于数组（两数之和）、链表（回文链表）。** 而它的适用前提（两端关系能逐步确定答案），则是一条需要判断的条件。**把"工具"与"适用条件"一起记住，你才能在遇到新题时判断"这题能不能用对撞"。** 这是本专栏反复强调的"适用条件比写法更重要"。
