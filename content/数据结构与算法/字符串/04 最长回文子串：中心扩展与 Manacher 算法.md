# 最长回文子串：中心扩展与 Manacher 算法

**摘要：**

LeetCode 5（Longest Palindromic Substring）是字符串算法里的经典高频题。本篇系统梳理四种解法的演进：暴力 $O(n^3)$ → 动态规划 $O(n^2)$ → 中心扩展 $O(n^2)$、空间 $O(1)$ → Manacher $O(n)$。**中心扩展是面试的标准答案**——它抓住了一条关键观察："每个回文都有一个中心"（奇数是字符、偶数是缝隙），于是"枚举所有中心向外扩展"就能找到最长回文。而 **Manacher 算法**通过"镜像利用"把时间降到线性，是字符串领域最优雅的优化案例之一。本文用 Go 语言实现四种解法，并逐层追问：为什么"枚举中心"比"枚举子串"好、Manacher 的"镜像"到底在利用什么、以及"右边界只增不减"为什么能保证线性。掌握本篇，你就理解了回文结构的核心性质。

---

## 第 1 章 题目分析与核心观察

### 1.1 题目

**LeetCode 5 - Longest Palindromic Substring**（中等）

给你一个字符串 `s`，找到其中最长的回文子串。

```text
输入: s = "babad"  →  "bab"（"aba" 也是答案）
输入: s = "cbbd"   →  "bb"
输入: s = "a"      →  "a"
```

### 1.2 核心观察：每个回文都有中心

**找最长回文子串的关键观察是：每个回文都有一个中心**——奇数长度回文的中心是一个字符，偶数长度回文的中心是"两个字符之间的缝隙"。

```text
"racecar"：中心是 'e'（奇数长度）
"abba"：中心在两个 'b' 之间（偶数长度）
```

**一个长度为 $n$ 的字符串，共有 $2n-1$ 个可能的中心**（$n$ 个字符 + $n-1$ 个缝隙）。**从每个中心向外扩展、检查最大回文半径，就能找到以该中心为中心的最长回文。**

> [!info] "枚举中心"为什么优于"枚举子串"
> 暴力法枚举所有子串（$O(n^2)$ 个），每个都要判回文（$O(n)$），总 $O(n^3)$。**而"枚举中心"只有 $2n-1$ 个，每个向外扩展最多 $O(n)$，总 $O(n^2)$。** 更关键的是——**"中心"这一结构，把"回文的对称性"直接暴露了出来**：以某点为中心，只需"向两边比"，而无需"判断整段是否回文"。**这正是"找对枚举对象"带来的降维。**

## 第 2 章 方法一：暴力 $O(n^3)$

枚举所有子串，逐一判断是否为回文：

```go
func longestPalindromeBrute(s string) string {
    n := len(s)
    best := s[:1]
    for i := 0; i < n; i++ {
        for j := i + 1; j < n; j++ {
            if j-i+1 > len(best) && isPal(s, i, j) {
                best = s[i : j+1]
            }
        }
    }
    return best
}

func isPal(s string, l, r int) bool {
    for l < r {
        if s[l] != s[r] {
            return false
        }
        l++
        r--
    }
    return true
}
```

$O(n^3)$ 时间——$n=1000$ 时约 $10^9$ 次操作，**面试中会超时**，仅作推导起点。

## 第 3 章 方法二：动态规划 $O(n^2)$

**状态**：`dp[i][j]` = 子串 `s[i..j]` 是否是回文。

**转移**：若 `s[i] == s[j]` 且 `dp[i+1][j-1]` 为真，则 `dp[i][j]` 为真。

**边界**：单字符 `dp[i][i] = true`；双字符 `dp[i][i+1] = (s[i] == s[i+1])`。

**遍历顺序**：由于 `dp[i][j]` 依赖 `dp[i+1][j-1]`（内层子串），必须**按子串长度从小到大**遍历。

```go
func longestPalindromeDP(s string) string {
    n := len(s)
    if n == 0 {
        return ""
    }
    dp := make([][]bool, n)
    for i := range dp {
        dp[i] = make([]bool, n)
        dp[i][i] = true // 单字符
    }
    start, maxLen := 0, 1
    // 长度 2
    for i := 0; i < n-1; i++ {
        if s[i] == s[i+1] {
            dp[i][i+1] = true
            start, maxLen = i, 2
        }
    }
    // 长度 3..n
    for length := 3; length <= n; length++ {
        for i := 0; i <= n-length; i++ {
            j := i + length - 1
            if s[i] == s[j] && dp[i+1][j-1] {
                dp[i][j] = true
                if length > maxLen {
                    start, maxLen = i, length
                }
            }
        }
    }
    return s[start : start+maxLen]
}
```

**复杂度**：时间 $O(n^2)$、空间 $O(n^2)$。**思路清晰，但空间大**——这是它的短板。

> [!note] "按长度遍历"为什么必须
> 区间 DP 的一条通则：**当 `dp[i][j]` 依赖更小的区间（`dp[i+1][j-1]`）时，必须"按区间长度从小到大"遍历**，否则依赖的区间还没算出来。**这与二叉树专栏"后序"（先算子树再算自己）是同一道理——依赖必须先被满足。** 区间 DP 专栏会反复用到这条。

## 第 4 章 方法三：中心扩展 $O(n^2)$，空间 $O(1)$

### 4.1 思路

对 $2n-1$ 个中心，分别向外扩展，记录最长的回文：

```go
func longestPalindrome(s string) string {
    n := len(s)
    if n == 0 {
        return ""
    }
    start, maxLen := 0, 1
    for center := 0; center < 2*n-1; center++ {
        // 偶数 center：单字符中心；奇数 center：缝隙中心
        left := center / 2
        right := left + center%2
        for left >= 0 && right < n && s[left] == s[right] {
            left--
            right++
        }
        // 扩展结束后，[left+1, right-1] 是当前最长回文
        length := right - left - 1
        if length > maxLen {
            maxLen = length
            start = left + 1
        }
    }
    return s[start : start+maxLen]
}
```

**注意 `left := center/2; right := left + center%2` 这一映射**——它把 `2n-1` 个"中心编号"映射到具体的 `(left, right)`：
- `center` 为偶数 → 单字符中心，`left == right`；
- `center` 为奇数 → 缝隙中心，`right == left + 1`。

**复杂度**：时间 $O(n^2)$、空间 $O(1)$。**这是面试的标准答案，必须能流畅写出。**

### 4.2 手动验证 `s = "cbbd"`

```text
center=0（'c'）: left=0,right=0 → 扩展一次后 'b'!='c' 停 → len=1
center=1（缝隙 c|b）: left=0,right=1 → 'c'!='b' 停 → len=1
center=2（'b'）: left=1,right=1 → 扩展后 left=0,right=2 → 'c'!='b' 停 → len=1
center=3（缝隙 b|b）: left=1,right=2 → 'b'=='b' → left=0,right=3 → 'c'!='d' 停
                     len = 3-0-1 = 2 → maxLen=2, start=1
center=4（'b'）: left=2,right=2 → 扩展后 left=1,right=3 → 'b'!='d' 停 → len=1
center=5（缝隙 b|d）: left=2,right=3 → 'b'!='d' 停 → len=1
center=6（'d'）: left=3,right=3 → 越界停 → len=1

结果：start=1, maxLen=2 → s[1:3] = "bb" ✓
```

### 4.3 最容易写错的地方

**中心扩展的代码细节最容易出错**：奇偶中心的边界计算、`right-left-1` 与 `left+1` 的偏移。**建议在纸上用 `"aba"`（奇）和 `"abba"`（偶）两个最小用例各验证一遍**，确保代码正确。

**特别是 `length = right - left - 1`**：扩展结束后，`left` 和 `right` 停在"第一个不匹配的位置"，所以有效回文是 `[left+1, right-1]`，长度为 `right-left-1`。**这个 `-1` 的偏移，是本题最容易记错的一处。**

## 第 5 章 方法四：Manacher 算法 $O(n)$

### 5.1 为什么还能更快

中心扩展对每个中心**独立扩展**，没有复用之前的结果。**Manacher 的核心思想是：利用已找到的最长回文的"镜像对称性"，直接初始化新中心的回文半径，跳过不必要的扩展。**

### 5.2 预处理：统一奇偶

为了统一处理奇偶长度的回文，Manacher 在每个字符之间（及首尾）插入特殊字符 `#`：

```text
原串: "cbbd"
新串: "#c#b#b#d#"（长度 2n+1 = 9）
```

**插入 `#` 后，所有回文都变成奇数长度**——于是只需处理一种情形。**这是"把两种情形统一成一种"的经典手法**（与第 03 篇"DFA 统一处理各种状态"、二叉树专栏"哑节点统一头节点边界"是同一种思想）。

### 5.3 核心：利用右边界与镜像

维护两个变量：`center`（当前向右延伸最远的回文中心）、`right`（其右边界）。

对新位置 `i`（`i < right`），利用**镜像位置** `mirror = 2*center - i` 的半径来初始化 `p[i]`：

- 若 `mirror` 的回文完全在 `[center-p[center], right]` 内，则 `p[i] = p[mirror]`；
- 若 `mirror` 的回文超出左边界，则 `p[i] = right - i`（被边界限制）；
- 之后再尝试继续扩展。

```go
func longestPalindromeManacher(s string) string {
    // 预处理：插入 #，并加首尾哨兵防越界
    var t []byte
    t = append(t, '^')
    for i := 0; i < len(s); i++ {
        t = append(t, '#', s[i])
    }
    t = append(t, '#', '$')
    n := len(t)
    p := make([]int, n) // p[i] = 以 i 为中心的回文半径（不含中心）
    center, right := 0, 0
    maxLen, maxCenter := 0, 0

    for i := 1; i < n-1; i++ {
        if i < right {
            mirror := 2*center - i
            p[i] = min(right-i, p[mirror]) // 镜像初始化
        }
        // 尝试扩展
        for t[i+p[i]+1] == t[i-p[i]-1] {
            p[i]++
        }
        // 更新最右边界
        if i+p[i] > right {
            center = i
            right = i + p[i]
        }
        if p[i] > maxLen {
            maxLen, maxCenter = p[i], i
        }
    }
    // 还原到原串坐标
    start := (maxCenter - maxLen) / 2
    return s[start : start+maxLen]
}

func min(a, b int) int { if a < b { return a }; return b }
```

**哨兵 `^` 与 `$` 的作用**：它们不与任何字符相等，**保证扩展时不会越界**——省去了边界检查。**这与第 05 篇柱状图最大矩形的"首尾哨兵"、二叉树专栏 117 题的"哑节点"是同一种"用哨兵抹平边界"的手法。**

**复杂度**：时间 $O(n)$、空间 $O(n)$。

### 5.4 为什么"右边界只增不减"保证了线性

**用一个比喻**：想象你从左到右扫描，记录自己能"看到"的最远位置 `right`。

- 到达位置 `i`（在视野内 `i < right`）时，左边有一面"镜子"（对称中心 `center`）。通过镜像，你已知对面 `mirror` 有一个大小为 `p[mirror]` 的回文。
- **若镜像回文完全在视野内**，则 `i` 的回文至少是 `p[mirror]`（镜像对称保证）；
- **若镜像回文超出左边界**，则只能确认到 `right - i`，需继续扩展验证。

**关键性质是"`right` 从不退缩"**——每次扩展成功，`right` 要么不动、要么右移。**总右移量 $\le n$，因此所有"扩展比较"的总次数 $\le 2n = O(n)$。** 这是摊还分析（与 KMP 的 `j`、单调栈的入栈出栈同源）。

> [!info] Manacher 与 KMP 的共性
> KMP 用"已匹配的前缀信息"避免回退，Manacher 用"已找到的回文信息"避免重复扩展——**两者都在"复用已经算出的结果"**。这正是字符串算法里最核心的优化思想：**不要重复计算已经知道的东西。** 理解了这一点，你看 KMP 与 Manacher 就不再是两个孤立的技巧，而是同一思想的两个实例。

## 第 6 章 四种方法对比与面试建议

| 方法 | 时间 | 空间 | 推荐度 |
|------|------|------|--------|
| 暴力 | $O(n^3)$ | $O(1)$ | 推导起点，不直接给 |
| 动态规划 | $O(n^2)$ | $O(n^2)$ | 思路清晰，空间大 |
| 中心扩展 | $O(n^2)$ | $O(1)$ | **面试标准答案** |
| Manacher | $O(n)$ | $O(n)$ | 进阶加分 |

**面试策略**：

1. 先说"暴力是 $O(n^3)$，可优化"；
2. 简述 DP 思路（`dp[i][j]` 依赖 `dp[i+1][j-1]`），说明空间 $O(n^2)$；
3. **给出中心扩展（必须能手写正确）**，说明空间降到 $O(1)$；
4. 若面试官追问"有没有更优"，介绍 Manacher 的核心思想（镜像利用），不要求手写完整代码。

**这个"由浅入深"的表达顺序，是面试里的通用套路**——它展示了你的推导能力与优化意识，而非"直接背出最优解"。

## 第 7 章 延伸：回文结构的更多应用

### 7.1 回文子串计数（LeetCode 647）

**题目**：统计一个字符串中回文子串的数目（位置不同即算不同）。

**思路与"最长回文子串"完全同构**——**枚举所有中心、向外扩展，每扩展成功一次就计数加一：**

```go
func countSubstrings(s string) int {
    n := len(s)
    count := 0
    for center := 0; center < 2*n-1; center++ {
        left := center / 2
        right := left + center%2
        for left >= 0 && right < n && s[left] == s[right] {
            count++ // 每扩展一层，就多一个回文子串
            left--
            right++
        }
    }
    return count
}
```

**注意这里"计数"代替了"求最长"**——扩展循环里不再比较长度，而是每次成功就 `count++`。**同一套中心扩展，换个"结算动作"就换了道题。**

### 7.2 分割回文串（LeetCode 131 / 132）

**题目（131）**：把字符串分割成若干回文子串，返回所有可能的分割方案。
**题目（132）**：求把字符串分割成回文子串的**最少分割次数**。

**这两道题都建立在"快速判断任意子串是否回文"之上**——而"回文子串"的 DP（第 3 章）恰好提供了 `dp[i][j]`。于是：

- **131 用"回溯 + 回文判定"**：从位置 `i` 出发，枚举所有"是回文"的结束位置 `j`，递归处理 `j+1`；
- **132 用"DP + 回文预处理"**：`minCut[i]` = 前 `i` 个字符的最少分割数，若 `s[j..i-1]` 是回文则 `minCut[i] = min(minCut[i], minCut[j] + 1)`。

```go
// 132：最少分割次数
func minCut(s string) int {
    n := len(s)
    // 预处理：isPal[i][j] = s[i..j] 是否回文
    isPal := make([][]bool, n)
    for i := range isPal {
        isPal[i] = make([]bool, n)
    }
    for i := n - 1; i >= 0; i-- {
        for j := i; j < n; j++ {
            if s[i] == s[j] && (j-i < 2 || isPal[i+1][j-1]) {
                isPal[i][j] = true
            }
        }
    }
    minCut := make([]int, n+1)
    for i := 1; i <= n; i++ {
        minCut[i] = i - 1 // 最坏情况：每个字符切一刀
        for j := 0; j < i; j++ {
            if isPal[j][i-1] {
                if minCut[j]+1 < minCut[i] {
                    minCut[i] = minCut[j] + 1
                }
            }
        }
    }
    return minCut[n]
}
```

**这两道题说明：回文结构的"价值"，在于它能被"预处理"成一张表（`isPal[i][j]`），供上层问题反复查询。** 这与第 03 篇"用哈希表预存查找结果"、第 06 篇"用标识符预分组"是同一思路——**把"反复要用的信息"先算出来存好。**

### 7.3 回文对（LeetCode 336）

**题目**：给定一组互不相同的单词，找出所有不同的索引对 `(i, j)`，使得两单词拼接后是回文。

**思路用"哈希表 + 回文判定"**：对每个单词，枚举"在哪个位置切开"，判断"左半或右半是否是回文"，再去哈希表里找"能与之拼成回文的另一半"。**它的核心是"把'拼接成回文'转化为'某一半是回文 + 另一半的逆序存在'"。**

**这道题较难，但它的思路很有启发性**——**它把"两两配对"（$O(n^2)$）转化为"对每个单词查哈希表"（$O(nk^2)$）**，又一次体现了"用哈希表把配对问题降维"的通用思路。

### 7.4 三道延伸题的共性

647、131/132、336 三道题，都在用"回文的结构性质"：

| 题目 | 用到的性质 | 关键技巧 |
|------|-----------|---------|
| LC 647 回文子串计数 | 中心扩展 | 每扩展一层就计数 |
| LC 131/132 分割回文串 | 回文子串 DP 预处理 | 预处理 `isPal` 表 |
| LC 336 回文对 | 回文判定 + 哈希 | 配对转哈希查询 |

**它们共同说明：回文题的"上层应用"，几乎都依赖"能快速判断任意子串是否回文"这一能力。** 而这一能力，可以用"中心扩展"或"回文 DP"来提供。**理解了这一点，你面对任何"回文相关"的复杂问题，都会先问一句"我需要一张回文判定表吗"。**

> [!info] 从"一道题"到"一张表"
> 回文相关的问题，往往有一个共同的"基础设施"——**"任意子串是否回文"的判定表**。一旦有了它，最长回文、回文计数、分割回文、回文对都变得可解。**这提示我们：很多"一族题"背后，都有同一个"基础设施"；先搭好它，上层问题就都成了"查表"。** 这与本专栏反复出现的"预处理"思想一脉相承。

## 第 9 章 回文算法的性能与工程细节

### 9.1 中心扩展的常数因子

中心扩展是 $O(n^2)$，但它的**常数因子很小**——每个中心只做"向两边比"这一件事。**在实际数据（如自然语言）上，回文很少很长，所以"扩展很快停止"，实测性能往往远好于最坏情况。**

**这也是为什么中心扩展是"面试标准答案"**——它 $O(n^2)$ 的最坏复杂度虽不如 Manacher，但代码简单、常数小、实际够快。**"理论最优"与"工程最优"的差别，又一次显现**（回顾第 02 篇 KMP vs 朴素）。

### 9.2 Manacher 的适用边界

**Manacher 虽好，但有几个边界要注意**：

- **它需要 $O(n)$ 的额外空间**（`p` 数组 + 变换后的串）——对"空间敏感"的场景不划算；
- **它依赖"插入 `#`"的预处理**——这会让串长度翻倍，常数上不占优；
- **它的正确性依赖"镜像"这一精巧的论证**——实现出错率高。

**所以工程上，Manacher 并不常用**——除非"确实需要线性时间且能接受 $O(n)$ 空间"。**这与"KMP 虽优但工程常用朴素算法"是同一现象。**

### 9.3 一个关于"回文结构"的深入观察

**回文的"中心扩展"之所以有效，是因为回文具有"局部决定整体"的性质**——若以某中心能扩展出长度 $L$ 的回文，则其内部所有更短的回文也都以该中心为中心。**这种"嵌套结构"，是回文能被高效处理的根本原因。**

**更一般地，"具有嵌套/自相似结构的对象，往往能被高效算法处理"**——回文（Manacher）、字符串匹配（KMP）、树（Morris）都是如此。**它们共享"利用结构避免重复计算"这一思想。**

> [!info] 结构决定算法
> "什么结构，用什么算法"——**回文的嵌套结构催生了 Manacher，字符串的前后缀自相似催生了 KMP，树的递归结构催生了树形 DP。** 这提示我们：**学习算法时，要关注"它利用了对象的什么结构性质"**——因为结构性质才是算法成立的根本，而代码只是它的实现。**理解了"结构与算法的对应关系"，你就能举一反三。**

## 第 11 章 回文问题的复杂度阶梯与算法选择

### 11.1 复杂度阶梯

**"最长回文子串"的四种解法，构成一条清晰的复杂度阶梯**：

$$O(n^3) \xrightarrow{\text{DP}} O(n^2) \xrightarrow{\text{中心扩展}} O(n^2)\text{（空间 }O(1)\text{）} \xrightarrow{\text{Manacher}} O(n)$$

**这条阶梯的每一步，都对应一次"视角的转变"**：暴力→DP 是"记录子问题"；DP→中心扩展是"换枚举对象"；中心扩展→Manacher 是"复用已算结果"。**理解了这三步，你就理解了"算法优化"的一般路径。**

### 11.2 各解法的适用场景

| 解法 | 何时选它 |
|------|---------|
| 暴力 | 只作推导起点，不实用 |
| DP | 需要"任意子串是否回文"的表时（如回文分割） |
| 中心扩展 | **面试首选**：$O(n^2)$、$O(1)$ 空间、代码简单 |
| Manacher | 需要线性时间、且能接受 $O(n)$ 空间时 |

**"面试首选中心扩展"这一判断很重要**——**它体现了"面试选型的现实考量"：代码简单、易讲清、空间优，往往比"复杂度最低"更重要。** 这与第 02 篇"KMP vs 朴素"是同一逻辑。

### 11.3 面试表达的三层

**讲最长回文子串时，建议分三层**：

1. **第一层**：暴力 $O(n^3)$，指出可优化；
2. **第二层**：中心扩展（**必须手写**），$O(n^2)$、$O(1)$ 空间；
3. **第三层**：Manacher（**能讲原理即可**），$O(n)$。

**"能讲原理即可"是 Manacher 的定位**——**面试官通常不要求手写 Manacher（它太精巧、易错），但希望你知道"有更优的算法、它的核心思想是什么"。** 这提示我们：**不同算法在面试中的"要求深度"不同**——核心算法要能手写，进阶算法能讲原理即可。

> [!info] "必须能手写"vs"能讲原理即可"
> 面试里，算法的要求分两档：**核心算法（如中心扩展、KMP、DP）必须能手写；进阶算法（如 Manacher、AC 自动机）能讲原理即可。** 分清这两档，能让你的备考有的放矢——**把时间花在"必须手写"的那些上，而不是纠结于"手写 Manacher"。** 这是一种"按回报分配精力"的策略。

## 第 13 章 回文问题的完整知识地图

### 13.1 回文家族的全景

**把本专栏与延伸涉及的回文题汇总起来，可以看到一张完整的"回文地图"**：

| 问题 | 题目 | 核心方法 |
|------|------|---------|
| 是否回文 | LC 125、9、234 | 双指针 / 反转一半 |
| 最长回文子串 | LC 5 | 中心扩展 / Manacher |
| 回文子串计数 | LC 647 | 中心扩展计数 |
| 回文分割 | LC 131、132 | 回文 DP + 回溯/DP |
| 回文对 | LC 336 | 哈希 + 回文判定 |
| 所有回文中缀 | 回文树 | Eertree |

**这张地图的"根"，是"如何判断一段是否回文"**——**所有上层问题，都建立在它之上。** 而"判断回文"有三种手段：双指针（$O(k)$）、哈希（$O(1)$ 期望）、回文 DP（$O(n^2)$ 预处理、$O(1)$ 查询）。

### 13.2 解题的"三步走"

**遇到任何回文相关的问题，按这三步走**：

1. **确定"回文判定"的需求**：是"判一次"还是"反复判"？——决定用双指针还是预处理；
2. **确定"上层问题"的类型**：是"最长""计数""分割"还是"配对"？——决定用哪种聚合方式；
3. **组合**：用"回文判定"作为基础设施，支撑"上层聚合"。

**这三步的关键，是"把'回文判定'与'上层聚合'分开"**——**判定是"基础设施"，聚合是"应用逻辑"。** 分开了，问题就清晰了。

### 13.3 一个跨领域的观察

**"回文"不只出现在字符串题里，它是"对称结构"的一般概念**：

- **DNA 序列**：回文序列在基因编辑（如 CRISPR）里有特殊意义（限制酶识别位点常是回文）；
- **自然语言**：回文句（如 "A man, a plan, a canal: Panama"）；
- **数据结构**：回文链表（LC 234）、回文树；
- **数学**：回文数（LC 9）、回文素数。

**它们的共同点是"以某个中心对称"**——**而"中心扩展"这一方法，正是"对称结构"的通用处理方式。** 理解了这一点，你面对任何"对称结构"的问题，都会想到"枚举中心、向外扩展"。

> [!info] 从"回文"到"对称结构"
> 回文是"线性对称"的一种。**而"对称"这一概念，在数学、物理、生物、数据结构里无处不在。** **"枚举中心、向外扩展"这一方法，可以迁移到任何"有中心对称性"的对象上。** 这提示我们：**抓住一个具体问题的"抽象结构"（如对称性），能让你的方法迁移到更广的范围。**

## 第 14 章 常见误区与自测方法

### 7.1 四个高频误区

**误区一：中心扩展的 `length = right-left-1` 写成 `right-left+1`。** 偏移错一位，长度就错。

**误区二：DP 没按长度遍历。** 依赖的区间还没算出来，结果错。

**误区三：Manacher 忘了哨兵。** 会越界。

**误区四：Manacher 的镜像初始化写成 `p[i] = p[mirror]`。** 应取 `min(right-i, p[mirror])`，否则可能超出右边界。

### 7.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `"a"` | 单字符 |
| `"aa"` | 偶数回文 |
| `"aba"` | 奇数回文 |
| `"abba"` | 偶数回文（缝隙中心） |
| `"abcda"` | 无长回文 |

**其中 `"aa"` 与 `"abba"` 最值得测**——它们专治"偶数长度回文"（缝隙中心）的处理。**凡是回文题，都要用一个偶数长度的回文验证。**

## 第 15 章 一句话带走

**如果只能从本篇带走一句话，那就是：**"回文问题的关键，是'枚举中心'——而算法的优化，是'复用已算的回文'。"

- **枚举中心**（而非子串），把暴力 $O(n^3)$ 降到 $O(n^2)$——**这是"选对枚举对象"的胜利**；
- **复用已算的回文**（Manacher），把 $O(n^2)$ 降到 $O(n)$——**这是"复用信息"的胜利**。

**这两步，正是"算法优化"的一般路径**：先"换一个更好的枚举对象"，再"复用已经算出的结果"。

**而这道题的另一层启示，是"面试选型的现实考量"**——中心扩展虽 $O(n^2)$，但代码简单、空间 $O(1)$，是**面试首选**；Manacher 虽 $O(n)$，但精巧易错，**能讲原理即可**。**"面试选型"要考虑"代码简单、易讲清"，而非只看复杂度。**

**最后，回文是"对称结构"的实例**——"枚举中心、向外扩展"这一方法，可以迁移到任何"有中心对称性"的对象上（DNA、回文树、对称结构）。

> [!note] 一个可复用的判断
> 遇到"回文/对称"类问题，**先问两句**：需要"判一次"还是"反复判"？上层是"最长/计数/分割/配对"中的哪种？**前者决定用双指针还是预处理，后者决定聚合方式。** 这两问，能定下回文题的骨架。

## 第 16 章 回文算法复杂度速查

| 解法 | 时间 | 空间 | 手写要求 |
|------|------|------|---------|
| 暴力 | $O(n^3)$ | $O(1)$ | 不要求 |
| DP | $O(n^2)$ | $O(n^2)$ | 要求（回文分割要用） |
| 中心扩展 | $O(n^2)$ | $O(1)$ | **必须能手写** |
| Manacher | $O(n)$ | $O(n)$ | 能讲原理即可 |

**"必须能手写"的是中心扩展**——它是面试的标准答案。**DP 在"回文分割"类题里也要求手写**（因为要用到 `isPal` 表）。**Manacher 能讲原理即可**（它太精巧，面试官通常不要求手写）。

**这张表的价值，是"分清'必须手写'与'能讲原理即可'"**——**它帮你把有限的备考时间，花在回报最高的地方。**

> [!note] 一个总体判断
> 遇到"最长回文子串"，**面试默认答中心扩展**（$O(n^2)$、$O(1)$ 空间、代码简单）；被追问"能否更快"时，讲 Manacher 的"镜像利用"思想。**这个策略，既稳妥又能体现深度。**

## 小结

本篇用四种解法，把"最长回文子串"从一个 $O(n^3)$ 的暴力问题，逐步优化到 $O(n)$。**核心观察是"每个回文都有中心"**——它把"枚举子串"降维成"枚举中心"，从而得到中心扩展这一面试标准答案。Manacher 则在中心扩展的基础上，用"镜像利用"把时间降到线性，其正确性来自"右边界只增不减"这一摊还性质。

贯穿全篇的核心认知有两条。其一，**"找对枚举对象"是优化的第一步**——枚举"中心"而非"子串"，就得到了 $O(n^2)$ 的中心扩展。其二，**字符串算法的核心优化思想是"复用已算出的结果"**——KMP 复用前缀信息、Manacher 复用回文信息。**把这两条握住，你面对任何字符串搜索/匹配题，都会先问"该枚举什么、能复用什么"。**

下一篇 [[05 动态规划字符串匹配：正则表达式与通配符]] 将进入字符串 DP 的深水区：LeetCode 10（正则表达式匹配）与 44（通配符匹配）。两道题都被标为困难，核心都是二维 DP，但 `.*` 与 `?*` 的语义差异导致状态转移大相径庭。

**再补充一段落点。** 回文算法从 $O(n^3)$ 到 $O(n)$ 的演进，本质上演示了"算法优化"的三条通用路径：**换枚举对象**（从"枚举子串"到"枚举中心"）、**记录子问题**（DP）、**复用已算结果**（Manacher）。**这三条路径，适用于几乎所有算法优化**——当你在别的领域遇到"太慢"的算法时，不妨依次问："能不能换一个枚举对象？能不能记录子问题？能不能复用已算结果？"

**再看一个更深的落点。** 回文问题看似是"字符串专属"，实则是"对称结构"的实例。**"以某中心对称"这一性质，在 DNA 序列（限制酶位点）、数据结构（回文树）、数学（回文数）里都出现。** 而处理它们的方法——"枚举中心、向外扩展"——是通用的。**当你把一个具体问题抽象成"结构性质"（如对称性）时，你的方法就能迁移到更广的范围**，这正是"从题目到结构"的思维跃迁。

**最后再强调一点"练习方法"。** 中心扩展的代码必须练到"能默写"——**尤其是 `left := center/2; right := left + center%2` 与 `length = right-left-1` 这两处偏移。** 建议用 `"aba"`（奇）与 `"abba"`（偶）两个最小用例，在纸上把每一步的 `left`、`right` 都写出来。**手算一遍，比读十遍代码管用。**

**最后，留一道值得回味的思考题。** 若题目改成"最长回文子序列"（可以不连续），还能用中心扩展吗？**答案是"不能"**——因为中心扩展依赖"连续性"，而子序列不连续，必须改用区间 DP（`dp[i][j]` 表示 `s[i..j]` 的最长回文子序列长度）。**这个对比说明："连续性"是中心扩展的前提，一旦去掉，方法就得换。** 读题时先确认"连续还是可以不连续"，是一个好习惯——**因为"连续"与"不连续"在算法上是两个世界**（前者可用窗口/扩展，后者往往要 DP）。**这也解释了为什么"子串"与"子序列"看似一字之差，解法却天差地别**——"最长回文子串"用中心扩展，"最长回文子序列"用区间 DP。**读题时抓住"子串 vs 子序列"，能少走很多弯路。**
