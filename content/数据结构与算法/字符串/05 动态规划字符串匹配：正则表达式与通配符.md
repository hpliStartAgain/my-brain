# 动态规划字符串匹配：正则表达式与通配符

**摘要：**

本篇深入字符串动态规划的最难范式：LeetCode 10（Regular Expression Matching）与 44（Wildcard Matching）。两道题都被标为困难，核心都是二维 DP，但**通配符语义的细微差异（`.*` vs `?*`）导致状态转移截然不同**。彻底理解它们，不只是学会写 `dp[i][j]`，更是掌握"从左到右逐字符匹配"的思维方式，以及"如何把'匹配到目前的状态'精确编码成 DP 状态"。本文用 Go 语言完整实现两道题，并逐层追问：为什么用"双前缀"定义状态、`*` 在两道题里的语义差在哪、为什么正则的 `*` 要"回头看一个字符"、以及通配符为什么还有一个 $O(1)$ 空间的贪心解法。掌握本篇，你就掌握了字符串 DP 最难的范式。

## 第 1 章 字符串匹配 DP 的通用框架

### 1.1 二维 DP 的含义

字符串匹配类 DP 通常定义为：

$$dp[i][j] = \text{模式串前 } i \text{ 个字符能否匹配文本串前 } j \text{ 个字符}$$

**"两个字符串各取一个前缀，问这两个前缀能否匹配"**——这是"从两个维度同时缩减问题规模"的经典思路。

**下标约定**（0 表示空前缀）：

- `dp[0][0] = true`：空模式匹配空文本；
- `dp[i][0]`：模式前 `i` 个字符匹配空文本；
- `dp[0][j]`：空模式匹配文本前 `j` 个字符（通常为 `false`，除非模式有"可匹配空"的部分）。

**文本字符访问**：`s[j-1]` 是文本第 `j` 个字符（1-indexed 的 DP 用 `j-1` 访问 0-indexed 字符串）。

> [!info] 为什么用"双前缀"而不是"单前缀"
> 若只用一个下标（如"文本前 `i` 个字符"），就无法表达"模式串当前匹配到哪"。**匹配问题是"两个序列的同步推进"，必须两个下标同时刻画。** 这与"编辑距离""最长公共子序列"等经典字符串 DP 是同一框架——**它们的共同点是"两个序列的前缀"**。

## 第 2 章 LeetCode 10：正则表达式匹配

### 2.1 题目

**LeetCode 10 - Regular Expression Matching**（困难）

实现支持 `.` 与 `*` 的正则匹配：`.` 匹配任意单字符；`*` 匹配**零个或多个前面的那个元素**。匹配须涵盖**整个**字符串 `s`。

```text
输入: s="aa",  p="a"     → false
输入: s="aa",  p="a*"    → true
输入: s="ab",  p=".*"    → true
输入: s="aab", p="c*a*b" → true
```

### 2.2 关键难点：`*` 的语义

**这道题最难的地方不是 DP，而是正确理解 `*` 的语义：**

> **`*` 不是独立元素**，它总是与前面的字符组成一个"单元"（如 `a*`、`.*`）。这个单元可以匹配**0 个或多个**该字符。

于是 `a*` 是一个原子单元：可以匹配 0 个 `a`（丢弃单元、不消耗文本）、1 个 `a`（消耗 1 个文本字符、单元留用）、2 个 `a`……**"单元"这一概念，是理解本题的钥匙。**

### 2.3 状态转移

设 `dp[i][j]` = `p[0..i-1]` 能否匹配 `s[0..j-1]`。对模式第 `i` 个字符 `p[i-1]`：

**情况一：`p[i-1] != '*'`**（普通字符或 `.`）——直接比较：

$$dp[i][j] = dp[i-1][j-1] \ \wedge\ (p[i-1] == s[j-1] \ \vee\ p[i-1] == '.')$$

**情况二：`p[i-1] == '*'`**——`*` 与 `p[i-2]` 组成单元，两种选择：

- **选择 A：匹配 0 次**（丢弃 `p[i-2]*` 单元）：`dp[i][j] = dp[i-2][j]`；
- **选择 B：匹配 1 次或更多**（消耗一个文本字符、单元留用）：`dp[i][j] = dp[i][j-1] ∧ match(p[i-2], s[j-1])`。

**注意选择 B 用的是 `dp[i][j-1]` 而非 `dp[i-2][j-1]`**——因为 `*` 单元"还没用完"，可以继续匹配下一个字符。**这是本题最容易被写错的一处。**

合并：

$$dp[i][j] = dp[i-2][j] \ \vee\ (dp[i][j-1] \ \wedge\ \text{match}(i-2, j-1))$$

### 2.4 Go 实现

```go
func isMatch(s, p string) bool {
    m, n := len(p), len(s)
    dp := make([][]bool, m+1)
    for i := range dp {
        dp[i] = make([]bool, n+1)
    }
    dp[0][0] = true

    // 初始化 dp[i][0]：只有 x* 这样的组合才能匹配空文本（* 匹配 0 次）
    for i := 2; i <= m; i++ {
        if p[i-1] == '*' {
            dp[i][0] = dp[i-2][0]
        }
    }

    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            pc, sc := p[i-1], s[j-1]
            if pc == '*' {
                // 选择 A：* 匹配 0 次
                dp[i][j] = dp[i-2][j]
                // 选择 B：* 匹配 1+ 次
                prev := p[i-2]
                if prev == '.' || prev == sc {
                    dp[i][j] = dp[i][j] || dp[i][j-1]
                }
            } else if pc == '.' || pc == sc {
                dp[i][j] = dp[i-1][j-1]
            }
        }
    }
    return dp[m][n]
}
```

**复杂度**：时间 $O(mn)$，空间 $O(mn)$。

### 2.5 手动验证 `s="aab", p="c*a*b"`

```text
初始化：dp[0][0]=true
dp[2][0]：p[1]='*' → dp[0][0]=true（c* 匹配 0 次）
dp[4][0]：p[3]='*' → dp[2][0]=true（a* 匹配 0 次）

dp[3][1]：p[2]='a', s[0]='a' → dp[2][0]=true → true
dp[4][1]：p[3]='*', prev='a', s[0]='a'
   A: dp[2][1]=false；B: 'a'=='a' → dp[4][0]=true → true
dp[4][2]：p[3]='*', prev='a', s[1]='a'
   A: dp[2][2]=false；B: 'a'=='a' → dp[4][1]=true → true
dp[5][3]：p[4]='b', s[2]='b' → dp[4][2]=true → true ✓

最终 dp[5][3]=true ✓
```

## 第 3 章 LeetCode 44：通配符匹配

### 3.1 题目

**LeetCode 44 - Wildcard Matching**（困难）

实现支持 `?` 与 `*` 的通配符匹配：`?` 匹配任意单字符；`*` 匹配**任意字符串（含空串）**。匹配须涵盖整个 `s`。

```text
输入: s="aa",    p="*"    → true
输入: s="cb",    p="?a"   → false
输入: s="adceb", p="*a*b" → true
```

### 3.2 与正则的关键区别

| 特性 | 正则（LC 10） | 通配符（LC 44） |
|------|--------------|----------------|
| `*` 含义 | 匹配**前一个字符** 0 次或多次 | 匹配**任意字符串**（含空） |
| `?` 含义 | 不支持 | 匹配任意单字符 |
| `.` 含义 | 匹配任意单字符 | 不支持 |
| `*` 是否独立元素 | 否（配合前一个字符） | **是**（`*` 本身即元素） |

**核心差异在于"`*` 是不是独立元素"**：正则的 `*` 必须"回头看一个字符"，通配符的 `*` 本身就能匹配任意串。**这一差异，让通配符的转移方程更简单。**

### 3.3 状态转移

对模式第 `i` 个字符 `p[i-1]`：

**情况一：`p[i-1] == '*'`**——匹配空串或任意串：

$$dp[i][j] = dp[i-1][j] \ \vee\ dp[i][j-1]$$

（`dp[i-1][j]`：`*` 匹配空串、丢弃它；`dp[i][j-1]`：`*` 匹配一个字符、留用。）

**情况二：`p[i-1] == '?'` 或 `p[i-1] == s[j-1]`**：`dp[i][j] = dp[i-1][j-1]`。

**情况三：不匹配**：`false`。

**注意情况一里没有"检查字符类型"**——因为 `*` 能匹配任意字符。**这正是"独立元素"带来的简化。**

### 3.4 Go 实现

```go
func isMatchWild(s, p string) bool {
    m, n := len(p), len(s)
    dp := make([][]bool, m+1)
    for i := range dp {
        dp[i] = make([]bool, n+1)
    }
    dp[0][0] = true

    // 初始化：只有全为 * 的模式才能匹配空文本
    for i := 1; i <= m; i++ {
        dp[i][0] = dp[i-1][0] && p[i-1] == '*'
    }

    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            pc, sc := p[i-1], s[j-1]
            if pc == '*' {
                dp[i][j] = dp[i-1][j] || dp[i][j-1]
            } else if pc == '?' || pc == sc {
                dp[i][j] = dp[i-1][j-1]
            }
            // else: 保持 false
        }
    }
    return dp[m][n]
}
```

**复杂度**：时间 $O(mn)$，空间 $O(mn)$（可用滚动数组降到 $O(n)$）。

### 3.5 手动验证 `s="adceb", p="*a*b"`

```text
dp[0][0]=true
dp[1][0]=true（p[0]='*'）
dp[2][0]=false（p[1]='a'）

dp[1][j]（pc='*'）：dp[1][j] = dp[0][j] || dp[1][j-1] → 全部 true
dp[2][1]（pc='a', sc='a'）: dp[1][0]=true → true
dp[2][2..5]（pc='a', sc='d'/'c'/'e'/'b'）: 不匹配 → false
dp[3][j]（pc='*'）: dp[3][j] = dp[2][j] || dp[3][j-1] → j>=1 全 true
dp[4][5]（pc='b', sc='b'）: dp[3][4]=true → true ✓
```

## 第 4 章 两道题的对比与深度理解

### 4.1 核心区别归纳

**正则的 `a*`**（绑定对）：`*` 的能力取决于前面的字符 `a`——匹配 0 次是 `dp[i-2][j]`（跳过整个 `a*`），匹配 1+ 次是 `dp[i][j-1] && match(p[i-2], s[j-1])`（消耗一个字符、单元留用）。

**通配符的 `*`**（独立元素）：能匹配任意串——匹配空串是 `dp[i-1][j]`（丢弃 `*`），匹配一个字符是 `dp[i][j-1]`（留用，**无需检查字符类型**）。

**直观对比**：通配符 `*` 相当于正则 `.*`，但无需"前一个字符"约束，所以转移更简单。**这正是"约束越少、转移越简单"的体现。**

### 4.2 通配符的贪心解法

通配符匹配还有一个 $O(1)$ 空间的贪心解法：

```go
func isMatchGreedy(s, p string) bool {
    si, pi := 0, 0
    starIdx, sMatch := -1, 0 // 记录上一次 * 的位置与对应的 s 下标

    for si < len(s) {
        if pi < len(p) && (p[pi] == '?' || p[pi] == s[si]) {
            si++
            pi++
        } else if pi < len(p) && p[pi] == '*' {
            starIdx = pi // 记录 * 位置
            sMatch = si  // * 先匹配空
            pi++
        } else if starIdx != -1 {
            // 回退：让上一个 * 多匹配一个字符
            pi = starIdx + 1
            sMatch++
            si = sMatch
        } else {
            return false
        }
    }
    // 检查剩余模式是否全是 *
    for pi < len(p) && p[pi] == '*' {
        pi++
    }
    return pi == len(p)
}
```

**核心思想是"贪心 + 回退"**：遇到 `*` 时先让它匹配空、并记下位置；若后续失配，就回退到那个 `*`、让它多匹配一个字符。**最坏复杂度仍是 $O(mn)$**（如 `s="aaab"`, `p="*ab"`），但空间 $O(1)$。**它是"用回退替代表格"的典型——用少量重复计算换掉 $O(mn)$ 的空间。**

> [!info] 从"填表"到"回退"
> 通配符的贪心解法，展示了"同一问题的两种实现哲学"：**DP 用表格记录所有子问题（空间换时间），贪心用回退在必要时重算（时间换空间）。** 两者最坏复杂度相同，取舍在"空间"与"代码直观度"。**理解了这一点，你就明白"DP 不是唯一解"——很多 DP 题都有对应的贪心/双指针写法。**

## 第 5 章 延伸：字符串 DP 的更多范式

本篇的两道题是"匹配类"字符串 DP。字符串 DP 还有几道经典题，值得一并看看。

### 5.1 编辑距离（LeetCode 72）

**题目**：给你两个单词，计算把 `word1` 转换成 `word2` 所需的最少操作数。可用操作：插入、删除、替换一个字符。

**状态**：`dp[i][j]` = 把 `word1` 前 `i` 个字符变成 `word2` 前 `j` 个字符的最少操作数。

**转移**（三种操作对应三个来源）：

$$dp[i][j] = \min\begin{cases} dp[i-1][j] + 1 & \text{删除} \\ dp[i][j-1] + 1 & \text{插入} \\ dp[i-1][j-1] + (w1[i-1] \ne w2[j-1]) & \text{替换/相同} \end{cases}$$

```go
func minDistance(word1, word2 string) int {
    m, n := len(word1), len(word2)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    // 边界：空串到前 j 个字符需 j 次插入；前 i 个字符到空串需 i 次删除
    for i := 0; i <= m; i++ {
        dp[i][0] = i
    }
    for j := 0; j <= n; j++ {
        dp[0][j] = j
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            cost := 1
            if word1[i-1] == word2[j-1] {
                cost = 0 // 相同，无需替换
            }
            dp[i][j] = min3(dp[i-1][j]+1, dp[i][j-1]+1, dp[i-1][j-1]+cost)
        }
    }
    return dp[m][n]
}

func min3(a, b, c int) int {
    if b < a {
        a = b
    }
    if c < a {
        a = c
    }
    return a
}
```

**编辑距离是"字符串 DP"的标杆题**——它把"三种操作"对应到"三个转移来源"，是"分类讨论"思想的完美体现。**它与本篇的正则/通配符共享同一框架（双前缀 + 分类讨论），只是"操作"不同。**

### 5.2 交错字符串（LeetCode 97）

**题目**：给定三个字符串 `s1`、`s2`、`s3`，判断 `s3` 是否由 `s1` 与 `s2` 交错组成（`s1`、`s2` 的字符保持各自相对顺序）。

**状态**：`dp[i][j]` = `s1` 前 `i` 个 + `s2` 前 `j` 个能否交错组成 `s3` 前 `i+j` 个。

**转移**（当前字符来自 `s1` 还是 `s2`）：

$$dp[i][j] = (dp[i-1][j] \wedge s1[i-1] = s3[i+j-1]) \vee (dp[i][j-1] \wedge s2[j-1] = s3[i+j-1])$$

**注意 `s3` 的下标是 `i+j-1`**——**因为 `s3` 的前 `i+j` 个字符，恰好由 `s1` 的前 `i` 个与 `s2` 的前 `j` 个组成。** 这个"下标关系"是本题的关键。

### 5.3 两个字符串的删除操作（LeetCode 583）

**题目**：给定两个单词，返回使它们相同所需的最小步数（每步可删除任意一个字符串中的一个字符）。

**洞察**：**最少删除数 = 两串长度之和 − 2 × 最长公共子序列长度**。于是问题转化为"求最长公共子序列（LCS）"：

```go
func minDistance583(word1, word2 string) int {
    m, n := len(word1), len(word2)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
    }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if word1[i-1] == word2[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1 // 匹配，LCS 加一
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1]) // 不匹配，取较大
            }
        }
    }
    return m + n - 2*dp[m][n]
}
```

**这道题展示了"问题转化"的价值**——把"最少删除"转化为"最长公共子序列"，一下就落到熟悉的 LCS 上。**很多看似新颖的题，本质是某个经典题的"换皮"。**

### 5.4 四道题的共同框架

72、97、583 加上本篇的 10、44，构成"字符串 DP 家族"：

| 题目 | 状态含义 | 转移来源 |
|------|---------|---------|
| LC 10 正则匹配 | 模式前 i 能否匹配文本前 j | 分类讨论（`*` 的两种选择） |
| LC 44 通配符 | 同上 | 分类讨论（`*` 匹配空/一个） |
| LC 72 编辑距离 | 转换的最少操作数 | 三种操作 |
| LC 97 交错字符串 | 能否交错组成 | 当前字符来自哪串 |
| LC 583 删除操作 | 转化为 LCS | 匹配/不匹配 |

**它们共享"双前缀 + 分类讨论"这一框架**——**这正是"字符串 DP"的统一形态：两个下标刻画"两个序列各推进到哪"，转移则按"当前字符的语义"分类。**

> [!info] 字符串 DP 的统一视角
> 从正则匹配到编辑距离，字符串 DP 的题面各异，但框架高度一致——**"双前缀状态 + 按字符分类讨论"**。**理解了这一点，你面对任何字符串 DP 题，都能先问"状态是什么、当前字符有几种处理方式"。** 这两问，几乎能定下字符串 DP 的骨架。

## 第 6 章 字符串 DP 的空间优化与工程细节

### 6.1 滚动数组：从 $O(mn)$ 到 $O(n)$

**字符串 DP 的空间，通常可以压到 $O(n)$**——因为 `dp[i][j]` 只依赖 `dp[i-1][*]`（上一行）与 `dp[i][*]`（本行）。**于是只需保留"上一行"和"本行"两行：**

```go
// 以通配符匹配为例，滚动数组版
func isMatchRolling(s, p string) bool {
    m, n := len(p), len(s)
    prev := make([]bool, n+1) // 上一行
    cur := make([]bool, n+1)  // 本行
    prev[0] = true
    for i := 1; i <= m; i++ {
        cur[0] = prev[0] && p[i-1] == '*'
        for j := 1; j <= n; j++ {
            if p[i-1] == '*' {
                cur[j] = prev[j] || cur[j-1]
            } else if p[i-1] == '?' || p[i-1] == s[j-1] {
                cur[j] = prev[j-1]
            } else {
                cur[j] = false
            }
        }
        prev, cur = cur, prev // 交换
    }
    return prev[n]
}
```

**"滚动数组"是 DP 空间优化的通用技巧**——它把"二维表"压成"两行"，空间从 $O(mn)$ 降到 $O(n)$。**注意 `dp[i-1][j-1]`（左上角）在滚动数组里要小心——因为 `prev[j-1]` 会被本行覆盖前先用到，所以要在覆盖前保存。** 上面的实现用"交换两行"避免了这个问题。

### 6.2 为什么"初始化"最容易错

**字符串 DP 的初始化，是最容易出错的地方**：

- `dp[0][0] = true`（空匹配空）；
- `dp[i][0]`：模式前 `i` 个匹配空文本——**只有 `x*`（正则）或全 `*`（通配符）才能匹配空**；
- `dp[0][j]`：空模式匹配文本前 `j` 个——**通常全 `false`**（除非模式可匹配空）。

**这三行初始化的规则各不相同**，需要逐题分析。**很多人"转移写对了、初始化写错了"，结果在某些边界输入上出错。**

### 6.3 一个"从暴力到 DP"的表达模板

面试中讲字符串 DP，建议按这条链：

1. **定义状态**：`dp[i][j]` = 两个前缀能否匹配；
2. **分析边界**：`dp[0][0]`、`dp[i][0]`、`dp[0][j]`；
3. **分类转移**：当前字符是普通字符/`*`/`?`，分别对应什么；
4. **确定顺序**：从小到大双层循环；
5. **返回 `dp[m][n]`**。

**这条链的价值，是它把"DP"变成了一套"填空流程"**——而非"灵感"。

> [!info] 字符串 DP 的"三步走"
> 任何字符串 DP，都可以按"**定状态 → 定边界 → 定转移**"三步走。**状态是"两个前缀"，边界是"空前缀"，转移是"按当前字符分类"。** 这三步想清楚，代码就自然出来了。**把 DP 变成"流程"而非"灵感"，是应对这类难题的关键。**

## 第 7 章 字符串 DP 的面试策略与常见追问

### 7.1 面试表达的四步

**讲字符串 DP，建议按这个顺序**：

1. **定义状态**："`dp[i][j]` 表示模式前 `i` 个能否匹配文本前 `j` 个。"
2. **分析边界**："`dp[0][0]=true`；`dp[i][0]` 只在 `x*` 时可能为真；`dp[0][j]` 通常为假。"
3. **分类转移**："当前字符是普通字符、`.`、`*` 时，分别对应什么转移。"
4. **确定顺序与返回**："从小到大双层循环，返回 `dp[m][n]`。"

**这四步的核心是"先定义、再分析"**——**很多人一上来就写转移，结果状态定义模糊、边界漏掉。**

### 7.2 常见追问

**追问一："正则的 `*` 和通配符的 `*` 有什么区别？"** 答：正则的 `*` 是"绑定对"（配合前一个字符），通配符的 `*` 是"独立元素"（匹配任意串）。**这一区别决定了转移方程的不同。**

**追问二："为什么正则要用 `dp[i-2][j]`？"** 答：因为 `*` 与 `p[i-2]` 组成单元，匹配 0 次时要"跳过整个单元"。

**追问三："能否优化空间？"** 答：能，用滚动数组从 $O(mn)$ 降到 $O(n)$。

**追问四："通配符有没有非 DP 解法？"** 答：有，贪心 + 回退（$O(1)$ 空间）。

**追问五："这题在生产里对应什么？"** 答：正则匹配对应"正则引擎"（如 RE2、PCRE），通配符匹配对应"文件通配、防火墙规则匹配"。

### 7.3 一个易被忽视的"陷阱"

**字符串 DP 的测试用例，往往包含大量"边界组合"**——如 `""`、`"a"`、`"a*"`、`".*"`、`"*"` 的各种搭配。**手动测试时，很难覆盖全。** 建议**"用穷举式的小输入组合"**：把所有长度 ≤2 的模式与文本组合起来，逐一验证。**这比"挑几个用例"更能暴露 bug。**

**"穷举小输入"是一个通用的测试策略**——**因为 bug 往往藏在"罕见组合"里，而小规模的穷举能覆盖它们。** 这与二叉树专栏"先用三节点小树验证"是同一做法。

> [!info] DP 的"边界组合爆炸"
> 字符串 DP 的边界（空串、`*` 的位置、初始化）会组合出大量情形。**这正是它"看着会、写着错"的原因**——不是转移难，而是"边界组合太多"。**应对办法是"穷举小输入 + 逐个验证"，而非"凭感觉检查"。** 这也解释了为什么 DP 题在面试里"讲得清"比"写得快"更重要——**因为边界一旦漏掉，写得快也没用。**

## 第 9 章 从正则到引擎：真实的正则实现

### 9.1 两类正则引擎

**真实的正则引擎分两大类**：

- **回溯引擎（NFA）**：如 PCRE、Java 的 `java.util.regex`、Python 的 `re`——**它按"尝试 + 回溯"匹配，支持反向引用等高级特性，但可能"指数级回溯"**；
- **自动机引擎（DFA/NFA 混合）**：如 RE2（Google）、Go 的 `regexp`——**它把正则编译成自动机，保证线性时间，但不支持反向引用**。

**本专栏的正则匹配（LC 10）用 DP，本质上是"模拟回溯引擎的匹配过程"**——它保证 $O(mn)$，避免了"指数回溯"。**理解了这一点，你就明白"为什么 LC 10 要用 DP 而不是递归回溯"。**

### 9.2 回溯爆炸：一个真实的性能陷阱

**回溯引擎有一个著名的问题——"灾难性回溯"（catastrophic backtracking）**：某些正则（如 `(a+)+b`）在特定输入下（如 `"aaaaaaaaaaaaaaaaaaaaaaaaaac"`）会尝试指数级种匹配方式，导致"卡死"。

**这就是"正则拒绝服务攻击（ReDoS）"的原理**——攻击者构造恶意输入，让服务器的正则匹配卡死。**防御办法之一，就是用"自动机引擎"（如 RE2），它保证线性时间。**

**"回溯引擎可能指数爆炸，自动机引擎保证线性"——这是"能力"与"性能"的权衡**：回溯引擎支持更多特性（反向引用、环视），但代价是最坏情况可能爆炸。**这与本专栏反复出现的"约束换性能"是同一主题。**

### 9.3 为什么 Go 的 regexp 不支持反向引用

**Go 的 `regexp` 选择了"自动机引擎"**——**它保证线性时间，代价是"不支持反向引用与环视"**。**这是一个明确的工程取舍**：Go 团队认为"**保证线性时间、避免 ReDoS**"比"支持高级特性"更重要。

**这个取舍值得深思**——**在"性能可预测"与"功能强大"之间，Go 选了前者。** 这与"Go 语言整体偏向简单、可预测"是一致的。

> [!info] 从"一道题"到"一个工程决策"
> 正则匹配这道 DP 题，背后是"正则引擎的实现选择"这一工程决策——**回溯引擎 vs 自动机引擎，本质是"功能"与"性能"的权衡。** 理解了这一点，你不仅会解 LC 10，也理解了"为什么 Go 的 regexp 和 Python 的 re 行为不同"。**这种"从题到工程决策"的视野，是面试中"深度"的体现。**

## 第 10 章 常见误区与自测方法

### 7.1 做字符串 DP 的通用步骤

1. **定义状态**：`dp[i][j]` 的含义（通常是两个字符串各取前缀）；
2. **明确初始值**：空前缀的边界（`dp[0][0]`、`dp[i][0]`、`dp[0][j]`）；
3. **推导转移**：对当前字符的每种情况分类讨论；
4. **确定遍历顺序**：确保依赖的子问题已计算（通常双层循环从小到大）；
5. **返回 `dp[m][n]`**。

### 7.2 四个高频误区

**误区一，下标偏移。** `dp[i][j]` 对应 `p[0..i-1]` 与 `s[0..j-1]`，访问字符用 `p[i-1]`、`s[j-1]`。

**误区二，正则的 `*` 判断时机。** 看到 `*` 时要操作的是 `p[i-2]`（`*` 前的字符），不是 `p[i-1]`。

**误区三，正则选择 B 用错下标。** 应是 `dp[i][j-1]`（单元留用），不是 `dp[i-2][j-1]`。

**误区四，通配符初始化一次性填 true。** 应是 `dp[i][0] = dp[i-1][0] && p[i-1]=='*'`，逐个判断。

### 7.3 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| `s="", p="a*"` | 正则：`*` 匹配空 |
| `s="", p=".*"` | 正则：`.` 配 `*` |
| `s="a", p="a*"` | 正则：基本单元 |
| `s="", p="*"` | 通配符：`*` 匹配空 |
| `s="ab", p="?*"` | 通配符：`?` 配 `*` |

**其中 `s="", p="a*"` 最值得测**——它专治"初始化 `dp[i][0]`"这一陷阱（只有 `x*` 才能匹配空文本）。

## 第 11 章 一句话带走

**如果只能从本篇带走一句话，那就是：**"字符串匹配 DP 的全部，就是'双前缀状态 + 按字符分类讨论'。"

- **状态**：两个下标，刻画"两个序列各推进到哪"；
- **边界**：空前缀（`dp[0][0]`、`dp[i][0]`、`dp[0][j]`）；
- **转移**：按"当前字符是普通字符、`.`、`*`、`?`"分类。

**这三件事想清楚，代码就自然出来了。** 而两道题的差异（正则的 `*` 是"绑定对"、通配符的 `*` 是"独立元素"），**只是"分类讨论"里的一种情形不同**——**框架不变，细节变。**

**更进一步，这份"双前缀"框架可以迁移到一切"两个序列的对比"问题**：编辑距离、最长公共子序列、交错字符串、正则匹配。**看到"两个序列"，就该问一句"能不能用双前缀 DP"。**

**而这道题的另一层启示，是"边界组合爆炸"**——字符串 DP 的难点不在转移，而在"边界情形太多"。**应对办法是"穷举小输入、逐个验证"，而非"凭感觉检查"。** 这与本专栏反复强调的"边界周全"一脉相承。

> [!note] 一个可复用的判断
> 遇到"两个序列的匹配/编辑/对齐"问题，**先问三句**：状态是不是双前缀？边界（空前缀）怎么定？当前字符有几种处理方式？**这三问，能定下字符串 DP 的骨架。**

## 第 12 章 字符串 DP 的复杂度速查与选型

### 12.1 复杂度速查

| 题目 | 时间 | 空间 | 可优化到 |
|------|------|------|---------|
| LC 10 正则匹配 | $O(mn)$ | $O(mn)$ | $O(n)$（滚动数组） |
| LC 44 通配符 | $O(mn)$ | $O(mn)$ | $O(n)$（滚动数组）/ $O(1)$（贪心） |
| LC 72 编辑距离 | $O(mn)$ | $O(mn)$ | $O(n)$（滚动数组） |
| LC 97 交错字符串 | $O(mn)$ | $O(mn)$ | $O(n)$ |
| LC 583 删除操作 | $O(mn)$ | $O(mn)$ | $O(n)$ |

**共同点：时间 $O(mn)$、空间可压到 $O(n)$。** **"$O(mn)$ 时间 + $O(n)$ 空间"是字符串 DP 的标准形态。**

### 12.2 选型：DP vs 贪心

**通配符匹配有两种解法**（DP 与贪心），选哪个？

- **DP**：$O(mn)$ 时间、$O(n)$ 空间（滚动数组），**思路清晰、不易错**；
- **贪心**：$O(mn)$ 最坏时间、$O(1)$ 空间，**空间更优但正确性难证**。

**面试中推荐先给 DP（清晰），若面试官追问"能否 $O(1)$ 空间"，再提贪心。** **这与"先给好懂的、再给更优的"是同一策略。**

### 12.3 一个总体判断

**什么时候该用字符串 DP？** **当"两个序列的匹配/编辑/对齐"里，当前状态依赖"前面的状态组合"时。** 若只依赖"前一个状态"（如 KMP 的 `next`），那就不是 DP，而是"线性扫描 + 状态复用"。

**"依赖前一个"vs"依赖前面一组"，是 DP 与线性扫描的分界线**——**DP 的"状态"要能表达"前面若干种情况的组合"，而线性扫描只需一个游标。**

> [!info] 从"一道题"到"一类题"
> 字符串 DP 的五道题（10、44、72、97、583），共享"双前缀 + $O(mn)$ 时间 + $O(n)$ 空间"这一形态。**记住这个形态，你遇到新的"两个序列"问题，就能立刻判断"这是不是字符串 DP"。** **把"一类题"的共性提炼出来，比记住"五道题"更有价值。**

## 小结

本篇用两道困难题，把字符串 DP 的"双前缀"框架讲透。LeetCode 10 的关键是理解 `*` 的"单元"语义——它必须"回头看一个字符"，转移要分"匹配 0 次"与"匹配 1+ 次"两种情况；LeetCode 44 的 `*` 是独立元素，能匹配任意串，转移因此更简单。两者的对比揭示了"约束越少、转移越简单"这一规律。延伸的贪心解法（通配符）则展示了"用回退替代表格"的另一种实现哲学。

贯穿全篇的核心认知有两条。其一，**字符串匹配 DP 的通用框架是"双前缀 + 分类讨论"**——两个下标刻画"两个序列各推进到哪"，转移则按"当前字符的语义"分类。其二，**DP 不是唯一解**——很多 DP 题都有对应的贪心/双指针写法，取舍在"空间"与"直观度"。**把这两条握住，你面对任何字符串匹配题，都能先定状态、再分类讨论。**

下一篇 [[06 字符串整理：最长公共前缀、异位词与计数说]] 进入相对轻松的解析类题目。最长公共前缀考察多字符串的纵向扫描；字母异位词分组考察哈希表的分组设计；Count and Say 是递推生成题。三道题类型不同，但都考察字符串的基本操作，是面试前的"热身"。

**再补充一段落点。** 字符串 DP 的学习，其实是一条"从具体到抽象"的路径：先理解某一道题（如正则匹配）的状态与转移，再发现"编辑距离、交错字符串、LCS"用的是同一套"双前缀"框架，最后上升到"任何两个序列的对比，都能用双前缀 DP"这一抽象。**当你完成这三级跳跃，字符串 DP 就不再是"几道难题"，而是"一个可以套用的框架"。** 而这，正是本专栏反复强调的"从题目到模式"——**题目会忘，框架不会。**

**再看一个更深的落点。** 正则匹配这道题，其实触及了"计算能力"的一个边界——**正则语言（能被 DFA 识别）与上下文无关语言（需要栈）的分界**。LC 10 的 `.` 与 `*` 构成的仍是正则语言，所以能用 DP（本质是模拟 DFA）解决；而"括号匹配"（需要计数嵌套）就不是正则语言，必须用栈。**理解了这条边界，你就明白"为什么有些字符串问题用 DP、有些必须用栈"。** 这是形式语言理论给算法设计的直接指导。

**最后再强调一点"练习方法"。** 字符串 DP 的难点在"边界组合爆炸"，所以最好的练习方式是"穷举小输入"——把所有长度 ≤3 的模式与文本组合起来，逐一验证。**这比"挑几个用例"更能暴露 bug，也更能让你"看清边界"。** 面试前，把 LC 10 与 44 的所有小输入组合过一遍，你对"边界"的理解会深一大截。

**最后，留一道值得回味的思考题。** 若把 LC 10 的 `.` 改成"匹配任意字符串（含空）"、`*` 保留原义，问题会变简单还是变复杂？**答案是变复杂**——因为 `.` 从"单字符"变成"任意串"，状态转移里就多了一层"`. 匹配多少字符"的选择。**这个思考题说明：符号的语义，直接决定了转移的复杂度。** 理解了这一点，你在读题时就会格外关注"每个符号的确切语义"——**因为语义差一点，转移就差很多。** 这也是字符串 DP"读题比写码更重要"的原因——**很多人写错，不是不会写 DP，而是没把符号的语义读准。** 动笔前先把"每个符号的确切含义"写下来，是一个值得养成的习惯。**先对齐语义，再推导转移，是字符串 DP 的正确顺序**——很多失分，不是因为"想不出 DP"，而是因为"从一开始就把符号理解错了"。**这也是为什么本篇花了不少篇幅讲"`*` 的语义"——它比转移方程本身更重要。**
