# 二分查找核心模板：从基础到左右边界锁定

**摘要：**

二分查找的思想极简单（每次排除一半），但**代码极容易写错**——"`mid` 怎么算""区间是闭还是开""`left` 更新为 `mid` 还是 `mid+1`"，任何一处出错都会导致死循环或漏解。**写对二分的钥匙，是"不变量"——明确"搜索区间"是什么、每次循环后它如何缩小。** 本文用三道题展开：**二分查找**（LC 704，基础）、**搜索插入位置**（LC 35，找"第一个 ≥ target"的位置）、**在排序数组中查找元素的第一个和最后一个位置**（LC 34，左右边界）。全文用 Go 语言实现，并逐层追问：`mid = left + (right-left)/2` 为什么能防溢出、"闭区间"与"左闭右开"两种写法的差异、以及"找左边界"与"找右边界"为什么只需改一处。

---

## 第 1 章 二分的本质：不变量

### 1.1 从"猜数字"说起

**二分查找的思想，可以用"猜数字游戏"理解**——**1 到 100 之间猜一个数，每次告诉"大了/小了"，最优策略是"每次猜中间"。** **因为每次都能排除一半，所以 $\log_2 100 \approx 7$ 次就能猜中。**

**二分查找的复杂度 $O(\log n)$，正来自"每次排除一半"。**

### 1.2 不变量：写对二分的钥匙

**二分的代码容易写错，根本原因是"区间定义不清晰"。** **解决办法是"明确不变量"**——**即"每次循环开始时，`target` 一定在哪个区间内"。**

**最常见的两种写法**：

- **闭区间 `[left, right]`**：不变量是"`target` 在 `[left, right]` 内"。初始 `left=0, right=n-1`；循环条件 `left <= right`（因为 `left == right` 时区间还有 1 个元素）；`left = mid+1`、`right = mid-1`。
- **左闭右开 `[left, right)`**：不变量是"`target` 在 `[left, right)` 内"。初始 `left=0, right=n`；循环条件 `left < right`；`left = mid+1`、`right = mid`。

**"明确不变量"，就能推出"循环条件"与"指针更新"**——**这是写对二分的通用方法。**

> [!info] 核心概念：不变量——二分查找的"宪法"
> 二分查找的每一行代码，都应由"不变量"推出——**"区间是闭还是开"决定了"循环条件"；"`target` 在区间内"决定了"指针如何更新"。** **写二分时，先写下不变量，代码就自然出来了。** **很多人"凭记忆写二分"，结果边界总是错——因为他们没有"不变量"这一锚点。**

## 第 2 章 LeetCode 704：二分查找

### 2.1 题目

**LeetCode 704 - Binary Search**（简单）

给定一个 $n$ 个元素有序的（升序）整型数组 `nums` 和一个目标值 `target`，写一个函数搜索 `nums` 中的 `target`，如果目标值存在返回下标，否则返回 -1。

### 2.2 闭区间写法

```go
func search(nums []int, target int) int {
    left, right := 0, len(nums)-1 // 闭区间 [left, right]
    for left <= right {           // left == right 时区间还有 1 个元素
        mid := left + (right-left)/2 // 防溢出
        switch {
        case nums[mid] == target:
            return mid
        case nums[mid] < target:
            left = mid + 1 // target 在右半，新区间 [mid+1, right]
        default:
            right = mid - 1 // target 在左半，新区间 [left, mid-1]
        }
    }
    return -1
}
```

**复杂度**：时间 $O(\log n)$、空间 $O(1)$。

### 2.3 左闭右开写法

```go
func searchHalfOpen(nums []int, target int) int {
    left, right := 0, len(nums) // 左闭右开 [left, right)
    for left < right {          // left == right 时区间为空
        mid := left + (right-left)/2
        switch {
        case nums[mid] == target:
            return mid
        case nums[mid] < target:
            left = mid + 1 // 新区间 [mid+1, right)
        default:
            right = mid // 新区间 [left, mid)
        }
    }
    return -1
}
```

**两种写法都正确**，**区别只在"区间是闭还是开"**——**闭区间用 `right = mid-1`、循环 `left <= right`；左闭右开用 `right = mid`、循环 `left < right`。**

### 2.4 `mid = left + (right-left)/2` 为什么能防溢出

**若写成 `mid = (left + right) / 2`，当 `left`、`right` 都很大时，`left + right` 可能溢出**（如两个 `2^31-1` 相加）。**而 `left + (right-left)/2` 先算差值、再加，避免了溢出。**

**注意这是"向下取整"**——**当 `left + right` 为奇数时，`mid` 取较小的那个。** **"向下取整"影响"二分是否收敛"**——**若用 `mid = left + (right-left+1)/2`（向上取整），则"`left = mid`"的更新可能死循环。**

**"防溢出"与"取整方向"是两个细节**——**它们共同决定二分是否正确。**

> [!warning] 生产避坑：`mid` 的取整方向与死循环
> 当"`left = mid`"（而非 `mid+1`）时，**必须用"向上取整"（`mid = left + (right-left+1)/2`），否则会死循环**（如 `left=0, right=1` 时 `mid=0`，`left = mid` 后 `left` 不变）。**"`mid` 的取整方向"要与"指针更新方式"匹配**——这是二分最隐蔽的坑。

## 第 3 章 LeetCode 35：搜索插入位置

### 3.1 题目

**LeetCode 35 - Search Insert Position**（简单）

给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。

```text
输入: nums = [1,3,5,6], target = 5  →  2
输入: nums = [1,3,5,6], target = 2  →  1
输入: nums = [1,3,5,6], target = 7  →  4
```

### 3.2 思路：找"第一个 ≥ target"的位置

**这道题求的是"第一个 $\ge$ target 的位置"**——**即"下界（lower bound）"**：

```go
func searchInsert(nums []int, target int) int {
    left, right := 0, len(nums)-1
    for left <= right {
        mid := left + (right-left)/2
        if nums[mid] < target {
            left = mid + 1 // 太小，去右半
        } else {
            right = mid - 1 // 太大或相等，去左半
        }
    }
    return left // left 就是"第一个 >= target"的位置
}
```

**复杂度**：时间 $O(\log n)$、空间 $O(1)$。

### 3.3 为什么返回 `left`

**循环结束时 `left > right`**——**此时 `left` 恰好是"第一个 $\ge$ target 的位置"。**

**直觉**：**`left` 的语义是"候选答案的起点"**——**每次 `nums[mid] < target` 时，`left = mid+1`（说明 `mid` 及左边都 < target）；否则 `right = mid-1`（说明 `mid` 可能是答案，但还要看左边）。** **循环结束时，`left` 就是"第一个不满足 `< target`"的位置，即"第一个 $\ge$ target"。**

**"找下界（第一个 ≥ target）"是二分的一个重要变体**——**它广泛用于"插入位置""第一个满足条件的位置"等场景。**

### 3.4 三种"边界"的统一

**二分查找的"边界"问题，可以统一成三种"找"**：

- **找"第一个 ≥ target"**（下界）：`nums[mid] < target` 时 `left = mid+1`，否则 `right = mid-1`；
- **找"第一个 > target"**（上界）：`nums[mid] <= target` 时 `left = mid+1`，否则 `right = mid-1`；
- **找"最后一个 ≤ target"**：等价于"上界 − 1"。

**"三种找"的差异，只在"比较符用 `<` 还是 `<=`"**——**理解了这一点，你就掌握了二分的全部变体。**

> [!info] 核心概念：二分的"三种找"
> 二分查找的变体，可以统一成"三种找"——**找第一个 ≥（下界）、找第一个 >（上界）、找最后一个 ≤。** **它们的差异只在"比较符"，而框架完全一致。** **"把变体归纳成'三种找'"，是掌握二分的关键**——**你不再需要"记多个模板"，而是"记一个框架 + 三种比较符"。**

## 第 4 章 LeetCode 34：在排序数组中查找元素的第一个和最后一个位置

### 4.1 题目

**LeetCode 34 - Find First and Last Position of Element in Sorted Array**（中等）

给你一个按照非递减顺序排列的整数数组 `nums`，和一个目标值 `target`。请你找出给定目标值在数组中的开始位置和结束位置。若不存在则返回 `[-1, -1]`。

```text
输入: nums = [5,7,7,8,8,10], target = 8  →  [3,4]
```

### 4.2 思路：找左边界 + 找右边界

**"第一个位置"= "第一个 ≥ target 的位置"（若该位置的值 == target）**；**"最后一个位置"= "第一个 > target 的位置 − 1"。**

```go
func searchRange(nums []int, target int) []int {
    left := lowerBound(nums, target)
    if left == len(nums) || nums[left] != target {
        return []int{-1, -1}
    }
    right := lowerBound(nums, target+1) - 1
    return []int{left, right}
}

// 找"第一个 >= target"的位置
func lowerBound(nums []int, target int) int {
    left, right := 0, len(nums)-1
    for left <= right {
        mid := left + (right-left)/2
        if nums[mid] < target {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }
    return left
}
```

**复杂度**：时间 $O(\log n)$（两次二分）、空间 $O(1)$。

### 4.3 关键：为什么用"找 target+1 的下界"求右边界

**"最后一个 target" = "第一个 > target 的位置 − 1"**——**而"第一个 > target"就是"`target+1` 的下界"**（**在整数数组里，"$>$ target"等价于"$\ge$ target+1"**）。

**"用 `target+1` 的下界求右边界"，避免了一个"找上界"的独立函数**——**它复用了"找下界"。**

**但注意**：**若 `target` 是 `MaxInt`，`target+1` 会溢出**——**此时需改用"找上界"的独立写法。** **这是一个隐蔽的边界。**

### 4.4 手动验证 `[5,7,7,8,8,10]`、`target=8`

```text
lowerBound(8):
  left=0, right=5, mid=2(7): 7<8 → left=3
  left=3, right=5, mid=4(8): 8>=8 → right=3
  left=3, right=3, mid=3(8): 8>=8 → right=2
  left=3 > right=2 → 返回 3 ✓

lowerBound(9):
  left=0, right=5, mid=2(7): 7<9 → left=3
  left=3, right=5, mid=4(8): 8<9 → left=5
  left=5, right=5, mid=5(10): 10>=9 → right=4
  left=5 > right=4 → 返回 5
  右边界 = 5 - 1 = 4 ✓

结果: [3,4] ✓
```

> [!note] 设计哲学：复用"找下界"
> "找右边界"可以复用"找下界"——**"最后一个 target" = "`target+1` 的下界 − 1"。** **这个复用避免了一个独立函数，但也引入了"`target+1` 溢出"的隐患。** **"复用"与"边界安全"之间的权衡，是工程中常见的取舍。**

## 第 5 章 常见误区与自测方法

### 5.1 四个高频误区

**误区一，`mid = (left + right) / 2` 溢出。** 应用 `left + (right-left)/2`。

**误区二，"闭区间"与"左闭右开"混用。** 循环条件与指针更新必须匹配。

**误区三，`left = mid` 时用"向下取整"。** 会死循环，应用"向上取整"。

**误区四，LC 34 用 `target+1` 时忘了溢出。** `target` 是 `MaxInt` 时会出错。

### 5.2 一套自测用例

| 用例 | 检验什么 |
|------|---------|
| 空数组 | 边界 |
| 单元素（等于/不等） | 最简 |
| target 小于所有元素 | 下界 = 0 |
| target 大于所有元素 | 下界 = n |
| 全部等于 target（LC 34） | 左右边界 = 0, n-1 |

**其中"全部等于 target"最值得测**——它检验"左右边界"的极端情形。

## 小结

本篇用三道题讲清了二分查找。**核心是"不变量"**——明确"搜索区间"是什么，就能推出循环条件与指针更新。**LC 704** 展示了"闭区间"与"左闭右开"两种写法；**LC 35** 展示了"找下界（第一个 ≥ target）"；**LC 34** 展示了"用 `target+1` 的下界求右边界"。

贯穿全篇的核心认知有两条。其一，**"不变量"是写对二分的钥匙**——先写下不变量，代码就自然出来了。其二，**二分的变体可以归纳成"三种找"**（找第一个 ≥、找第一个 >、找最后一个 ≤）——**它们的差异只在比较符。** **把这两条握住，你面对任何二分查找的问题，都有了实现的起点。**
