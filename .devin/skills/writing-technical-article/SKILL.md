# 技术文章写作（凤凰架构风格 DNA）

## 一、定位与边界

- **风格基准**：周志明《凤凰架构》（icyfenix.cn）全站 43.4 万字蒸馏出的六层 Writing DNA，经老板确认（2026-09-04，demo：`content/可观测/链路追踪/03 OpenTelemetry 统一标准.md`）。
- **适配目标**：my-brain 知识库（Quartz + Obsidian 语法）优先，兼容一般中文技术长文。
- **核心原则**：复刻写法，不复刻内容——原文观点与事实不得搬进新文章；保留 my-brain 既有骨架（frontmatter/摘要/章节/mermaid/思考题），只做**句法层 + 认知层**注入。
- **不适用**：公众号短内容、小红书/推特体、纯标题摘要（这些走对应的其他 skill）。

## 二、写前必读（硬性步骤，不可跳过）

1. **通读 `references/style-rules.md` 全文**——六层规则与正反例，一份不跳。
2. **通读 `references/delivery-standard.md`**——仓库交付硬指标（篇幅 12000-16000 字/500+ 行、论述五问、Mermaid/Callout/双向链接/tags 规范、批量执行与验证流程）。本文件管"达不达标"，style-rules.md 管"像不像"，两者并列生效。
3. **读目标系列最近的 1-2 篇现有文章**——校准骨架约定（frontmatter 字段、摘要格式、章节编号、`[[wiki链接]]`、mermaid 主题、思考题格式）。新系列无历史文章时跳过。
4. **判定文章类型**，从四套结构模板中选一套（见 style-rules.md L2 节）：
   - 历史演进类 / 概念原理类 / 流程实践类 / 叙事前言类

## 三、写作规则速览（细则与例句见 style-rules.md）

| 层 | 一句话要求 | 硬性检查点 |
|---|---|---|
| L1 语言 | 长句多逗号的绵密书面语，短句只用于强调 | 转折用「但/不过」；举例用「譬如」；自称「笔者」；感叹号禁用 |
| L2 结构 | 按类型套模板，开头三式之一 | 开场不直陈定义，先历史/设问/范围限定 |
| L3 选题 | 历史/起源先行 → 问题与定义 → 标准与实现分离评价 | 不写安装命令、API 手册、Hello World |
| L4 素材 | 年份锚点 + 权威序列 + 贯穿案例 + 比喻 | 每个大章节至少 1 个贴切比喻；引用给年份/版本 |
| L5 认知 | 落点必须是权衡取舍、因地制宜，不吹不踩 | 争议话题设「不足与争议」式小节，正反逐项权衡 |
| L6 视觉 | 加粗 1-2 处/千字，加在术语、结论、对比词 | 首次术语「中文（English）」格式；表格做方案对比 |

## 四、写作流程

1. **骨架决策**：改写已有文章 → 保留全部技术资产（图/表/代码/链接/思考题），重写叙述性文字；新文章 → 按模板搭骨架。
2. **认知层铺排**：先写「这条主线的叙事弧」（为什么分裂→为什么统一→代价是什么→如何取舍），再填技术内容。
3. **句法层成文**：按 L1/L4 规则写，每完成一章对照检查点过一遍。
4. **收束**：结论式（由此可见…因地制宜）或展望留有余地式（目前仍然言之尚早），禁止口号式升华。

## 五、写后自检（硬性）

逐项执行 `references/checklist.md`，任何一项不达标则改写后再交付。

## 六、与其他 skill 的协作

- **去 AI 味**：成稿后可调用 `unclecheng-reduce-ai-perception-v2` 清理；**与本 skill 规则冲突时，以本 skill 为准**（如「长句多逗号」「笔者」是目标风格特征，不是 AI 痕迹）。
- **配图**：架构图/流程图走 `sre-architecture-visual-style`；mermaid 遵循目标系列既有主题（my-brain 现行 dracula 主题）。
